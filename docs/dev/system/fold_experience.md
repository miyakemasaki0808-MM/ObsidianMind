## 1. 何のための文書か

**Fold の原則が2箇所に分かれ、Fold の体験が増えるほど余白ペインの設計書に積もる形だった。**
線引きは UIデザインの指針の1項目、具体は margin_pane の判断1にあった。
本文の見開き・卓上の形・外画面・面を越える移動はどれも余白ペインの派生ではないので、上位に置く。

**北極星は変えない** — 「過去の自分の思考と再会し、もう一段深める、オンデバイスAIの読書相手」。
この文書は、それを開いた Fold でどう実現するかだけを決める。

## 2. 机の一文

> **開いた Fold では、一冊を読む場所が、思考を並べて考える机になる。机の上で並べたものも、次の再会の材料として残る。**

**広げたのは再会の対象である。** 1冊のノートから、並べて考えた組み合わせへ。
Fold の体験を北極星の外に置かず、Rediscover から Reflect へのループを濃くする側に入れる。

## 3. 面の名前 — 位置ではなく役割で呼ぶ

| 役割 | 呼び名 | Google の語 | 中身 |
|---|---|---|---|
| 今のノートを読む面 | **主の面** | main pane | 本文 |
| 並べて考える面 | **補助の面** | supporting pane | 余白メモ・前回の跡・部分要約・並べ読み・探索 |

- **原則・契約・機能の仕様では左右上下を使わない。** 折り目が横なら上下に分かれ、端末を回せば向きが変わり、
  折り目の無い窓でも2面に分かれる。位置で定義すると、そのたびに判断が割れる
- **役割を位置へ割り当てるのは純関数1か所だけ**（今は [`readerLayoutFor`](../../../app/src/main/java/com/example/newproject/ui/screen/ReaderLayout.kt)）。
  割り当ての表は下の「姿勢の割り当て」が持つ
- **「ヒンジ」も契約の語にしない。** 折り目の無い Expanded の窓も、中央で2面に分かれる。外へ向けて「ヒンジの向こうへ」と言うのは構わない

## 4. 不変条件 — 今のノートは主の面の1つだけ

- **補助の面のノートは今のノートにならない。** 訪問の記録・要約・分野判定・余白メモ・再会カードは、主の面のノートだけを相手にする
- **補助の面のノートを今のノートへ替えるのは、利用者の明示の操作だけ**（今は「このノートへ移る」）。替えたノートは主の面へ移る
- **今は型で守られている。** [`SideReadingController`](../../../app/src/main/java/com/example/newproject/controller/SideReadingController.kt) が
  受け取るのは自分の Writer だけで、今のノートや痕跡を書く口を持たない（→ [architecture](architecture.md) 判断5の2）
- 理由と、採らなかった案（2つ目の今のノート・複数インスタンス）は [ADR-0006](../decisions/ADR-0006-single-current-note.md)

## 5. 契約

| # | 契約 | 今 | 機能か体験か |
|---|---|---|---|
| 1 | 主の面の今のノートを保ったまま、補助の面を独立して探索できる | 実装済み。関連ノートか本文のリンクから右で開き、右のノートの中のリンクで右のまま辿る。辿った順は持たない（→ [desk_foundation](../features/desk_foundation.md)） | 体験 |
| 2 | 面を越えて情報を移せる。**行き先はサイドカーの余白メモだけ**で、本文には書かない | 未実装 | 移す操作は体験。移した結果の余白メモは機能 |
| 3 | 並べて考えた結果を、痕跡として残せる | 未実装。今の並べ読みは痕跡を残さない | **機能** — 保存するデータが増えるので、スマホでも再会から読める形を置く |
| 4 | 同じ読書の中なら、閉じて開いても、**操作すれば**補助の面の配置が戻る | 実装済み。窓が変わると机は閉じるが並べ読みは終えず、出せる窓へ戻った後に ✎ で机を開くと同じノートを同じ位置で出す。余白の面の位置は戻さない（→ [desk_foundation](../features/desk_foundation.md)） | 体験 |

- **契約4で保つのは机の中身で、画面の形ではない。** 閉じて開いた直後はふだんの画面から始め、✎ で机を開くと同じ配置で戻る（→ §6 の初期状態）
- **翌日の机は契約にしない。** 日をまたいで配置を戻すと、アプリの入口が「昨日の机」になり、
  偶然に引く入口と取り合う。日をまたぐ再開は契約3の痕跡を経由し、再会カードから返す
- **契約2の行き先を広げない。** 本文へ書くと [ADR-0004](../decisions/ADR-0004-do-not-rewrite-vault-body.md) を破る
- **Fold 専用の体験を足すときは、どの契約か、§6 の姿勢の割り当てのどの行から導けるかを先に書く。** どちらからも導けないものは机の外にあり、北極星の判断基準からやり直す。
  姿勢の行を足したのは、補助の面を使わない主の面だけの体験（本文の見開き → [note_spread](../features/note_spread.md)）が契約からは導けず、姿勢の行に行き先が書いてあったため（2026-10-19、オーナー判断）
- **構造への影響（見立て）:** 補助の面に AI を載せない限り、契約1の寿命は [architecture](architecture.md) 判断4 の既存の行に収まり、
  世代の三層目は要らない。AI を載せる案は、この見立てを崩すので先に判断4を当て直す

### 機能と体験の線引き

**機能は共有し、体験は Fold 専用を許す。** Fold 専用のデータや重複した機能は作らないが、Fold でしか成立しない表示と操作は作ってよい。
迷ったら2つを問う — **閉じたときに書いたものや記録を失うか**、**保存するデータが増えるか**。
どちらかに当たれば機能として扱い、スマホにも同じものを置く。
**今のノートを増やす案は、この問いにかける前に不変条件で落ちる。**

## 6. 姿勢の割り当て

**位置の語が出てくるのはこの表だけ。** 判定の順と寸法の下限は [margin_pane](../features/margin_pane.md) の「並べ方と、判定の優先順」が持つ。

| 窓と折り目 | 今 | 契約での行き先 |
|---|---|---|
| 縦の折り目（本の形・平らに開いた形） | **初期状態はふだんの画面**（下の「初期状態」）。✎ で折り目で主と補助に分ける（主が左）。左のレールの見開きのタブで、本文を左右2ページの見開きに組む（→ [note_spread](../features/note_spread.md)） | 同じ |
| 横の折り目（卓上の形） | 縦積み。補助の面は出さない | 上に主、下に補助。書くとキーボードが下を覆うので、この形で読む頻度を確かめてから |
| 折り目なしで Expanded | 初期状態はふだんの画面。✎ で本文領域の中央で分ける。見開きのタブは出さない | 同じ |
| 高さの足りない横長 | 左右2列（操作と再会カード／本文）。補助の面ではない | 同じ |
| それ以外の狭い窓 | 補助の面はシートで出す | 同じ |
| 閉じた外画面 | スマホと同じ | 外画面だけの体験は未定 |

- **初期状態 — 開いた窓でも、閉じた画面と同じふだんの画面から始める（2026-10-21、オーナー判断）。**
  ふだんの画面は、見出しの操作の行（Rediscover・💬・✎・⛶・別のノートをひらく・冊子）・題名・ノートの縦積みで、閉じた画面とスマホで見ているものと同じである。
  机（補助の面）と本文の見開きは、**利用者の操作でだけ出す** — 机は ✎（と、別のノートへのリンク → [note_links](../features/note_links.md)）、見開きは左のレールの見開きのタブ。
  Fold を閉じて開いたとき・内側を横にして戻したとき・狭い分割から広げたとき・アプリを起動し直したときは、どれも自分からは出さない。
  - **理由:** 姿勢とペインの設定で画面の形が自動で替わると、開いた瞬間に、閉じた画面で読んでいたものと違う画面が出る（オーナーが実機で触って違和感を持った）。入り方を操作に寄せれば、開いても読んでいた画面のまま続く
  - **机と見開きは、出せない窓へ移ったら閉じ、出せる窓へ戻っても開かない。** 閉じるのは画面の形だけで、机の中身（並べ読みのノートと位置）は保ち、✎ で開けば同じ配置で戻る（契約4）
  - **窓の判定は窓の情報が揃ってから行う。** 画面の作り直しの直後は1フレームだけ折り目が届かず、それを「出せない窓」と読むと、作り直しのたびに机を閉じてしまう（→ [margin_pane](../features/margin_pane.md) §5.4）
  - **出せるかの判定は、閉じる判定と描画の側で同じ値を読む。** 横幅の区分と折り目だけでは決まらず（高さの足りない横長・幅の下限）、本文領域の寸法まで入力に入れる（→ [margin_pane](../features/margin_pane.md) §5.4）
  - 個々の規則は、机が [margin_pane](../features/margin_pane.md) §5.4、見開きが [note_spread](../features/note_spread.md) §5・判断2、レールのタブが [tab_navigation](tab_navigation.md) §1 にある
- **折り目に操作を置かない。** 面を越えて移すときの落とし先も、折り目から離す
- **補助の面を出している間は、主の面と補助の面を同じ大きさで並べる。** タブのレールと主の面に付いた操作は出さず、
  操作は主の面の上のつまみを下へ払って呼ぶ（→ [margin_pane](../features/margin_pane.md) の「並べ方と、判定の優先順」）
- **縦の払いはつまみで操作を呼び、横の払いは片側を1画面にする。** 横は主の面と補助の面のどこからでも受け、本文のスクロール・文字の選択・画面の端の戻る操作とは、
  縦横を動き始めで決めることと長押しを待つことで分ける。折り目（溝）では受けない（→ [margin_pane](../features/margin_pane.md) の「並べ方と、判定の優先順」）。
  補助の面を1画面にしても今のノートは主の面のまま（§4）で、契約1から導く
- **窓の大きさで決め、端末の種類では決めない。** 分割窓で狭ければ、開いた Fold でも補助の面はシートになる

## 8. この文書が持たないもの

- **入力（キーボード・マウス・スタイラス）とアクセシビリティ。** 全端末に効くので Fold の契約ではない。ここへ足すと、この文書が余白ペインの代わりに積もる先になる
- **着手の順。** ロードマップが持つ
- **個々の機能の仕様。** `features/` が持つ
- **外向けの呼び名。** 「ワークステーション」のような語は何でも正当化できるので、判断の物差しにしない。外へ向けて名乗るのは配布が決まってからで、置き場は README

## 9. 検査

**規則が守られたのは検査に載せたときだけ**（→ [lessons](../lessons.md) L29）。契約は実装と同時に検査を置く。

| 対象 | 固定の仕方 | 今 |
|---|---|---|
| 不変条件 | 補助の面の Controller が受け取る口を、自分の Writer に限る。契約1で口が増えるときに、今のノートの切替と訪問の記録を呼ばないことをテストで固定する | 型で成立。右で別のノートへ辿っても今のノートと記録が変わらないことを `NoteSessionCoordinatorTest` が固定 |
| 契約1 | 補助の面の要求と失効の契機を、両方向のテストで（`SideReadingControllerTest` を広げる） | 右で辿るのは右で開くのと同じ口なので、選び直しの失効の検査（`SideReadingControllerTest`）がそのまま覆う。右のリンクの行き先は `NoteLinkActionsTest` |
| 契約2 | 行き先を余白メモの型に限る | 未 |
| 契約3 | 痕跡のスキーマ版と移行のテスト | 未 |
| 契約4 | 開閉の遷移を純関数にして JVM で確かめる。組み合わせの順序は実機ケースで見て、実機で起こせない順序は正本で先に宣言する | 閉じて開くとふだんの画面で始まり ✎ で同じ配置へ戻ること、窓でペインが閉じても並べ読みを終えず机をしまう操作で終えることを `NoteReadingFlowTest`。起こせない順序は [desk_foundation](../features/desk_foundation.md) §10 |
| 初期状態 | 机と見開きのタブを窓で閉じる判定を純関数にして JVM で確かめる（横幅の区分と折り目が同じまま高さだけが替わる窓を含む）。ほかのタブにいる間に窓が替わる順序を instrumentation で | 窓の値と戻し・見開きのタブの窓を `ReaderLayoutTest`、レールの並びと押したときの選択を `AppScaffoldRailTest`。外殻で高さを往復する順序（ノートの画面とさがすの画面）を `ReaderWindowShellTest` |
