## 1. 背景

読む面は静かなのに、設定・余白メモ・蒸留・さがすの面では、状態の言い直しや操作の説明がいつも出ていた。
機能を足すたびに「誤解を防ぐ一文」を足してきた結果で、書き方を決めた正本が無かった。
いつも出る説明が多いと、本当に読んでほしい警告（平文の退避がクラウドへ渡る、取り消せない書き換え）が埋もれる。

## 2. 規則

1. **状態を言い直さない。** スイッチ・選択・札が見せている状態を、副題の文で繰り返さない。副題は「何が変わるか」を名詞か短い句で言う
2. **操作の手順を説明しない。** 引ける・押せる・選べることは部品の形で伝える。手順の文が要るなら、その部品を直す
3. **内部の数字と技術語を出さない。** 上限の本数・件数・バイト数・文字コード・ハッシュの語を画面の文にしない。利用者の次の行動に関わる結果だけを言う（「大きすぎて蒸留できません」）
4. **助言と指示の口調を使わない。** 「〜すると〜になりますが」「〜してください」で教えない。起きていることと、できることを言う（「時間をおいて開き直せます」）
5. **安全の説明は要る瞬間に出す。** 書き出す・確定する・消す瞬間の確認に置き、いつも出る説明にしない。いつも出すなら1行の結論に絞る
6. **安心の文と警告を混ぜない。** 取り消せないことは、それだけを別の行で言う
7. **1つの文に1つのことを言う。** 回数・経過・位置・割合を1文に詰めない

**削らないもの:** 安全の意味は言い方を変えても残す — ノート本体が変わらないこと、「見つからない」と「読み取れない」の区別、
まだ書き戻していないこと、平文の退避が同期でクラウドへ渡ること、取り消せない書き換え。

## 3. 語の組（ボタンの言葉）

**重さで使い分ける**（2026-11-28、オーナー判断）。

| 働き | 軽い操作（取り消せる・失うものが無い） | 取り消せない操作の確認 |
|---|---|---|
| 取り消し（何もせずに閉じる） | やめる | キャンセル |
| 削除 | 消す | 削除 |
| 中断（走っているものを止める） | 止める | — |

- 取り消せない操作の確認では、実行のボタンに起きることの動詞を書く（「削除」「復元する」）。「OK」「はい」にしない
- 「閉じる」は、何も起きない表示を閉じるときだけに使う
- **確認の場でも、失うものが無い操作は軽い組にする。** 痕跡の読み戻しは損失の無い合わせ込み（→ [reading_trace_backup](../features/reading_trace_backup.md)）なので、下見の確認の取り消しは「やめる」のまま。重い組は、取り消すと元に戻せないものを失う操作（削除・上書き・取り消せない書き換え）だけに使う

## 4. ブランドの語

**残す**（2026-11-28、オーナー判断。ブランドの感じを出したい）。

- 4つのタブの見出し **Rediscover・Explore・Connect・Reflect** は英語のまま
- 関連のタブの札 **linked** は英語のまま
- 規則 3 の「技術語を出さない」はブランドの語に当てない。ブランドの語は意味を説明する文を添えずに使う

## 5. 色

- **赤（`ErrorText`）は失敗にだけ使う。** 既定の状態で出る注記を赤にしない。さがすの「すべて」の注記は補助の色で静かに出す（2026-11-28、オーナー判断 → [ai_picker](../features/ai_picker.md) 判断1）

## 6. 検査

- **文言の契約テストは意味を見る。** 否定語・禁止語・必須の概念（「ノート本体は変わらない」など）を検査し、全文一致では固定しない。書き換えのたびにテストを書き直す形にしない
- 規則 3 の内部の言葉（復旧情報・復旧レコード・URI・現在の走査・めやすに）は、画面へ渡す文の層（ui・controller・蒸留の書き込みの結果）で走査する（`UiCopyScanTest`）
- 規則 3 の内部の数字（40本・3件・256KB・UTF-8・1MB）と、語の組の外の直書き（取り消しの「キャンセル」を軽い操作に使うなど）は、書き換えと一緒にソース走査で落とす
- 失敗の文は `failureText`（場面ごとの `FailureScene`）の1か所で決め、例外の文と `Unknown error` を画面の状態へ入れない（`FailureTextTest`）
