**状態:** 構想。Room と KSP を足したビルドの確認まで済み、索引そのものは未実装
**最終検証:** 未検証（実装前）
**関連コード:** `data/KnowledgeIndexDatabase.kt`（空のエンティティ1つ）。走査の共有は `NoteScanCache.kt`、リンクの読み方は `domain/NoteLinks.kt`

## 1. 責務と利用者

**Vault のノートを一度読み、次からは変わったノートだけ読み直して、ノートをまたぐ問いに速く答える。**
今の走査（`NoteScanCache`）は60秒の寿命しか持たず、ノートの本文を読まない。索引はその外側に、プロセスを越えて残る層を足す。

| 利用者 | 索引から引くもの | 段 |
|---|---|---|
| バックリンク（→ [backlinks](../features/backlinks.md)） | 今のノートを指すリンクと、リンクを含む1文 | 区切り2 |
| ランダム表示（→ [rediscover](../features/rediscover.md)） | 起動直後に使うノートの一覧 | 区切り3 |
| 余白メモと引用（出し方は未定） | ほかのノートに書いた自分の言葉 | 区切り4 |

**全文検索はここに入れていない。** バックリンクを使ってから決める（2026-11-14、オーナー判断）。
入れるなら、さがすの非ゴール「全文検索をしない」（→ [ai_picker](../features/ai_picker.md) §2）を書き換える。
**目次（今のノートの見出し一覧）は扱わない。** DB が要らない別の話なので、段5の範囲から外した（同日、オーナー判断）。

## 2. 判断1: DB を正にしない

永続化の置き場は3つになる。**DB に置いてよいのは、Vault から作り直せるものと、アプリの外へ出す必要が無いものだけ。**

| 置き場 | 役割 | 消えたら |
|---|---|---|
| Vault の `.md`・サイドカー（`_ReadingTraces/`） | **利用者の資産。** 他端末や Obsidian から読める | 失う。だから正 |
| SharedPreferences | 小さな設定値と当日の閲覧履歴 | 設定が戻る |
| **DB（知識索引）** | **Vault から作った派生物** | **作り直すだけ。ノートもメモも無傷** |

- **DB にしか無い情報を作らない。** 利用者が書いたものは必ず Vault 側へ先に書き、索引はそれを読み写す
- **余白メモと引用は載せる**（2026-11-14、オーナー判断）。メモと引用は、書いたノートをもう一度引くまで戻ってこない。
  500本の Vault から一様に引くと、同じノートを引き直すのはまれである。索引に載せれば、ほかのノートを読んでいるときに
  自分の言葉を補助の面へ出す下地になる。正は痕跡ファイルのままで、索引は読み写すだけなので、判断1の範囲に収まる。
  出し方はまだ決めていない（→ §11 の区切り4）
- **閲覧履歴を DB へ移さない。** さがすの非ゴール「履歴を翌日へ持ち越さない」を保つ（2026-11-14、オーナー判断）
- **痕跡の集計は載せない。** 見せる面が決まっていない（同日、オーナー判断）
- **エンティティと DAO は `data` に閉じる。** `model` は依存グラフの葉なので Room を知らない（`PackageDependencyTest`）。
  `controller` からはインターフェース越しに触り、Android 非依存を保つ（→ [architecture](architecture.md) 判断5）

## 3. 判断2: 索引は走査の結果に合わせて直す

**いつ作るか:** Vault を開いたら背景で作る（2026-11-14、オーナー判断）。
**公開された走査の結果を受け取るたびに、索引を突き合わせて直す。** 走査は寿命の切れた一覧を誰かが頼んだときにしか走らず、
60秒の寿命は自動で走るタイマーではない。そこで、**索引を作る側が自分で走査を頼む契機**を次に限って持つ。

| 契機 | 頼み方 | 公開されなかったら |
|---|---|---|
| Vault を開いた | 復元・選び直しの後始末がすべて終わってから頼む | 下の2行と同じ |
| アプリが本文を書き換えた | 一覧を捨てた（`expireAfterBodyWrite`）後に頼む | **頼んだ走査の途中でまた書き換えると、その走査は公開されない。** そのときは書き換えの後でもう一度頼む。書き換えが止まれば必ず公開される |
| 頼んだ走査が読めずに空だった | 寿命を与えられないので公開されない | **既存の行を消さずに残し**、次の契機（Vault を開く・本文の書き換え・ほかの機能の走査の公開）を待つ。待つ間に繰り返し頼まない |

- **ほかの機能（ランダム表示・さがす・関連・冊子など）が頼んだ走査が公開されたときも、同じく突き合わせる。** 外部の編集が索引に入る契機はこれである
- **公開の知らせに、走査が読み切れたかを載せる。** 今の `onPublished` は一覧だけを渡し `VaultScan.isComplete` を落とすので、手順3の判断に要る形へ広げる

1. 走査の結果（`NoteFile` の相対パスと更新日時）と、索引にあるノートを比べる
2. 次のどれかに当たるノートだけ本文を読み、リンクを取り出して入れ替える
   - 索引に無い（新しいノート）
   - 更新日時が索引のものと違う
   - **更新日時が走査でも索引でも空。** 日時を返さないプロバイダでは「日時が同じ」を「変わっていない」と読めないので、突き合わせのたびに読む。
     読んだ本文の指紋（ハッシュ）が索引のものと同じなら、行を書き換えない
   - **アプリが本文を書き換えたと控えてある**（→ 手順4）。日時が同じでも読む

   **「日時が同じ」と「変わっていないと確かめた」を分ける。** 前者で飛ばしてよいのは、両方の日時が空でないときだけ
3. 走査に無いノートは索引から消す。**ただし走査が読み切れたときだけ**（`VaultScan.isComplete`）。
   読めなかったフォルダがある走査で消すと、一時的に読めないだけのノートの索引を失う
4. アプリが本文を書き換えた（蒸留の保存・太字の復元）ときは、**そのノートの相対パスを「読み直す」と控える。**
   控えは次の突き合わせで日時に関わらず読み、読み終えたら外す。日時の変化だけに頼ると、日時を返さないプロバイダや、同じ秒の書き換えで読み直しが漏れる

- **走査は今の `NoteScanCache` を共有する。** 索引のために別の走査を走らせない。ランダム表示・さがす・関連と同じ1回の走査に相乗りする
- **本文の読み方は表示と同じ上限（1MB）で切る。** それを超える分にあるリンクは、本文のリンクとしても描かれないので数えない
- **リンクの読み方は、本文で押せるリンクと同じにする。** `parseMarkdownBlocks` と `scanInlineSyntax` が押せると決めたものだけを数え、
  コードの中や画像のリンクは数えない（→ [note_links](../features/note_links.md) §5 の表）。押せないのにバックリンクに出る、を作らない

## 4. 判断3: 今の Vault の分だけ持つ

- 索引は**1つの Vault の分だけ**持ち、どの Vault の索引かを DB に控える。開いた Vault と違えば、全部消して作り直す
- **Vault を A→B→A と選び直すと、A の索引も作り直しになる。** 複数の Vault を使い分けることはまれで、持ち続けると消し忘れの面が増える
- 照合は Vault の URI の文字列で行う。**実行中の索引作りを止める照合は `vaultGeneration` で行い、URI で代用しない**
  （A→B→A で同じ値になって旧い作業が素通りする → [architecture](architecture.md) 判断4）

## 5. 判断4: 作る側は Vault 単位、引く側はノート単位

[architecture](architecture.md) 判断4 の表の別々の行に置くので、**Controller を2つに分ける。**

| Controller（予定） | 形 | 止める契機 | 結果を捨てる契機 | 契約への登録 |
|---|---|---|---|---|
| 索引を作る側 | Vault 単位 | Vault 切替（`vaultGeneration`） | Vault 切替 | **どちらにも載せない。** `onVaultChanged()` だけ |
| バックリンクを引く側 | ノート単位 | ノート切替（`activeRequestId`） | ノート切替 | `cancelNoteScopedJobs()` と `withNoteScopedReset()` の両方 |

- **作る側の進み具合（作ったノートの数と全体の数）は Vault 単位の状態。** ノートを開き直しても消さない
- **索引が直るたびに、引く側は今のノートの分を引き直す。** 索引の世代（直すたびに進む数）を引く側が見る。
  引き直しの結果は、照合した世代と今のノートがまだ同じときだけ書く
- **引く側は AI を呼ばない。** 補助の面に AI を載せない限り、[fold_experience](fold_experience.md) §5 の見立てどおり世代の三層目は要らない

## 6. データの形

| 表 | 1行 | 主な欄 |
|---|---|---|
| 索引の素性 | 1行だけ | Vault の URI・索引の版・最初の作成を終えたか |
| ノート | 1ノート | 相対パス（主キー）・documentId・名前・**読んだときの更新日時（空でありうる）**・**読んだ本文の指紋**・読めたか |
| リンク | 1リンク | 出どころの相対パス・本文の中の順番・記法（名前／パス）・**書かれた行き先**・見出し・リンクのある節の見出し・リンクを含む1文 |
| 余白メモと引用 | 区切り4で決める | — |

- **リンクは書かれたまま持ち、行き先を索引の時点で決めない。** `[[名前]]` がどのノートを指すかは、同じ名前のノートが増減すると変わる。
  引くときに、今のノートの名前で候補を絞り、本文のリンクを押したときと同じ規則（`resolveNoteLink`）で出どころから解いて、
  **本当に今のノートへ着くものだけを残す**（→ [note_links](../features/note_links.md) §8 判断3）
- 名前で絞るための鍵は、リンクの末尾の名前を正規化したもの（大文字小文字を区別せず `.md` を外す）。パスで書いたリンクも末尾の名前で鍵を作る
- 1文は `splitIntoSentences` で切った、リンクを含む文。長ければ切り詰める

## 7. ランダム表示との関係（大きな Vault の最初の待ち）

**ランダム表示も索引のノートの一覧から引く**（2026-11-14、オーナー判断）。

- **索引の一覧は、走査の共有の入れ物（`NoteScanCache`）へ入れない。** 入れ物の公開は、一覧・リンクの索引・`knownNotes`・分野の索引を1か所で替える。
  関連ノートや本文のリンクは、入れ物にある一覧を寿命を見ずに使うので、古い一覧を入れるとランダム表示の外へ漏れる
- **索引を作る側が「復元した一覧」を別に持ち、ランダム表示だけがそれを読む。** ほかの機能は今どおり入れ物だけを使い、入れ物の使い方は変えない
  1. 入れ物に寿命の中の一覧があれば、それから引く（今どおり）
  2. 無ければ、**今の Vault の世代で復元した一覧**があるときだけ、それから引き、裏で走査を頼む
  3. どちらも無ければ、今どおり走査を待つ
- **復元した一覧は、読み出した時点の `vaultGeneration` を控える。** 照合が合わなければ使わず、Vault 切替で捨てる。A→B→A と選び直しても旧い一覧は戻らない
- 走査が公開されたら、入れ物の一覧を先に使う（手順1）。復元した一覧は、次に Vault を開くまで使わない
- **痕跡のセッションと紙の地色は、今どおり本文より先に決める**（→ [rediscover](../features/rediscover.md) 判断3）。材料は引いた `NoteFile`（相対パスと、索引に控えた更新日時）。
  **紙の地色は Vault 全体の更新日時の分布と比べて決め、その分布は今は入れ物の一覧から作る**（→ [note_age_paper](../features/note_age_paper.md)）。
  入れ物が空のあいだに復元した一覧から引いたときは、分布も復元した一覧から作る。引いたノートの色を決めるためだけに使い、入れ物には入れない
- **消えたノートを引いたら、黙って引き直す。** 開けなかったことを利用者には見せない。何度も続くなら走査を待つ
- 実装のときに [rediscover](../features/rediscover.md) の判断1・判断2（どの一覧から引くか・60秒の寿命）を直す
- **初めて開く Vault は今と同じだけ待つ。** 索引がまだ無いため
- **受理:** 3,000本の合成 Vault で、索引がある状態から最初のランダム表示まで測り直し、今の値（約15.5秒）より短ければよい。数字の線は引かない（同日、オーナー判断）。測り方と今の値は課題台帳の、大きな Vault ほど最初のランダム表示まで長く待つ件が持つ

## 8. 上限・性能・スレッド

> **未確認:** 500本・3,000本で最初の作成にかかる時間と、DB の大きさは測っていない。区切り1の実機で測る。

- **本文の読み込みは同時に数本まで。** 関連ノートの並列読込と同じく上限を置く（→ [related_notes_ai](../features/related_notes_ai.md) 判断6）
- **本文の解析は Main の外。** 入力の大きさに比例するので `Dispatchers.Default` で行い、`ThreadingScanTest` の表へ1行足す（→ [architecture](architecture.md) 判断3）
- DB の読み書きは Room の suspend で、Main を塞がない
- 1つのノートから取るリンクの数と、1文の長さに上限を置く。値は区切り1で決める

## 9. プライバシーとバックアップ

- **DB は端末の外へ出さない。** ネットワーク権限が無いうえ、端末の自動バックアップからも外す（`backup_rules.xml`・`data_extraction_rules.xml`、`BackupExclusionTest`）。
  リンクを含む1文と、区切り4のメモの本文は利用者の個人的な内容である
- Vault を替えたら前の Vault の索引を消す（→ §4）

## 10. 検証

- **JVM:** リンクの取り出し（押せる記法だけ・コードの中を除く・1文の切り出し）、差分の決め方（新規・更新・消えた・読み切れない走査では消さない）、
  バックリンクの解き方（同じ名前が複数のときに今のノートへ着くものだけ）、Vault の照合。DB は偽物のインターフェースで差し替える
- **instrumentation:** Room の DAO をメモリ上の DB で確かめる。索引の素性が違えば消して作り直すこと
- **実機:** 合成 Vault（500・3,000本）で最初の作成の時間と、2回目の起動のランダム表示の時間
- **実機で起こせないので自動テストが持つ順序:**
  - 索引作りの途中で Vault を替える → 旧い Vault の結果を書かない（両方向。替えた後に旧い本文の読み込みが終わる場合も）
  - 索引作りの途中で蒸留が本文を書き換える → 書き換え後の本文で読み直す
  - 更新日時が走査の前後ともに空のノートで、リンクを足す・消す → 次の突き合わせで反映される。アプリの書き換えは日時が同じでも読み直す
  - 引く側の要求の途中で索引が直る → 新しい世代で引き直し、旧い結果で上書きしない
  - 走査が一部のフォルダを読めない → そのフォルダのノートを索引から消さない
  - 走査の途中で本文を書き換える（公開されない）／走査を終えた後に書き換える → どちらも画面を操作せずに新しい索引へ進む
  - 頼んだ走査が読めずに空だった → 既存の行を消さず、次の契機で直る
  - 走査を止めた状態でランダム表示する → 復元した一覧から引き、関連・さがす・リンクの解決・`knownNotes`・分野の索引には流れない。
    走査を終えた後は入れ物の一覧から引く。Vault を A→B→A と選び直しても旧い復元の一覧から引かない
- **保証していないこと:** Obsidian で書き換えたノートは、次に走査が公開されるまで索引に入らない。
  走査が走るのは、寿命（60秒）の切れた一覧をどれかの機能が頼んだとき（ノートを開く・ランダム表示・さがすなど）と、Vault を開いたとき・アプリが本文を書き換えたときで、タイマーでは走らない。
  DB の作成に失敗した端末では、バックリンクとランダム表示の先出しが使えない（今の動きに戻るだけ）。
  復元した一覧から引いたノートの紙の地色は、索引に控えた更新日時で決まるので、外部で書き換えた直後は前の年代の色になりうる

## 11. 区切り（実装の順）

1. **索引の土台。** 表・作る側の Controller・走査との突き合わせ・Vault の照合・バックアップの除外。画面は変えない
2. **バックリンク。** 引く側の Controller と、余白ペイン・関連タブの節（→ [backlinks](../features/backlinks.md)）
3. **ランダム表示の先出し。** §7 と、大きな Vault での測り直し
4. **余白メモと引用を載せる。** 載せる理由はこの文書に書く。補助の面への出し方は、それまでにオーナーが決める

全文検索を入れるかは、区切り2を使ってから決める。
