## 1. 責務と利用者

**Vault のノートを一度読み、次からは変わったノートだけ読み直して、ノートをまたぐ問いに速く答える。**
今の走査（`NoteScanCache`）は60秒の寿命しか持たず、ノートの本文を読まない。索引はその外側に、プロセスを越えて残る層を足す。

| 利用者 | 索引から引くもの | 段 |
|---|---|---|
| バックリンク（→ [backlinks](../features/backlinks.md)） | 今のノートを指すリンクと、リンクを含む1文。互いのリンクを除くために、今のノートから出るリンクも引く | 区切り2 |

**ランダム表示は索引から引かない**（→ §7）。**余白メモと引用は載せない**（保留 → §2）。
**全文検索は入れない**（2026-11-21、オーナー判断）。バックリンクを使ってから決めると置いていた件で、
さがすの非ゴール「全文検索をしない」（→ [ai_picker](../features/ai_picker.md) §2）を保つ。
意図を持った探索は、さがすのタイトルと AI のモードが受ける。本文で探すことは再会から省察へのループを濃くせず、
入れるには本文を DB に持ち、分かち書きの無い日本語の区切り方まで決めることになる。
**目次（今のノートの見出し一覧）は扱わない。** DB が要らない別の話なので、段5の範囲から外した（同日、オーナー判断）。

## 2. 判断1: DB を正にしない

永続化の置き場は3つになる。**DB に置いてよいのは、Vault から作り直せるものと、アプリの外へ出す必要が無いものだけ。**

| 置き場 | 役割 | 消えたら |
|---|---|---|
| Vault の `.md`・サイドカー（`_ReadingTraces/`） | **利用者の資産。** 他端末や Obsidian から読める | 失う。だから正 |
| SharedPreferences | 小さな設定値と当日の閲覧履歴 | 設定が戻る |
| **DB（知識索引）** | **Vault から作った派生物** | **作り直すだけ。ノートもメモも無傷** |

- **DB にしか無い情報を作らない。** 利用者が書いたものは必ず Vault 側へ先に書き、索引はそれを読み写す
- **余白メモと引用は載せない。段5では保留にした**（2026-11-21、オーナー判断）。2026-11-14 には載せると決めていた。
  メモと引用は書いたノートをもう一度引くまで戻ってこず、500本の Vault から一様に引くと同じノートを引き直すのはまれなので、
  索引に載せてほかのノートを読んでいるときに出す下地にする考えだった。
  補助の面への出し方が決まらず、**使い道の無い索引を先に作らない**ことにした。バックリンクを使ってみて、
  補助の面に一覧を足すと読む負荷が増えると分かったことも背景にある。
  載せ直すとしても、正は痕跡ファイルのままで索引は読み写すだけなので、判断1の範囲に収まる
- **閲覧履歴を DB へ移さない。** さがすの非ゴール「履歴を翌日へ持ち越さない」を保つ（2026-11-14、オーナー判断）
- **痕跡の集計は載せない。** 見せる面が決まっていない（同日、オーナー判断）
- **エンティティと DAO は `data` に閉じる。** `model` は依存グラフの葉なので Room を知らない（`PackageDependencyTest`）。
  `controller` からはインターフェース越しに触り、Android 非依存を保つ（→ [architecture](architecture.md) 判断5）

## 3. 判断2: 索引は走査の結果に合わせて直す

**いつ作るか:** Vault を開いたら背景で作る（2026-11-14、オーナー判断）。
**公開された走査の結果を受け取るたびに、索引を突き合わせて直す。** 走査は寿命の切れた一覧を誰かが頼んだときにしか走らず、
60秒の寿命は自動で走るタイマーではない。そこで、**索引を作る側が自分で走査を頼む契機**を次に限って持つ。

| 契機 | 頼み方 | 公開されなかったら |
|---|---|---|
| Vault を開いた | 復元・選び直しの後始末がすべて終わってから頼む | 下の2行と同じ |
| アプリが本文を書き換えた | 一覧を捨てた（`expireAfterBodyWrite`）後に頼む | **頼んだ走査の途中でまた書き換えると、その走査は公開されない。** そのときは書き換えの後でもう一度頼む。書き換えが止まれば必ず公開される |
| 頼んだ走査が読めずに空だった | **入れ物は寿命を与えずに、空の一覧として公開する**（一覧とリンクの索引を空に替え、知らせも出す） | 作る側はこれを準備完了と見なさない。**既存の行を消さずに残し**、次の契機（Vault を開く・本文の書き換え・ほかの機能の走査の公開）を待つ。待つ間に繰り返し頼まない |

- **ほかの機能（ランダム表示・さがす・関連・冊子など）が頼んだ走査が公開されたときも、同じく突き合わせる。** 外部の編集が索引に入る契機はこれである
- **公開の知らせに、走査の種別を載せる。** 今の `onPublished` は一覧だけを渡し `VaultScan.isComplete` を落とすので、次の3つを区別できる形へ広げる
  - **読み切れた**（空の Vault を含む）— 準備完了。手順3で消してよい。読み切った空の Vault なら索引の行を全部消し、空と確定する
  - **一部を読めた**（読めないフォルダがあるが、一覧は空でない）— 準備完了。ただし手順3では消さない
  - **読めずに空**（読めないフォルダがあり、一覧も空）— **準備完了と見なさない。** 突き合わせもしない
- **入れ物の動きは変えない。** 読めずに空でも公開する今の作りに、ほかの機能（さがす・関連・冊子など）が乗っているので、区別は知らせを受ける側で行う

1. 走査の結果（`NoteFile` の相対パスと更新日時）と、索引にあるノートを比べる
2. 次のどれかに当たるノートだけ本文を読み、リンクを取り出して入れ替える
   - 索引に無い（新しいノート）
   - 更新日時が索引のものと違う
   - **更新日時が走査でも索引でも空。** 日時を返さないプロバイダでは「日時が同じ」を「変わっていない」と読めないので、突き合わせのたびに読む。
     読んだ本文の指紋（ハッシュ）が索引のものと同じなら、行を書き換えない
   - **アプリが本文を書き換えたと控えてある**（→ 手順4）。日時が同じでも読む

   **「日時が同じ」と「変わっていないと確かめた」を分ける。** 前者で飛ばしてよいのは、両方の日時が空でないときだけ
3. 走査に無いノートは索引から消す。**ただし走査が読み切れたときだけ**（`VaultScan.isComplete`）。
   読めなかったフォルダがある走査で消すと、一時的に読めないだけのノートの索引を失う
4. アプリが本文を書き終えた（蒸留の保存・保存前の本文への復元）ときは、**そのノートを「読み直す」と控え、書き換えの番号を進める。**
   控えは次の突き合わせで日時に関わらず読む。日時の変化だけに頼ると、日時を返さないプロバイダや、同じ秒の書き換えで読み直しが漏れる。
   **知らせは書き込みの完了の直後に、I/O の中から出す**（`DistillController` の `onBodyWritten`）。画面用の読み直しの成否・表示中のノートかどうか・
   保存中のノート切替に関わらず届く。**書き込みを始めた後の失敗**（書いた後の検証の失敗など）でも、本文は変わっているかもしれないので知らせる。
   **控えはその I/O の中で同期で永続する**（`markRewrittenNow`）— 画面のスコープへ渡すと、書いている途中に ViewModel が破棄されたとき控えが作られない。
   控えさえ残れば、次に Vault を開いたときの突き合わせが読み直す。走査の一覧を捨てて走査を頼むのだけは、調停が Main へ移してから行う。
   **控えは参照そのもので持つ** — 相対パスがその場で引けなくても、索引に無いノートでも控えられる。索引に無いノートを初めて読んでいる途中に
   書き換えても、読み始めたときに控えが無く書くときにあるので、古い本文は書かれない。参照は Vault ごとに違うので、前の Vault の控えは今の Vault のノートに当たらない。
   読み切れた走査に無い参照の控え（消えたノート・前の Vault の参照）は、突き合わせで外す。
   **控えを外せるのは、同じ参照のパスを全部書き終え、番号が読み始めたときのままのときだけ。** 控えは参照の単位で持つので、外すのも参照の単位にする —
   同じ文書を2つのフォルダに見せるプロバイダでは1つの参照に2つのパスがあり、先に書いた1件が外すともう1件が読み直されない。
   読んでいる途中にもう一度書き換えると番号が進むので、古い読み込みは控えを外さず、次の突き合わせで新しい本文を読む。1件でも読めなかったときも外さない。
   **外すのは読み切れた走査のときだけ** — 一部を読めない走査では、その回に読んだパスが同じ参照の全部のパスとは限らない。控えのあるノートは、読み切れた走査が来るまで毎回読み直す。
   **ノートの行を消しても控えは消さない** — 参照を保ったまま名前を変えたノートは、新しいパスで読み直す。読み切れた走査に無い参照の控えだけを外す。
   控え（パスと書き換えの番号）は DB の表に置き、プロセスが終わっても残す

**古い読み込みに新しい結果を上書きさせない。** 控えを外す条件だけを守っても、2つの突き合わせが重なって新しい読み込みが先に終わると、
遅れた古い読み込みが DB を古い本文へ戻し、控えも外れた後なので以後読み直さない。次の2つを両方持つ。

- **突き合わせは Vault ごとに1本ずつ順に走らせる。** 走っている間に公開の知らせや本文の書き換えが届いたら「もう一度」の印を1つ立て、
  走り終えたら印を下ろしてもう1回走らせる。届いた知らせは1回にまとめてよいが、捨てない。Vault 切替で印も捨てる
- **DB へ書くのは、読み始めたときの書き換えの番号が、書くときもその参照の最新であるときだけ。** 照合と行の入れ替えを1つのトランザクションで行う。
  番号が進んでいれば、読んだ結果を捨てて控えを残し、次の回で新しい本文を読む。控えを外すのは、同じ参照のパスを全部書き終えた後に、番号が同じときだけ（別のトランザクション）

- **走査は今の `NoteScanCache` を共有する。** 索引のために別の走査を走らせない。ランダム表示・さがす・関連と同じ1回の走査に相乗りする
- **本文の読み方は表示と同じ上限（1MB）で切る。** それを超える分にあるリンクは、本文のリンクとしても描かれないので数えない
- **リンクの読み方は、本文で押せるリンクと同じにする。** `parseMarkdownBlocks` と `scanInlineSyntax` が押せると決めたものだけを数え、
  コードの中や画像のリンクは数えない（→ [note_links](../features/note_links.md) §5 の表）。押せないのにバックリンクに出る、を作らない

## 4. 判断3: 今の Vault の分だけ持つ

- 索引は**1つの Vault の分だけ**持ち、どの Vault の索引かを DB に控える。開いた Vault と違えば、全部消して作り直す
- **Vault を A→B→A と選び直すと、A の索引も作り直しになる。** 複数の Vault を使い分けることはまれで、持ち続けると消し忘れの面が増える
- 照合は Vault の URI の文字列で行う。**実行中の索引作りを止める照合は `vaultGeneration` で行い、URI で代用しない**
  （A→B→A で同じ値になって旧い作業が素通りする → [architecture](architecture.md) 判断4）

## 5. 判断4: 作る側は Vault 単位、引く側はノート単位

[architecture](architecture.md) 判断4 の表の別々の行に置くので、**Controller を2つに分ける。**

| Controller（予定） | 形 | 止める契機 | 結果を捨てる契機 | 契約への登録 |
|---|---|---|---|---|
| 索引を作る側 | Vault 単位 | Vault 切替（`vaultGeneration`） | Vault 切替 | **どちらにも載せない。** `onVaultChanged()` だけ |
| バックリンクを引く側 | ノート単位 | ノート切替（`activeRequestId`） | ノート切替 | `cancelNoteScopedJobs()` と `withNoteScopedReset()` の両方 |

- **作る側の進み具合（読み終えたノートの数と読む予定の数）は Vault 単位の状態**（`knowledgeIndexProgress`）。ノートを開き直しても消さず、Vault 切替で捨てる。
  Vault を開いた時点で最初の作成を終えていれば「出来上がり」、まだなら「作っている途中」で、最初の作成の間だけ数を出す。その後の差分の読み直しでは出さない。
  **書くのは百分の一ごとと最後だけ** — 3,000本の Vault で読むたびに画面の状態を替えると、状態を見ている画面がそのたびに描き直す。
  **最初の作成が止まったら「作れなかった」にする**（置き場を開けない・書けない・走査を頼めない）。「作っています」のまま残すと待てば出ると誤って伝えるため。
  次の正常な作成で戻る。作り終えた後の失敗では出来上がりのまま（索引は差分が古いだけで引ける）。旧い Vault の遅れた失敗は書かない。
  **Vault を開いたときの初期値は、突き合わせか失敗が先に決めていれば書かない** — 初期化が置き場を開く途中で待つ間に、ほかの機能の走査の公開で突き合わせが先に終わると、
  遅れて戻った古い控えが決まった値を「作っています」に戻し、走査の寿命の中では公開が来ないので戻らない。突き合わせが走っている間に走査を頼めなかったときも、その結果に任せる
- **引く側の結果は、DB の行と、走査の入れ物にあるリンクの索引（`NoteLinkIndex`）の2つで決まる。** 候補は DB から絞り、解くのは入れ物の索引で行うため。
  そこで、**どちらかが替わったら引き直す。** 作る側が、公開を受けたときと索引を直し終えたときに知らせ（`onChanged`）、調停が本文を出しているノートの分を引き直す。
  最新の公開（種別つき）は作る側が持ち、Vault 切替で捨てる
- **その Vault で準備完了の公開（§3 の種別）がまだ一度も無い間は「引いている」のまま待つ。** リンクの索引が空だと、`resolveNoteLink` はほかのノートへのリンクをすべて「まだ引けない」（`NotReady`）と返す。
  これを0件に畳まない。DB に差分が無い起動でも、最初の走査が公開された時点で引き直して一覧が出る
- **最新の公開が「読めずに空」なら、引かずに「読めない」にする。** リンクの索引が空に替わっているので、解けば全部が「まだ引けない」になる。「確かめた0件」にはしない。次に準備完了の公開が届いたら引き直して通常へ戻る
- **出どころが入れ物の索引に無いときは、その出どころを解かずに除く。** 一部のフォルダを読めなかった走査では、DB に残した出どころが入れ物の索引に無いことがある。
  出どころの相対パスが分からないまま解くと、根からの相対で解いて行き先を誤るので、代用しない。DB の行は消さない（→ §3 の手順3）
- **結果を書くのは、その照会がまだ取り消されていないときだけ。** ノートの切替・索引の直し・公開のどれでも前の照会を取り消して新しい照会を始めるので、
  世代の数を別に照合しない（照合しても、それを消すと落ちるテストを書けない → [architecture](architecture.md) の並行処理の規約）。
  置き場の読み出しは取り消しで止まらないことがあり、取り消した後に失敗や別の Vault の答えで戻ると取り消しを確かめずに届くので、**書く前に照会が生きているかを確かめる**（並べ読みと同じ形）
- **引く側は AI を呼ばない。** 補助の面に AI を載せない限り、[fold_experience](fold_experience.md) §5 の見立てどおり世代の三層目は要らない

## 6. データの形

| 表 | 1行 | 主な欄 |
|---|---|---|
| 索引の素性 | 1行だけ | Vault の URI・最初の作成を終えたか・書き換えの番号の最後の値（Vault を替えても戻さない）。索引の版は DB の版で、上げたら移行を書かずに作り直す |
| ノート | 1ノート | 相対パス（主キー）・参照・名前・**読んだときの更新日時（空でありうる）**・**読んだ本文の指紋**。読めなかったノートは行を作らず、次の突き合わせで読み直す |
| 読み直しの控え | 1参照 | 参照（主キー）・**書き換えの番号**。アプリが本文を書き終えたときに足し、§3 の条件で外す。索引に無いノートの参照も持つ |
| リンク | 1リンク | 出どころの相対パス・本文の中の順番・記法（名前／パス）・**書かれた行き先**・見出し・**リンクのある節の見出しと、同じ見出しのうち何番目か**・リンクを含む1文・**1文の中のリンクの位置**（始まりと終わり。1行の切り出しと「このノート」への置き換えに使う → [backlinks](../features/backlinks.md) §6） |

- **リンクは書かれたまま持ち、行き先を索引の時点で決めない。** `[[名前]]` がどのノートを指すかは、同じ名前のノートが増減すると変わる。
  引くときに、今のノートの名前で候補を絞り、本文のリンクを押したときと同じ規則（`resolveNoteLink`）で出どころから解いて、
  **本当に今のノートへ着くものだけを残す**（→ [note_links](../features/note_links.md) §8 判断3）
- **名前で絞るための鍵は、解決の規則から導く。** 1つのリンクに鍵を最大2つ持つ。同じなら1つ
  - 書かれたままの末尾の名前に、解決が名前で引くときの正規化（`toNormalizedObsidianTitle`）をかけたもの
  - `normalizeVaultImagePath` を通した（パーセント復号した）末尾の名前に、同じ正規化をかけたもの

  解決は、パスのリンク（相対・根から）と `[[フォルダ/名前]]` を復号してから引くので、書かれたままの鍵だけでは `[x](my%20note.md)` が `my%20note` になって候補から落ちる。
  逆に一律に復号すると、`100%` のように文字としての `%` を含む名前で別の取りこぼしを作る。**鍵で多めに拾っても、最後に `resolveNoteLink` で絞るので誤りにはならない**。
  今のノートの鍵は、ノートの名前に同じ正規化をかけたもの
- 1文は `splitIntoSentences` で切った、リンクを含む文。長ければ切り詰める

## 7. ランダム表示との関係（大きな Vault の最初の待ち）

**ランダム表示は索引から引かない。** 走査の一覧から引く今の形のままにする（2026-11-21、オーナー判断）。

- 2026-11-14 には、索引のノートの一覧を復元して先に引く形（先出し）を区切り3として決めていた。
  索引を入れた後の測り直しで、最初のランダム表示が索引の前より短くなったので、入れないことにした
  （500本 5.465秒→2.842秒、3,000本 15.521秒→11.257秒。各3回の中央値 → §8）
- **入れ直すなら、索引の一覧を走査の共有の入れ物（`NoteScanCache`）へ入れない。** 入れ物の公開は、一覧・リンクの索引・`knownNotes`・分野の索引を1か所で替え、
  関連ノートや本文のリンクは入れ物にある一覧を寿命を見ずに使うので、古い一覧を入れるとランダム表示の外へ漏れる。
  索引を作る側が別に持ち、ランダム表示だけが読む形にする。紙の地色の分布（→ [note_age_paper](../features/note_age_paper.md)）と、消えたノートを引いたときの引き直しも合わせて決める
- **初めて開く Vault と、寿命の切れた後のランダム表示は、今どおり走査を待つ**（→ [rediscover](../features/rediscover.md) 判断2）

## 8. 上限・性能・スレッド

> **実測（2026-11-21、Pixel 10 Pro Fold、合成 Vault）:** 最初の作成は、フォルダを許可してから500本で約5〜8秒、3,000本で約35〜37秒（1回目は35〜49秒の間）で終わった。
> DB（`-wal`・`-shm` を含む）は500本で約1.2MB、3,000本で約4.3MB。作っている間もランダム表示と本文を読むことは塞がれなかった。
> 時間は画面の文字の繰り返し取得で測り、1回の取得に2.1〜2.7秒かかるので、終わった時刻はその幅でしか言えない。
> 索引を作り終えた後の起動は500本538ms・3,000本520ms（各3回の中央値。索引の前は497ms・483ms）で、差は3回のばらつきと同じくらいだった。
> 最初のランダム表示は500本2.842秒・3,000本11.257秒（同じく中央値。索引の前は5.465秒・15.521秒）。
> 起動は `am start -W` の TotalTime、最初のランダム表示は OP が終わった後にタップしてから題名を取得するまで。fixture の生成手順と測るケースは [実機ケース](../../review/device_validation/knowledge_index.md) が持つ。

- **本文の読み込みは同時に4本まで。** 関連ノートの並列読込と同じく上限を置く（→ [related_notes_ai](../features/related_notes_ai.md) 判断6）
- **本文の解析は Main の外。** 入力の大きさに比例するので `Dispatchers.Default` で行い、`ThreadingScanTest` の表に載せた（→ [architecture](architecture.md) 判断3）
- DB の読み書きは Room の suspend で、Main を塞がない
- **1つのノートから取るリンクは500まで、1文は160字まで**（`KnowledgeIndexLimits`）。超えた1文は末尾を「…」で切る
- **起動のたびに走査が1回走る。** Vault を開いたときに索引のために走査を頼むため。寿命の中なら、その後のランダム表示・さがすは同じ一覧を使う

## 9. プライバシーとバックアップ

- **DB は端末の外へ出さない。** ネットワーク権限が無いうえ、`noBackupFilesDir` に作って端末の自動バックアップに載せない（結晶の材料の控えと同じ）。
  Room の既定の置き場（バックアップの対象）へ戻すと `BackupExclusionTest` が落ちる。
  リンクを含む1文は利用者の個人的な内容である
- Vault を替えたら前の Vault の索引を消す（→ §4）

## 10. 検証

- **JVM:** リンクの取り出し（押せる記法だけ・コードの中を除く・1文の切り出し）、差分の決め方（新規・更新・消えた・読み切れない走査では消さない）、
  バックリンクの解き方（同じ名前が複数のときに今のノートへ着くものだけ）、Vault の照合。DB は偽物のインターフェースで差し替える。
  **鍵の取りこぼし:** 相対パス・根からのパス・フォルダつきの `[[…]]` のそれぞれで、`%20`・符号化した日本語・文字としての `%` を含む入力について、
  `resolveNoteLink` が今のノートへ解くリンクを、鍵による絞り込みが落とさないこと（解ける入力の全部を鍵の側にも通す形で書く）
- **instrumentation:** `KnowledgeIndexDaoTest` — Room の DAO をメモリ上の DB で確かめる。索引の素性が違えば消して作り直すこと・古い番号の読み込みを書かないこと・旧い Vault の書き込みを受けないこと・変数の上限を超える数を消せること
- **実機**（[実機ケース](../../review/device_validation/knowledge_index.md)）**:** 合成 Vault（500・3,000本）で最初の作成の時間と、2回目の起動のランダム表示の時間
- **実機で起こせないので自動テストが持つ順序:**
  - 索引作りの途中で Vault を替える → 旧い Vault の結果を書かない（両方向。替えた後に旧い本文の読み込みが終わる場合も）
  - 索引作りの途中で蒸留が本文を書き換える → 書き換え後の本文で読み直す
  - 更新日時が走査の前後ともに空のノートで、リンクを足す・消す → 次の突き合わせで反映される。アプリの書き換えは日時が同じでも読み直す
  - アプリがノートNを本文Aへ書き換えて控える → 索引がAを読み始める → 読み終える前にアプリがNを本文Bへ書き換える → Aの読み込みが終わる。日時は空でない同じ値のまま固定する → Aの完了は控えを外さず、画面を操作しなくても最後はBのリンクになる
  - 突き合わせXがNの本文Aを読んで書く前に止まる → アプリがNをBへ書き換え、公開の知らせが届く → Xが終わる。日時は空でない同じ値のまま固定する。
    Xの間に届いた知らせは「もう一度」の印になり、2本目は同時に走らない。Xは番号が進んだので DB へ書かず控えを残し、2回目の突き合わせがBを書く。最後は画面を操作しなくてもBのリンクになる
  - 上と同じ書き換えで、Bの読み込みが先に DB へ書いて控えを外し、その後にAの読み込みが書こうとする並びを無理に作る → Aは番号が最新でないので書かず、DB はAへ戻らない（完了の順を両方向で固定する）
  - 引く側の要求の途中で索引が直る、または入れ物が新しい走査を公開する → 新しい版で引き直し、旧い結果で上書きしない
  - 構築済みの DB で起動し、最初の走査が公開される前に引く → 0件にせず待ち、DB の差分が0件でも公開の後に一覧が出る
  - 一部のフォルダを読めない走査で、出どころがそのフォルダにある → その出どころを根からの相対で解かずに除く
  - 走査が一部のフォルダを読めない → そのフォルダのノートを索引から消さない
  - 走査の途中で本文を書き換える（公開されない）／走査を終えた後に書き換える → どちらも画面を操作せずに新しい索引へ進む
  - 頼んだ走査が読めずに空だった（入れ物は寿命を与えずに公開する）→ 既存の行を消さず、バックリンクは「確かめた0件」ではなく「読めない」になる。その場で頼み直しを繰り返さず、次の契機で読めた走査が届けば通常へ戻る
  - 走査が読み切った空の Vault を返す → 準備完了として扱い、索引の行を全部消し、バックリンクは0件と確定する
- **保証していないこと:** Obsidian で書き換えたノートは、次に走査が公開されるまで索引に入らない。
  走査が走るのは、寿命（60秒）の切れた一覧をどれかの機能が頼んだとき（ノートを開く・ランダム表示・さがすなど）と、Vault を開いたとき・アプリが本文を書き換えたときで、タイマーでは走らない。
  DB の作成に失敗した端末では、バックリンクが使えない（ほかの機能は今の動きのまま）。
