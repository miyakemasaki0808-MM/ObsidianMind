# 設計思想 — テーマ基盤と配色コントラスト

**対象領域:** 色トークンの設計・WCAG基準の当て方・テーマの通し方
**状態:** 実装済み・稼働中。文字4.5:1／塗り3:1／記号3:1 を `AppColorContrastTest` が強制している。
**関連:** **[ui_design_principles](ui_design_principles.md)（先に読む）**・[dark_mode](dark_mode.md)・[note_age_paper](note_age_paper.md)
**経緯:** [開発日誌 2026-07](../../owner/journal/2026-07.md#2026-07-29--07-30--ライト配色のaa是正で2度差し戻される)

## 構造（R-1〜R-4 で確立した形）

- `AppTheme` が `AppColorScheme` を `CompositionLocal` で配り、画面は直書きの色を持たない
- **`AppColorScheme` は `Brush` ではなく停止色のリストを受け取り、`Brush` をその場で組み立てる。**
  `Brush` からは色を取り出せないため、渡すとテストが同じ値を書き写すことになり二重管理になる
- Vigilith の状態は `VigilithActionStatus` に統一（かつて `SectionFabStatus` と重複していた）
- 色トークンは意味ベース（`onSurfaceMuted`・`aiHeading`・`buttonSecondary` など）で命名する

---

## 判断1: 階調の数は好みではなく「AAの床」から決まる

パネル `#FDFEFF` の上で 4.5:1 を満たす最も薄いグレーは **`#767676`（ちょうど4.50）**。
本文 `#202124` からこの床までが、弱い文字に使える全範囲になる。
**ここに4段階以上を置くと、名前は違うのに実質同じ濃さのトークンが生まれ「どれを使うか」が決められなくなる。**

5段階（Muted / Subtle / Faint / Hint / Disabled）を3段階へ統合した。
ダークは元から全段が基準内だが、**片方だけ段数が増える事故を防ぐため明暗で段数を揃えた。**

> **「トークンが多すぎる」型の課題は、減らす根拠を美意識で用意しようとすると決着しない。**
> 先に**制約（この場合はAAの床）を測ると、取りうる段数が自動的に決まる。**

## 判断2: 彩度を持つ色は、色相を動かさずに明度で落とす

見出し2色と更新日時は 11sp なので、**AAの大文字例外（18pt相当／Bold 14pt相当）には入らず** 4.5:1 が要る。

**3色とも色相を1度も動かしていない。** 「関連ノート」と「AI推薦」は同じ大きさ・同じ位置の見出しで、
**見分けの根拠が色相の差しか無い**。ここを動かすと可読性と引き換えに意味が壊れる。

## 判断3: 塗りと文字は別の基準なので、同じ色を共有できない

塗りには**下限と上限の両方**がある。

- 塗り vs 面 ≥ 3:1 → **暗いほど有利**
- 黒ラベル vs 塗り ≥ 4.5:1 → **明るいほど有利**

両立するのは相対輝度 **0.175〜0.297** の帯だけ。結果として `buttonSecondary` は
**明暗で別値**になった（それまでは「明暗どちらでも成立する色」として共有していた）。
同じ理由で `aiHeading`（文字用・4.5必要）と `buttonSecondary`（塗り用・3.0必要）は**同系色だが別値**になる。

## 判断4: 「文字」の側をさらに分ける — 読む対象か、示す対象か

| | 基準 | 根拠 |
|---|---:|---|
| ボタンのラベル | 4.5:1 | 1.4.3。**読んで意味を取る文字** |
| バッジの中の ✓ / ! | **3:1** | 1.4.11。**状態を示す記号** |

**WCAG は実装ではなく機能で分類するので、`Text()` で描いていても ✓ は記号である。**

**同じ塗りの上で前景が2つに割れる。** `buttonSecondary` はボタンの塗りでもバッジの塗りでもあり、
ラベルは黒・記号は白になる。1つに揃えると**記号側が不必要に 4.5:1 で制約される**ので `onStatusBadge` を分けた。

> **基準の当て方を間違えると、満たす必要のない制約を自分に課したまま見た目を犠牲にする。**
> 実際、白の「✓」を 2.49 だからと黒へ変えたが、10dp のバッジでは黒い記号が面積の大半を占めて重く見えた。
> 3:1 を当てれば白のまま通っていた。

## 判断5: グラデーション直上は「文字色」では解けない

`AppGradient` の停止色は相対輝度 0.121〜0.458 に散っており、**全停止色に3:1を満たす塗りは
L≤0.007（ほぼ黒）か L≥1.47（存在しない）しかない。** 緑1色の問題ではなく、
**「彩度の高い広い輝度幅の背景に、色付きの塗りを置く」構図の問題**である。

- **ボタン:** WCAG 1.4.11 が認める**隣接輪郭**で解く（`buttonOutlineOnGradient`）。
  ダークは塗りが足りているので置かない。**「足りているから置かない」こともテストで示す**
  （忘れたのではない、と区別できるようにするため）
- **見出し:** **白を薄く重ねて停止色を持ち上げ、そこへ濃い文字を置く**（`Panel` α=0.35 ＋ `LogoNavy`）。
  暗幕（`LogoNavy` α=0.42 ＋ 白文字）は基準を満たしたが、**実機で見ると帯として重く、
  角丸を付けた時点でカードにしか見えなかった**（すぐ下に白い本文カードがあるため）

**白文字と濃い文字では、苦しくなる停止色が逆になる。** 白は最も明るい停止色、濃い文字は最も暗い停止色で苦しくなる。
ダークは何も敷かない（暗いグラデーションでは白文字が元から基準を満たす）ため、
**面と文字が明暗で反転する。** 反転していること自体もテストで固定する
（片方の値をもう片方へコピーする事故は、この形でしか検出できない）。

> **「基準を満たす実装」と「成立しているデザイン」は別で、前者だけを見ていると後者で必ず差し戻される。**
> 数値で決まるのは「満たすかどうか」だけで、**どう満たすかは最後まで設計判断**として残る。

## 判断6: 半透明の面は「色の選び直し」では解けない

AIタブの空状態は `Panel` を22%でグラデーションへ重ねており、白文字とのコントラストが
**下地しだいで 1.82〜4.10 に動いていた**。不透明化して解消した。
一方、親が `PanelBlue` の部品は実効面が計算できるので構造を変えていない。
**「半透明だから危ない」ではなく、何の上に重なっているかで決まる。**

## 判断7: テストは「記録」ではなく「強制」。そして条件を実物から引く

従来の `AppColorContrastTest` は未達を**実測値のまま固定して失敗させない**形だった。
悪化も改善も検出できるが、裏を返すと**テストが全緑でもAA準拠を意味しなかった。**

**強制へ移したが、強制する条件が実物と一致しているかは別の検証である。**

| 誤り | 実際 |
|---|---|
| 全色を `panel #FDFEFF`（アプリで最も明るい面）の上で測っていた | 実際に載る面では 4.19〜4.41 で未達 |
| グラデーション直上の白文字を、最も**有利な**停止色でだけ測っていた | 最悪の停止色では 2.07 |

**弱い文字の基準面は `panelChip`（文字を載せる面のうち最も暗い）。**
面ごとに上限を変えないのは、トークンを別の面へ移した瞬間に静かに割れるため。

**検証は列挙ではなく総当たりにする。** どれが最悪かは色を変えれば入れ替わるので、
代表の停止色を選んだ時点で同じ間違いの余地が残る。

**表に載らない書き方をソース走査で禁じる。** 画面から直接 `onVibrant` を使う、
文字色へ任意の `copy(alpha)` を掛ける、といった経路は対応表に載らない。
`VibrantTextUsageTest` が許可リスト方式で塞ぎ、**許可リストへ足したらその面の比を
`AppColorContrastTest` へ足す決まり**にした（許可だけ増やして検証を増やさないと穴になる）。

> **対応表は正しい方向だったが、表に載せる範囲を自分で決められる以上、載せ忘れは必ず起きる。**
> 防ぐには2つ要る — ①検証対象を総当たりにする ②表に載らない書き方をソース走査で禁じる。
> → [lessons L9](../lessons.md#l9-検証条件が実物と一致しているかはテストが通ることでは分からない)

## 不変条件（テストが強制しているもの）

| 対象 | 基準 | テスト |
|---|---:|---|
| 文字トークン（明暗とも） | 4.5:1 | `AppColorContrastTest` |
| 塗りボタン3役（明暗とも） | 3:1 | 同上 |
| バッジの記号 | 3:1 | 同上 |
| グラデーション上の文字 | **全停止色に対して**基準 | 同上（総当たり） |
| 明暗で反転すべきトークン | 反転していること | 同上 |
| `onVibrant` / 文字色への `copy(alpha)` | 許可リスト外で使わない | `VibrantTextUsageTest` |

**旧値へ戻す変異でテストが落ちることを確認済み。**

## やらないこと

- **色相を動かして基準を満たすこと**（判断2）。見分けの根拠を壊す
- **代表値でのコントラスト検証**（判断7）。総当たりにする
- **巨大な暗幕でグラデーションを潰すこと**（判断5）。デザインとして成立しない
