# Rediscover（ランダム表示）

**状態:** Implemented — 稼働中。**アプリの入口であり心臓**
**最終検証:** 2026-08-11 / `1cbdf13`（`loadRandomNote` の全手順・走査キャッシュ・除外フォルダ・上限を実装から起こした）
**関連コード:** `NoteViewModel.loadRandomNote()` / `NoteViewModel.collectAllNotesCached()` / `data/NoteRepository.kt`（走査と読み取り）/ `ui/screen/NoteReaderTab.kt`（ボタン）
**関連テスト:** `NoteRepositoryTest` / `NoteSessionCoordinatorTest` / androidTest: `VaultScanInstrumentationTest` / `NoteReadingFlowTest`

**対象領域:** Vault からノートを1件無作為に引き、読める状態にするまで

---

## 1. 概要

Vault 全体から `.md` を1件**無作為に**引いて表示する。

> **引きは偶然のまま、引いた後に「前回の自分」を重ねる。**

これがアプリの中心的な体験で、他の機能（要約・関連ノート・読書痕跡・蒸留）はすべて
**引いた後に乗る**。Rediscover が最初に走り、そこから派生する。

## 2. ゴールと非ゴール

### ゴール
- 過去のノートと**偶然**再会させる
- 引いた直後に、読むために必要なものを揃える（本文・紙の地色・痕跡・要約・関連ノート）

### 非ゴール
- **引きに意図を混ぜない。** 未読優先・分野で絞る・最近読んでいない順、いずれも入れない。
  条件を足したいものは**別の引き方**として別機能にする（→ [ADR で守っている一線ではないが、この文書の判断1]）
- **履歴を辿る導線にしない。** 「さっき読んだノート」は当日履歴（さがすタブ）の担当

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| ランダム表示 | Vault から1件引いて本文を表示する | ノートタブの「別のノートをひらく」 |
| Vault未選択時の案内 | 「Vaultフォルダを選択して…」と出し、**ボタンは無効** | Vault が未選択 |
| 空Vault | ノートが1件も無いことを伝える | 走査結果が0件 |
| 再会カード | 「前回のあなた」を出す | **Rediscover 経路だけ**（`openNote` では出さない） |

## 4. 現在のユーザーフロー

1. ノートタブの **「別のノートをひらく」** を押す
2. `onNoteChanged()` — 前のノートのジョブを止め、ノート単位の状態を一括リセットする
3. Vault 全体を走査して `.md` を集める（**60秒のTTLキャッシュ**あり → §5）
4. `notes.random()` で1件引く
5. 本文を読む（**最大1MBで切り詰め**）
6. **読書痕跡のセッションを作る** — **本文を出す前**に作る（→ §8 判断3）
7. **紙の地色を決める** — これも**本文より前**（→ §8 判断3）
8. 本文を表示する
9. 当日履歴へ記録する
10. **再会カードを出す**（この経路だけ）
11. 要約と関連ノートの生成を始める（どちらもバックグラウンド）

**Vault未選択なら何もせず返る。** ボタン自体も無効になっている。

## 5. 機能仕様

- **前提条件:** Vault が選択済みであること
- **母集団:** Vault 配下の `.md` すべて。**ただし機能フォルダは除外する** —
  `_AI補記` / `_ReadingTraces` / `.obsidian`
- **抽選:** `notes.random()` の一様抽選。**重み付けも履歴の考慮もしない**
- **上限:**

  | 対象 | 値 | 定数 |
  |---|---|---|
  | 表示用に読む本文 | **1MB**（超過分は切り詰め） | `NoteReadLimits.DISPLAY_MAX_BYTES` |
  | 関連ノート候補用のスニペット | 8KB | `NoteReadLimits.SNIPPET_MAX_BYTES` |
  | 走査キャッシュの寿命 | **60秒** | `NOTES_CACHE_TTL_MS` |

- **走査キャッシュ:** Vault 全体の走査は SAF の IPC が重いので、結果を60秒保持する。
  **連打しても走査は1回**で、関連ノートの補填もこのキャッシュを使う。
  **Vault切替で破棄する**（`saveVault()` が `cachedNotes` を空にする）
- **走査が部分的に失敗しても続行する。** 読めた分でランダム表示と関連ノートを続ける
  （止めるほうが体験として悪い）。**完全性を要求するのは、不在を根拠に何かを消す処理だけ**
  （＝痕跡の孤児掃除）
- **エラー時:** `NoteState.Error` を出す。`CancellationException` は再throwする
- **空のとき:** `NoteState.Empty`

## 6. 状態とデータ

**UI状態:** `NoteState`（`Idle` / `Loading` / `Success` / `Empty` / `Error`）。

**永続化しない。** 引いた結果そのものは残らない。残るのは副産物 —
当日履歴（SharedPreferences・日付が変われば破棄）と読書痕跡（Vault内サイドカー）。

**走査キャッシュ `cachedNotes` は `NoteViewModel` が持つ。** `NoteUiState` の外にあるが、
これは表示状態ではなく I/O のキャッシュなので「状態の単一ソース」の例外にはあたらない。
**破棄の契機は Vault 切替だけ**（ノート切替では捨てない — 次の抽選で使う）。

## 7. システム設計

```
NoteReaderTab（ボタン）
 └─ NoteViewModel.loadRandomNote(contentResolver)
      ├─ session.onNoteChanged()            ← 旧ノートのジョブ停止＋状態リセット
      ├─ collectAllNotesCached()            ← 60秒TTL・Vault切替で破棄
      │    └─ NoteRepository.collectNotes() ← SAF再帰走査（機能フォルダを除外）
      ├─ notes.random()
      ├─ loadNoteForDistill()               ← 本文読み取り（1MB上限）
      ├─ startReadingTrace()                ← **本文表示より前**
      ├─ setNotePaperTone()                 ← **本文表示より前**
      ├─ setNoteState()                     ← ここで初めて画面が変わる
      ├─ recordHistory() / revealReadingTrace()
      └─ fetchSummary() / fetchRelatedNotes()  ← バックグラウンド
```

## 8. 設計判断と代替案

### 判断1: 純粋ランダムを守る

**引きに意図を混ぜない。** 未読優先・分野フィルタ・最近読んでいない順は、いずれも
「偶然の再会」を「システムの推薦」に変えてしまう。**驚きは抽選ではなく、引いた後に重ねる
「前回の自分」から作る。**

条件付きで引きたいという要望は繰り返し出るが、**それは Rediscover の改良ではなく別の引き方**として扱う
（未実装候補の「放置ノートフィルター」がこれにあたる）。

### 判断2: 走査は60秒キャッシュする

SAF の再帰走査は1フォルダごとに IPC が発生して重い。**連打・関連ノートの補填・短時間の往復**で
毎回走らせると体感が壊れる。一方で長く持つと Obsidian 側の追加が見えなくなるので、60秒に置いた。

**Vault切替では即座に捨てる。** 世代（`vaultGeneration`）ではなく参照の破棄で行う —
キャッシュは状態ではなく I/O の写しなので、無効化ではなく破棄でよい。

### 判断3: 痕跡セッションと紙の地色は、本文より先に決める

**どちらも順序を逆にすると壊れる。**

| 先に置くもの | 後にすると起きること |
|---|---|
| 読書痕跡のセッション作成 | 痕跡レポータの**初回 emit がセッションより先に届き、訪問を取りこぼす** |
| 紙の地色（`setNotePaperTone`） | **現行色で1フレーム描かれてから**変わる（ちらつく） |

**この経路は走査結果を手元に持つので、紙の段階が常に確定する。**
`openNote`（関連ノート・さがすタブ経由）はVault全体の分布を持たないため、同じ計算ができない —
**Rediscover だけが持つ強み**である。

### 判断4: 再会カードは Rediscover 経路だけで出す

`revealReadingTrace()` は `loadRandomNote` からしか呼ばない。**`openNote` では呼ばない。**

「前回のあなたはここまで読んだ」は**偶然引き当てたときにこそ効く**。
関連ノートやさがすタブから意図して開いたノートでは、驚きにならない。

### 判断5: 部分的な走査失敗では止めない

走査結果は「読めた分」で使う。**完全性を要求するのは、不在を根拠に何かを消す処理だけ** —
読書痕跡の孤児掃除がそれで、そちらは不完全な走査では動かさない
（→ [reflect_reading_trace](reflect_reading_trace.md)）。

## 9. 品質要件

- **性能:** 走査は `Dispatchers.IO`、本文の Markdown 解析は `Dispatchers.Default`。
  Main を塞がない（→ [architecture](../system/architecture.md) 判断3）
- **プライバシー:** 読むだけ。Vault へ書かない
- **オフライン:** ネットワークを使わない（→ [ADR-0002](../decisions/ADR-0002-on-device-ai-only.md)）

## 10. 検証と受け入れ条件

- **JVMテスト:** `NoteRepositoryTest`（走査と除外）/ `NoteSessionCoordinatorTest`（ノート切替の後始末）
- **instrumentation:** `VaultScanInstrumentationTest`（実物SAFでの走査）/ `NoteReadingFlowTest`（読書画面）
- **保証していないこと:**
  - **抽選の分布は検証していない。** `notes.random()` に委ねており、偏りのテストは無い
  - **走査キャッシュのTTL境界は実測していない。** 60秒は見積もり
  - **1MB超のノートの表示品質**は切り詰め後のもので、末尾が欠ける

## 11. 既知の制約・未解決事項

| | |
|---|---|
| 同じノートが連続で出うる | 一様抽選なので当然だが、体感としては指摘されうる。**直近を除外すると純粋ランダムでなくなる**ので入れていない |
| 走査キャッシュ中は Obsidian 側の追加が見えない | 最大60秒。痕跡の索引側は別途、外部同期の追加を検出する仕組みを持つ |
| 大きなVaultでの走査時間 | 実測していない |
