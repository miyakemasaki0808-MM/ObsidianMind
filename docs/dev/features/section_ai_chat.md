# セクションAI（浮遊吹き出し・ボトムシート）

**状態:** Implemented — 稼働中。会話履歴の永続化・横断チャットは見送り継続
**最終検証:** 2026-08-11 / `c25bcea`（セッションの寿命・上限・AI非対応時の分岐を実装から起こし直した）
**関連コード:** `controller/SectionChatController.kt` / `domain/markdown/NoteSections.kt` / `ui/screen/SectionChatSheet.kt` / `controller/NoteSectionController.kt`
**関連テスト:** `SectionChatControllerTest` / `SurroundingContextTest`
**正本:** この文書

**対象領域:** ノート読書中のAI対話と、**この部分に対するAI操作の起点**

---

## 1. 概要

読んでいる位置に追従する**浮遊吹き出し**を置き、タップするとボトムシートが開く。
シートは**いま見ているセクション**について、要約・質問候補・クイズを出す。

> **吹き出し＝「この部分へのAI操作」の起点。**
> クイズの入口もここにあり、AIタブには置いていない（→ [quiz](quiz.md)）。

## 2. ゴールと非ゴール

### ゴール
- 長いノートでも**入力をコンテキスト長に収める**
- 回答の根拠を「今見ている部分」に絞る
- **読書を止めずに**AIへ問える

### 非ゴール
- **自由記述の質問欄を持たない。** AIが出した候補のタップだけ
- **セクション範囲外を答えない。** 範囲外は「記載なし」と返させる
- **会話履歴を永続化しない**（シートを閉じるまでの揮発）
- **ノート横断のチャットにしない**

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 浮遊吹き出し | 画面上をドラッグで移動できる吹き出し | 本文表示中 |
| セクション追従 | スクロールすると対象セクションが変わる | 常時 |
| セクション要約 | シート上部に要約が出る | シートを開いたとき |
| 質問候補 | AIが作った質問をタップで訊ける | 要約の生成後 |
| この部分でクイズ | 周辺本文から設問を作る（→ [quiz](quiz.md)） | シート内のボタン |

## 4. 現在のユーザーフロー

1. 本文をスクロールすると、`firstVisibleItemIndex` から**直近の見出し**が対象セクションになる
   - **見出しが無いノートはノート全体へフォールバック**する
2. 浮遊吹き出しをタップ → `open(section)`
   - **既にセッションがあれば、それを再表示するだけ**（→ §8 判断2）
3. `checkAvailability()` を見る
   - `Ready` → 4へ
   - それ以外 → `aiStatusNotice()` の説明を `summaryProblem` へ載せる。
     **文言も導線も `AiStatusNotice` が持つ**（message だけ取り出すと再試行できず、
     赤いエラー表示になる）。再試行は `retrySummary()` が受ける。**ここではDLしない** → §8 判断4
4. セクション要約と質問候補を生成する
5. 質問候補をタップ → `sendMessage()` が回答を生成し、シート内のログへ積む
6. 「📝 この部分でクイズ」→ 周辺本文（約1,200字）から設問を作る
7. シートを閉じる → 会話は残るが、**セッションを明示終了すると破棄される**

## 5. 機能仕様

- **前提条件:** ノートが表示されていること
- **対象セクション:** 直近の見出しから**次の同レベル以下の見出しの直前まで**
- **上限:**

  | 対象 | 値 | 定数 |
  |---|---|---|
  | プロンプトへ渡すセクション本文 | **1500文字** | `NoteExcerptLimits.SECTION` |
  | クイズ用の周辺本文 | **約1200文字** | `SURROUNDING_CONTEXT_TARGET_LENGTH` |
  | 出力枠 | 256トークン | `genai-prompt` |

- **状態 `SectionChatState`:** `sectionTitle` / `sectionContext`（**LLMへ渡すだけで表示しない**）/
  `summary` / `isSummaryLoading` / `suggestions` / `messages` / `isGenerating` /
  `summaryProblem` / `answerProblem`
- **出せなかった理由は要約側と回答側で別の欄に持つ**（`SectionChatProblem`）。
  **1つで兼ねない** — ①要約があると回答の失敗が表示に負けて消え、
  ②同時に起きたとき「再試行がどちらを指すか」を決められない
- **`GenerationFailed(message)`:** 生成が落ちた（タイムアウト・出力打ち切り）。赤で出す
- **`AiStatus(notice)`:** 端末AIが使えない。通常色で出す
  （→ [background_ai_ux](../system/background_ai_ux.md) §6）
- **再試行は2本:** `retrySummary()` は要約を作り直し、`retryAnswer()` は答えを返せていない
  質問を作り直す（**ログへ積み直さない**）。**押されたボタンの位置が対象を決める**
- **キャンセル:** ノート・Vault切替、セッションの開始・終了で `cancelAndClear()`

## 6. 状態とデータ

**UI状態:** `NoteUiState.sectionChat`（`null` ならセッション無し）＋ `isSectionChatSheetVisible`。
**シートの表示状態とセッションの存在を分けている** — 閉じても会話は残る。

**永続化しない。** 保存先の設計が要るため、ニーズが出るまで見送っている。

**契約2箇所への登録（ノート単位の状態）:**
`cancelNoteScopedJobs()` → `sectionChat.cancelAndClear()`、
`withNoteScopedReset()` → `sectionChat = null` / `isSectionChatSheetVisible = false`。**両方に登録済み。**

**セクション構造の解析は別 Controller が持つ。** `NoteSectionController` が
`Dispatchers.Default` で解析して `StateFlow<NoteSectionModel?>` を配る
（→ [architecture](../system/architecture.md)。**最大1MBの解析はMainで走らせない**）。

## 7. システム設計

```
本文（LazyColumn）── firstVisibleItemIndex ──> 対象セクションの決定
 └─ 浮遊吹き出し（ドラッグ可）
      └─ SectionChatSheet
           ├─ SectionChatController.open()        ← セッション作成・要約・質問候補
           ├─ SectionChatController.sendMessage() ← 候補タップで回答生成
           └─ QuizController.create()             ← 「この部分でクイズ」
                └─ surroundingContext()           ← 純関数・約1200字

NoteSectionController（Dispatchers.Default）── NoteSectionModel ──> 上記
```

## 8. 設計判断と代替案

### 判断1: なぜ「セクション単位」なのか

長いノート全体を Nano に渡すと**コンテキスト長制限で後半が切り捨てられ**、回答の的確さも落ちる。
「今見ている部分だけ」を対象にすれば、長いノートでも入力が収まり、**回答の根拠も絞られる。**

**対象はユーザーに選ばせず、スクロール位置から自動追従する。** 選ばせると手数が増え、
「読んでいる場所について訊く」という動機と噛み合わない。

### 判断2: セッションは開始時のセクションに固定する

既にセッションがあれば `open()` は**再表示するだけ**で、対象を作り直さない。

**スクロール先の別セクションで重複生成しないため。** 固定しないと、
シートを閉じて少しスクロールして開き直すたびに Nano が走る。

### 判断3: 自由記述欄を持たない

質問はAIが生成した候補のタップのみ。**入力の手間を省くと同時に、
セクション範囲外の質問を構造的に防ぐ。** 範囲外を訊けてしまうと、
「記載なし」と返すか推測で答えるかをモデルに委ねることになる。

### 判断4: ここではモデルDLを始めない

`NeedsDownload` のときは**文言で案内するだけ**で、ダウンロードを開始しない
（要約とクイズは自動で始める）。

**読書中に開くシートなので、数分かかる処理をここから起こさない。**
DLの起点は自動生成される要約側に寄せてある（→ [architecture](../system/architecture.md) の比較表）。

### 判断5: 出題対象を「フォーカス周辺」に転換した

クイズは当初「ノート全体（実際は先頭1,200文字）から5問」で、**2つの問題が同時にあった。**

1. 超長いノートは**冒頭からしか出題されない**
2. Nano の出力上限（256トークン）に5問は収まらず、
   **暗黙に途切れた分だけがパースされて動いていた**（`finishReason` 検知で可視化された）

→ **吹き出しがフォーカスしているセクションの周辺**へ転換した。
ノートの長さが無関係になり、「読んだ部分を試す」という学習体験としても正しい形になる。

**周辺はセクション単位ではなくブロック単位で広げる。** 核となるセクションの前後ブロックを
交互に足して約1,200字にする（`surroundingContext`）。
**ブロック単位なら親子セクションの本文重複が起きない。**

### 撤退した試み: 「もう2問」の追い生成

2問では物足りない対策として、既出問題の除外リスト付きの追い生成を実装した。
素材拡張（2,400字）と一般知識出題の許可まで試したが、**実機での成功率が低く廃止した。**

> **小型モデルに「同じ素材から別の問題を作る」類の差分生成は難しい。要求は毎回独立・自己完結にする。**

### 撤退した試み: UIの初期案（6版の反復）

浮遊UIは**6版の反復**を経て今の形になった。個々の版は [開発日誌](../../owner/journal/2026-07.md) が持つ。
残す結論は1つ。

> **浮遊UIは「本文と区別できる色」と「タップまでの手数最小」が生死を分ける。**
> 白基調はノートと同化し、タップ後の中間メニューは邪魔になる。

## 9. 品質要件

- **性能:** セクション解析は `Dispatchers.Default`（`NoteSectionThreadingTest` がソース走査で固定）
- **プライバシー:** セクション本文はプロンプトへ入るが端末外へ出ない
  （→ [ADR-0002](../decisions/ADR-0002-on-device-ai-only.md)）
- **端末制約:** Nano 非対応・モデル未準備は**シート内の文言**で伝える

## 10. 検証と受け入れ条件

- **JVMテスト:** `SectionChatControllerTest`（セッションの寿命・状態遷移）/
  `SurroundingContextTest`（周辺本文の広げ方）/ `NoteSectionThreadingTest`
- **instrumentation:** `OnDeviceGenerationTest`
- **保証していないこと:**
  - **セクション追従の精度を測っていない。** `firstVisibleItemIndex` 基準なので、
    画面上端の見出しが対象になる（読んでいる位置とずれうる）
  - **質問候補の質を測っていない**
  - 出題形式の閾値（コード比率45%・180字・700字など）は**初期ルールで、実機結果を見て調整する前提**
