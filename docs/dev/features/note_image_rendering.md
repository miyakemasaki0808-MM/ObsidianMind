## 1. 概要

ノート本文に埋め込まれた画像を表示する。**読み取り専用**で Vault には書かない。

**難所は描画ではなくパス解決だった。** Obsidian の既定は wikilink 埋め込みで、
貼り付けた画像は `![[Pasted image ….png]]` になる。**この形はファイル名しか持たない**ので、
ディレクトリを1段ずつ辿る方式では原理的に解けない。

## 2. ゴールと非ゴール

### ゴール
- Obsidian で貼り付けた画像がそのまま出る
- **読書痕跡を汚さない**（→ §8 判断5）

### 非ゴール
- **EXIF回転・SVG・アニメーション・インライン画像に対応しない**
- **同名が複数あるときは解決しない**（→ §8 判断3）
- **AI入力を変えない**（→ §8 判断4）

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 画像表示 | `![alt](path)` と `![[image.png]]` が画像として出る | 本文表示時 |
| プレースホルダ | 読み込み前も**高さを確保**して場所を空ける | 同上 |
| 失敗の表示 | 理由の文＋枠＋記号（**色だけに頼らない**） | 解決・復号に失敗したとき |

## 4. 現在のユーザーフロー

1. 本文の解析で画像ブロックが見つかる
2. **Vault横断の画像索引**から実体を解決する（→ §8 判断1・判断2）
3. **プレースホルダで高さを確保**したうえで復号を始める
4. 復号できれば描画する。できなければ理由を出す

## 5. 機能仕様

- **上限（`ImageDecodePolicy`）:**

  | 対象 | 値 | 定数 |
  |---|---|---|
  | 入力サイズ | 16MB | `MAX_INPUT_BYTES` |
  | 辺の長さ | 20,000px | `MAX_DIMENSION` |
  | 復号後のピクセル数 | 4,000,000 | `MAX_DECODED_PIXELS` |
  | キャッシュ | 32MB | `CACHE_MAX_BYTES` |
  | サンプルサイズ | 1,024 | `MAX_SAMPLE_SIZE` |

- **索引の除外:** `_AI補記` / `_ReadingTraces` / `.obsidian`
- **索引のTTL:** **60秒**（Vault切替だけでは、Obsidian 側で足した画像が出ないため → §8「索引の鮮度」）
- **エラー時:** 結果型で表す（→ §8「結果型と失敗の見せ方」、語彙は §6）

### パス正規化の規則（照合前に適用）

| 正規化（照合前に適用） | 扱い |
|---|---|
| `%20` などのパーセントエンコード | デコードする |
| `./` | 除去する |
| `../` | 1段上へ畳む。ルートを超えたぶんは捨てる |
| 先頭 `/` | Vaultルート基準として除去する |
| `\` 区切り | `/` へ寄せる |
| 大文字小文字 | **完全一致は区別し、ファイル名一致は区別しない**（SAFプロバイダで挙動が違うので拾える側を広く取る） |
| `\|400` / `\|400x300` | **区切って捨てる**（サイズヒントは使わない） |


### 対応範囲

| 項目 | |
|---|---|
| `![alt](path)`・`![[image.png]]`（単独行・画像拡張子のみ） | **対応** |
| PNG / JPEG / WebP（静止） / BMP | **対応** |
| GIF / WebP のアニメーション | 非対応（先頭フレームのみ） |
| SVG | **非対応**（`BitmapFactory` が扱えない。対応するなら依存追加＝別判断） |
| 外部URL | **非対応**（ネットワーク権限を持たない）。理由を出す |
| EXIF の回転 | **非対応。カメラ写真が横倒しになりうる** |
| インライン画像（段落の途中） | 非対応（`InlineTextContent` が非同期読込と相性が悪い）。alt をテキストとして残す |
| `![[note]]`（拡張子なし） | **画像として扱わない**（別機能） |
| 1行に画像が2つ／画像の後ろに文が続く／alt に `[` `]` | **画像として扱わない**（段落のまま＝従来どおり） |
| 表示 | 本文幅にフィット。高さは原寸比（上限なし） |


## 6. 状態とデータ

**Vault へは書かない。** 読み取り専用。

### Vault横断の画像索引

| | |
|---|---|
| スコープ | **Vault単位。** 無効化の契機は Vault 切替だけなので、**ノート単位の契約2箇所には登録しない** |
| 世代 | `vaultGeneration` を `() -> Long` で受ける（新しい配線機構は持たない） |
| 永続化 | **しない。** メモリのみで、起動のたび走査し直す |
| 鮮度 | Vault切替 ＋ TTL（値は §5）。**miss かつ TTL 超過のときだけ1回**再走査する |
| 載っている値の鮮度 | **索引の作り直しとは別問題。** TTL を過ぎたヒットは、当たった1件だけ更新日時を引き直す（→ §8「索引の鮮度」） |
| 不完全な索引 | **キャッシュする。** 「無い」と断定させない保証は `Unverifiable` の型が持つ |

### 失敗の語彙

`model` の **`NoteImageFailure`（8種）**。解決結果も復号結果も同じ語彙で返す。
「見つからない」は `NotFound`（索引は完全で、そのうえで無い）と
`Unverifiable`（索引が不完全なので断定できない）を**型で分ける**。

### 復号結果のキャッシュ

| | |
|---|---|
| 追い出し | **バイト量の LRU**（件数ではない。1件の重さが2桁違う） |
| 鍵 | 参照 ＋ 表示幅 ＋ **中身の世代（更新日時）** |
| 失敗 | **載せない**（一時的な失敗が次のVault切替まで固定されるため） |

## 7. システム設計

```
本文の解析（画像ブロック）
 └─ NoteImageGateway
      ├─ VaultImageIndexStore   ← Vault横断の索引。解決まで引き受ける
      ├─ resolveImage()          ← 2段照合・純関数
      └─ ImageDecodePolicy       ← 上限の判定・純関数
           └─ ui/markdown/NoteImage（プレースホルダで高さ確保 → 描画）
```

## 8. 設計判断と代替案

> 以下は既存の判断をそのまま保存したもの。**節番号は本文の12節体系とは独立**で、内容は現在も有効。

### 判断1: Vault横断の索引1本で解く（ディレクトリ walk は採らない）

| 記法 | Obsidianでの位置づけ | 解決に要るもの |
|---|---|---|
| `![[Pasted image ....png]]` | **既定**（貼り付け・ドラッグはこの形） | ファイル名だけ → **Vault横断の索引** |
| `![alt](attachments/img.png)` | 手書き・他ツール由来 | パス解決 |
| `![alt](https://...)` | 外部 | **ネットワーク権限が無いので構造的に不可能** |

**`![[...]]` を外すと機能がほとんど役に立たない**が、**この形はファイル名しか持たないので
ディレクトリを1段ずつ辿る方式では原理的に解けない。**

**索引を持つと `![](path)` 側も同じ索引の相対パス照合で解けるので、機構は1つで済む。**
「まずパスで辿り、駄目なら索引」の二段構えは、**索引が必ず要る以上は純粋な追加コスト**にしかならない。

走査の骨格は `traverseMarkdownPaths` が持つ（**全フォルダを歩いて `.md` 以外を捨てている**だけなので、
受理条件を引数へ出せば画像も同じ走査で拾える）。**この関数は孤児掃除が依存しているので、
一般化の前に等価性テストを置く。**

### 判断2: 照合は2段。ノート相対パスは入れない

**照合順は「正規化した完全パス一致 → ファイル名一致」。**

ノート相対（`./img.png` をノートのフォルダ基準で解く）を入れない理由は2つ。

1. **既定設定では相対パスが生成されない**（Obsidian の既定は「Shortest path when possible」で opt-in）
2. **表示中ノートの相対パスがUIに存在しない。** `NoteState.Success` は `title` / `content` / `targetUri` しか持たず、
   `openNote` 経由では相対パスが**表示時点で未確定**。ここへ通すと
   「画像だけ遅れて解決し直す」挙動を表示経路へ持ち込む

**入れなくても大半は救われる** — `attachments/img.png` は完全一致が外れればファイル名 `img.png` へ落ちて索引が拾う。

**正規化の規則は §5。**

> **サイズヒントの `\|` は「どちら側を取るか」に注意。** リンク `[[note\|別名]]` は表示名が後ろなので `last()` だが、
> 埋め込み `[[file\|400]]` は**ファイル名が前**なので `first()`。既存の `inlineMarkdown` は `last()` なので
> **そのまま流用すると必ず外れる。**

**wiki埋め込みは画像拡張子を持つものだけを画像として扱う。** `![[note]]`（拡張子なし）は
他ノートの埋め込みという別機能なので、画像として解決しにいってはいけない。

**判定は「迷ったら段落のまま」に倒す。** 正規表現の最長一致をそのまま使うと
`![図](zu.png) と説明(補足)` の対象が `zu.png) と説明(補足` になる。
**どちらも往復テストは通ってしまう**（原文どおり復元されるため）ので、テストの緑では気づけない。
対象から `[` `]` `)` を除外して曖昧な行は段落へ落とす。**段落は変更前の扱いなので現状維持**になる。

### 判断3: 同名が複数あるときは解決しない

`a/img.png` と `b/img.png` が両方ある Vault で `![[img.png]]` を解くとき、
BFSで最初に見つかったほうを黙って出すのは**誤った画像を確信を持って表示する**ことになる。
**曖昧なら表示せず、「同名の画像が複数あります」と候補数を出す。**

根拠が一意に定まらないときに**それらしい答えを1つ選んで見せるのが一番悪い** —
誤りが誤りとして見えないので報告もされない（→ [lessons L24](../lessons/L24.md)）。

**「見つからない」も2種類に分ける。** `NotFound`（索引は完全で、そのうえで無い）と
`Unverifiable`（索引が不完全なので断定できない）を型で分ける。
**完全性を見るのは見つからなかったときだけ**でよい — 見つかったなら索引が不完全でも答えは正しい。

**再検討の契機は症状**（「同名の画像が実際にあって、どちらを出すべきか自明なケース」が出たとき）。
ただし**ノート相対を入れない限り「同じフォルダを優先」は書けない**ので、判断2と一緒に見る。

### 判断4: AI入力は現状維持。レンダラは分離しない

`MarkdownBlock.Image` を足すと、`blocksToMarkdown` の書き戻し方で
**往復不変条件とAI入力からのパス除去が両立しなくなる。**

| 案 | 往復 | AI入力 | |
|---|---|---|---|
| **`![alt](path)` を忠実に復元** | ○ | 現状維持 | **採用** |
| alt だけを返す | **×**（再パースで段落になる） | パスが消える | 不変条件を壊す |
| レンダラを2本に分ける | ○ | パスが消える | 利得に対して高い |

**分離して得られるものを先に数えた。** 予算内のノートは `buildNoteExcerpt` が原文を無加工で返すので
**何も変わらない**。利得は「予算超過のノートで画像1つあたり数十文字」に限られ、
[ai_input_excerpt](../system/ai_input_excerpt.md) は**予算を600→800へ増やしても品質は動かなかった**と記録している。
**自分たちで測って「効かない」と結論した軸に、レンダラ2本と全経路のテストを払うのは筋が悪い。**

> **ただし段落の切れ方は変わる。** 空行を挟まず本文の直後へ画像を置く書き方は従来1つの段落へ吸収されていたが、
> 画像として描くには切る必要があるので**画像行を段落の区切りに加えた**。
> **「無回帰」と言えるのはパスの扱いについてであって、出力が1バイトも変わらないという意味ではない。**

### 判断5: プレースホルダの高さ確保は必須要件（読書痕跡が汚染される）

**本機能で最も見落としやすい欠陥。見た目の話ではなく永続データの話になる。**

`visibleFractionOfBlock` は `if (itemSize <= 0) return 1f`（高さが測れていないブロックは全可視扱い）。
これは**到達率を不当に下げないための意図的な既定値**で、高さ0が常態でない前提に立つ。画像はこの前提を破る。

1. 読み込み待ちの画像ブロックの高さが0だと、**そのブロックは「全部読んだ」と報告される**
2. 高さ0なので画面に一度に入るブロック数が増え、**`deepestBlockIndex` が実際より先へ進む**
3. **「スクロールを戻しても最深到達点は下げない」**ので、
   **水増しがそのセッションに固着し、サイドカーへ永続化される**

**したがって「高さを確保したほうが跳ねなくて良い」ではなく、「確保しないと痕跡が壊れる」。**

- 寸法取得パス（`inJustDecodeBounds`）で得た縦横比からプレースホルダ領域を確保する
- **寸法取得に失敗した場合も固定の最低高さを必ず置く。高さ0のブロックを作らない**
- **確保した高さは3つの状態（プレースホルダ・成功・失敗）すべてに渡す。**
  成功経路だけ幅指定にすると、最低高さで留めた横長画像が**成功した瞬間に縮む**
- **縦横比どおりに確保するので、復号が終わってもレイアウトは動かない**

**この要件が読み込み口の形を決めた。** 寸法を中身より先に知る必要があるので、`NoteImageLoader` は
`measure`（寸法だけ・ヘッダのみ読む）と `load`（復号）の**2段**に分かれている。
1本にすると高さが決まるのが中身の到着と同時になり、それまでを高さ0で埋めることになる。

#### 高さの確保だけでは足りない — 未測定より後ろは報告しない

**「大きすぎる確保は到達率を低く見積もるだけだから安全」は誤りだった。**
成り立つのは**プレースホルダが実際の高さ以上のとき**だけで、**画面高はそれを保証しない**
（縦長画像なら実際は画面2〜3枚ぶんになり得る）。成立する順序は2つ。

1. **全画面への遷移。** 位置を引き継ぐが新しいコンポジションなので**寸法は未計測に戻る**。
   引き継いだオフセットが仮の高さを超えると後続ブロックが可視になる
2. **測定を待っている間のスクロール**

**対処も2つ。**

- **寸法を hoist して共有する**（`NoteImageMeasurements`）。`sectionModel` を鍵に `MainActivity` で作り、
  通常表示と全画面へ配る
- **未測定より後ろの報告を止める**（`shouldReportReadingProgress`）。`snapshotFlow` の中、
  **報告の直前1箇所**で弾く。測定が終われば判定が動いて報告は再開する

**「失敗」は測れたものとして扱う。** 失敗パネルの高さは以後動かないので、そこから先の可視判定は正しい。
止めたいのは**これから高さが変わるもの**だけ。

**判定材料は「本文の構造」と「測定キャッシュ」だけにする。**
「いま描かれている画像」から判定すると、**画面外へスクロールした画像は Composable ごと破棄され測定もキャンセルされる**ため、
破棄を「確定した」と読んで報告が通る。`imageBlockRefs()` で本文から画像の位置を拾い、
`firstUnmeasuredImageIndex()` が測定キャッシュと突き合わせる。**どちらもコンポジションの寿命に依存しない。**

> **「いま画面にあるもの」を状態の根拠にしない。** LazyList は見えなくなった項目を捨てるので、
> **捨てられたことと確定したことは別**である。
>
> **「安全な側へ倒す」と言うときは、それが本当に上限かを確かめる。**
> 向きの議論は上限が取れているときにしか使えない。**巨大な仮高で解こうとする限り、
> どれだけ大きくしても「上限である」ことは言えない。**

### 索引の鮮度

索引は **Vault 単位**の状態なので、**ノート単位の契約2箇所には登録しない**。
無効化の契機は Vault 切替だけで、世代は `vaultGeneration` を `() -> Long` で渡す（新しい配線機構は要らない）。

**Vault切替だけでは足りない**（Obsidian 側で画像を足しても切替まで出ないのは誤り）ので、
`collectAllNotesCached` に倣って **TTL** を持たせる（値は §5）。

- **外部URLと空の参照では索引を作らない。** Vault を見るまでもなく結論が出る。
  作ると**外部画像しか無いノートを開いただけでVault全走査が走る**
- **miss時の再走査は「miss かつ索引がTTLより古いときだけ、1回」。**
  無条件だと**リンク切れの画像1つで再コンポーズのたびに全走査**が走る
- **不完全な索引もキャッシュする。** キャッシュを禁じる目的は「無い」と断定させないことだが、
  **その保証は `Unverifiable` の型が持っている**。禁じたままだと読めないフォルダが1つあるだけで
  **画像1枚ごとにVault全走査**が走る（1ノートは画像を何枚も持つ）

**索引を作り直す契機と、載っている値の鮮度は別問題である。** 当たり続ける限り作り直されないので、
更新日時は初回走査時の値で固定され、**同じ参照を上書きされても復号キャッシュの鍵が変わらない**
（＝再起動まで古い画像が出続ける）。そこで **TTL を過ぎたヒットに限り、当たった1件だけ引き直す。**

| 引き直した結果 | 扱い | なぜ |
|---|---|---|
| 値が取れた | 実測値を鍵へ載せる | 索引の値より新しい |
| 存在するが列を返さない | 索引の値のまま | **世代では見分けられないと分かるだけ。** ここで作り直すと、そのプロバイダでは走査が永久に繰り返される |
| 存在を確かめられない | **miss へ落とす** | 索引が古い可能性がある。既存の再走査規則へ合流させれば、削除して同名で作り直した場合も引き当て直せる |

- **索引ごと作り直す案は採らない。** 画像を含むノートを読んでいる間、TTLごとにVault全走査が走る。
  1件の照会なら桁違いに安く同じ問いに答えられる
- **TTL未満では引き直さない。** 走査直後は索引の値が新しいと分かっており、
  1ノートは画像を何枚も持つので、無条件にすると表示のたびに照会が積み上がる
- **確かめた結果は参照ごとに控え、次のTTLまで再利用する。** 索引の読込時刻は作り直しでしか
  動かないので、控えないと**TTLを過ぎた後は解決のたびに外部I/O**になる
  （1枚の表示でも寸法と復号の二段があり、スクロールや全画面遷移で作り直される）。
  **読込時刻のほうを進める案は採らない** — まだ確かめていない別の画像まで新鮮と誤認する
- **「消えている」と「照会が失敗した」は分けない。** SAF は消えたドキュメントの照会に
  **空のカーソルではなく例外**で答えるので、分けても「消えている」側が来ない。
  取り違えの代償も「索引を1回作り直す」だけで、しかも合流先の歯止めにより
  **作り直しはTTLごとに1回に収まる**（`RootFolderLookup` が両者を分けているのは、
  取り違えるとフォルダを二重に作る**不可逆な**副作用があるため。同じ形に見えても理由が違う）

> **反映は「秒数」ではなく「次に読み込むとき」で決まる。** 表示中の `Bitmap` は
> `remember(block)` に保持されるので、上書きしても勝手には差し替わらない。
> 契機はスクロールでの再生成・ノートを開き直す・全画面へ入る・画面幅の変化である。

> **同じ型の失敗を避ける規則でも、避け方が2つあるなら安いほうを採る。**
> 「キャッシュしない」（実行時コスト）と「型で分ける」（設計コスト）が同じ性質を守っており、
> 後者を先に払ったので前者が要らなくなった。

### 復号とキャッシュ

**`BitmapFactory` の二段**（`inJustDecodeBounds` → `inSampleSize`）。minSdk 26 のため `ImageDecoder`（API 28+）は使えない。
12MP の写真を素で復号すると 48MB になるので、この段を省くと確実に OOM する。
**SAF のストリームは2回開く**（`reset()` できる前提には立てない）。

**上限は4つを別々に持つ。** ファイルサイズ1つでは画像爆弾を防げない（小さな圧縮ファイルが巨大な寸法を宣言しうる）。

| 上限 | 目的 |
|---|---|
| 入力バイト数 | 読み込み自体の暴走を止める |
| 縦・横の寸法 | 寸法取得の時点で弾く |
| 復号後のピクセル数 | `inSampleSize` を決めたうえで、なお大きいものを弾く |
| LRU の総バイト数 | 積み上がりを止める |

- **LRU は件数ではなくバイトで管理する**（1件の重さが2桁違うので件数では上限の意味がない）
- **表示中の `Bitmap` を eviction 時に `recycle()` しない**（描画中に呼ぶとクラッシュする）。参照を落として GC に任せる
- **single-flight が要る。** 同じ画像が同じ画面に複数回現れる／通常表示と全画面で同じノートを開く場合に重複する。
  **Compose のコンポジション破棄だけでは、実行中のブロッキング復号が直ちに止まる保証はない**
- **記帳は要求元ではなく読み込み側で行う。** 「待って、返ってきたら計上する」形だと、
  待っている間に要求元がキャンセルされる（＝素早くスクロールする）と取り下げも計上も飛び、
  **そのキーは予算の外で生き続け追い出しの対象にもならない**。
  **キャッシュの整合を要求元の寿命に依存させてはいけない**
- **入力バイトの上限は、メタデータではなく実際に読んだ量で効かせる。**
  `COLUMN_SIZE` を返さないプロバイダでは照会が null になり上限が素通りする。
  上限つきストリームで包んで打ち切り、**打ち切ったことを別に持って理由を「大きすぎる」へ直す**
  （`BitmapFactory` は途中で終わったストリームを「復号失敗」としか言わない）
- **復号結果の鍵には中身の世代（更新日時）を含める。** 参照と表示幅だけだと、
  同じファイルを上書きしても**古い画像を返し続ける**
- **寸法のキャッシュも同じ鍵で持つ。** Bitmapだけ世代で分けても、寸法が参照文字列だけで
  共有されていると、**縦横比の違う画像へ上書きしたときに新しいBitmapが古い比率の枠へ収まる**
  （`ContentScale.Fit` なので本文幅を使わない小さな表示か大きな余白になる）。
  **復号後にBitmapの寸法で高さを直す案は採らない** — プレースホルダから成功表示への
  レイアウト移動を再導入し、確保していた意味が消える
- **表示側は「測ってあっても確かめ直す」。** 共有の入れ物（`NoteImageMeasurements`）は
  参照文字列を鍵にするので、そこで打ち切ると世代の変化に追従できない。
  世代が同じならヘッダは読み直されないので、**全画面へ入り直したときの測り直しは起きない**
  （守るのは「呼ばない」ではなく**「読み直さない」**）
- **確かめ終えるまで復号を始めない。** 共有された寸法は高さの初期値としては正しいが、
  **世代が変わっていないことの根拠にはならない**。待たずに読み始めると、新しいBitmapが
  古い比率の枠へ収まった状態が**見えている時間**になる（最終状態は正しいので、
  即時Fakeと `waitForIdle()` だけのテストでは通ってしまう）
- **「高さが確定した」と「もう試さない」を畳まない。** 測定に失敗しても高さは固定できるが、
  再確認まで止めると、画像を足した・壊れた画像を直した・プロバイダが復旧した、の
  いずれでも失敗表示がノート切替まで残る。**再試行の頻度は索引のTTLと
  「失敗はキャッシュしない」方針が決める**
- **寸法のキャッシュはBitmapと同じ入れ物を使う。** 素の `LinkedHashMap` で持つと
  読みは呼び出し側スレッド・書きはIOスレッドの同時アクセスになり、
  `accessOrder` の付け替えまで同期なしで走る。**要るのは予算の単位ではなく
  single-flightと排他**なので、1件を1と数えて件数上限として流用する
- **失敗は復号側ではキャッシュしない。** 壊れた画像は表示のたび読み直すが**寸法読みの段階で失敗するので安い**。
  逆に載せると一時的な失敗が次のVault切替まで固定される

> **既存の `KeyedMemoCache` は流用しない。** 形は似ているが、追い出しの単位（件数 / バイト）と
> 同一キー同時要求の扱い（両方走る / 1回だけ）が違う。
> **共通化の判断は「形が似ているか」ではなく「制約が同じか」で決める。**

### 結果型と失敗の見せ方

**ローダの戻り値を `ImageBitmap?` にしない。** null だけでは
「未解決／外部URL／SVG／巨大／復号失敗／曖昧」を区別できず、**理由を出すという要件と型が矛盾する。**

**理由の語彙は解決と復号で1つにまとめる**（型は §6）。
分けると表示側が2つの型を突き合わせ、同じ意味の分岐が2箇所へ散る。
葉である `model` に置くのは、`domain`（解決）・`data`（復号）・`ui`（表示）の3層が同じ語彙を使うため。

- **失敗は必ず見える形にする。** 枠＋アイコン＋**ファイル名と理由の文字**
- **色だけで伝えない**（WCAG 1.4.1 → [ui_design_principles](../system/ui_design_principles.md) §1）
- **alt が空のときはファイル名を読む**（本アプリはビューアなので、ノートに置かれた画像は装飾ではなく内容である）

## 9. 品質要件

- **性能:** 復号は4種の上限で守り、キャッシュはバイト量で頭打ちにする（実値は §5）
- **アクセシビリティ:** 失敗表示は**理由の文＋枠＋記号**で、色だけを手がかりにしない
  （→ [ui_design_principles](../system/ui_design_principles.md) の 1.4.1）
- **プライバシー:** 読み取りのみ。Vault へ書かない

## 10. 検証と受け入れ条件

- **JVMテスト:** `ImageLinkResolutionTest`（2段照合）/ `ImageDecodePolicyTest`（上限）/
