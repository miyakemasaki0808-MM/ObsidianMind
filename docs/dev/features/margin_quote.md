## 1. 概要

**本文の一節を選び、余白メモへ移す。** 移した一節は引用として書きかけに付き、自分の言葉を添えて置くと引用つきの余白メモになる。
置いたメモの引用を押すと、本文がその段落へ飛ぶ。スマホでも開いた Fold でも、文字を選んだときのメニューの「余白へ」から移せる。
開いた Fold の机では、選んだ範囲の端に出る札をつまんで余白の面へ運んでもよい。

**あわせて、引用の無いメモも段落まで辿れるようにする。** 今の余白メモは書いたときの見出し名だけを控えるので、
同名の見出しが複数あると先頭の節へ飛び、長い節ではどの段落について書いたかが本文から辿れない。
書き始めたときに見えていた段落を自動で控え、メモの行の「書いた段落へ」から飛べるようにする。利用者の操作は増えない。

**どこから導くか:** [fold_experience](../system/fold_experience.md) §5 の契約2「面を越えて情報を移せる。行き先はサイドカーの余白メモだけ」。
**機能と体験の線引き（同 §5）:** 移した結果の引用つきメモと段落の控えは**機能**で、保存するデータが増えるのでスマホにも同じものを置く。
札を運ぶ操作は**体験**で、開いた Fold の机にだけ置く。メニューの「余白へ」は全端末の入口である。

## 2. ゴールと非ゴール

### ゴール
- 本文の一節を選んで余白メモへ移せる。全端末で選択メニューから、開いた Fold の机では札を運んでも移せる
- 引用には自分の言葉を添えて置く。置いたメモの引用を押すと、本文が引用した段落へ飛ぶ
- 引用の無いメモも、書き始めたときに見えていた段落を控え、「書いた段落へ」で飛べる
- 控えた段落が見つかれば、同名の見出しがあってもどの節のメモかが1つに決まる
- 並べ読みの間に引用しても、右のノートは隠して保ち、置くか引用をやめれば同じ位置で戻る
- **書いた言葉と引用を失わない。** 器の切替・窓の変化・ノートの行き来をまたいでも、書きかけは引用ごと残る

### 非ゴール
- **右のノート（補助の面）から引く。** どのノートの一節かを控えることになり、並べた組を残す段4（机の記憶・契約3）と重なる（→ 判断6）
- **本文へ書くこと。** 契約2の行き先は余白メモだけで、本文の範囲に印も付けない（→ [ADR-0004](../decisions/ADR-0004-do-not-rewrite-vault-body.md)）
- **引用だけで置くこと。** 自分の言葉が要る（→ 判断2）
- **置いた後に引用を付け替える・外すこと。** 余白メモは編集しない（→ [reflect_margin_memo](reflect_margin_memo.md) 判断9）。消して置き直す
- **段落の脇の印。** 見出しの脇の印は今どおりで、件数の数え方だけが控えた段落に従う
- **端末のクリップボードを通すこと・ほかのアプリとの間で運ぶこと**（→ 判断8）
- **再会カードと冊子に引用を出すこと。** 段4で、並べた組と一緒に決める
- **見出し・表・コードを特別扱いすること。** 選んだ文字をそのまま引用にする

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 選択メニューの「余白へ」 | 本文の文字を選ぶとメニューの「コピー」の隣に「余白へ」が出る。押すと余白の面（出せる窓ではペイン、出せない窓ではシート）が出て、入力欄の上に引用が付く | 今のノートの本文で文字を選んだとき（ふだんの画面・机の左の面・見開き・全画面・スマホ） |
| 札を運ぶ | 選んだ範囲の終わりの近くに小さな札が出る。つまんで余白の面へ運ぶと、メニューと同じく引用が付く。札を押すだけでも同じ | 開いた Fold の机で、2面が並んでいるとき |
| 引用つきの書きかけ | 入力欄の上に引用が出て、✕ で外せる。書き込み先は引用した段落の節になる。入力が空なら「置く」は押せない | 引用を付けたとき |
| 引用つきのメモ | メモの行の本文の上に引用が出る。押すと本文が引用した段落へ飛ぶ | 引用つきで置いたメモ |
| 書いた段落へ | 引用の無いメモの添え書きの横に「書いた段落へ」が出る。押すと本文がその段落へ飛ぶ | 書き始めたときの段落を控えたメモで、その段落が今の本文に見つかるとき |
| 節の決まり方 | 控えた段落が見つかれば、その段落を含む節のメモとして並ぶ。同名の見出しに共通、とは出ない | 控えた段落を持つメモ |
| 並べ読み中の引用 | 右のノートが余白に替わって引用が付く。置くか ✕ で引用を外すと、右のノートが同じ位置で戻る | 机で並べ読みをしている間に引用したとき |

## 4. 現在のユーザーフロー

> **構想。** 実装はこれからで、下は実装後の流れである。

**開いた Fold の机**
1. 本文（左の面）の文字を長押しして範囲を選ぶ。選んだ範囲の終わりの近くに札が出て、メニューに「余白へ」が出る
2. 札をつまんで右の余白の面へ運ぶ。余白の面に入ると面の縁が強まり、「今のノートの余白へ」と出る。指を離すと、入力欄の上に引用が付き、入力欄にフォーカスが移る
   - メニューの「余白へ」か、札を押すだけでも同じになる
   - 余白の面の外で指を離すと、運んでいた一節は捨てる。選んだ範囲は戻らない（→ §11）
3. 引用に添える言葉を書いて「置く」。引用つきのメモが「この節のメモ」の先頭に出る
4. メモの引用を押すと、本文がその段落へ飛ぶ

**並べ読みの間（右に関連ノートを出している）**
1. 左の本文で引用すると、右のノートが余白に替わり、引用が付く。右のノートの位置は保たれている
2. 言葉を書いて「置く」。受け取れたら、右が同じノートの同じ位置へ戻る
3. 置かずにやめるときは、引用の ✕ か戻る操作。どちらも右のノートへ戻り、戻る操作のときは引用と書いた言葉が書きかけに残る

**ふだんの画面・見開き（開いた Fold）**
1. 文字を選んで「余白へ」。✎ と同じく机が開き、右の余白の面に引用が付く（見開きから入ったなら、閉じると見開きへ戻る → [margin_pane](margin_pane.md) §5.4）

**スマホ・カバー画面・全画面**
1. 文字を選んで「余白へ」。余白のシートが出て、入力欄の上に引用が付く。全画面では全画面の上にシートが出る
2. 札は出ない

**引用の無いメモ**
1. 今どおり ✎ で書き始める。書き始めた瞬間に、本文の最上端に見えている段落が控えられる（見える操作は無い）
2. 置いたメモの添え書きの横に「書いた段落へ」が出る。押すと本文がその段落へ飛ぶ

## 5. 機能仕様

- **前提条件:** Vault 選択済み・ノート表示中。**端末 AI の可否は前提に入らない**（余白メモと同じく AI を呼ばない）
- **入力と出力:** 入力は利用者が選んだ本文の文字と、書き始めたときの本文の位置。出力は余白メモの保存だけ
- **上限:** 引用と控えた段落は **256バイト**（日本語で約85字 → 判断4）。メモの本文1,024バイト・1ノート20件は今どおり
- **状態遷移:** §5.3 の書きかけの規則と §5.6 の並べ読みの表
- **保存と寿命:** 引用と控えた段落は余白メモの欄として痕跡サイドカーへ書く（**スキーマ v8** → §6）。札・運んでいる一節は端末に残さない
- **画面遷移:** ルートを増やさない。余白の面の出し方は ✎ と同じ規則に従う（→ [margin_pane](margin_pane.md) §5.4）
- **他機能との連携:** 退避と読み戻しは欄ごと運ぶ。合流の鍵 `(日時, 本文)` は変えない（→ §6）。蒸留で本文が解析し直されたら、照合をやり直す
- **エラー／AI非対応／キャンセル時:** AI は関係しない。保存の失敗・満杯・確認できないは今の余白メモと同じに出し、**引用も書きかけに残す**。ノート切替では書きかけを捨てない（今どおり）

### 5.1 移す操作

- **入口は今のノートの本文の選択メニューだけ。** 右のノート（並べ読み）・余白の面の中・再会カードの文字を選んでも「余白へ」は出ない（→ 判断6）
- **「余白へ」は ✎ と同じ規則で面を出す。** ペインを出せる窓ではペイン（机）、出せない窓ではシート。全画面では全画面の上のシート。
  机がもう出ていれば面は替えず引用だけを付ける。出す面が決まる規則は [margin_pane](margin_pane.md) §5.4 の「✎ の規則は1つ」をそのまま使う
- **付けた後は入力欄へフォーカスを送る。** 引用には言葉が要るので、次にすることは書くことである
- **札は机の画面で、2面が並んでいるときだけ出す。** 片側を1画面にしている間・帯を出している間・見開き・スマホ・全画面には出さない。
  落とし先の余白の面が見えていないときに運ぶ先が無いため
- **札は選んだ範囲の終わりの近くに出す。** 位置は選択メニューが受け取る範囲の矩形から決め、左の面の内側に収める。**折り目には置かない**（→ [fold_experience](../system/fold_experience.md) §6）
- **札を押すだけでも「余白へ」と同じ。** TalkBack では札を押す操作として読ませる（運ぶ操作は読み上げで扱わない）
- **落とし先は右の面のうち、折り目の側の帯を除いた範囲。** 折り目のすぐ横で離したものは落とさない。余白の面に入ると縁を強め、「今のノートの余白へ」と出す
- **並べ読みの間は右の面（右のノート）が落とし先になる。** 縁の言葉で行き先が今のノートの余白だと示し、落とすと §5.6 のとおり右を余白に替える
- **札から始まった指は、横の払い（片側を1画面）にも本文のスクロールにも渡さない。** 札は机の画面のいちばん上の層に置く
- **札は押した瞬間に一節を受け取り、運び終えるまで自分で持つ。** 受け取ると本文の選択は解ける（Compose の選択メニューのコピーは渡した後に選択を解く → §11）。
  余白の面の外で離したら、運んでいた一節は捨てる

### 5.2 引用の取り込み

- **選んだ文字をそのまま引用にする。** 表示の文字であって、本文の Markdown の原文ではない（太字の記号は含まない）
- **整え方はメモ本文と同じ形にそろえる。** 改行とタブ以外の制御文字を落とし、前後の空白を削る。**256バイトで切り、切ったら「ここまでを引用しました」と示す**（文字の途中では切らない）
- **空白だけの選択は引用にしない。** メニューは出るが、押しても何も付かない
- **書き込み先は引用した段落の節にする。** 引用の最初の部分を今の本文と照合し（§5.5）、見つかった段落の節を書き込み先にする。
  **すでに書いている途中でも書き込み先を移す** — 引用は利用者が場所を選ぶ明示の操作で、本文のスクロールとは違う（→ [margin_pane](margin_pane.md) 判断3 の「書いている間に固定するのは書き込み先だけ」は、スクロールで動かないことを守る）。
  見つからなければ、そのときの本文の節を書き込み先にする
- **引用は書きかけに1つだけ。** もう一度引用すると、付いていた引用と入れ替える。書いていた言葉は残す

### 5.3 書きかけと置く

書きかけは今の一組（文字・書き込み先・未確定の送信 → [margin_pane](margin_pane.md) §6.1）に、**引用**と**控えた段落**を足して一組で持つ。

| 規則 | 中身 |
|---|---|
| 書き始め | 入力が空から1文字になった瞬間に、書き込み先の節と一緒に、そのときの本文の最上端の段落を控える（§5.4）。引用が付いていれば控えない |
| 引用を付ける | 引用を入れ、書き込み先を引用の節へ移す。文字・未確定の送信はそのまま |
| 引用を外す（✕） | 引用だけを消す。文字があれば書き込み先はそのまま、空なら放す |
| 空かどうか | 文字も引用も未確定の送信も無いときだけ空。**引用だけの書きかけも、窓の変化やノートの行き来で残す** |
| 置けるか | **入力を整えた本文が空なら置けない**（引用だけでは置かない → 判断2）。引用が付いていて文字が空なら、入力欄の案内を「引用にひとこと添えて置く」にする |
| 置く | 送信は本文・時刻・見出し名に加えて、引用か控えた段落を持つ（§6）。整えるのは送信を作るときの1回だけ |
| 確かめる | 未確定の送信と、**整えた本文も引用も同じ**ときだけ「保存を確かめる」。引用を替えたら別のメモとして「置く」 |
| 受け取れた | 入力が送った原文のままで、**引用も送ったものと同じ**ときだけ、文字・書き込み先・引用・控えを空にする |

- **受理の照合は今どおり保存値と時刻の組で行う**（→ [margin_pane](margin_pane.md) §6.2）。引用は照合の鍵に入れない
- **書きかけの書き手は2つになる**（入力と引用）。書き込み先を動かすのは、書き始め（空から1文字）と引用を付けたときだけ。
  ほかの経路（本文のスクロール・窓の変化・解析し直し）は書き込み先を動かさない（→ [lessons L66](../lessons.md#l66-直した状態を別の書き手が戻す)）
- **本文が解析し直されたら**、書き込み先は今どおり見出し名と順番で引き直す。引用と控えた段落は文字なので引き直さない

### 5.4 自動で控える段落

- **書き始めた瞬間の、本文の最上端に見えているブロック**を控える。書き込み先の節を決めるのと同じ瞬間・同じ基準である（2026-10-24 オーナー判断。実機で使って見直す → 判断5）
- 最上端のブロックが見出し・画像・区切り線・表なら、**同じ節の中で次の本文のブロック**（段落・リストの項目・引用の行・コード）を控える。同じ節に無ければ控えない
- 控えるのはそのブロックの表示の文字の頭から256バイトまで。**画面には出さない** — 出すのは「書いた段落へ」の語だけ（→ 判断5）
- 控えられなかったメモは今のメモと同じく見出しまでで辿る

### 5.5 段落への照合と飛び方

**位置は保存しない。文字で照合する**（→ 判断10）。本文は Obsidian で編集されうるので、段落の番号は次に開いたときに別の段落を指す。

- **照合の鍵は、引用か控えた段落の最初のブロック分**（最初の改行まで）。空白と改行の並びは1つの空白に畳み、両側を同じに整える
- **今の本文の各ブロックを、表示と同じ解釈器で文字にしてから比べる**（`InlineSyntax` → [lessons L51](../lessons/L51.md)）。鍵を含む最初のブロックを採る
- **探す順は2段。** ①控えた見出し名に一致する節（同名なら候補のすべて）の中を本文の順に、②見つからなければ本文の全体を本文の順に
- **見つかったら、そのブロックを含む節のメモとして並べる。** 見出しの照合の3値（一意・同名に共通・見つからない → [margin_pane](margin_pane.md) §5.6）より優先する。見出しの脇の印と件数もこの結果に従う
- **見つからなければ、今の見出しの照合に戻る。** 引用は表示したまま押せなくし、添え書きに「引用した一節は本文に見つかりません」と出す。控えた段落は「書いた段落へ」を出さない
- **飛び方は節へ飛ぶのと同じ口を使う**（`BodyPosition` → 見開きの間も同じ位置へ送る）。飛び越した画像の測定も同じく頼む
- **照合は本文の大きさに比例するので Main で走らせない**（最大1MB × メモ20件 → [architecture](../system/architecture.md) 判断3）。メモか解析結果が替わったときに Main の外で作り直し、`ThreadingScanTest` の表へ1行足す

### 5.6 並べ読み中の引用（2026-10-24、オーナー判断 → 判断7）

**右のノートは隠して保ち、置いたら戻す。** 並べ読みの状態に「引用のために余白を出している」印を足す。

| 並べ読みの間の出来事 | 右の面 | 並べ読み |
|---|---|---|
| 左で引用する（メニュー・札） | 余白に替え、引用を付ける。印を立てる | 終えない。右のノートと位置は窓で隠すときと同じ持ち方で保つ |
| 引用つきのメモが受け取れた | 右のノートへ戻す。印を下ろす | 同じノートを同じ位置で |
| 引用の ✕ | 右のノートへ戻す。印を下ろす | 同じ |
| 戻る操作 | 右のノートへ戻す。印を下ろす。**引用と書いた言葉は書きかけに残る** | 同じ |
| 置いたが満杯・失敗・確認できない | 余白のまま（保存の状態を見せる） | 保ったまま |
| 余白の「このノートの関連」から別の候補を開く | 新しい候補を右に出す。印を下ろす | 新しい並べ読みに替わる。書きかけは残る |
| 帯の ✎・重ねたレールのタブ・ノート切替・Vault 切替 | 今どおり | 今どおり終える（印も一緒に消える） |
| 窓が変わってペインが閉じる | — | 今どおり隠して保つ。書きかけがあるのでシートへ移す（→ [margin_pane](margin_pane.md) §5.4） |
| 出せる窓へ戻って ✎ で机を開く | **印が立っていれば余白、下りていれば右のノート** | 保ったまま |

- **印は並べ読みと同じ寿命で持つ**（ノート単位。並べ読みが終われば一緒に消える）
- **戻すかどうかは書きかけから決める。** 印が立っていて、書きかけに引用も引用つきの未確定の送信も無くなったら戻す。受け取れたとき・✕ のときはどちらもこれに当たる。
  決めるのは調停側（`NoteSessionCoordinator`）で、書きかけの規則が引用を消した結果を並べ読みへ伝える

### 5.7 窓・器の切替

- 書きかけは ViewModel 側にあるので、引用はシートとペインの切替・全画面の往復・Fold の開閉・画面の作り直しをまたいで残る（今の一組と同じ）
- **引用だけの書きかけも「書きかけがある」に数える。** ペインが窓で閉じるときシートへ移す規則（[margin_pane](margin_pane.md) §5.4）は、文字が空で引用だけがあるときも移す
- **札は窓が変わったら消す。** 運んでいる途中でも、机の画面が組み直されたら運ぶのをやめ、一節は捨てる

## 6. 状態とデータ

**余白メモに欄を1つ足し、痕跡のスキーマを v7 から v8 へ上げる。** 読める版は v1〜v8 で、書き戻しは v8。

```kotlin
data class MarginMemo(
    val text: String,
    val writtenAtEpochMillis: Long,
    val sectionTitle: String? = null,
    /** 書いた段落。引用か、書き始めたときに見えていた段落。v7 以前のメモは null */
    val passage: MemoPassage? = null
)

data class MemoPassage(val text: String, val kind: PassageKind)

/** 引用は画面に出し、控えた段落は「書いた段落へ」だけを出す。 */
enum class PassageKind { Quoted, Seen }
```

- **1つの欄に種類を付けて持つ**（→ 判断3）。引用と控えた段落を別の欄にすると、両方が入った意味の無い組を型として作れる
- **検証:** `passage.text` は空でなく、256バイト以内（`ReadingTraceLimits.MAX_PASSAGE_BYTES`）。種類は既知の値だけ。v7 以前は欄が無いので null として読む
- **容量:** 全欄を上限まで詰めた痕跡は今 112,843 バイトで、上限 128KB まで 18,229 バイト残る（2026-10-24、実シリアライザで測った）。
  20件すべてに256バイトの引用を足しても収まる見込みで、**実装時に `ReadingTraceLimitsTest` の最悪の痕跡へ passage を足して測り直す**（→ [reflect_margin_memo](reflect_margin_memo.md) 判断11）
- **合流:** 鍵 `(日時, 本文)` は変えない。メモは編集できないので、同じ鍵のメモは同じ段落を持つ。退避ファイルは痕跡と同じ版で欄ごと運ぶ
- **退避と読み戻し:** 退避ファイルの痕跡は v8 で書き出し、v1〜v8 を読み戻せる。退避ファイルの版（`ReadingTraceBackupLimits.FORMAT_VERSION`）は、痕跡のスキーマ版と別に要否を実装時に確かめる（→ [reading_trace_backup](reading_trace_backup.md)）
- **スキーマを上げたら、今の版を名指しする文書を全部直す**（`SchemaVersionDocsTest` → [lessons L14](../lessons.md#l14-横展開は最後の1本を取り残す)）

| 状態 | 変更 | 登録 |
|---|---|---|
| 余白メモ（永続） | `passage` を足す | 痕跡の欄なので登録しない。`reflect_reading_trace` のデータ表と `reflect_margin_memo` の永続化モデルを直す |
| 書きかけ（`MarginMemoDraft`） | 引用（文字・切ったか）と控えた段落を足す | 今と同じ。**`NoteUiState` の外**で、Vault 切替でだけ捨てる（アーキテクチャ判断4の3行目） |
| 送信（`MemoSubmission`） | 保存値のメモが `passage` を持つ | 今と同じ |
| 並べ読み（`SideReadingState`） | 「引用のために余白を出している」印 | 並べ読みと同じく `cancelNoteScopedJobs()` と `withNoteScopedReset()`（既に登録済みの状態の中に足す） |
| 札・運んでいる一節 | **新規。** 画面だけの状態 | 状態に入れない。机の画面が組み直されたら捨てる |
| 照合の結果 | **新規。** メモごとに見つかったブロックと節 | 画面側で導き、Main の外で作る（§5.5）。状態に入れない |

| 層 | 新規 | 変更 |

| `domain` | `MemoPassages.kt` — 引用を整える（`composeQuote`）・書き始めの段落を選ぶ（`seenPassageAt`）・段落を照合する（`locatePassage`）。いずれも純関数 | `arrangeMemos` が照合の結果を優先して節を決める。書きかけの規則（`quoted`・`unquoted`・`edited`・`sendAction`・`accepted`）に引用を足す |
| `data` | — | `ReadingTraceJson` が `passage` を読み書きし、v1〜v8 を読む |
| `controller` | — | `MarginMemoController` の送信が引用か控えを持つ。`SideReadingController` に印の立て下げ。`NoteSessionCoordinator` が引用を付けたことと消えたことを並べ読みへ伝える |
| `ui` | `QuoteTextToolbar.kt` — 選択メニューに「余白へ」を足し、選んだ文字を端末のクリップボードを通さずに受け取る。`QuoteChip.kt` — 札の表示と運び、落とし先の判定（`quoteDropTargetFor`。純関数） | `MarkdownRenderer` と `NoteSpread` の本文の選択に上の2つを渡す（右のノートには渡さない）。余白の面に引用の欄・メモの行に引用と「書いた段落へ」。`DeskSpread` に札の層 |
| 窓口 | — | `NoteViewModel` に引用を付ける・外す口 |

- **選んだ文字の受け取り方。** Compose 1.7.3 の `SelectionContainer` は、選択メニューを `LocalTextToolbar` から、コピー先を `LocalClipboardManager` から読む（2026-10-24、バイナリで確かめた）。
  今のノートの本文の選択の内側だけで両方を差し替える — メニューは「余白へ」を足した自前のもの、コピー先は普段は端末のクリップボードへ渡し、「余白へ」の間だけ文字を受け取って端末へは渡さないもの
- **札は机の画面の Composable の最上層に置き、指を自分で受ける。** 机の横の払いは子より先に指を見るが（`detectDeskSpread`）、札は兄弟として上に重なるので、札から始まった指は払いに届かない。これは実装時に instrumentation で確かめる
- **落とし先の判定は純関数にする**（指の位置・余白の面の範囲・折り目の帯 → 落とす／落とさない）。札の位置の決め方（選択の矩形・左の面の範囲 → 置く位置）も同じ
- 純関数の置き場所は責務で分ける（→ [architecture](../system/architecture.md) 判断5の4）。照合と書きかけの規則は `domain`、札と落とし先は画面の形なので `ui/screen`

### 実装の区切り

着手の順はロードマップが持つ。この文書は区切り方だけを決める。

1. **土台（JVM）:** スキーマ v8（`passage`）・引用の整え方・書き始めの段落の選び方・照合・並べ方・書きかけの規則・容量の測り直し・退避と読み戻し。送信が引用か控えを運ぶところまで。画面に出るものは変えない
2. **引用と段落へ飛ぶ（全端末）:** 選択メニューの「余白へ」・引用つきの書きかけ・メモの行の引用と「書いた段落へ」・書き始めの控え・照合を Main の外で作る
3. **机の札（開いた Fold）:** 札の表示と運び・落とし先・横の払いとの取り合い
4. **並べ読み中の引用:** 並べ読みの印・戻す契機・窓が変わったときの扱い

2〜4は同じ実機検証に載せる（1は画面を変えないので載せない）。余白メモが段落まで辿れない課題は、その実機検証で閉じる。

## 8. 設計判断と代替案

### 判断1: 入口は全端末の選択メニュー。札は開いた Fold の机だけ（2026-10-24、オーナー判断）

メニューの「余白へ」はスマホでも Fold でも同じ操作で、読み上げでも届く。札はその上に足す Fold の体験で、2面を並べたときにしか意味を持たない。
**採らなかった案:** 段落の脇に引用のボタンを置く（範囲を選べず、本文の脇に印が増える）。メニューだけにする（Fold の契約2が Google の言うドラッグ&ドロップに当たるのに、机の上で運べない）。

### 判断2: 引用だけでは置けない。自分の言葉が要る（2026-10-24、オーナー判断）

余白メモは利用者自身の言葉を置く場所で、引用はそれに添えるものとして扱う。引用だけを置ける形にすると、メモの一覧が本文の抜き書きで埋まり、次の再会で自分が何を思ったかが残らない。

### 判断3: 引用と控えた段落を、種類つきの1つの欄で持つ

どちらも「書いた段落」を指し、照合も飛び方も同じである。違うのは画面での出し方だけなので、種類で分ける。
2つの欄にすると両方が入った組を型として作れる。種類を真偽値にしない — 呼び出し側が次にすること（引用を出す／語だけ出す）で名前を付ける（→ [lessons L28](../lessons/L28.md)）。

### 判断4: 引用と控えた段落は256バイト（約85字）（2026-10-24、オーナー判断）

痕跡ファイルの最悪の大きさから逆算した。今の余りは18,229バイトで、20件すべてに256バイトを足しても約7KB残り、段4で欄を足す余地がある。
**採らなかった案:** 384バイト（余りが約2KBで次の欄を足せない）、メモ本文と同じ1,024バイト（ファイルの上限を128KBから上げることになり、読み込み・退避・読み戻しの境界を測り直す）。

### 判断5: 控える段落は、書き始めたときの最上端のブロック。画面には「書いた段落へ」だけを出す（2026-10-24、オーナー判断。仮の決定）

書き込み先の節を決めるのと同じ瞬間・同じ基準なので、節と段落が食い違わない。反応した段落が画面の下のほうにあるとずれるのが弱みで、
**オーナーは「使ってみないとわからない」として、いったんこの形にした。** 実機で使って見直す（→ §10）。
控えた文字を画面に出さないのは、引用と見分けが付かなくなるため。

### 判断6: 段3は今のノートの本文だけから引く（2026-10-24、オーナー判断）

右のノートの一節を引くと、どのノートの一節かを控えることになる。それは並べて考えた組を残す段4（契約3）の中身そのもので、先に作ると段4のデータを先取りする。

### 判断7: 並べ読みの間に引用したら、右のノートを隠して保ち、置いたら戻す（2026-10-24、オーナー判断）

並べ読みは右のノートと照らしながら書くための形で、引用するたびに終わると、比べていたノートを開き直すことになる。
**採らなかった案:** 「← 余白へ戻る」と同じく並べ読みを終える。状態は増えないが、置いた後に右のノートを開き直す手間が毎回かかる。
状態は並べ読みの中の印1つに留め、戻す契機を書きかけの規則から決める（§5.6）。

### 判断8: 端末のクリップボードも、端末のドラッグ&ドロップの仕組みも使わない

**クリップボードを通すと、利用者が前にコピーしたものを黙って上書きする。** 選択メニューのコピー先をこの本文の中だけで差し替えれば、端末のクリップボードに触れずに選んだ文字を受け取れる。
**端末のドラッグ&ドロップ（`dragAndDropSource`）を使わないのは、落とし先がこのアプリの余白の面だけだから。** ほかのアプリへ運べる形にすると、本文の一節がアプリの外へ出ていく入口が増える。画面の中だけで運べば、折り目の帯を落とし先から外す規則も、払いとの取り合いも自前の判定で書ける。

### 判断9: 余白メモの判断2（本文の範囲へ紐づけない）との関係

[reflect_margin_memo](reflect_margin_memo.md) 判断2 は「長押しした段落に付ける」案を、**利用者が「どこに付けるか」を決めることになる**ので採らなかった。
引用はこれに当たらない — 引用は付けなくても置け（引用の無いメモが今どおりの入口）、付けるのは利用者が場所を選びたいときだけである。
控えた段落は自動で、要求を1つも増やさない。**本文が編集されれば紐づけ先が壊れる**という懸念には、位置ではなく文字で照合し、見つからなければ今の見出しの照合へ戻すことで応える（判断10）。

### 判断10: 段落は位置ではなく文字で照合する

ブロックの番号や文字の位置を保存すると、Obsidian で本文が編集された次の読書で別の段落を指し、それに気づけない。文字なら、見つからないことが分かる。
**採らなかった案:** 番号と文字の両方を保存して番号を先に試す。番号が当たっても段落が変わっていれば誤って飛ぶので、結局文字で確かめることになる。

## 9. 品質要件

- **データ保護:** 書いた言葉に加えて、付けた引用も失わない。引用だけの書きかけも書きかけとして預かる（§5.3・§5.7）。v7 以前の痕跡はメモ・訪問ともに読める
- **性能:** 段落の照合は Main の外で行う（§5.5）。本文の表示とメモの読み込みを照合で待たせない
- **プライバシー:** 選んだ文字を端末のクリップボードへ渡さず、ほかのアプリへ運べる形にもしない（判断8）
- **アクセシビリティ:** 運ぶ操作は読み上げで扱わず、メニューの「余白へ」と札を押す操作で同じことができる。引用と「書いた段落へ」は押せる範囲を広く取り、読み上げ名を「引用した段落へ本文を送る」「書いた段落へ本文を送る」にする

## 10. 検証と受け入れ条件

- **JVMテスト:**
  - 引用を整える（制御文字・前後の空白・256バイトの切り口が文字の途中にならない・切ったことを返す・空白だけは null）
  - 書き始めの段落を選ぶ（最上端が見出し・画像・区切り線・表のときは同じ節の次の本文のブロック、無ければ null）
  - 照合（控えた見出しの節が先・同名の候補すべて・全体へ広げる・空白と改行の畳み方・表示の解釈器と同じ文字・見つからない）
  - 並べ方（段落が見つかれば同名の見出しでも一意の節、見つからなければ今の見出しの照合、印の件数がそれに従う）
  - 書きかけの規則（引用を付けると書き込み先が移る・書いている途中でも移る・✕ で文字があれば書き込み先を保つ・引用だけの書きかけは空ではない・文字が空なら置けない・引用を替えたら確かめるではなく置く・受け取れたときに引用が送ったものと違えば消さない）
  - 痕跡の JSON（v8 の往復・v1〜v7 を null で読む・種類の未知の値を弾く・256バイト超を弾く）と、最悪の痕跡を実シリアライザで測ってファイル上限に収まること
  - 合流（同じ鍵のメモの段落・片側だけ v7 の退避の読み戻し）
  - 並べ読みの印（引用で立つ・受け取れたら下りる・✕ で下りる・戻る操作で下りて書きかけが残る・満杯や失敗では立ったまま・別の候補で下りる・✎ とノート切替で消える）。**片方の実行中にもう片方を操作する両方向**（保存の途中に右の候補を替える、右の読み込み中に引用する）
  - 落とし先と札の位置（折り目の帯・余白の面の外・左の面に収める・片側1画面と帯の間は出さない）
- **instrumentation:** 選択メニューに「余白へ」が出て、押すと引用が付き入力欄にフォーカスが移る（スマホのシート・机）。端末のクリップボードの中身が変わらない。
  札を運んで落とすと引用が付き、札から始めた指で片側1画面にならない。並べ読みの間に引用して置くと、右が同じノートの同じ位置へ戻る。
  引用つきのメモの引用を押すと本文がその段落へ飛ぶ（縦の流しと見開き）
- **実機確認:** 机で札を運ぶ手触り（つまみやすさ・落とし先の縁・折り目の近くで離したとき）。長押しの選択・横の払い・本文のスクロールとの取り合い。
  **書き始めの段落の控え方が、反応した段落と合っているか**（判断5 の見直しの材料。オーナーが使って判断する）。
  引用の無いメモの「書いた段落へ」で、長い節の中の段落へ届くこと（課題台帳の段落まで辿れない課題の受理条件）
- **実機で起こせないので自動テストが持つ順序:** 引用を付けた直後の保存の結果と、右の候補の替えが同時に届く順序。照合を Main の外で作っている間にメモか解析結果が替わる順序。
  窓が変わって机が組み直される途中で札を離す順序
- **保証していないこと:** 本文に同じ文が2度出るとき、控えた見出しの節の外の一致へ飛ぶこと（節の中を先に探すが、節の中にも2度あれば先の方）。
  表・リスト・引用の行をまたいで選んだときの引用の文字の形（§11 で着手時に確かめる）。段落を書き換えたノートで、言い回しが少し変わった段落を同じ段落とみなすこと（見つからない扱いになる）

## 11. 既知の制約・未解決事項

- **着手時に確かめること（Compose 1.7.3 の実物で）:**
  - 自前の選択メニューを、端末の浮かぶメニュー（`ActionMode` の浮動型）で組めること。「コピー」「すべて選択」を今どおり出せること
  - 複数のブロックをまたいで選んだときに、コピー先へ渡る文字の形（ブロックの境目の改行・リストの記号・表のセルの区切り）。照合の鍵の切り方をそれに合わせる
  - 札を机の最上層に置いたとき、札から始まった指が `detectDeskSpread` に届かないこと
- **選んだ範囲は札をつかむと解ける。** 選択メニューのコピーは、文字を渡した後に選択を解く作りになっている（`toolbarCopy` が `copy` の後に `onRelease` を呼ぶ。2026-10-24、バイナリで確かめた）。
  運ぶのをやめたら範囲を選び直す。選択の中身を直接読む公開の口は無い
- **控える段落は仮の決定である**（判断5）。実機で使って、画面の中央の段落など別の基準へ替える余地を残す
- **余白メモが段落まで辿れない課題**（課題台帳）は、この段の実機検証が終わるまで台帳に残す
- 段4（机の記憶）で、右のノートから引く・再会カードに引用を出す・並べた組を残すをまとめて決める
