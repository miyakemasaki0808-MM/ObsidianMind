## 1. 概要

**本文の一節を選び、余白メモへ移す。** 移した一節は引用として書きかけに付き、自分の言葉を添えて置くと引用つきの余白メモになる。
置いたメモの引用を押すと、本文がその段落へ飛ぶ。スマホでも開いた Fold でも、文字を選んだときのメニューの「引用して書く」から移せる。
開いた Fold の机では、選んだ範囲の端に出る札をつまんで余白の面へ運んでもよい。

**引用元は、選んだその場所で決める。** 本文に同じ文が2度あっても、選んだほうの段落を引用の時点で控え、前後の文字と一緒に残す。
次に開いたときに1つに絞れなければ、黙って先の方へ飛ばず、候補を見せる。

**あわせて、引用の無いメモにも位置の手掛かりを残す。** 今の余白メモは書いたときの見出し名だけを控えるので、
同名の見出しが複数あると先頭の節へ飛び、長い節ではどこで書いたかが本文から辿れない。
書き始めたときに読んでいた位置を自動で控え、メモの行の「書いた頃の位置へ」から戻れるようにする。利用者の操作は増えない。
**これは読んでいた位置の手掛かりで、何について書いたかの記録ではない**（→ 判断5）。

**どこから導くか:** [fold_experience](../system/fold_experience.md) §5 の契約2「面を越えて情報を移せる。行き先はサイドカーの余白メモだけ」。
**機能と体験の線引き（同 §5）:** 移した結果の引用つきメモと位置の控えは**機能**で、保存するデータが増えるのでスマホにも同じものを置く。
札を運ぶ操作は**体験**で、開いた Fold の机にだけ置く。メニューの「引用して書く」は全端末の入口である。

## 2. ゴールと非ゴール

### ゴール
- 本文の一節を選んで余白メモへ移せる。全端末で選択メニューから、開いた Fold の机では札を運んでも移せる
- 引用には自分の言葉を添えて置く。置いたメモの引用を押すと、本文が引用した段落へ飛ぶ
- **引用元を取り違えない。** 同じ文が本文に2度あっても選んだ段落へ戻り、絞れないときは候補を見せて自動では飛ばない
- **長い一節も意味を落とさずに扱う。** 約340字まで引け、それを超えるなら置く前に切れる部分が分かり、選び直せる
- 引用の無いメモも、書き始めた頃に読んでいた位置へ「書いた頃の位置へ」で戻れる。それを書いた対象とは言わない
- 並べ読みの間に引用しても、右のノートは隠して保ち、書く途中で右のノートと書きかけを1操作ずつ行き来できる
- **書いた言葉と引用を失わない。** 器の切替・窓の変化・ノートの行き来をまたいでも、書きかけは引用ごと残る

### 非ゴール
- **右のノート（補助の面）から引く。** どのノートの一節かを控えることになり、並べた組を残す段4（机の記憶・契約3）と重なる（→ 判断6）
- **本文へ書くこと。** 契約2の行き先は余白メモだけで、本文の範囲に印も付けない（→ [ADR-0004](../decisions/ADR-0004-do-not-rewrite-vault-body.md)）
- **引用だけで置くこと。** 自分の言葉が要る（→ 判断2）
- **置いた後に引用を付け替える・外すこと。** 余白メモは編集しない（→ [reflect_margin_memo](reflect_margin_memo.md) 判断9）。消して置き直す
- **控えた位置を、置く前に確かめさせる・直させること。** 位置は手掛かりで、全メモで対象を選ばせる手順は足さない（→ 判断5）
- **段落の脇の印。** 見出しの脇の印は今どおりで、件数の数え方だけが照合に従う
- **端末のクリップボードを通すこと・ほかのアプリとの間で運ぶこと**（→ 判断8）
- **再会カードと冊子に引用を出すこと。** 段4で、並べた組と一緒に決める
- **見出し・表・コードを特別扱いすること。** 選んだ文字をそのまま引用にする

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 選択メニューの「引用して書く」 | 本文の文字を選ぶとメニューの「コピー」の隣に「引用して書く」が出る。押すと余白の面（出せる窓ではペイン、出せない窓ではシート）が出て、入力欄の上に引用が付き、入力欄にフォーカスが移る | 今のノートの本文で文字を選んだとき（ふだんの画面・机の左の面・見開き・全画面・スマホ） |
| 札を運ぶ | 選んだ範囲の終わりの近くに小さな札が出る。つまんで余白の面へ運ぶと、メニューと同じく引用が付く。札を押すだけでも同じ。余白の外で離すと札は元の位置へ戻り、もう一度運べる | 開いた Fold の机で、2面が並んでいるとき |
| 引用つきの書きかけ | 入力欄の上に「今のノートの余白へ · まだ置いていません」と引用が出て、✕ で引用だけを外せる。書き込み先は引用した段落の節になる。入力が空なら「置く」は押せない | 引用を付けたとき |
| 長すぎる一節 | 約340字を超える選択は、残る部分と「ここから先は入りません」の部分を分けて見せる。選び直すか、そのまま書く | 引用を付けたとき |
| 引用つきのメモ | メモの行の本文の上に引用が出る。押すと本文が引用した段落へ飛ぶ。途中までの引用は末尾に「…」が付く | 引用つきで置いたメモ |
| 引用元が絞れないとき | 引用の下に「同じ一節が本文に N か所あります」と出し、押すと候補を並べて選ばせる | 前後の文字でも1か所に絞れないとき |
| 書いた頃の位置へ | 引用の無いメモの添え書きの横に「書いた頃の位置へ」が出る。押すと本文が書き始めた頃に読んでいた位置へ戻る | 控えた位置が今の本文で1か所に決まるとき |
| 書きかけ｜資料の切替 | 並べ読みの間、右の面の上に「書きかけ」と「資料（右のノートの題名）」が並び、押すたびに右が替わる。どちらも位置を保つ | 並べ読みの間に、右が書きかけを出しているか、書きかけが空でないとき |

## 4. 現在のユーザーフロー

> **構想。** 実装はこれからで、下は実装後の流れである。

**開いた Fold の机**
1. 本文（左の面）の文字を長押しして範囲を選ぶ。選んだ範囲の終わりの近くに札が出て、メニューに「引用して書く」が出る
2. 札をつまんで右の余白の面へ運ぶ。余白の面に入ると面の縁が強まり、「今のノートの余白へ」と出る。指を離すと、入力欄の上に引用が付き、入力欄にフォーカスが移る
   - メニューの「引用して書く」か、札を押すだけでも同じになる
   - 余白の面の外で指を離すと、札は元の位置へ戻る。もう一度運ぶか押せば付く。本文のほかの場所に触れるか別の文字を選ぶと札は消える
3. 引用に添える言葉を書いて「置く」。引用つきのメモが「この節のメモ」の先頭に出る
4. メモの引用を押すと、本文がその段落へ飛ぶ

**並べ読みの間（右に関連ノートを出している）**
1. 左の本文で引用すると、右が書きかけに替わり、引用が付く。右の面の上に「書きかけ｜資料（ノートの題名）」の切替が出る
2. 書く途中で右のノートを確かめたくなったら「資料」を押す。右のノートが同じ位置で出る。「書きかけ」を押せば、引用と書いた文字のまま戻る
3. 引用が要らなくなったら ✕。引用だけが外れ、書いた文字と入力面はそのまま。引用の無いメモとして置ける
4. 「置く」で受け取れたら、右が資料（右のノート）へ戻り、切替は消える。満杯・失敗・確認できないときは書きかけのまま状態を見せる

**ふだんの画面・見開き（開いた Fold）**
1. 文字を選んで「引用して書く」。✎ と同じく机が開き、右の余白の面に引用が付く（見開きから入ったなら、閉じると見開きへ戻る → [margin_pane](margin_pane.md) §5.4）

**スマホ・カバー画面・全画面**
1. 文字を選んで「引用して書く」。余白のシートが出て、入力欄の上に引用が付く。全画面では全画面の上にシートが出る
2. 札は出ない

**引用の無いメモ**
1. 今どおり ✎ で書き始める。書き始めた瞬間に、そのとき読んでいた位置（本文の最上端のブロック）が控えられる（見える操作は無い）
2. 置いたメモの添え書きの横に「書いた頃の位置へ」が出る。押すと本文がその位置へ戻る

## 5. 機能仕様

- **前提条件:** Vault 選択済み・ノート表示中。**端末 AI の可否は前提に入らない**（余白メモと同じく AI を呼ばない）
- **入力と出力:** 入力は利用者が選んだ本文の文字と選んだ位置、書き始めたときの本文の位置。出力は余白メモの保存だけ
- **上限:** 引用は **1,024バイト**（日本語で約340字、メモ本文と同じ → 判断4）。引用の前後の文字は各32バイト。控えた位置は64バイト。メモの本文1,024バイト・1ノート20件は今どおり。
  痕跡ファイルの上限は **128KB から 192KB へ上げる**（§6）
- **状態遷移:** §5.3 の書きかけの規則と §5.6 の並べ読みの表
- **保存と寿命:** 引用と控えた位置は余白メモの欄として痕跡サイドカーへ書く（**スキーマ v8** → §6）。札・札が持つ一節は端末に残さない
- **画面遷移:** ルートを増やさない。余白の面の出し方は ✎ と同じ規則に従う（→ [margin_pane](margin_pane.md) §5.4）
- **他機能との連携:** 退避と読み戻しは欄ごと運ぶ。合流の鍵 `(日時, 本文)` は変えない（→ §6）。蒸留で本文が解析し直されたら、照合をやり直す
- **エラー／AI非対応／キャンセル時:** AI は関係しない。保存の失敗・満杯・確認できないは今の余白メモと同じに出し、**引用も書きかけに残す**。ノート切替では書きかけを捨てない（今どおり）

### 5.1 移す操作

- **入口は今のノートの本文の選択メニューだけ。** 右のノート（並べ読み）・余白の面の中・再会カードの文字を選んでも「引用して書く」は出ない（→ 判断6）
- **語は「引用して書く」。** これから書く操作だと分かる語にし、押しただけで保存したように見せない（→ 判断1）
- **「引用して書く」は ✎ と同じ規則で面を出す。** ペインを出せる窓ではペイン（机）、出せない窓ではシート。全画面では全画面の上のシート。
  机がもう出ていれば面は替えず引用だけを付ける。出す面が決まる規則は [margin_pane](margin_pane.md) §5.4 の「✎ の規則は1つ」をそのまま使う
- **付けた後は入力欄へフォーカスを送る。** 引用には言葉が要るので、次にすることは書くことである
- **札は机の画面で、2面が並んでいるときだけ出す。** 片側を1画面にしている間・帯を出している間・見開き・スマホ・全画面には出さない。
  落とし先の余白の面が見えていないときに運ぶ先が無いため
- **札は選んだ範囲の終わりの近くに出す。** 位置は選択メニューが受け取る範囲の矩形から決め、左の面の内側に収める。**折り目には置かない**（→ [fold_experience](../system/fold_experience.md) §6）
- **札を押すだけでも「引用して書く」と同じ。** TalkBack では札を押す操作として読ませる（運ぶ操作は読み上げで扱わない）
- **落とし先は右の面のうち、折り目の側の帯を除いた範囲。** 折り目のすぐ横で離したものは落とさない。余白の面に入ると縁を強め、「今のノートの余白へ」と出す
- **並べ読みの間は右の面（右のノート）も落とし先になる。** 縁の言葉で行き先が今のノートの余白だと示し、落とすと §5.6 のとおり右を書きかけに替える
- **札から始まった指は、横の払い（片側を1画面）にも本文のスクロールにも渡さない。** 札は机の画面のいちばん上の層に置く
- **札は押した瞬間に一節と引用元（§5.2）を受け取り、付くか消えるまで自分で持つ。** 受け取ると本文の選択は解ける（Compose の選択メニューのコピーは渡した後に選択を解く → §11）。
  **余白の外で離したら、札は元の位置へ戻る**（2026-10-24、オーナー判断 → 判断12）。消えるのは、本文のほかの場所に触れたとき・別の文字を選んだとき・本文がスクロールしたとき・窓が変わったとき

### 5.2 引用の取り込み

- **選んだ文字をそのまま引用にする。** 表示の文字であって、本文の Markdown の原文ではない（太字の記号は含まない）
- **引用元のブロックは、選んだ時点の位置で決める**（→ 判断11）。選択メニューが受け取る範囲の矩形と、本文の一覧の今の並び（見えているブロックの位置）から、範囲の始まりを含むブロックを求める。
  文字の照合では決めない — 本文に同じ文が2度あると、文字だけではどちらを選んだか分からない
  - 位置からブロックが決まらないとき（範囲の始まりが画面の外にある、など）は、文字の照合（§5.5）で候補を求め、1つに絞れたときだけ使う。絞れなければ引用元を決めずに引用を付ける
- **引用元を決めたら、そのブロックの中で引用の直前と直後の文字を各32バイトまで控える**（前後の文脈）。次に開いたときの照らし直しに使う
- **整え方はメモ本文と同じ形にそろえる。** 改行とタブ以外の制御文字を落とし、前後の空白を削る
- **1,024バイトを超えたら、置く前に切れる部分を見せる。** 引用の欄に残る部分を出し、続けて「ここから先は入りません」と切れる部分を薄く添える（文字の途中では切らない）。
  選び直すか、そのまま書くかは利用者が決める。置いたメモの引用は末尾に「…」を付け、途中までであることを残す
- **空白だけの選択は引用にしない。** メニューは出るが、押しても何も付かない
- **書き込み先は引用元の節にする。** **すでに書いている途中でも書き込み先を移す** — 引用は利用者が場所を選ぶ明示の操作で、本文のスクロールとは違う
  （→ [margin_pane](margin_pane.md) 判断3 の「書いている間に固定するのは書き込み先だけ」は、スクロールで動かないことを守る）。引用元が決まらなければ、そのときの本文の節を書き込み先にする
- **引用は書きかけに1つだけ。** もう一度引用すると、付いていた引用と入れ替える。書いていた言葉は残す
- **引用の欄には行き先を出す。** 「今のノートの余白へ · まだ置いていません」。右のノートを並べていても、引用が左のノートのメモになることと、まだ保存していないことが分かる

### 5.3 書きかけと置く

書きかけは今の一組（文字・書き込み先・未確定の送信 → [margin_pane](margin_pane.md) §6.1）に、**引用**（文字・引用元の前後・切れた部分）と**控えた位置**を足して一組で持つ。

| 規則 | 中身 |
|---|---|
| 書き始め | 入力が空から1文字になった瞬間に、書き込み先の節と一緒に、そのとき読んでいた位置を控える（§5.4）。引用が付いていれば控えない |
| 引用を付ける | 引用を入れ、書き込み先を引用元の節へ移す。文字・未確定の送信はそのまま |
| 引用を外す（✕） | **引用だけを消す。** 文字があれば書き込み先はそのまま、空なら放す。**面は替えない**（並べ読みの間も → §5.6） |
| 空かどうか | 文字も引用も未確定の送信も無いときだけ空。**引用だけの書きかけも、窓の変化やノートの行き来で残す** |
| 置けるか | **入力を整えた本文が空なら置けない**（引用だけでは置かない → 判断2）。引用が付いていて文字が空なら、入力欄の案内を「引用にひとこと添えて置く」にする |
| 置く | 送信は本文・時刻・見出し名に加えて、引用か控えた位置を持つ（§6）。整えるのは送信を作るときの1回だけ |
| 確かめる | 未確定の送信と、**整えた本文も引用も同じ**ときだけ「保存を確かめる」。引用を替えたら別のメモとして「置く」 |
| 受け取れた | 入力が送った原文のままで、**引用も送ったものと同じ**ときだけ、文字・書き込み先・引用・控えを空にする |

- **受理の照合は今どおり保存値と時刻の組で行う**（→ [margin_pane](margin_pane.md) §6.2）。引用は照合の鍵に入れない
- **書きかけの書き手は2つになる**（入力と引用）。書き込み先を動かすのは、書き始め（空から1文字）と引用を付けたときだけ。
  ほかの経路（本文のスクロール・窓の変化・解析し直し）は書き込み先を動かさない（→ [lessons L66](../lessons.md#l66-直した状態を別の書き手が戻す)）
- **書きかけの中身と、右の面がどちらを出しているかは別の状態にする。** 引用の有無で右の面を決めない（→ §5.6）
- **本文が解析し直されたら**、書き込み先は今どおり見出し名と順番で引き直す。引用と控えた位置は文字なので引き直さない

### 5.4 自動で控える位置

- **書き始めた瞬間の、本文の最上端に見えているブロック**を控える。書き込み先の節を決めるのと同じ瞬間・同じ基準である（2026-10-24 オーナー判断。実機で使って見直す → 判断5）
- 最上端のブロックが見出し・画像・区切り線・表なら、**同じ節の中で次の本文のブロック**（段落・リストの項目・引用の行・コード）を控える。同じ節に無ければ控えない
- 控えるのはそのブロックの表示の文字の頭から64バイトまで。**画面には出さない** — 出すのは「書いた頃の位置へ」の語だけ
- **これは読んでいた位置の手掛かりで、書いた対象の記録ではない。** 反応した段落が画面の中ほどにあれば、控えた位置はその少し上になる。
  語と読み上げ（「メモを書いた頃に読んでいた位置へ本文を送る」）は引用と分け、対象が分かっているようには言わない（→ 判断5）
- 控えられなかったメモは今のメモと同じく見出しまでで辿る

### 5.5 段落への照合と飛び方

**ブロックの番号は保存しない。文字で照らし直す**（→ 判断10）。本文は Obsidian で編集されうるので、番号は次に開いたときに別の段落を指す。

- **候補を求める。** 引用（控えた位置）の最初のブロック分（最初の改行まで）を鍵にし、鍵を含むブロックをすべて候補にする。
  空白と改行の並びは1つの空白に畳み、両側を同じに整える。今の本文の各ブロックは、表示と同じ解釈器で文字にしてから比べる（`InlineSyntax` → [lessons L51](../lessons/L51.md)）
- **引用は前後の文字で絞る。** 候補のうち、控えた直前と直後の文字がどちらも一致するものが1つなら、それが引用元である。
  どちらも一致するものが無ければ、片側だけ一致するものが1つのとき、それを引用元とする。**それ以外（同じ強さの候補が2つ以上、または前後がどちらも合わない候補しか無い）は絞れない**
- **控えた位置は前後の文字を持たないので、候補が1つのときだけ使う。** 候補を探す範囲は、まず控えた見出し名に一致する節（同名なら候補のすべて）の中、無ければ本文の全体
- **1つに絞れたら、そのブロックを含む節のメモとして並べる。** 見出しの照合の3値（一意・同名に共通・見つからない → [margin_pane](margin_pane.md) §5.6）より優先する。見出しの脇の印と件数もこの結果に従う
- **絞れなければ、黙って先の方を採らない。** 引用は「同じ一節が本文に N か所あります」と添え、押すと候補を並べて選ばせる（同名の見出しで候補を選ばせるのと同じ形）。
  節の割り当ては、候補の節のどれにも出す「同名に共通」と同じ扱いにし、一意の節として数えない。控えた位置は「書いた頃の位置へ」を出さず、見出しの照合へ戻る
- **見つからなければ、今の見出しの照合に戻る。** 引用は表示したまま押せなくし、添え書きに「引用した一節は本文に見つかりません」と出す。
  **本文の編集で元の段落が消え、同じ文の別の段落だけが残ったとき**は、前後の文字が合わなければ「絞れない」に入り、元の場所とは言わない
- **飛び方は節へ飛ぶのと同じ口を使う**（`BodyPosition` → 見開きの間も同じ位置へ送る）。飛び越した画像の測定も同じく頼む
- **照合は本文の大きさに比例するので Main で走らせない**（最大1MB × メモ20件 → [architecture](../system/architecture.md) 判断3）。メモか解析結果が替わったときに Main の外で作り直し、`ThreadingScanTest` の表へ1行足す

### 5.6 並べ読み中の引用（2026-10-24、オーナー判断 → 判断7）

**右のノートは隠して保ち、右の面が何を出すかは明示の状態で持つ。** 並べ読みの状態に、右の面の出し分け（資料＝右のノート／書きかけ）を足す。

| 並べ読みの間の出来事 | 右の面 | 並べ読み |
|---|---|---|
| 左で引用する（メニュー・札） | 書きかけに替え、引用を付ける | 終えない。右のノートと位置は窓で隠すときと同じ持ち方で保つ |
| 切替の「資料」 | 右のノートを同じ位置で出す。書きかけはそのまま残る | 保ったまま |
| 切替の「書きかけ」 | 書きかけを出す（引用・文字・フォーカスの前の位置のまま） | 保ったまま |
| 引用の ✕ | **替えない。** 引用だけが外れる（§5.3） | 保ったまま |
| 引用つきのメモが受け取れた | 資料へ戻す。書きかけが空になるので切替も消える | 同じノートを同じ位置で |
| 戻る操作（右が書きかけのとき） | 資料へ戻す。**引用と書いた言葉は書きかけに残る** | 保ったまま |
| 置いたが満杯・失敗・確認できない | 書きかけのまま（保存の状態を見せる） | 保ったまま |
| 書きかけの「このノートの関連」から別の候補を開く | 新しい候補を資料として出す | 新しい並べ読みに替わる。書きかけは残る |
| 帯の ✎・重ねたレールのタブ・ノート切替・Vault 切替 | 今どおり | 今どおり終える（出し分けも一緒に消える） |
| 窓が変わってペインが閉じる | — | 今どおり隠して保つ。書きかけがあるのでシートへ移す（→ [margin_pane](margin_pane.md) §5.4） |
| 出せる窓へ戻って ✎ で机を開く | **出し分けのまま**（書きかけなら書きかけ、資料なら右のノート） | 保ったまま |

- **切替は、並べ読みの間に、右が書きかけを出しているか、書きかけが空でないときに出す。** 右が書きかけのときは必ず出すので、書きかけを空にしても右のノートへ戻る入口は消えない
- **出し分けは並べ読みと同じ寿命で持つ**（ノート単位。並べ読みが終われば一緒に消える）
- **受け取れたときに資料へ戻すのは調停側（`NoteSessionCoordinator`）。** 書きかけの規則が送信の受理を決めた結果を、並べ読みへ伝える。引用が消えたこと自体では戻さない

### 5.7 窓・器の切替

- 書きかけは ViewModel 側にあるので、引用はシートとペインの切替・全画面の往復・Fold の開閉・画面の作り直しをまたいで残る（今の一組と同じ）
- **引用だけの書きかけも「書きかけがある」に数える。** ペインが窓で閉じるときシートへ移す規則（[margin_pane](margin_pane.md) §5.4）は、文字が空で引用だけがあるときも移す
- **札は窓が変わったら消す。** 運んでいる途中でも、机の画面が組み直されたら運ぶのをやめる。メニューから同じ一節を選び直せる

## 6. 状態とデータ

**余白メモに欄を1つ足し、痕跡のスキーマを v7 から v8 へ上げる。痕跡ファイルの上限を 128KB から 192KB へ上げる。** 読める版は v1〜v8 で、書き戻しは v8。

```kotlin
data class MarginMemo(
    val text: String,
    val writtenAtEpochMillis: Long,
    val sectionTitle: String? = null,
    /** 引用か、書き始めた頃に読んでいた位置。v7 以前のメモは null */
    val passage: MemoPassage? = null
)

sealed interface MemoPassage {
    /** 利用者が選んだ一節。前後の文字で引用元を照らし直す。途中まで（`truncated`）なら末尾に「…」を出す */
    data class Quoted(val text: String, val before: String, val after: String, val truncated: Boolean) : MemoPassage

    /** 書き始めた頃に読んでいた位置の手掛かり。画面には「書いた頃の位置へ」だけを出す */
    data class Seen(val text: String) : MemoPassage
}
```

- **種類ごとに型を分ける**（→ 判断3）。前後の文字は引用にしか無いので、控えた位置に前後の文字が入った組を型として作らない
- **検証:** 引用の `text` は空でなく1,024バイト以内（`ReadingTraceLimits.MAX_QUOTE_BYTES`）、`before`・`after` は各32バイト以内（`MAX_QUOTE_CONTEXT_BYTES`。空でよい）。
  控えた位置の `text` は空でなく64バイト以内（`MAX_SEEN_BYTES`）。種類は既知の値だけ。v7 以前は欄が無いので null として読む
- **容量:** 全欄を上限まで詰めた痕跡は今 112,843 バイト（2026-10-24、実シリアライザで測った）。20件すべてに最大の引用と前後の文字を足すと、
  エスケープで2倍に膨らむ最悪で約45KB 増え、約158KB になる見込みで、128KB に収まらない。**上限を 192KB へ上げる**（余りは約34KB）。
  **実装時に `ReadingTraceLimitsTest` の最悪の痕跡へ passage を足して測り直す**（→ [reflect_margin_memo](reflect_margin_memo.md) 判断11）
- **上限を上げるときに同じ変更で直すもの:** `ReadingTraceLimits.MAX_FILE_BYTES` とその KDoc、`ReadingTraceLimitsTest`・`ReadingTraceStoreTest` の KDoc、
  [reflect_margin_memo](reflect_margin_memo.md) の上限の表と判断11、[reflect_reading_trace](reflect_reading_trace.md) の上限の表（2026-10-24 に「128KB」を名指ししている箇所を数えた）。
  上げても退避ファイル全体の上限（5,000件かつ8MB → [reading_trace_backup](reading_trace_backup.md)）は変えない。配布前なので、上げた後のファイルを古い版のアプリが読む場面は考えない
- **合流:** 鍵 `(日時, 本文)` は変えない。メモは編集できないので、同じ鍵のメモは同じ passage を持つ。退避ファイルは痕跡と同じ版で欄ごと運ぶ
- **退避と読み戻し:** 退避ファイルの痕跡は v8 で書き出し、v1〜v8 を読み戻せる。退避ファイルの版（`ReadingTraceBackupLimits.FORMAT_VERSION`）は、痕跡のスキーマ版と別に要否を実装時に確かめる（→ [reading_trace_backup](reading_trace_backup.md)）
- **スキーマを上げたら、今の版を名指しする文書を全部直す**（`SchemaVersionDocsTest` → [lessons L14](../lessons.md#l14-横展開は最後の1本を取り残す)）

| 状態 | 変更 | 登録 |
|---|---|---|
| 余白メモ（永続） | `passage` を足す | 痕跡の欄なので登録しない。`reflect_reading_trace` のデータ表と `reflect_margin_memo` の永続化モデルを直す |
| 書きかけ（`MarginMemoDraft`） | 引用（文字・前後・切れた部分・引用元の節）と控えた位置を足す | 今と同じ。**`NoteUiState` の外**で、Vault 切替でだけ捨てる（アーキテクチャ判断4の3行目） |
| 送信（`MemoSubmission`） | 保存値のメモが `passage` を持つ | 今と同じ |
| 並べ読み（`SideReadingState`） | 右の面の出し分け（資料／書きかけ） | 並べ読みと同じく `cancelNoteScopedJobs()` と `withNoteScopedReset()`（既に登録済みの状態の中に足す） |
| 札・札が持つ一節と引用元 | **新規。** 画面だけの状態 | 状態に入れない。§5.1 の契機で捨てる |
| 照合の結果 | **新規。** メモごとに、1つに絞れたブロック・絞れない候補・見つからない | 画面側で導き、Main の外で作る（§5.5）。状態に入れない |

## 7. システム設計

| 層 | 新規 | 変更 |
|---|---|---|
| `model` | `MemoPassage`（`Quoted`・`Seen`）、`MAX_QUOTE_BYTES`・`MAX_QUOTE_CONTEXT_BYTES`・`MAX_SEEN_BYTES` | `MarginMemo` に `passage`。スキーマ版を v8 に。`MAX_FILE_BYTES` を 192KB に。`MarginMemoDraft` に引用と控え |
| `domain` | `MemoPassages.kt` — 引用を整えて切れる部分を分ける（`composeQuote`）・引用元の前後を控える（`quoteContextOf`）・書き始めの位置を選ぶ（`seenPassageAt`）・照らし直す（`locatePassage`。1つ・絞れない候補・見つからないの3値）。いずれも純関数 | `arrangeMemos` が照合の結果を優先して節を決める。書きかけの規則（`quoted`・`unquoted`・`edited`・`sendAction`・`accepted`）に引用を足す |
| `data` | — | `ReadingTraceJson` が `passage` を読み書きし、v1〜v8 を読む |
| `controller` | — | `MarginMemoController` の送信が引用か控えを持つ。`SideReadingController` に右の面の出し分け。`NoteSessionCoordinator` が受理を並べ読みへ伝える |
| `ui` | `QuoteTextToolbar.kt` — 選択メニューに「引用して書く」を足し、選んだ文字と範囲の矩形を端末のクリップボードを通さずに受け取る。`QuoteChip.kt` — 札の表示と運び、落とし先の判定（`quoteDropTargetFor`）、範囲の矩形から引用元のブロックを決める判定（`quoteSourceBlockAt`）。いずれも判定は純関数 | `MarkdownRenderer` と `NoteSpread` の本文の選択に上の2つを渡す（右のノートには渡さない）。余白の面に引用の欄・メモの行に引用と「書いた頃の位置へ」と候補の選択。並べ読みの右の面に切替。`DeskSpread` に札の層 |
| 窓口 | — | `NoteViewModel` に引用を付ける・外す口と、右の面の切替の口 |

- **選んだ文字の受け取り方。** Compose 1.7.3 の `SelectionContainer` は、選択メニューを `LocalTextToolbar` から、コピー先を `LocalClipboardManager` から読む（2026-10-24、バイナリで確かめた）。
  今のノートの本文の選択の内側だけで両方を差し替える — メニューは「引用して書く」を足した自前のもの、コピー先は普段は端末のクリップボードへ渡し、「引用して書く」の間だけ文字を受け取って端末へは渡さないもの。
  **範囲の矩形はメニューを出す呼び出しが渡してくる**ので、文字と一緒に受け取って引用元のブロックを決める（§5.2）
- **引用元のブロックは、矩形の始まりと本文の一覧の見えているブロックの位置から決める**（縦の流しは `LazyListState` の見えている項目、見開きはページに組んだブロック）。
  一覧の位置は窓の座標へ直してから比べる
- **札は机の画面の Composable の最上層に置き、指を自分で受ける。** 机の横の払いは子より先に指を見るが（`detectDeskSpread`）、札は兄弟として上に重なるので、札から始まった指は払いに届かない。これは実装時に instrumentation で確かめる
- **落とし先の判定は純関数にする**（指の位置・余白の面の範囲・折り目の帯 → 落とす／落とさない）。札の位置の決め方（選択の矩形・左の面の範囲 → 置く位置）も同じ
- 純関数の置き場所は責務で分ける（→ [architecture](../system/architecture.md) 判断5の4）。照合と書きかけの規則は `domain`、札と落とし先と矩形からブロックを決める判定は画面の形なので `ui/screen`

### 実装の区切り

着手の順はロードマップが持つ。この文書は区切り方だけを決める。

1. **土台（JVM）:** スキーマ v8（`passage`）・ファイルの上限を 192KB に・引用の整え方と切れる部分・前後の文字の控え・書き始めの位置の選び方・照らし直し（3値）・並べ方・書きかけの規則・容量の測り直し・退避と読み戻し。送信が引用か控えを運ぶところまで。画面に出るものは変えない
2. **引用と段落へ飛ぶ（全端末）:** 選択メニューの「引用して書く」・矩形からの引用元・引用つきの書きかけ（行き先と未保存の表示・切れる部分）・メモの行の引用と「書いた頃の位置へ」と候補の選択・書き始めの控え・照合を Main の外で作る
3. **机の札（開いた Fold）:** 札の表示と運び・落とし先・外で離したときに戻す・横の払いとの取り合い
4. **並べ読み中の引用:** 右の面の出し分けと切替・受け取れたら資料へ戻す・窓が変わったときの扱い

2〜4は同じ実機検証に載せる（1は画面を変えないので載せない）。余白メモが段落まで辿れない課題と、並べ読み中に引用を外すと入力面まで隠れる課題は、その実機検証で閉じる。

## 8. 設計判断と代替案

### 判断1: 入口は全端末の選択メニューの「引用して書く」。札は開いた Fold の机だけ（2026-10-24、オーナー判断）

メニューはスマホでも Fold でも同じ操作で、読み上げでも届く。札はその上に足す Fold の体験で、2面を並べたときにしか意味を持たない。
**語を「引用して書く」にしたのは、押した後に書くことになると分かるため。** 「余白へ」だけだと、押した時点で保存したように見えうる（外部レビューの指摘）。
**採らなかった案:** 段落の脇に引用のボタンを置く（範囲を選べず、本文の脇に印が増える）。メニューだけにする（Fold の契約2が Google の言うドラッグ&ドロップに当たるのに、机の上で運べない）。

### 判断2: 引用だけでは置けない。自分の言葉が要る（2026-10-24、オーナー判断）

余白メモは利用者自身の言葉を置く場所で、引用はそれに添えるものとして扱う。引用だけを置ける形にすると、メモの一覧が本文の抜き書きで埋まり、次の再会で自分が何を思ったかが残らない。
引用だけの書きかけは保存していないので、引用の欄に「まだ置いていません」と出し、預かっている書きかけと保存したメモを取り違えさせない。

### 判断3: 引用と控えた位置を1つの欄に、種類ごとの型で持つ

どちらも「メモを書いた場所」を指し、照らし直しも飛び方も同じ口を使う。違うのは画面での出し方と、前後の文字を持つかどうかである。
1つの欄に入れるので、両方が入った組は作れない。種類ごとに型を分けるので、控えた位置に前後の文字が入った組も作れない。種類を真偽値にしない（→ [lessons L28](../lessons/L28.md)）。

### 判断4: 引用は1,024バイト（約340字）。痕跡ファイルの上限を192KBへ上げる（2026-10-24、オーナー判断）

上限で自動に切った文章をそのまま確定すると、末尾の否定・例外・結論だけが落ちうる（外部レビューの指摘）。約85字は容量の余りから決めた値で、読み手にとっての意味の区切りではなかった。
メモ本文と同じ1,024バイトなら短い段落は丸ごと引け、超えるときは置く前に切れる部分を見せるので、意味が落ちたことに気づかないまま置くことはない。
容量は §6 のとおり 128KB に収まらないので、ファイルの上限を上げる。配布前で古い版との互換は問題にならず、退避ファイル全体の上限も変えずに済む。
**採らなかった案:** 約85字のまま置く前に切れる部分を見せる（引ける一節が一文から二文に留まる）。約85字を超える選択を引用にせず選び直させる（意味は切れないが、長い一節は引けない）。

### 判断5: 引用の無いメモは、書き始めたときの最上端のブロックを位置の手掛かりとして控え、「書いた頃の位置へ」と言う（2026-10-24、オーナー判断。控え方は仮の決定）

書き込み先の節を決めるのと同じ瞬間・同じ基準なので、節と位置が食い違わない。反応した段落が画面の下のほうにあるとずれる。
**だから「書いた段落」とは言わない。** 推測を断定に見せると、節だけの記録より精密に見える分、後日の解釈を誤らせる（外部レビューの指摘）。語は「書いた頃の位置へ」にし、読み上げも引用と分ける。
**採らなかった案:** 置く前に控えた段落を見せて変えられるようにする（断定してよくなるが、すべてのメモの入力の周りが増える）。自動の控えをやめる（引用の無いメモが今どおり見出しまでになる）。
控え方（最上端か、画面の中央か）は、**オーナーが「使ってみないとわからない」としていったんこの形にした。** 実機で使って見直す（→ §10）。

### 判断6: 段3は今のノートの本文だけから引く（2026-10-24、オーナー判断）

右のノートの一節を引くと、どのノートの一節かを控えることになる。それは並べて考えた組を残す段4（契約3）の中身そのもので、先に作ると段4のデータを先取りする。
利用者には段の区切りが見えないので、引用の欄に行き先（今のノートの余白）を出し、右へ落としても左のノートのメモになることを見せる（§5.2）。

### 判断7: 並べ読みの間に引用したら、右のノートを隠して保ち、右の面の出し分けを明示の状態で持つ（2026-10-24、オーナー判断）

並べ読みは右のノートと照らしながら書くための形で、引用するたびに終わると、比べていたノートを開き直すことになる。
**書く途中で右のノートを確かめたくなるので、「書きかけ｜資料」の切替で1操作ずつ行き来できるようにする。**
**引用の有無で右の面を決めない。** 決めると、引用だけを外したい ✕ が右のノートへの切替を兼ね、書き続ける入力面が隠れる（外部レビューの指摘）。
置いて受け取れたら資料へ戻す方針は保つ — 書き終えたら、比べていたノートへ戻るのが自然な次の手である。
**採らなかった案:** 「← 余白へ戻る」と同じく並べ読みを終える（置いた後に右のノートを開き直す手間が毎回かかる）。それぞれの面に戻るボタンを置く（切替より目立たないが、今どちらにいるかを面の中身で判断することになる）。

### 判断8: 端末のクリップボードも、端末のドラッグ&ドロップの仕組みも使わない

**クリップボードを通すと、利用者が前にコピーしたものを黙って上書きする。** 選択メニューのコピー先をこの本文の中だけで差し替えれば、端末のクリップボードに触れずに選んだ文字を受け取れる。
**ドラッグを画面の中だけで運ぶのは、落とし先がこのアプリの余白の面だけで、落とし先の規則を自前で書きたいから。** 折り目の帯を落とし先から外す、横の払いと取り合わない、外で離したら札を元の位置へ戻す、のどれも、
画面の中の判定なら純関数にして JVM で確かめられる。端末の仕組み（Compose の `dragAndDropSource`）は、他のアプリへ渡すかを `DRAG_FLAG_GLOBAL` で選べるので、アプリの外へ出ることを理由にはしない。
採用中の Compose 1.7.3 で使えるかは確かめていない。札の手触りが実機で足りなければ、そのとき端末の仕組みと比べる。

### 判断9: 余白メモの判断2（本文の範囲へ紐づけない）との関係

[reflect_margin_memo](reflect_margin_memo.md) 判断2 は「長押しした段落に付ける」案を、**利用者が「どこに付けるか」を決めることになる**ので採らなかった。
引用はこれに当たらない — 引用は付けなくても置け（引用の無いメモが今どおりの入口）、付けるのは利用者が場所を選びたいときだけである。
控えた位置は自動で、要求を1つも増やさず、書いた対象とも言わない。**本文が編集されれば紐づけ先が壊れる**という懸念には、番号ではなく文字で照らし直し、絞れなければ候補を、見つからなければ今の見出しの照合を出すことで応える（判断10・判断11）。

### 判断10: ブロックの番号は保存せず、文字で照らし直す

ブロックの番号や文字の位置を保存すると、Obsidian で本文が編集された次の読書で別の段落を指し、それに気づけない。文字なら、見つからないこと・絞れないことが分かる。
**採らなかった案:** 番号と文字の両方を保存して番号を先に試す。番号が当たっても段落が変わっていれば誤って飛ぶので、結局文字で確かめることになる。

### 判断11: 引用元は選んだ時点の位置で決め、前後の文字で照らし直す。絞れなければ候補を見せる

選んだ文字だけで場所を決めると、本文に同じ文が2度あるとき、後ろを選んでも先の方へ確定する。ノートを編集していなくても起き、選んだ文字は正しく見えるので誤りに気づきにくい（外部レビューの指摘）。
そこで、引用した時点では選択の範囲の矩形から選んだブロックそのものを決め、照らし直しのために前後の文字を控える（引用に前後の文字を添えて同じ文を区別する考え方は、W3C の Text Quote Selector と同じ）。
**照らし直しても1つに絞れないときは、どれも引用元と断定しない。** 曖昧さを見せる形にすれば、完全な特定を作らずに誤った案内を避けられる。
**採らなかった案:** 本文の何番目の一致かを控える（編集で数がずれると黙って別の一致を指す）。

### 判断12: 札を余白の外で離したら、元の位置へ戻す（2026-10-24、オーナー判断）

選んだ範囲は札をつかんだ時点で解けるので、外で離すたびに一節を捨てると、長押しと範囲の調整からやり直しになる（外部レビューの指摘）。
札が一節と引用元を持ったまま戻れば、もう一度運ぶか押すだけで済む。本文のほかの場所に触れる・別の文字を選ぶ・スクロール・窓の変化で消すので、古い札が残り続けることはない。
**採らなかった案:** 段3はメニューだけにして、札は実機で価値を確かめてから足す。

## 9. 品質要件

- **データ保護:** 書いた言葉に加えて、付けた引用も失わない。引用だけの書きかけも書きかけとして預かる（§5.3・§5.7）。v7 以前の痕跡はメモ・訪問ともに読める
- **誤った案内をしない:** 引用元が1つに絞れないとき・見つからないときは、そう言う。自動で控えた位置を、書いた対象のようには見せない（§5.4・§5.5）
- **性能:** 段落の照合は Main の外で行う（§5.5）。本文の表示とメモの読み込みを照合で待たせない
- **プライバシー:** 選んだ文字を端末のクリップボードへ渡さず、ほかのアプリへ運べる形にもしない（判断8）
- **アクセシビリティ:** 運ぶ操作は読み上げで扱わず、メニューの「引用して書く」と札を押す操作で同じことができる。引用・「書いた頃の位置へ」・候補は押せる範囲を広く取り、
  読み上げ名を「引用した段落へ本文を送る」「メモを書いた頃に読んでいた位置へ本文を送る」「同じ一節の候補を選ぶ」と分ける。右の面の切替は今どちらを出しているかを読み上げる

## 10. 検証と受け入れ条件

- **JVMテスト:**
  - 引用を整える（制御文字・前後の空白・1,024バイトの切り口が文字の途中にならない・切れる部分を返す・空白だけは null）と、前後の文字の控え（ブロックの端では短い・各32バイト）
  - 書き始めの位置を選ぶ（最上端が見出し・画像・区切り線・表のときは同じ節の次の本文のブロック、無ければ null）
  - 照らし直し: **同じ節に「この方法は有効である。ただし条件Aでは使わない。」と「この方法は有効である。ただし条件Bでは使わない。」を置き、後ろから「この方法は有効である。」を引用したメモが後ろへ戻る**。
    同名の見出しの中で同じ形でも同じ。前後の文字が同じ強さで2つに合えば絞れない。元の段落を消して同じ文の別の段落だけを残すと、元の場所と言わない。
    空白と改行の畳み方・表示の解釈器と同じ文字・見つからない。控えた位置は候補が2つ以上なら使わない
  - 並べ方（1つに絞れれば同名の見出しでも一意の節、絞れなければ候補の節のどれにも出して一意として数えない、見つからなければ今の見出しの照合、印の件数がそれに従う）
  - 範囲の矩形から引用元のブロックを決める（矩形の始まりを含むブロック・画面の外に始まる範囲では決めない・見開きのページに組んだブロック）
  - 書きかけの規則（引用を付けると書き込み先が移る・書いている途中でも移る・✕ は引用だけを消し文字があれば書き込み先を保つ・引用だけの書きかけは空ではない・文字が空なら置けない・引用を替えたら確かめるではなく置く・受け取れたときに引用が送ったものと違えば消さない）
  - 痕跡の JSON（v8 の往復・v1〜v7 を null で読む・種類の未知の値を弾く・各上限を超えたら弾く・控えた位置に前後の文字が入らない）と、最悪の痕跡を実シリアライザで測って 192KB に収まること。上限を上げても読み込みと保存が同じ上限を使うこと
  - 合流（同じ鍵のメモの passage・片側だけ v7 の退避の読み戻し）
  - 右の面の出し分け（引用で書きかけ・切替で行き来して両方の位置を保つ・✕ では替わらない・受け取れたら資料・戻る操作で資料へ戻って書きかけが残る・満杯や失敗では書きかけのまま・別の候補で資料・✎ とノート切替で消える・窓が変わって ✎ で開き直すと出し分けのまま）。
    **片方の実行中にもう片方を操作する両方向**（保存の途中に切替や右の候補の替えを押す、右の読み込み中に引用する）
  - 落とし先と札（折り目の帯・余白の面の外で離すと元の位置へ戻る・本文に触れる／別の文字を選ぶ／スクロール／窓の変化で消える・左の面に収める・片側1画面と帯の間は出さない）
- **instrumentation:** 選択メニューに「引用して書く」が出て、押すと引用が付き入力欄にフォーカスが移る（スマホのシート・机）。端末のクリップボードの中身が変わらない。
  同じ文が2度ある本文で後ろを選ぶと、引用元が後ろに決まる（縦の流しと見開き）。札を運んで落とすと引用が付き、札から始めた指で片側1画面にならない。
  並べ読みの間に引用して ✕ を押しても入力面のまま。切替で右のノートと書きかけを行き来し、置くと右が同じノートの同じ位置へ戻る。引用つきのメモの引用を押すと本文がその段落へ飛ぶ
- **実機確認:** 机で札を運ぶ手触り（つまみやすさ・落とし先の縁・折り目の近くで離したとき・外で離して戻った札をもう一度運ぶ）。長押しの選択・選択の端の調整・横の払い・本文のスクロールとの取り合い。
  **比べながら書く流れを補助なしで一度通す** — 左の一節を引用 → 右の別の一節を資料で確かめる → 引用と書きかけを保ったまま続きを書く → 引用だけ外す → 置く。
  **書き始めの位置の控え方が、読んでいた位置の手掛かりとして役に立つか**（判断5 の見直しの材料。オーナーが使って判断する）。
  長い一節（約340字を超える）を選んだときに、切れる部分が置く前に分かること。キーボードを出した後に本文がどれだけ見えるか。大きな文字と狭い窓
- **実機で起こせないので自動テストが持つ順序:** 引用を付けた直後の保存の結果と、右の候補の替えが同時に届く順序。照合を Main の外で作っている間にメモか解析結果が替わる順序。
  窓が変わって机が組み直される途中で札を離す順序
- **保証していないこと:** 同じブロックの中に同じ文が2度あるときに、どちらの位置かまでは決めない（飛ぶ先はブロックなので足りる）。
  表・リスト・引用の行をまたいで選んだときの引用の文字の形（§11 で着手時に確かめる）。段落の言い回しが少し変わったときに同じ段落とみなすこと（前後の文字が合わなければ絞れない扱いになる）。
  書き始めた頃の位置が、書いた対象と一致すること（手掛かりであって記録ではない）

## 11. 既知の制約・未解決事項

- **着手時に確かめること（Compose 1.7.3 の実物で）:**
  - 自前の選択メニューを、端末の浮かぶメニュー（`ActionMode` の浮動型）で組めること。「コピー」「すべて選択」を今どおり出せること
  - メニューを出す呼び出しが渡す範囲の矩形の座標系と、縦の流し（`LazyListState`）・見開きのページのブロックの位置を同じ座標へ直せること
  - 複数のブロックをまたいで選んだときに、コピー先へ渡る文字の形（ブロックの境目の改行・リストの記号・表のセルの区切り）。照合の鍵の切り方をそれに合わせる
  - 札を机の最上層に置いたとき、札から始まった指が `detectDeskSpread` に届かないこと
- **選んだ範囲は札をつかむと解ける。** 選択メニューのコピーは、文字を渡した後に選択を解く作りになっている（`toolbarCopy` が `copy` の後に `onRelease` を呼ぶ。2026-10-24、バイナリで確かめた）。
  選択の中身を直接読む公開の口は無いので、札が一節と引用元を持って戻る形で補う（判断12）
- **控える位置は仮の決定である**（判断5）。実機で使って、画面の中央など別の基準へ替える余地を残す
- **余白メモが段落まで辿れない課題**と、**並べ読み中に引用を外すと入力面まで隠れる課題**（課題台帳）は、この段の実機検証が終わるまで台帳に残す
- 段4（机の記憶）で、右のノートから引く・再会カードに引用を出す・並べた組を残すをまとめて決める
