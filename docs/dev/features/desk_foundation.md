## 1. 概要

**開いた Fold の机で、右（補助の面）に開いたノートの中のリンクを押すと、右のままそのノートへ辿れる。**
Fold を閉じても内側を横にしても並べ読みは終わらず、ペインを出せる窓へ戻ると、右に出していたノートが読んでいた位置で戻る。
左の今のノートは、どの間も替わらない。

[fold_experience](../system/fold_experience.md) の契約1（補助の面を独立して探索できる）と契約4（同じ読書の中なら、閉じて開いても補助の面の配置が戻る）にあたる。
どちらも保存するデータを増やさない体験で、スマホに同じものは置かない（→ 同 §5 の機能と体験の線引き）。

## 2. ゴールと非ゴール

### ゴール
- 右のノートの中の、別のノートへのリンクを押すと、右がそのノートに替わる。見出しつきならその見出しから始める
- 右のノートの中の、同じノートの見出しへのリンクを押すと、右がその見出しまで進む
- 右のノートから今のノート（左）へのリンクを押すと、左の本文がその見出しまで進む
- Fold を閉じる・内側を横に持つ・狭い分割にするなど、**窓のせいでペインを出せない間も並べ読みを保つ。** 出せる窓へ戻ったら、同じノートを同じ位置で出す

### 非ゴール
- **右で辿った順は持たない（2026-10-18、オーナー判断）。** 「← 余白へ戻る」と戻る操作は、何回辿っても余白へ戻る。
  途中のノートへ戻る道は作らない — 本文のリンクで戻る道を作らなかったのと同じ線である（→ [note_links](note_links.md) 判断5）。
  引き返したい場面が多いと分かったら、後から足す
- 右のノートを今のノートにするのは「このノートへ移る」だけのまま（不変条件 → [fold_experience](../system/fold_experience.md) §4）
- 右のノートでは、訪問の記録・要約・分野判定・余白メモ・再会カードのどれも動かさない（→ [margin_pane](margin_pane.md) §5.9）
- ペインを出せない窓で、右のノートを見せない。狭い窓の補助の面はシートで、シートは余白だけを出す
- プロセスが終わった後と、日をまたいだ後には戻さない（翌日の机は契約にしない → [fold_experience](../system/fold_experience.md) §5）
- 余白の面の位置は戻さない。余白は本文の節についていくので、位置より今の節で決まる

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 右で辿る | 右のノートの中のリンクを押すと、右がリンク先のノートに替わる | ペインで並べ読み中、右のノートが読めている |
| 右の中の見出しへ送る | 右のノート自身の見出しへのリンクは、右をその見出しへ送る | 同上 |
| 左へ送る | 右から今のノートへのリンクは、左の本文をその見出しへ送る。本文が隠れていれば2面へ戻す | 同上 |
| 窓が変わっても保つ | ペインを出せない窓の間、並べ読みを終えずに隠しておく | 並べ読み中に窓が変わった |
| 出せる窓で戻る | 右に同じノートを、閉じる前に読んでいた位置で出す。片側を1画面にしていたなら2面から始める | 隠している間にペインを出せる窓へ戻った |

## 4. 現在のユーザーフロー

1. 開いた Fold の机で、関連の候補か本文のリンクから、右でノート X を開く（→ [margin_pane](margin_pane.md) §5.9・[note_links](note_links.md)）
2. X の中のリンクを軽く押す。右が Y に替わる。左は替わらない。続けて辿れる
3. 「← 余白へ戻る」か戻る操作で、どこまで辿っていても余白へ戻る。関連の候補から始めたなら関連の一覧まで面を送り、
   本文のリンクから始めたなら余白は開く前の位置のまま戻す（辿り始めた入口で決まり、最後に辿ったリンクでは決まらない）
4. Fold を閉じる。外画面はスマホと同じ並べ方で、右のノートは出ない。並べ読みは終わっていない
5. 開き直す。右に Y が、閉じる前に読んでいた位置で出る

**隠している間に並べ読みが終わる契機:** 今のノートを替える・Vault を替える・✎ でペインをしまう（設定を閉じる）・**余白のシートを出す**。
シートは狭い窓と全画面での補助の面なので、シートに余白を出すことは余白へ戻ることと同じに扱う。全画面で開いて閉じてから戻っても同じ（→ §8 判断2）。

## 5. 機能仕様

- **前提条件:** ペインで並べ読み中で、右のノートが読めている。読み込み中と失敗の間は本文が無いので、押せるリンクも無い
- **入力と出力:** 右のリンクは**右のノートを出発点に**引く（相対パスの起点と、同じフォルダを先に見る規則 → [note_links](note_links.md) 判断3）。
  押せる記法・長押しで開かないこと・読み上げから押せることは本文のリンクと同じ（→ 同 §5）

  | 引いた結果 | 画面の操作 |
  |---|---|
  | 別のノート | 右をそのノートに替える。見出しつきならその見出しから。見出しが見つからなければ先頭から開き、そう知らせる |
  | 右のノート自身 | 右をその見出しへ送る。見出しの無いリンクなら先頭へ。見出しが見つからなければ動かさずに知らせる |
  | 今のノート（左） | 左の本文をその見出しへ送る。本文が隠れていれば2面へ戻す。見つからなければ動かさずに知らせる |
  | 見つからない・走査結果がまだ無い | 本文のリンクと同じ知らせだけを出し、何も開かない |

- **上限:** 辿る回数に上限は置かない。持つのは今右にあるノート1枚だけ
- **状態遷移:** 並べ読みが終わる契機は、「← 余白へ戻る」・戻る操作・✎ でペインをしまう・今のノートを替える・Vault を替える・余白のシートを出す、の6つだけ。
  **窓が変わっただけでは終えない**（Fold を閉じる・内側を横にする・狭い分割・高さの足りない横長・全画面への出入り）
- **保存と寿命:** 右のノートと読み込みの状態は ViewModel 側にあり、画面の作り直しをまたぐ（既存）。
  右の本文の位置・送り終えたリンクの要求・辿り始めた入口は、**右の面ではなくノートの画面の保存値**に置く（→ §8 判断3）
- **画面遷移:** 右で辿るときは、右で開くときと同じく書いているつもりを落とす（入力欄は面ごと隠れている）
- **閉じたときの書きかけ:** ペインからシートへ書きかけを移す規則（→ [margin_pane](margin_pane.md) §5.4 の2つ目の表）は、
  **並べ読み中は書きかけの文字だけでは移さない。** 余白は右のノートに隠れていたので、閉じた後も出さない。
  移すと余白のシートが出て、並べ読みが終わってしまう
- **他機能との連携:** 読み込みは並べ読みの経路そのまま（`SideReadingController.open`）。隠している間に読み込みが終われば、開き直したときに読めた本文が出る。
  失敗も右側だけに出る
- **エラー／AI非対応／キャンセル時:** AI を呼ばない。新しく辿ると前の読み込みを取り消す（並べ読みの既存の失効 → [margin_pane](margin_pane.md) §6）

## 6. 状態とデータ

> **保存するデータは増えない。** `NoteUiState` の欄も、契約2箇所（`cancelNoteScopedJobs()`・`withNoteScopedReset()`）への登録も増えない。

- 並べ読みの状態（`SideReadingState`）と本文の解析結果は既存のまま（→ [margin_pane](margin_pane.md) §6）。寿命は [architecture](../system/architecture.md) 判断4の1行目
- ノートの画面（`NoteReaderTab`）の保存値に3つを置く。右の本文の位置（右のノートごと）、送り終えたリンクの要求、辿り始めた入口（関連の候補か本文のリンクか）
- **世代の三層目は要らない。** 補助の面に AI を載せていないので、[fold_experience](../system/fold_experience.md) §5 の見立てどおり既存の行に収まる

## 8. 設計判断と代替案

### 判断1: 右で辿った順は持たない

オーナー判断（→ §2）。順を持つと、新しい状態が増え、窓が変わっても保つもの（契約4）にも入る。
余白へ戻れば関連の候補から選び直せるので、まず持たない形で使い、引き返したい場面が多ければ足す。持たない形から持つ形へは足せるが、逆は作りを捨てることになる。

### 判断2: 窓が変わっただけでは終えず、余白のシートを出したら終える

Fold を閉じたら終える形では、閉じて開くたびに右が消え、契約4を破る。
一方、閉じた窓で余白のシートを出し、開いたときに右のノートが戻ると、シートで書いていた入力欄が右に隠れ、フォーカスの引き継ぎ（→ [margin_pane](margin_pane.md) §5.4）が壊れる。
**補助の面は1つで、狭い窓ではシートがそれにあたる**（→ [fold_experience](../system/fold_experience.md) §6）ので、シートに余白を出すことを余白へ戻ることと同じに扱う。
✎・見出しの印・「前回のメモを見る」・要約を見に行く入口のどれから出しても、全画面から出しても同じになるよう、**シートを開く調停側の共通の口で終える。**
画面の側でシートの可視を見て終える形は採らない — 全画面の間は通常の画面が組まれないので、その間に開いて閉じたシートを見落とす。

### 判断3: 戻すものは右の面ではなく、ノートの画面に置く

右の面はペインを出せない窓では組まれない。面に置いた保存値は面と一緒に消える（Activity の作り直しを挟むと残る場合もあるが、当てにしない）。
**「同じノートを同じ位置で」という1つの受け入れ条件を、右のノート（ViewModel）・位置・送り終えた要求の3つで満たすので、寿命を揃える**（→ [lessons L56](../lessons/L56.md)）。
送り終えた要求だけが面に残ると、開き直すたびにリンクの見出しへ送り直し、読み進めた位置を失う。

### 判断4: Compose の `SupportingPaneScaffold` を使わない

[fold_experience](../system/fold_experience.md) §7 に残していた比較。

- **割り方の規則が自前にある。** `readerLayoutFor` は、折り目が本文領域の中にあるときだけ折り目で割り、外なら中央で割り、下限の幅（本文300dp・ペイン280dp）を割るなら縦積みにする。
  大きさはキーボードを除いて測る。これらは `ReaderLayoutTest` が固定している。Scaffold へ移すと、窓の情報からの指示を自前で作り直すことになり、規則の置き場が2つになる
- **机の操作は Scaffold を入れても残る。** 帯・つまみ・片側を1画面にする払い・外殻にレールを畳ませる通知は自前である
- **行き来の履歴が要らない。** 公開されている説明では、Scaffold の navigator が面の行き来の履歴を持つ。判断1で履歴を持たないので、使い道が無い
- **依存に無い。** material3-adaptive は今の依存に入っておらず、足すなら機能単位で Compose の版とあわせて上げ、実機で確かめることになる（→ [dependency_policy](../system/dependency_policy.md)）。中のふるまいはバイナリで確かめていない

**再検討するのは、自前の割り方の規則を Scaffold の指示で表せると、バイナリで確かめられたとき。**

- **アクセシビリティ:** 右のリンクは本文のリンクと同じ印で、読み上げからリンクとして押せる
- **性能:** 引くのは押したときに1回で、Main で同期に行う（→ [note_links](note_links.md) §7）。表示の経路には乗らない

## 10. 検証と受け入れ条件

- **JVMテスト:** `sideLinkActionFor` の4分岐（`NoteLinkActionsTest`）。並べ読みを終える判定が窓を見ないことと、閉じたときに書きかけをシートへ移すかの判定（`MarginSurfaceTest`）。
  右で2枚目へ辿っても今のノートと記録が何も変わらないこと、シートを開くと並べ読みが終わり閉じても戻らないこと、読み込み中に開いても後から届いた本文を書かないこと（`NoteSessionCoordinatorTest`）
- **instrumentation:** `NoteReadingFlowTest` — 右のリンクで辿る、どこまで辿っても余白へ戻り入口に応じて一覧まで送るか決まる、
  閉じた外画面へ替えて本の形へ戻すと同じノートが同じ位置で出る（作り直しを挟む形と挟まない形）、✎ でしまうと終わる。
  `NoteLinkTapUiTest` — 右の中の見出しへのリンクの送り方
- **実機確認:** 開いた Fold で右のリンクを辿る（別のノート・同じノートの見出し・左のノート・見つからない）。
  物理的に閉じて開く、内側を横にして戻す、分割の幅を変えて戻すで、右のノートと位置が戻ること。閉じている間に ✎ でシートを出してから開くと余白になること。全画面で ✎ のシートを開いて閉じてから戻ると余白になること
- **実機で起こせないので自動テストが持つ順序:**
  - 隠している間に右の読み込みが終わる・失敗する（読み込みは一瞬で終わり、閉じる操作と重ねられない）→ `NoteReadingFlowTest`（窓を閉じた形に替えてから状態を読めた・失敗へ進める）
  - 開き直した直後、窓の情報が揃う前の並べ方で終える判定が走る → 判定が窓を見ないこと自体で防ぐ。`MarginSurfaceTest` がペインの設定だけで決まることを固定する
  - 右で辿った読み込みの途中で、前のノートの読み出しが遅れて終わる → `SideReadingControllerTest` の既存の検査（選び直した後に前の候補の読み出しが終わっても新しい候補を覆わない）
- **保証していないこと:** プロセスが終わった後の復元（並べ読みの状態は保存しない）。余白の面の位置。辿った順。ペインを出せない窓で右のノートを見せること。
  開いた Fold を横に持ったときに2面を出すこと（今の仕様では縦積みで、別の課題）

## 11. 既知の制約・未解決事項

- **文字の大きさ2.0では並べ読み自体が出ない**（本文の幅が下限を割る → [margin_pane](margin_pane.md) §11）。辿る操作もその窓では使えない
- **開いた Fold を横に持つと2面が出ない。** 横の折り目は縦積みのまま（→ [fold_experience](../system/fold_experience.md) §6）。その間も並べ読みは隠して保つ
