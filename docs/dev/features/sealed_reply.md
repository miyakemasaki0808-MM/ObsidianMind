## 1. 概要

ひとことへの返事を書いたあと**封をする**と、次にそのノートと Rediscover で再会するまで、**自分でも返事を読めなくなる**。
再会カードで封を切ると、書いた当時の自分の言葉が、時間差で届く。

Reflect 系の中で、書いた言葉を**未来の自分へ宛てる**唯一の仕掛けである。AIは使わない。
返事の保存先と契約は [reflect_remark](reflect_remark.md) がそのまま持ち、本書はその上に「封」という状態を1つ足す。

出どころは [owner/idea_catalog](../../owner/idea_catalog.md) の「封をした返事」で、
北極星の「過去の自分と再会する」を、AIを1回も呼ばずに最も直接に作る案として選ばれた。

## 2. ゴールと非ゴール

### ゴール
- 返事を「その場で読み返すメモ」から「次の再会で読む手紙」へ変えられる
- 再会の瞬間に、AIの要約や問いではなく**自分の言葉**が待っている状態を作る
- 追加のAI呼び出し・追加のI/O経路を作らず、痕跡サイドカーの欄1つで実現する

### 非ゴール
- **秘匿はしない。** 封は表示の約束であって暗号ではない。退避ファイルには平文で入る（→ §9）
- **催促しない。** 封があることを通知せず、封の件数も出さない。封を知る場所は再会だけ
- **強制しない。** 既定は封なし。返事を保存した後にだけ、封をするかを選べる
- **さがす・関連・履歴から開いても封は切れない。** 意図して開くのは再会ではない

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 封をする | 返事と映し返しの本文が封筒の表示へ置き換わる | 返事が保存済みのとき、ひとこと画面のトグル |
| 封の表示 | 「封をしてあります。次にこのノートと再会したとき開きます」と、封をした日付 | 封があり、まだ開封していないとき |
| 封を切る | 再会カードの行が「封を切る」になり、タップで返事と映し返しが開く | Rediscover で同じノートを引き当て、封が未開封のとき |
| 封を破る | 再会を待たずに開く。破った後は通常の表示 | 封の表示の中の明示ボタン |
| 退避と復元 | 封の状態ごと書き出し、読み戻せる | 既存の退避と復元 |

## 4. 現在のユーザーフロー

1. ひとこと画面で返事を書き、保存する。保存結果が `Saved` か `Held` になる
2. 返事の下に「封をする」トグルが現れる。押すと、返事と映し返しの本文が封筒の表示へ置き換わる
3. ノートを離れる。封は返事と同じ経路で痕跡へ書かれる。`Held` なら預けた痕跡に載って離脱時に確定する
4. 後日、Rediscover で同じノートを引き当てる。再会カードの行が「前回の返事を見る」ではなく**「封を切る」**になる
5. タップするとひとこと画面が開き、「あなたはこう書いた」の前置きに続けて返事と映し返しが出る。開封の日時が痕跡へ書かれる
6. 以後は通常どおり「前回の返事を見る」で読める

**分岐。** さがす・関連・履歴から同じノートを開いてひとこと画面へ入ると、封筒の表示のままで「封を破る」だけが出る。
破ると即時に読め、開封の日時が書かれる。切ったか破ったかは区別して持たない。

**再封はしない。** 開封した返事に再び封はできない。返事を書き直すと封は消え、新しい返事に改めて封を付けられる。

## 5. 機能仕様

- **前提条件:** 返事が保存済みであること。`Failed` の返事には封を付けられない
- **入力と出力:** 入力はトグル1つ。出力は表示の切り替えと、痕跡の欄2つ
- **上限:** 1組の `Reflection` に封は1つ。件数の上限は持たない。封の期限も持たない（→ §8 判断2）
- **状態遷移:** 封なし → 封 → 開封。一方向で、戻るのは返事の書き直しによる「封なし」だけ
- **保存と寿命:** 痕跡サイドカーの `Reflection` に封をした日時と開封した日時を足し、スキーマを1版上げる。
  旧版の痕跡は封なしとして読む。寿命は返事と同じで、痕跡が消えれば封も消える
- **画面遷移:** 無し。ひとこと画面と再会カードの表示が変わるだけ
- **他機能との連携:** 再会カードの「前回の返事を見る」の行を置き換える。「まだ考えたい」の印とは独立で、同時に立つ。
  退避と復元では併合規則「端末に無いものを受け入れる」にそのまま乗り、新旧は返事の日時で見る
- **エラー／AI非対応／キャンセル時:** AIは関与しない。封の書き込みは返事の書き込みと同じ経路なので、
  失敗しても返事は先に保存済みで失われない。ノート切替でも封は離脱時の書き込みに乗るので取り消されない。
  開封の書き込みに失敗したときは画面には開いた状態で出し、次の再会でもう一度「封を切る」が出る

## 6. 状態とデータ

**ノート単位の新しい状態は足さない。** ひとこと画面が持つ `RemarkState.Ready` の `Reflection` に封の欄が含まれるので、
既存の `remarkState` の寿命と契約にそのまま乗る。契約2箇所への新規登録は不要で、
既存の `RemarkController.cancelAndClear()` と `withNoteScopedReset()` の `remarkState` が引き受ける。

**永続化モデル。** `Reflection` に2欄を足す。

| 欄 | 型 | 意味 |
|---|---|---|
| 封をした日時 | `Long?` | null なら封なし |
| 開封した日時 | `Long?` | 封があり、これが null なら未開封 |

返事を書き直す `withReply` は、映し返しを捨てるのと同じ理由で2欄とも捨てる。古い返事への封が新しい返事に残ると噛み合わない。

**破棄条件。** 返事の書き直し。痕跡の削除（孤児掃除・Vault 側の削除）。

**移行。** スキーマを1版上げ、旧版からの読み込みでは2欄を null にする。
`ReadingTraceJsonTest` が持つ旧版互換の固定に1版足す。上限の整合は `ReadingTraceLimitsTest` に2欄ぶんを足す。

## 7. システム設計

```text
ひとこと画面
  └─ 封をする ──► RemarkController.seal()
                     └─ 痕跡の read-modify-write（Coordinator が配る錠を通す）
                        ・痕跡がまだ無ければ、返事と同じ預かりへ相乗り（Held）

Rediscover で引き当て
  └─ ReunionCardController.revealTrace（既存の Rediscover 限定経路）
       └─ Reflection に封があり未開封なら、カードの行を「封を切る」にする
            └─ タップ ──► RemarkController.unseal()
                            └─ 開封の日時を書く（同じ錠）。画面は前置きつきで返事を出す

さがす・関連・履歴から開く
  └─ RemarkController.restoreSaved() が封つきの Reflection を読む
       └─ 画面は封筒。「封を破る」だけを出す ──► unseal()
```

錠は [architecture](../system/architecture.md) の並行処理の規約どおり、痕跡サイドカーの書き込みに使っている共有の `Mutex` を通す。
封と開封の書き込みは返事の保存と同じ read-modify-write で、経路を増やさない。

## 8. 設計判断と代替案

### 判断1: AIを使わない

封は時間の仕掛けであって、生成でも選別でもない。AIを挟むと「封を切るに値するか」を判断させる形になり、
自分の言葉の所有権が薄れる。Nano の錠も回数制限も消費しない。

### 判断2: 封が切れる契機は Rediscover の再会だけ。期限は置かない

さがすや履歴から開くのは意図した閲覧で、再会ではない。封を切る価値は「たまたま引いた」ことにある。
期限つきの自動開封は却下した。時間ではなく再会で開くほうが北極星に沿い、Vault が大きいほど封が長く続くのは仕様の範囲とする。
ただし**封を破ることは常に許す**。自分の言葉を自分が読めないのは、封の意図であって権利の制限ではない。

### 判断3: 秘匿にしない

暗号化は退避・復元と Obsidian の同期に敵対する。封は表示の約束で、退避ファイルを開けば読める。
そう明記することで、封に期待してよい範囲を利用者へ正しく伝える。

### 判断4: 既定は封なし。トグルは保存後にだけ出す

返事を書く前に封を選ばせると、書く前から「未来の自分へ」と構えることになり、返事の性質が変わる。
書き終えてから封をするかを決める。

### 判断5: 通知しない

封の存在は再会でしか知らされない。一覧も件数も出さない。出すと「封を開けるために引き続ける」催促になる。
純粋ランダムなので狙って引けないことが、催促に化けない土台である。

### 判断6: 映し返しも封の内側

映し返しだけ見えると返事の内容が推測でき、封の意味が薄れる。返事と映し返しは1組なので、封も1組に掛ける。

### 採らなかった案: 封の一覧画面

「封がいくつ残っているか」を見せる画面。判断5 に反するので採らない。

## 9. 品質要件

- **プライバシー:** 封は平文のまま。退避ファイル・Obsidian の同期先では読める。封の表示にその旨を1行添える
- **データ保護:** 封の書き込みが失敗しても返事は失われない。返事が先に保存済みであることは [reflect_remark](reflect_remark.md) §8 判断7 の契約に乗る
- **アクセシビリティ:** 封筒の状態と「封を切る」「封を破る」を読み上げ名で区別する
- **オフライン・端末制約:** 端末内で閉じる。AIも通信も使わない

## 10. 検証と受け入れ条件

- **JVMテスト:**
  - `ReadingTraceJsonTest` — 新版の往復、旧版からの読み込みで2欄が null、封なしの互換
  - `RemarkControllerTest` — 封で表示が封筒になる、書き直しで封が消える、`Held` からの封が離脱時に確定する、破ると開封の日時が書かれる、失敗した返事には封を付けられない
  - `ReunionCardControllerTest` — Rediscover の再会でだけ「封を切る」が出る、さがす由来では出ない、開封の書き込みは1回だけ、ノート切替で旧ノートの開封が後着しない
  - `ReadingTraceMergeTest` — 併合で封が消えない、端末に無い封を受け入れる
  - 文言テスト — 封筒・封を切る・封を破る・前置きの出し分け
- **instrumentation:** ひとこと画面の封筒表示と読み上げ名。再会カードの「封を切る」の行
- **実機確認:** 封 → 離脱 → さがすから開く（封のまま）→ 引き当て（開封）。退避と復元で封が残る。初読で返事と封まで書いた回（`Held` 経路）
- **保証していないこと:** 秘匿。封の件数管理。封の期限。他端末との同期での整合

## 11. 既知の制約・未解決事項

- **Vault が大きいと封は長く続く。** 645本の Vault では同じノートを引く確率が低く、封が数ヶ月開かないことがある。期限を置かない判断は実機の体感で見直す
- **痕跡が消えれば封も消える。** 孤児掃除や Vault 側の削除で返事ごと失われるのは返事と同じ
- **封の表示文言は未決。** 「封をしてあります」「封を切る」「封を破る」は仮で、実機で読んで決める
