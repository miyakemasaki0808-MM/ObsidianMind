## 1. 概要

蒸留の候補について「**この候補は重要か**」と「**どこからどこまでを太字にするか**」を分離し、後者をユーザーが決められるようにする。

**太字にする位置には個人差がある。** 規則とAIだけで最終範囲を一意に決めようとせず、AIは重要箇所のアンカーを探すことに集中し、**範囲の最終決定はユーザーが持つ**。自動の粒度判定（句分割・語句抽出）は「操作しなくても保存できる初期値」を作る役へ回る。

**未調整なら従来どおり**チェックして保存するだけで完了する。調整は増える口であって、増える手順ではない。

## 2. ゴールと非ゴール

### ゴール
- AIが選んだ箇所について、**太字の範囲を広げる／狭める**手段を与える
- 調整しても [reflect_distill](reflect_distill.md) の安全契約（AIはIDだけ返す／範囲はアプリが原文オフセットで解決する）を崩さない
- 未調整のときの保存結果を v1 と**完全に同じ**に保つ

### 非ゴール
- **汎用ノート編集機能にしない。** 文字を打てない・消せないだけでなく、**原文の任意の場所を指せない**（→ §8 判断1）
- **本文リーダー上での範囲選択をしない。** 表示用Markdown parser は原文オフセットを持たない（→ [reflect_distill](reflect_distill.md) §8 判断4）
- **調整結果を永続化しない。** 覚えるのはノート本文に入った `**` だけで、サイドカーへ調整履歴を書かない
- 太字以外の装飾（`==highlight==` 等）を扱わない

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 範囲の確認 | 候補カードに「太字にする範囲」が原文のまま出る | 候補表示中 |

| 重なりの自動解消 | 範囲を広げて他の選択候補と重なったら、**相手の選択が外れる**（画面で告げる） | 範囲変更時 |

## 5. 機能仕様

**この節が範囲モデル・プリセット導出・重なり解決の正本。** 数値と書き戻しの契約は [reflect_distill](reflect_distill.md) §5 が持ち、ここでは繰り返さない。

### 候補が持つ3つの範囲

**「範囲3分割」とはこれである。** プリセットの3段（後述）とは別物で、**混ぜない**。

| 範囲 | 意味 | 現状 |
|---|---|---|
| 文脈範囲 | カードとシートに読ませる親文。**太字にしない** | `DistillSentence.contextRange`（既存） |
| 提案範囲 | 非AI段＋AI選定が出した初期値 | `DistillSentence.range`（既存） |
| 確定範囲 | 実際に `**` を挿す範囲。**未調整なら提案範囲と同じ** | **新規** |

**提案範囲を上書きしない。** 上書きすると「提案へ戻す」を実装できず、再計算のたびに初期値が動く。確定範囲は別に持つ。

### 調整の外枠 — 確定範囲は必ず文脈範囲（＝親文）の内側

これが「汎用ノート編集機能」との一線である（理由は §8 判断1）。外枠を親文にすると、**次の3つが規則を書かずに満たされる**。

| 満たされること | 理由 |
|---|---|
| 既存の `**` 強調と重ならない | 親文は `subtractRanges(bodyStart, bodyEnd, strongSpans)` で既存強調を差し引いた区間から作られる |
| 見出し・コードフェンス・表・frontmatter に触れない | それらの行には親文が存在しない |
| 確定範囲は最大160文字 | 候補の入口が `contextRange.length <= MAX_SENTENCE_CHARACTERS` を見ている |

**着手前に挙がっていた懸念のうち「既存太字との重複」は、この外枠を選んだ時点で消える。** 追加の判定を置かない。

### プリセットの3段と、その導出

**新しい分割規則を作らない。** 3段はすべて `DistillSourceModel.sentences` に既にある要素を引き直すだけで、v1で確立した境界（記法をまたがない・リンクだけを避ける・鉤括弧の内側で割らない）がそのまま効く。

| 候補の種類 | `語句` | `意味節` | `文全体` |
|---|---|---|---|
| 語句候補（`isTerm`） | 自分 | 自分を含む非語句要素 | 文脈範囲 |
| 句・文の候補 | **提案範囲の内側にある語句要素がちょうど1つのときだけ** | 自分 | 文脈範囲 |

- **同じ範囲になる段は1つに畳む**（割れなかった文では `意味節` と `文全体` が一致する）
- **存在しない段のボタンを出さない。** 押せない選択肢は「なぜ押せないか」の説明を毎回要求する
- **語句が複数あるときに段を出さないのは、どれを指すか決められないから。** 語句は独立候補として一覧に並びうるので、そちらで選ぶ道が残る。任意の語句を選ぶのは段階2（自由範囲）の仕事
- **モデルへ欄を足さない。** 句・語句はすべて `sentences` に平らに入っているので、包含関係で引ける。**新しいノート単位の状態も増えない**ので、契約2箇所（`cancelNoteScopedJobs()` / `withNoteScopedReset()`）の変更は不要

### 重なりの解決

**調整は実行時に重なりを作れる。** v1 は選定の出口で候補集合を非重複にしていたので、`applyDistillBold` の `require` に届く経路が無かった。調整を入れると届く。

| 重なる形 | 起きる条件 |
|---|---|
| 同じ親文の2つの句を、両方 `文全体` にする | `MAX_CLAUSES_PER_SENTENCE = 2` なので1文から句が2つ候補に入りうる |
| 語句候補を `意味節` や `文全体` へ広げる | 親の内側にいた語句が親と同じ範囲になる |

**解決:** 確定範囲を変えた瞬間に、他の**選択済み**候補と重なるかを判定し、**重なる相手の選択を自動で外す。外したことを画面で告げる。**

- 選択を外すだけなので、**本文へ書く内容は増えない**（安全側へ倒れる）
- 既存の「選択件数・変更後の太字率」の表示がそのまま追随する
- **採らない案:** ①重なったまま保存時に弾く → どれを直せば解けるか分からない詰みを作る ②保存時に自動でマージする → 選んだ範囲と保存範囲が食い違い、「自動補正しない」（[reflect_distill](reflect_distill.md) §8 判断5）と逆を向く ③重なる操作自体を禁止する → 「句を文全体へ広げたい」という最も普通の操作が、同じ文の別の句がたまたま候補にいるだけで不能になる

### 太字率と短文例外の引き直し

- `projectedBoldRatio` / `isWithinDistillBoldLimit` は**範囲のコレクションを受ける**ので、確定範囲を渡すだけで正しく動く。計算式は変えない
- **範囲を読んでいる箇所を全部付け替える。** 現状 `updateCandidateState` と保存経路は `candidatesById[id].sentence.range`（＝提案範囲）を読んでいる。**ここが取り残されると「表示は広がったが保存は元の範囲」になり、しかもテストは緑のまま通る**（→ [lessons](../lessons.md) L14。同型の取り残しが句分割の回に2度出ている）
- **短文例外は「どの候補か」を固定したまま、超過判定だけ引き直す。** 例外の対象IDは v1 どおり最重要の1件に固定する（任意の候補を例外にできるようにしない）。**判定に使う範囲だけを確定範囲へ差し替える** — 範囲を狭めれば例外が要らなくなり、広げれば例外の説明に出す太字率が変わる

### 文言の単位

v1 は「箇所」へ統一し `DistillCandidateUnitCopyTest` が走査している。**調整シートの文言も同じ検査に載せる。** 検査の外に新しい文言を作らない（規則は検査に載せたときだけ守られた → [lessons](../lessons.md) L29）。

### プリセットでは記法が壊れない

段階1で選べるのは既存の分割器が出した範囲だけなので、**サロゲートペア・結合文字・コードスパン・リンク記法の途中に端が来ることは原理的に無い**。安全判定を新規に書かない。段階2で初めて要る規則は §11 に置く。

## 6. 状態とデータ

- **確定範囲は `DistillController.ActiveSession` が持つ**（候補ID → 確定範囲）。v1 が `candidatesById` を Controller 側に置いているのと同じ形で、**原文オフセットをUI状態へ出さない**
- `DistillCandidateItem` に足すのは**表示用の文字列と現在の段**まで（太字になる原文・選べる段の一覧・いま何段か）。`DistillState` に新しい variant を足さない
- **調整シートの開閉は `DistillState.Candidates` の中に持つ。** `NoteUiState` へ新しい欄を足さないので、契約2箇所への登録は不要（既存の `distillState` が既に登録済み）
- **永続化しない。** ノート切替・シート破棄・保存完了のいずれでも確定範囲は消える。残るのは本文の `**` だけ

## 7. システム設計

```
AiTab
 ├─ DistillCandidateRow      ← チェック＋「太字にする範囲」＋シートを開く導線
 └─ DistillRangeSheet（新規・ModalBottomSheet）
      ├─ 親文を原文のまま表示し、確定範囲だけを太字で見せる
      ├─ プリセット（存在する段だけ）
      ├─ 「AIの提案に戻す」
      └─ 変更後の太字率

DistillController
 ├─ presetRangesFor(candidate)   ← 新規・純関数。model.sentences の包含関係だけで引く
 ├─ applyRange(id, preset)       ← 確定範囲を更新 → 重なる相手の選択を外す → 太字率を引き直す
 └─ save()                        ← 確定範囲を applyDistillBold へ渡す（v1の4段書き込みは不変）
```

**器は既存のものを使う。** シートは `SectionChatSheet` と同じ `ModalBottomSheet`、保存前プレビューは現行のまま。

**`presetRangesFor` は Android 非依存の純関数にする。** 3段の導出と重なり解決はどちらも範囲の計算なので、`domain` へ置けばJVMテストで閉じる（→ [architecture](../system/architecture.md) 判断3）。

## 8. 設計判断と代替案

### 判断1: 一線は「原文の任意の場所を指せないこと」で引く

**「文字を打てない・消せない」だけでは一線にならない。** それは太字専用エディタの説明であって、Non-Goals が避けたい形そのものになる。**確定範囲を親文の内側に閉じる**ほうを一線にする。

- **採らない案（候補の内側だけ）:** 提案範囲より外へ出せない。最も安全だが、句分割が意味を切ってしまった場合に伸ばせず、この機能の動機（この部分だけを太字にしたい）の片側しか満たさない
- **採らない案（本文のどこでも）:** 一線を越える側。表示用parserが原文オフセットを持たないため、本文全体をオフセット付きで見せる仕組みを新規に作ることにもなる

**外枠を型で表す。** 確定範囲は「文脈範囲の内側」という不変条件を持つ値として作り、UIの分岐で守らない。

### 判断2: プリセット先行 — 新しい境界規則をゼロにする

`語句` / `意味節` / `文全体` は既存の分割器の出力を読み替えるだけなので、**段階1は安全判定を1つも新規に書かない**。本文を書き換える唯一の機能で、実機確認の面を一度に広げない。

- **採らない案（端を1段ずつ動かすボタン）:** プリセットより細かいが、**境界候補の列挙が新規実装**になる。段階2でスナップを作るなら、それと同じものを二度作ることになる
- **採らない案（最初から自由ドラッグ）:** 最終形へ直行できるが、境界の安全判定・タッチ精度・実機確認が同時に来る

**プリセットだけでは「この部分だけ」を常には満たせない。** それは承知の上で、最終形は段階2の自由範囲である。

### 判断3: 調整は候補ごとの専用シートで行う

候補一覧はチェックのための場所として保つ。**調整という別の作業を、同じ密度の一覧へ混ぜない。**

- **採らない案（カード内インライン展開）:** 最大6件が縦に並ぶ現在のパネルでカードが伸び、AIタブの他パネル（要約・ひとこと）が押し出される
- **採らない案（保存直前のプレビューで調整）:** **本文を書き換える直前の確認画面**に編集操作が同居し、確認の役割が薄まる

**シートを閉じることが確定。** 取り消しの口は「AIの提案に戻す」1つに絞り、キャンセルボタンを別に置かない（口が2つあると、どちらが効いたか読めなくなる）。

### 判断4: 置けない境界には止まれない（スナップ）

**不正な状態を作らせない側に倒す。** `applyDistillBold` が重なりを `require` で拒み、IDパーサーが桁落ちを自動補正せず破棄するのと同じ「入口で防ぐ」型に揃える。

- **採らない案（置けるが無効表示にして保存を止める）:** 詰んだ状態を作れるうえ、無効理由の文言が境界の種類だけ増える
- **採らない案（保存時に安全な位置へ丸める）:** 選んだ範囲と保存される範囲が食い違う。**唯一の本文書き換え機能で、黙って違う範囲を太字にすることになる**

**既存 `**` 強調はスナップ対象に入れない。** 外枠が親文である限り到達できないので、落ちるテストを書けない（→ [architecture](../system/architecture.md) の並行処理の規約と同じ判定）。**到達しうる形に変わったときに足す。**

### 判断5: 重なりは「相手の選択を外す」で解く

理由と却下案は §5 の「重なりの解決」に置く。**この判断の要点は、解決を保存時ではなく操作時に置いたこと。** 保存時に解決すると、ユーザーが最後に見た画面と保存内容が一致しない。

### 判断6: モデルへ欄を足さず、包含関係で引く

`buildDistillSourceModel` は句も語句もすべて `sentences` へ平らに入れているので、3段は包含関係で引ける。**欄を足すと、その欄を読む箇所を数え直す義務（影響面監査）が発生する** — 引けるものを持たない。

**ただし語句候補の親「句」は現状どこにも書かれていない**（語句の文脈範囲は句ではなく文）。これも `sentences` から包含で引く。**引けることを実装前に確かめたので、ここは未確認ではない。**

## 9. 品質要件

- **データ保護:** このアプリで唯一ノート本文を書き換える経路を通る。**確定範囲を渡す以外、[reflect_distill](reflect_distill.md) §7 の4段書き込み・競合検知・復旧レコードを一切変えない**
- **アクセシビリティ:** プリセットのボタンは [ui_design_principles](../system/ui_design_principles.md) §1 のタッチターゲットとコントラストに従う。**範囲の表示を色だけに依存させない**（太字そのものと、範囲を囲む表現を併用する）
- **性能:** 3段の導出も重なり判定も候補6件ぶんの範囲比較なので、Mainで足りる。AI呼び出しは増えない（**調整でNanoを呼ばない**）
- **プライバシー:** 端末外へ出るものは無い（→ [ADR-0002](../decisions/ADR-0002-on-device-ai-only.md)）

## 10. 検証と受け入れ条件

- **JVMテスト（5本）:**
  1. 3段の導出 — 括弧なし・割れない文（`意味節` と `文全体` が畳まれる）・語句候補の親句・語句が複数あるとき `語句` 段を出さない
  2. 重なり解決 — 同じ親文の2つの句を両方 `文全体` にしたとき、相手の選択が外れる
  3. 太字率と短文例外の引き直し — 範囲を広げて上限を超える／狭めて例外が不要になる
  4. **確定範囲＝提案範囲のとき、保存結果が v1 と同一**（回帰の要）
  5. 外枠 — 確定範囲が文脈範囲の外へ出る入力を作れない
- **instrumentation:** 追加しない（AI呼び出しが増えないため）
- **実機確認:** **必須。** 本文書き換え経路を通る。`DIST` ケースへ「範囲を変えて保存 → 追加した `**` を除くと原文と完全一致」「CRLF・BOM・絵文字より後ろの候補で範囲を変える」「重なり解消の告知」「外部編集後の競合中断が従来どおり起きる」を足す
- **保証していないこと:**
  - 選んだ範囲の**意味的な妥当性**
  - 段階1で**任意の範囲**を選べること（プリセットの3段だけ）
  - 調整結果が次回の蒸留に引き継がれること（**永続化しない**）

|---|---|
| 段階1では任意範囲を選べない | プリセット3段のみ。最終形は段階2 |
| 保護範囲がモデルに残っていない | `InlineSyntax`（コードスパン・リンク・鉤括弧）は `buildDistillSourceModel` の中で行ごとに作られ、捨てられる |

**段階2（自由範囲）の着手条件は、保護範囲を候補と一緒に持ち回れることである。** 段階1では要らないが、**ここが解けないと段階2は成立しない**ので先に書いておく。段階2でスナップの対象になるのは次の4つ。

1. サロゲートペアの内側
2. 結合文字・異体字セレクタ・ZWJ による絵文字連結の内側
3. コードスパン（`` ` ``）の内側
4. リンク記法（`[[...]]` / `[](...)`）の内側

**スナップの向きまで決めないと挙動が定まらない。** 広げているときは外側の安全境界へ、狭めているときは内側の安全境界へ倒す（句分割で「下限未満の余りは直前の句へ吸収する」と向きを固定したのと同じ型の決めごと）。端の空白は `trimmedRange` と同じ規則で落とす。
