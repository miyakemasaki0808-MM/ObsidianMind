## 1. 概要

蒸留の候補について「**この候補は重要か**」と「**どこからどこまでを太字にするか**」を分離し、後者をユーザーが決められるようにする。

**太字にする位置には個人差がある。** 規則とAIだけで最終範囲を一意に決めようとせず、AIは重要箇所のアンカーを探すことに集中し、**範囲の最終決定はユーザーが持つ**。自動の粒度判定（句分割・語句抽出）は「操作しなくても保存できる初期値」を作る役へ回る。

**未調整なら従来どおり**チェックして保存するだけで完了する。調整は増える口であって、増える手順ではない。

## 2. ゴールと非ゴール

### ゴール
- AIが選んだ箇所について、**太字の範囲を広げる／狭める**手段を与える
- 調整しても [reflect_distill](reflect_distill.md) の安全契約（AIはIDだけ返す／範囲はアプリが原文オフセットで解決する）を崩さない
- 未調整のときの保存結果を v1 と**完全に同じ**に保つ

### 非ゴール
- **汎用ノート編集機能にしない。** 文字を打てない・消せないだけでなく、**原文の任意の場所を指せない**（→ §8 判断1）
- **本文リーダー上での範囲選択をしない。** 表示用Markdown parser は原文オフセットを持たない（→ [reflect_distill](reflect_distill.md) §8 判断4）
- **調整結果を永続化しない。** 覚えるのはノート本文に入った `**` だけで、サイドカーへ調整履歴を書かない
- 太字以外の装飾（`==highlight==` 等）を扱わない

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 範囲の確認 | 候補カードに「太字にする範囲」が原文のまま出る | 候補表示中 |
| 調整シート | 候補をタップすると親文が開き、太字になる部分が強調表示される | 候補表示中 |
| プリセット切替 | `語句` / `意味節` / `文全体` から選ぶ。**存在する段だけ**出る | 調整シート表示中 |
| 最初の範囲に戻す | 調整前の初期範囲へ戻す | 調整シート表示中 |
| 重なりの自動解消 | 他の選択候補と重なったら、**相手の選択が外れる。** 外れた候補には理由の印が残る | **範囲変更時とチェック時の両方** |

## 4. 現在のユーザーフロー

1〜4 と 6 は v1 と同じで、**5 だけが増えた**。

1. AIタブで蒸留を始める
2. 非AIで候補を絞り、AIに1回だけIDを選ばせる
3. 候補が並ぶ（既定チェック済み）
4. 取捨する
5. **調整したい候補をタップし、プリセットで範囲を変えて閉じる**（任意）
6. 保存する

## 5. 機能仕様

**この節が範囲モデル・プリセット導出・重なり解決の正本。** 数値と書き戻しの契約は [reflect_distill](reflect_distill.md) §5 が持ち、ここでは繰り返さない。

### 候補が持つ3つの範囲

**「範囲3分割」とはこれである。** プリセットの3段（後述）とは別物で、**混ぜない**。

| 範囲 | 意味 | 現状 |
|---|---|---|
| 文脈範囲 | カードとシートに読ませる親文。**太字にしない** | `DistillSentence.contextRange`（既存） |
| 提案範囲 | 非AI段＋AI選定が出した初期値 | `DistillSentence.range`（既存） |
| 確定範囲 | 実際に `**` を挿す範囲。**未調整なら提案範囲と同じ** | **新規** |

**提案範囲を上書きしない。** 上書きすると「最初の範囲に戻す」を実装できず、再計算のたびに初期値が動く。確定範囲は別に持つ。

**画面では「提案」と呼ばない。** AIが選ぶのは候補IDだけで、初期範囲を決めているのは非AIの句・語句分割である（→ [reflect_distill](reflect_distill.md) §8 判断5）。**「AIの提案」と書くと、既存の安全契約と食い違う。**

### 調整の外枠 — 確定範囲は必ず文脈範囲（＝親文）の内側

これが「汎用ノート編集機能」との一線である（理由は §8 判断1）。外枠を親文にすると、**次の3つが規則を書かずに満たされる**。

| 満たされること | 理由 |
|---|---|
| 既存の `**` 強調と重ならない | 親文は `subtractRanges(bodyStart, bodyEnd, strongSpans)` で既存強調を差し引いた区間から作られる |
| 見出し・コードフェンス・表・frontmatter に触れない | それらの行には親文が存在しない |
| 確定範囲は最大160文字 | 候補の入口が `contextRange.length <= MAX_SENTENCE_CHARACTERS` を見ている |

**着手前に挙がっていた懸念のうち「既存太字との重複」は、この外枠を選んだ時点で消える。** 追加の判定を置かない。

### プリセットの3段と、その導出

**新しい分割規則を作らない。** 3段はすべて `DistillSourceModel.sentences` に既にある要素を引き直すだけで、v1で確立した境界（記法をまたがない・リンクだけを避ける・鉤括弧の内側で割らない）がそのまま効く。

| 候補の種類 | `語句` | `意味節` | `文全体` |
|---|---|---|---|
| 語句候補（`isTerm`） | 自分 | 自分を含む非語句要素 | 文脈範囲 |
| 句・文の候補 | **提案範囲の内側にある語句要素がちょうど1つのときだけ** | 自分 | 文脈範囲 |

- **同じ範囲になる段は1つに畳む**（割れなかった文では `意味節` と `文全体` が一致する）
- **存在しない段のボタンを出さない。** 押せない選択肢は「なぜ押せないか」の説明を毎回要求する
- **語句が複数あるときに段を出さないのは、どれを指すか決められないから。** 語句は独立候補として一覧に並びうるので、そちらで選ぶ道が残る。任意の語句を選ぶのは段階2（自由範囲）の仕事
- **モデルへ欄を足さない。** 句・語句はすべて `sentences` に平らに入っているので、包含関係で引ける。**新しいノート単位の状態も増えない**ので、契約2箇所（`cancelNoteScopedJobs()` / `withNoteScopedReset()`）の変更は不要

### 重なりの解決

**調整は実行時に重なりを作れる。** v1 は選定の出口で候補集合を非重複にしていたので、`applyDistillBold` の `require` に届く経路が無かった。調整を入れると届く。

| 重なる形 | 起きる条件 |
|---|---|
| 同じ親文の2つの句を、両方 `文全体` にする | `MAX_CLAUSES_PER_SENTENCE = 2` なので1文から句が2つ候補に入りうる |
| 語句候補を `意味節` や `文全体` へ広げる | 親の内側にいた語句が親と同じ範囲になる |

**解決:** **選択済み集合を変えるすべての入口**で非重複を維持する。範囲変更だけに置くと、外された候補を**チェックし直すだけで重なりが復活する**。

| 入口 | 挙動 |
|---|---|
| 選択中の候補の範囲を変えた | 重なる既選択候補の選択を外し、外したことを告げる |
| **未選択**の候補の範囲を変えた | **他候補の選択状態を変えない。** 保存対象でないものの編集が取捨を動かしてはいけない |
| 候補をチェックした | 重なる既選択候補の選択を外す（**最後の明示操作を残す**） |
| 保存直前 | 非重複を検証する。破れていたら保存へ進まない |

**未選択かどうかで呼び出し側が分岐しない（実装時の変更）。** `resolveOverlaps` は
選択集合に居ない候補を優先しても誰も押し出さないので、Controller側に
`isSelected` の分岐を置いても**落ちるテストを書けなかった**（変異で確認）。
契約は純関数側の検査で持ち、等価な分岐を増やさない（→ [architecture](../system/architecture.md) 判断4と同じ判定）。

- 選択を外すだけなので、**本文へ書く内容は増えない**（安全側へ倒れる）
- 既存の「選択件数・変更後の太字率」の表示がそのまま追随する
- **保存直前の検証は「念のため」ではない。** [`saveSelection`](../../../app/src/main/java/com/example/newproject/controller/DistillController.kt) は
  `applyDistillBold` を **Main で try なしに同期呼び出し**しているので、部分重複は例外ではなく**その場のクラッシュ**になる。
  同一範囲なら `distinct()` に畳まれて落ちない代わりに、**画面の選択件数と保存件数が食い違う**（`Saved.changedCount` は選択数を数える）。
  **`require` へユーザー操作から到達できない状態にする**のがこの契約の目的
- **採らない案:** ①重なったまま保存時に弾く → どれを直せば解けるか分からない詰みを作る ②保存時に自動でマージする → 選んだ範囲と保存範囲が食い違い、「自動補正しない」（[reflect_distill](reflect_distill.md) §8 判断5）と逆を向く ③重なる操作自体を禁止する → 「句を文全体へ広げたい」という最も普通の操作が、同じ文の別の句がたまたま候補にいるだけで不能になる

### 重なり解消の告知

**外れる候補はシートの裏にいる。** 範囲を変えている間、影響を受ける候補は画面に見えていない。
一時的な通知（Snackbar）にすると、**見ていない場所の変化を、見ていない間に流す**ことになる。
**状態として残し、対象そのものへ出す。**

| | |
|---|---|
| 何を持つ | 直近の解消で外した候補IDと理由。`DistillState.Candidates` の1欄（`NoteUiState` へ欄を足さない） |
| どこへ出す | ①調整シート内に1行 ②候補一覧の該当カードに印（**チェックが外れた理由がカード側に残る**） |
| 読み上げ | シート内の1行を live region にして、選択が外れたことを読み上げる |
| いつ消える | **次に選択集合か確定範囲が変わったとき。時間で消さない**（見ていない間に消えるものは告知にならない）。**同じ段をもう一度押しても確定範囲は変わらないので消えない** — 同値ガードはController境界に置く（UIで無効化しても別の呼び出し口から同じ形を作れる） |
| 複数外れたとき | 件数で言う。単位は「箇所」に揃える（→ 文言の単位） |
| **主語** | **開いている候補との関係で決まる。** 自分が外された側なら「ほか」と呼ばず「この箇所」と言う。**理由を再訪できるようにした結果、外された候補自身のシートも開ける**ようになったため、件数だけを言うと関係を逆に読ませる |

### 太字率と短文例外の引き直し

- `projectedBoldRatio` / `isWithinDistillBoldLimit` は**範囲のコレクションを受ける**ので、確定範囲を渡すだけで正しく動く。計算式は変えない
- **範囲を読んでいる箇所を全部付け替える。** 現状 `updateCandidateState` と保存経路は `candidatesById[id].sentence.range`（＝提案範囲）を読んでいる。**ここが取り残されると「表示は広がったが保存は元の範囲」になり、しかもテストは緑のまま通る**（→ [lessons](../lessons.md) L14。同型の取り残しが句分割の回に2度出ている）
- **短文例外は「どの候補か」を固定したまま、超過判定だけ引き直す。** 例外の対象IDは v1 どおり最重要の1件に固定する（任意の候補を例外にできるようにしない）。**判定に使う範囲だけを確定範囲へ差し替える** — 範囲を狭めれば例外が要らなくなり、広げれば例外の説明に出す太字率が変わる

### 文言の単位

v1 は「箇所」へ統一し `DistillCandidateUnitCopyTest` が走査している。**調整シートの文言も同じ検査に載せる。** 検査の外に新しい文言を作らない（規則は検査に載せたときだけ守られた → [lessons](../lessons.md) L29）。

### 既存のインライン装飾をまたがない（前提は満たされた）

**「既存の分割器の出力だから安全」は、いまは成り立たない。** 保護しているのはコードスパンとリンクだけで、
表示側の `inlineMarkdown` が解釈する**斜体 `*…*`・太字斜体 `***…***`・打ち消し線 `~~…~~` は保護も除外もされていない**。
装飾の内側で文・句が割れ、その候補を保存すると装飾の対応が変わっていた。**これは本設計が持ち込む欠陥ではなく、v1 に既にあった**
（対応の経緯は [change_history](../change_history.md) が持つ）。

**この機能の着手条件は、そこを先に直すことだった。2026-08-29 に実機検証まで完了している。**
段階1の「新しい境界規則をゼロにする」という設計の根拠が、
分割器の出す範囲が安全であることに全面的に寄りかかっているため。

いま成り立っている契約は次のとおり。

- **太字挿入の端がまたいではいけないインライン構文**を明示する — コードスパン・リンク・既存 `**`・
  **斜体 `*…*`・太字斜体 `***…***`・打ち消し線 `~~…~~`**
- **守る集合は、表示側が解釈する集合から決める。** 別々に育てると、書き込みが表示を壊す（→ [lessons](../lessons.md) L51）
- **`_…_` / `__…__` は対象にしない。** `some_var_name` を装飾と誤検出して候補を不当に減らすため。
  Obsidian 側では装飾として解釈されうるので、**保証しないことに数える**（→ §10）
- **端が対の内側に入る候補は、候補から外す。** コードスパンと同じ「またぐなら候補にしない」規則へ揃える。
  **端を内側へ寄せる形は使えない** — `*` の直後に `**` が並ぶと `***` になり、別の装飾として読まれる
- **段階1はこの判定を持たない。** プリセットの3段はいずれも候補生成時にこの条件で濾された
  `sentences` の要素（親文・句・語句）なので、**濾された時点で条件を満たしている**。
  段階1が保護範囲を持ち回る必要はなく、**§11 の「保護範囲がモデルに残っていない」が効くのは段階2だけ**である

**サロゲートペア・結合文字については、段階1では端が原理的に来ない**（分割器の出す境界しか選べないため）。
段階2で初めて要る規則は §11 に置く。

## 6. 状態とデータ

- **確定範囲は `DistillController.ActiveSession` が持つ**（候補ID → 確定範囲）。v1 が `candidatesById` を Controller 側に置いているのと同じ形で、**原文オフセットをUI状態へ出さない**
- `DistillCandidateItem` に足すのは**表示用の文字列と現在の段**まで（太字になる原文・選べる段の一覧・いま何段か）。`DistillState` に新しい variant を足さない
- **調整シートの開閉は `DistillState.Candidates` の中に持つ。** `NoteUiState` へ新しい欄を足さないので、契約2箇所への登録は不要（既存の `distillState` が既に登録済み）
- **常駐Vigilithは調整シート表示中も隠す。** 現在 [`rememberVigilithState`](../../../app/src/main/java/com/example/newproject/ui/vigilith/VigilithState.kt#L49) は
  `isBlockingOverlayVisible = uiState.isSectionChatSheetVisible` の1本しか見ておらず、
  放置すると `HoldingCandidate` の姿勢のままモーダルシートと重なる。
  **第二の状態を足さず、`DistillState.Candidates` が持つシート情報から導出する**（判断は純関数 `resolveVigilithPresentation` 側に残す）
- **シートを閉じても確定範囲は残る。** 閉じることが確定なので、`ActiveSession` が保持し続ける。
  同じ候補を開き直したら、直前に確定した範囲を表示する
- **破棄の契機は4つだけ** — 候補セッションのキャンセル・再解析・ノート切替・保存完了。**シートを閉じることは破棄ではない**
- **永続化しない。** 上記4つのいずれかで消える。ノートに残るのは本文の `**` だけ
- **太字率の再計算でシートを閉じない。** 範囲変更は `DistillState.Candidates` を作り直すので、
  シートの開閉情報を**同じ更新の中で持ち回る**（別の状態にすると、更新のたびにシートが落ちる）

## 7. システム設計

```
AiTab
 ├─ DistillCandidateRow      ← チェック＋「太字にする範囲」＋シートを開く導線
 └─ DistillRangeSheet（新規・ModalBottomSheet）
      ├─ 親文を原文のまま表示し、確定範囲だけを太字で見せる
      ├─ プリセット（存在する段だけ）
      ├─ 「最初の範囲に戻す」
      └─ 変更後の太字率

DistillController
 ├─ presetRangesFor(candidate)   ← 新規・純関数。model.sentences の包含関係だけで引く
 ├─ resolveOverlaps(selection)   ← 新規・純関数。非重複を回復し、外した候補を返す
 ├─ applyRange(id, preset)       ← 確定範囲を更新 →（選択中なら）resolveOverlaps → 太字率を引き直す
 ├─ toggleCandidate(id)          ← **既存。チェック時も resolveOverlaps を通す**（最後の明示操作を残す）
 └─ saveSelection()              ← 非重複を検証 → 確定範囲を applyDistillBold へ渡す（v1の4段書き込みは不変）
```

**衝突解消の呼び出し口は2つある。** `applyRange` だけに置くと、外された候補をチェックし直すだけで
重なりが戻る。**`resolveOverlaps` を純関数に切り出して両方から通す**のは、
入口が増えても判定が1つで済むようにするためである。

**器は既存のものを使う。** シートは `SectionChatSheet` と同じ `ModalBottomSheet`、保存前プレビューは現行のまま。

**`presetRangesFor` は Android 非依存の純関数にする。** 3段の導出と重なり解決はどちらも範囲の計算なので、`domain` へ置けばJVMテストで閉じる（→ [architecture](../system/architecture.md) 判断3）。

## 8. 設計判断と代替案

### 判断1: 一線は「原文の任意の場所を指せないこと」で引く

**「文字を打てない・消せない」だけでは一線にならない。** それは太字専用エディタの説明であって、Non-Goals が避けたい形そのものになる。**確定範囲を親文の内側に閉じる**ほうを一線にする。

- **採らない案（候補の内側だけ）:** 提案範囲より外へ出せない。最も安全だが、句分割が意味を切ってしまった場合に伸ばせず、この機能の動機（この部分だけを太字にしたい）の片側しか満たさない
- **採らない案（本文のどこでも）:** 一線を越える側。表示用parserが原文オフセットを持たないため、本文全体をオフセット付きで見せる仕組みを新規に作ることにもなる

**外枠を型で表す。** 確定範囲は「文脈範囲の内側」という不変条件を持つ値として作り、UIの分岐で守らない。

### 判断2: プリセット先行 — 新しい境界規則をゼロにする

`語句` / `意味節` / `文全体` は既存の分割器の出力を読み替えるだけなので、**段階1は安全判定を1つも新規に書かない**。本文を書き換える唯一の機能で、実機確認の面を一度に広げない。

- **採らない案（端を1段ずつ動かすボタン）:** プリセットより細かいが、**境界候補の列挙が新規実装**になる。段階2でスナップを作るなら、それと同じものを二度作ることになる
- **採らない案（最初から自由ドラッグ）:** 最終形へ直行できるが、境界の安全判定・タッチ精度・実機確認が同時に来る

**プリセットだけでは「この部分だけ」を常には満たせない。** それは承知の上で、最終形は段階2の自由範囲である。

### 判断3: 調整は候補ごとの専用シートで行う

候補一覧はチェックのための場所として保つ。**調整という別の作業を、同じ密度の一覧へ混ぜない。**

- **採らない案（カード内インライン展開）:** 最大6件が縦に並ぶ現在のパネルでカードが伸び、AIタブの他パネル（要約・ひとこと）が押し出される
- **採らない案（保存直前のプレビューで調整）:** **本文を書き換える直前の確認画面**に編集操作が同居し、確認の役割が薄まる

**シートを閉じることが確定。** 取り消しの口は「最初の範囲に戻す」1つに絞り、キャンセルボタンを別に置かない（口が2つあると、どちらが効いたか読めなくなる）。

### 判断4: 置けない境界には止まれない（スナップ）

**不正な状態を作らせない側に倒す。** `applyDistillBold` が重なりを `require` で拒み、IDパーサーが桁落ちを自動補正せず破棄するのと同じ「入口で防ぐ」型に揃える。

- **採らない案（置けるが無効表示にして保存を止める）:** 詰んだ状態を作れるうえ、無効理由の文言が境界の種類だけ増える
- **採らない案（保存時に安全な位置へ丸める）:** 選んだ範囲と保存される範囲が食い違う。**唯一の本文書き換え機能で、黙って違う範囲を太字にすることになる**

**装飾の対を片側だけ横断する範囲も、スナップで作れないようにする**（対象は §11 の5）。

**既存 `**` 強調はスナップ対象に入れない。** 外枠が親文である限り到達できないので、落ちるテストを書けない（→ [architecture](../system/architecture.md) の並行処理の規約と同じ判定）。**到達しうる形に変わったときに足す。**

### 判断5: 重なりは「相手の選択を外す」で解く

理由と却下案は §5 の「重なりの解決」に置く。**この判断の要点は、解決を保存時ではなく操作時に置いたこと。** 保存時に解決すると、ユーザーが最後に見た画面と保存内容が一致しない。

### 判断6: モデルへ欄を足さず、包含関係で引く

`buildDistillSourceModel` は句も語句もすべて `sentences` へ平らに入れているので、3段は包含関係で引ける。**欄を足すと、その欄を読む箇所を数え直す義務（影響面監査）が発生する** — 引けるものを持たない。

**ただし語句候補の親「句」は現状どこにも書かれていない**（語句の文脈範囲は句ではなく文）。これも `sentences` から包含で引く。**引けることを実装前に確かめたので、ここは未確認ではない。**

## 9. 品質要件

- **データ保護:** このアプリで唯一ノート本文を書き換える経路を通る。**確定範囲を渡す以外、[reflect_distill](reflect_distill.md) §7 の4段書き込み・競合検知・復旧レコードを一切変えない**
- **アクセシビリティ:** プリセットのボタンは [ui_design_principles](../system/ui_design_principles.md) §1 のタッチターゲットとコントラストに従う。**範囲の表示を色だけに依存させない**（太字そのものと、範囲を囲む表現を併用する）
- **性能:** 3段の導出も重なり判定も候補6件ぶんの範囲比較なので、Mainで足りる。AI呼び出しは増えない（**調整でNanoを呼ばない**）
- **プライバシー:** 端末外へ出るものは無い（→ [ADR-0002](../decisions/ADR-0002-on-device-ai-only.md)）

## 10. 検証と受け入れ条件

**実装済み。** 内訳は次のとおりで、`DistillRangeAdjustTest`（3段・重なり・外枠）と
`DistillControllerTest`（保存出力・太字率・例外・ガード）に分かれている。

- **JVMテスト（9本）:**
  1. 3段の導出 — 括弧なし・割れない文（`意味節` と `文全体` が畳まれる）・語句候補の親句・語句が複数あるとき `語句` 段を出さない
  2. 重なり解決 — 同じ親文の2つの句を両方 `文全体` にしたとき、相手の選択が外れる
  3. 太字率と短文例外の引き直し — 範囲を広げて上限を超える／狭めて例外が不要になる
  4. **確定範囲＝提案範囲のとき、保存結果が v1 と同一**（回帰の要）
  5. 外枠 — 確定範囲が文脈範囲の外へ出る入力を作れない
  6. 選択の入口 — 外された候補をチェックし直しても重複集合にならない／未選択候補の調整で選択中の候補が外れない
  7. **変換後を再パースし、既存のインライン装飾の対象文字列が変わらない**（斜体・太字斜体・打ち消し線の内外に読点／句点がある本文）
  8. **範囲を変えたら、変えた範囲で `**` が入る** — 保存出力を突き合わせる。
     **4だけでは足りない**（保存経路が提案範囲を読み続けていても、未調整のときは同じ出力になって緑のまま通る）。
     これが `sentence.range` を読む箇所の付け替え漏れを落とす唯一の検査である
  9. **保存直前のガード** — 重なる選択集合から `saveSelection()` を呼んでも `applyDistillBold` へ到達せず、
     状態が `Saving` へ進まない。**`require` へユーザー操作から到達できないことを、例外ではなく状態で確かめる**
  10. **同じ段の再適用では告知が消えず、別の段へ変えれば消える**（告知の寿命の両方向）
  11. **確定範囲の強調**（`DistillRangeHighlightTest`）と**告知の主語**（`DistillRangeNoticeTest`）。
      どちらもUI側の値なので、実機を待たずにJVMで観測できる形へ切り出してある
- **UIテスト（`DistillRangeAdjustUiTest`）:** **「AI呼び出しが増えないから不要」は理由にならない。** 増えるのはUI操作のほうである。
  1. 行タップとチェックボックスのタップが**別の操作へ届く**（シートを誤って開かない）
  2. 確定範囲に**太字と下線の両方が掛かったspanが1つだけあり、範囲外には無い**。
     存在する段だけが出て、未調整なら「最初の範囲に戻す」が押せない。
     **「親文が表示されている」ことを強調の証拠にしない** — 強調を丸ごと外す変異が素通りする
  3. 重なり解消が**シート内の1行と、外れた候補カードの印の両方**に出る。
     外された候補自身のシートでは「ほか」と言わない（読み上げも同じ1行から出る）

  **「開く→変更→閉じる→再度開くで確定範囲が残る」はJVM側へ置いた**
  （`DistillControllerTest`）。確定範囲の寿命は Controller の性質で、
  `ModalBottomSheet` の開閉アニメーションを待つ必要がある実機側へ置くと、
  検査したいものと無関係に落ちる（→ `QuizActionSectionTest` と同じ判断）。
  `VigilithModeTest` に「調整シート表示中は常駐Vigilithを出さない」を追加済み。
  **`androidTest` を触るので `assembleDebugAndroidTest` も通す。**
- **実機確認:** **必須・未実施。** 本文書き換え経路を通る。
  `DIST-21`〜`DIST-24` として追加済み（→ [実機検証ケース](../../review/device_validation/reflect_distill.md)）。
  **タッチ精度とシート操作の最終確認に使い、UIテストの代わりにはしない。**
- **保証していないこと:**
  - 選んだ範囲の**意味的な妥当性**
  - 段階1で**任意の範囲**を選べること（プリセットの3段だけ）
  - 調整結果が次回の蒸留に引き継がれること（**永続化しない**）
  - **`_…_` / `__…__` のような、アプリが描画しない Obsidian 記法の保全**（誤検出の代償として対象外にした）

## 11. 既知の制約・未解決事項

| | |
|---|---|
| **実機検証が済んでいない** | 本文を書き換える唯一の経路を通る。`DIST-21`〜`DIST-24` が対象（→ [実機検証ケース](../../review/device_validation/reflect_distill.md)） |
| 段階1では任意範囲を選べない | プリセット3段のみ。最終形は段階2 |
| 保護範囲がモデルに残っていない | `InlineSyntax` は `buildDistillSourceModel` の中で行ごとに作られ、捨てられる。**効くのは段階2だけ**（段階1は濾された候補要素しか選べない → §5） |

**段階2（自由範囲）の着手条件は、保護範囲を候補と一緒に持ち回れることである。** 段階1では要らないが、**ここが解けないと段階2は成立しない**ので先に書いておく。段階2でスナップの対象になるのは次の5つ。

1. サロゲートペアの内側
2. 結合文字・異体字セレクタ・ZWJ による絵文字連結の内側
3. コードスパン（`` ` ``）の内側
4. リンク記法（`[[...]]` / `[](...)`）の内側
5. **対になったインライン装飾（`*…*` / `***…***` / `~~…~~`）を、片側だけ横断する範囲**

**5 は「記号の内部で止まらない」だけでは足りない。** 対の片側だけを含む範囲は、記号の上に端が無くても
装飾の対応を変える。**内部かどうかではなく、対を割っているかどうかで数える。**

**スナップの向きまで決めないと挙動が定まらない。** 広げているときは外側の安全境界へ、狭めているときは内側の安全境界へ倒す（句分割で「下限未満の余りは直前の句へ吸収する」と向きを固定したのと同じ型の決めごと）。端の空白は `trimmedRange` と同じ規則で落とす。
