## 1. 概要

ノートを開くたびに目にする読む面を、白く事務的なカードから、モダンな紙面（**プレート**）に組み直す。
プレートの中の組み方は**ノートの型**（技術書・読書ノート・標準）で変える。

- **ノートの文字は変えない。** 見出しの役割に合わせて組むだけで、Vault も書き換えず、データも増えない
- **型は本文から表示の前に決まる。** 設定を作らず、AI も使わない（→ 判断1）
- **見え方はオーナーと合意したモックが基準になる**（Design キャンバス「読む面の紙 モック」の標準・技術書・読書ノートの型）。
  借りたのは Apple の開発者ドキュメントと Apple Books の組み方だけで、見た目と SF フォントは写さない

3つの区切りで入れる。**区切り1で白い紙面を全ノートに一度に解消し**、その後で当たるノートの多い型から作る
（Mac の写しの Vault で、コードの枠を持つノートは240本、資格試験の骨格は166本、読書の骨格は30本。端末の Vault と同じかは確かめていない）。

| 区切り | 入れるもの | 型の扱い |
|---|---|---|
| **1. 共通のプレートと型の判定** | プレート・紙面の書式・1行の長さ・ダークの夜の紺・最初の1枚を引く前の場・全画面の末尾の余白 | 判定の純関数を作るが、**組み方は全ノート標準** |
| 2. 技術書の型 | 見出しの番号・コード枠と言語・用語集・学習カード・注意点の面・コールアウトの色と面 | 技術書を組み分ける |
| 3. 読書ノートの型 | 本の情報カード・紹介文の帯・要点カード・関連の札・自分の言葉の面・章の扉 | 読書ノートを組み分ける |

## 2. ゴールと非ゴール

### ゴール

- 開いたノートが、型に合った紙面で読める。**白い紙面は区切り1で全ノートから消える**
- 書式は1か所にあり、縦の流し・全画面・見開き・右の並べ読みが同じ値で組む
- 型の判定はノートを開く前に終わり、読み始めた後に紙面が組み替わらない

### 非ゴール

- **型を選ばせる設定を作らない。** 型は本文から決まる（→ 判断1）。明示したいときは Obsidian 標準の `cssclasses` に書く
- **型で地の色・プレートの形を変えない。** 地の色は年代、プレートの形は面の役割が持つ（→ 判断2）
- **配色を選ばせない。** 年代の紙の案（地を生成りにする3案）は採らない。年代の紙は今のオプション（既定オフ）のまま、プレートの地に載せる
- **ノートの分野（AI の判定）で型を決めない。** 判定は開いた後に届く（→ 判断1）
- **書体を同梱しない（区切り1）。** 端末の標準の書体で組む。等幅の書体は区切り2で決める
- **和文と欧文の間のアキを入れない。** 文字列を書き換えずに入れる手段が無い（→ §11）
- **見開きを本の版面に組まない。** ノドと小口の非対称・1面のページ送りは別の変更で、版面の上にこの組み方が載る
- **記号の線画・クロームを退かせる形（読書中のスリープ防止を含む）・AI の短い文と再会カードの形は扱わない。** どれもプレートの外の部品で、面の形のチャネルと取り合うかを別に確かめる
- **人と AI の声を書体で分けない。** 書体と行間はノートの型が持つ（→ [bearing_channels](../system/bearing_channels.md) §11）

## 3. 詳細機能一覧

区切り1の分だけを書く。区切り2・3は着手するときにこの表へ足す。

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| プレート | 通常表示では、読む画面の場の上に、角の丸い紙が浮いて見える。全画面は画面全体が紙になる | ノートを開いているとき |
| 紙面の書式（標準） | 題が見出しより大きく、H1・H2 の上に藍の短い線が付く。最初の段落はリード文として少し大きく組まれる。行間が広がり、引用が斜体でなくなる | 全ノート（区切り1） |
| 1行の長さの上限 | 広い窓でも本文の1行が約32字を超えない | 本文の列が 520dp より広いとき |
| ダークの夜の紺 | ダークで、読む画面の場と紙が深い紺になる。紙の上端にごく淡い光が当たる | ダークのとき |
| 年代の紙 | オンにすると、プレートの地に年代の色が載る | 今のオプション（既定オフ）・ライトのとき |
| 最初の1枚を引く前の場 | ノートを引く前は、本文と同じ紙に、次の操作を1文で添えて静かに待つ | ノートが出ていないとき |
| 全画面の末尾の余白 | 全画面を出入りした後も、末尾へ送ると最後の段落が見える | 見出しから開いたノートで全画面を出入りしたとき |

## 4. 現在のユーザーフロー

1. ノートを引く（ランダム表示・リンク・関連・さがす・冊子）
2. 本文の解析と同じジョブで型が決まる（区切り2から使う → §7）
3. 紙面がプレートに組まれて出る。型は表示の前に決まっているので、出た後に組み替わらない
4. 全画面・見開き・右の並べ読みへ移っても、同じ書式で組まれる
5. ノートが出ていない間（起動の直後・Vault が空・読めない）は、最初の1枚を引く前の場が出る

## 5. 機能仕様

**数値は区切り1の初期値である。** 合意したモック（CSS の px を dp・sp と読む）から取り、実機で読み比べて動かす。
**値を動かすのは書式の1か所だけ**で、見開きの計測は同じ値を読む（→ 判断4）。

### 5.1 プレート

| 項目 | 値 |
|---|---|
| 形 | 読む面の形（`ReadingSurfaceShape`）。角を **8dp → 16dp** にする。冊子の眺める面（2dp）との差は広がる側に動く |
| 中の余白 | 上 26dp・左右 22dp・下 30dp（今は4辺 18dp） |
| 浮き | ライトは淡い影。ダークは影の代わりに、ごく細い明るい縁（大きい部品なので [ui_design_principles](../system/ui_design_principles.md) §3 に当たらない） |
| 紙の色 | ライトは今の `panel`。年代の紙がオンなら年代の色（今の `notePaperColor` の口のまま）。ダークは夜の紺（→ 5.4） |

- **通常表示は、今の場（読む画面の背景のグラデーション）の上にプレートを浮かせる。** モックの灰色の地は見本の台で、場は変えない（→ 判断9）
- **全画面は、プレートを浮かせず画面全体を紙にする。** 今の全ブリードのまま、本文の列だけを 5.3 の上限で絞る
- **見開きの左右のページは、プレートと同じ形と色を引く。** 版面の非対称は扱わない（→ §2）
- **右の並べ読みの本文**は同じ書式で組む。面の形は今のまま（右の面はプレートにしない）

### 5.2 紙面の書式（標準の型。区切り1では全ノート）

| 部品 | 今 | 区切り1 |
|---|---|---|
| ノートの題 | 20sp・太字 | **24sp**・太字・約物を詰める（`palt`） |
| 見出し | H1 24 / H2 21 / H3 19 / H4 17 / H5 15 / H6 14sp（H6 は斜体） | **H1 21 / H2 19 / H3 18 / H4 17 / H5 16 / H6 16sp**。すべて太字・斜体なし・約物を詰める |
| 見出しの線 | なし | **H1・H2 の上に、藍の短い線（22×2dp）**。線と見出しの間は 10dp |
| リード文 | なし | **本文の最初のブロックが段落なら（見出しより前）、16.5sp・中太**で組む |
| 本文（段落・箇条・引用） | 16sp・行の高さ 24sp | 16sp・**行の高さ 30sp** |
| 字間 | Material の本文の既定（0.5sp）を引き継ぐ | **0**（和文をベタで組む） |
| 引用 | 縦線＋控えめな色の**斜体** | 縦線＋控えめな色。**斜体をやめる** |
| 太字 | 太字 | 太字のまま。マーカーを敷かない |
| 箇条の点 | 本文の色 | **藍** |
| 本文のリンク | 青（`linkText`） | **藍**・細い下線 |
| ブロックの間 | 一律 8dp | 一律 **14dp** |
| 見出しの上の余白 | H1・H2 8dp / H3 以下 4dp | H1・H2 **18dp** / H3 以下 **10dp** |
| コード・表・コールアウトの頭 | — | 変えない（区切り2で組む） |
| 改行の規則 | `LineBreak.Simple` | 変えない（→ 判断4） |

- **藍は関連ノートの見出しの色と同じ値**（ライト `#6054DE`・ダーク `#A79EFF`）だが、**読む面のアクセントという別の役割の色として持つ**。
  値が同じでも、片方を動かしたときにもう片方が付いて動かないようにする（→ [ADR-0005](../decisions/ADR-0005-bearing-channel-allocation.md) の帰結「区別は値ではなく役割の違いとして持つ」）
- **書き手が `*…*` で付けた斜体は残す。** やめるのはアプリが付けていた斜体（引用・H6）だけである（→ 判断5）
- 余白は「ブロックの間の一律の間隔」と「見出しが自分の上に持つ余白」の2つだけで作る（→ 判断4）。
  **見出しの線は見出しのブロックの高さに含める** — 見開きの計測も同じ高さを足す
- **リード文かどうかはブロックの位置だけで決まる。** 描画と見開きの計測が同じ純関数を呼び、片方だけがリード文の書式で組む形にしない

### 5.3 1行の長さの上限

- **本文の列の最大幅を 520dp にする**（16sp で約32字）。列は紙の中で中央に置く
- 全画面は今の最大 720dp の列をこれに置き換える（720dp では余白を除いて約42字になる）
- 通常表示で本文の紙が広いとき（開いた Fold で机を出していないときなど）も、紙は幅いっぱいのまま、列だけを絞る
- 見開きの1面にも同じ上限を掛ける。今の窓では1面が 520dp に届かないので効かないが、**計測の幅と描画の幅は同じ上限から取る**
- 文字の倍率を上げた人は、同じ 520dp に入る字数が減る。dp で決めるのは、倍率を上げた人の1行を広げないため

### 5.4 ダークの夜の紺

- **読む画面の場と紙を、起動のオープニングと結晶の展示室と同じ LogoNavy 系の深い紺にする**（今の紙は `#2A2D45`）。
  紙の上端からごく淡い光を重ねる。**光はどのノートでも同じで、何も表さない**
- **載る面は読む画面だけにする**（→ 判断10）。ほかのタブの面は今の色のまま。読む画面がほかの画面より静かという関係（→ [dark_mode](dark_mode.md) 判断3）を深める側に動く
- **読む画面の上に乗る部品の明るさの段を、夜の紺に合わせて組み直す。** 今は `panelBlue`（`#22273F`）と `panelRow`（`#262A40`）が紙（`#2A2D45`）より暗い。
  地 < 紙 < 紙の上の部品、の順にそろえる
- 初期値はモックの値（地 `#0A1222`・紙 `#111A2E`）。**場のグラデーションとの合わせ方と部品の段は、実装の前にモックで決める**（→ [ui_design_principles](../system/ui_design_principles.md) §4）
- 年代の紙はダークでは今どおり効かない（→ [note_age_paper](note_age_paper.md) 判断5）。**年代の色を夜の紙へ持ち込む提案は、その判断を改める提案である**

### 5.5 最初の1枚を引く前の場

起動のオープニングの後、まだノートを引いていない読む面。今は「ノート未表示」と案内文の白いカードが出る。

- **本文と同じ位置に、同じプレートを置く。** 題（「ノート未表示」）は出さず、次の操作を1文で添えて静かに待つ。Vigilith はここに置かない（→ [character_vigilith](character_vigilith.md)）
- 文は状態ごとに1つ。**`「」` で指す名前は、今の画面にあるボタンの文字にする**

  | 状態 | 文（案） |
  |---|---|
  | Vault を選んでいない | 「Vaultを選択」から、読むノートのフォルダを選びます |
  | Vault を選んだが、まだ引いていない | 「別のノートをひらく」で、今日の1枚を引きます |
  | Vault に Markdown のノートが無い | このVaultにMarkdownノートが見つかりませんでした |
  | Vault を読めなかった | Vaultを読み込めませんでした |

- **案内の文は1か所に置き、本文の紙はそれを読むだけにする。** 今は読む面の空の場と本文の紙が別々に文を持ち、本文の紙の文は今は無い「ランダム表示」ボタンを指している
- **本文の紙は、読み込み中に案内の文を出さない。** 紙だけを出す。コードから読むと、全画面でリンクを開いて次のノートを読み込む間に、本文の紙の文が出る経路がある（実機で確かめる）
- 場の高さ（内容なりか、本文の紙と同じく伸ばすか）と文の置き方は、実装の前にモックで決める。失敗の2つの文は、失敗が分かる言葉のまま残す（色だけで伝えない）

### 5.6 全画面の末尾の余白

見出しから開いたノートで全画面に入って出ると、全画面で足した末尾の余白が通常表示へ運ばれ、末尾へ送ると本文が空白だけになる。
区切り1で全画面の1行の長さが変わり、2つの窓の高さの差が広がるので、ここで直す。

- **余白の量は運ばない。運ぶのは「どの見出しを上端に置いているか」だけにし、戻った窓で足りない分を測り直す**（→ 判断12）
- 不変条件: **末尾の余白は、その窓で見出しを上端に置くのに要る分を超えない**

### 5.7 型の判定（区切り1では作るだけ）

型は3つ: **技術書・読書ノート・標準**。上から順に当て、最初に当たったものに決める。

1. **frontmatter の `cssclasses` に型の名前があれば従う。** 名前は `techbook`・`readingnote`・`standard`（`技術書`・`読書ノート`・`標準` でもよい）。
   読めない frontmatter はこの段を飛ばす（失敗にしない）
2. **見出しの骨格で決める。** 見出しの頭の記号（絵文字・番号）を外した語を、型ごとの語の辞書と完全一致で照らす。
   **一方の型の語に当たる見出しが2つ以上あり、もう一方より多ければ**その型にする
   - 技術書: 目的・構文・注意点・実践・使い方・レベル・関連知識 など
   - 読書ノート: 概要・要点・要点メモ・紹介文・コメント・感想 など
   - 両方の型にまたがる語（「関連」など）は辞書に入れない。辞書の中身は実装で Vault の骨格の実物から決め、JVM テストに載せる
3. **どれにも当たらなければ、コードの枠を持つノートは技術書、持たないノートは標準**

- **入力は解析済みの本文（ブロックの並び）と frontmatter だけ。** AI の結果・痕跡・ファイルの場所を使わない
- **区切り1ではこの判定を画面に配線しない。** 全ノートを標準で組む。配線は区切り2で、本文の解析と同じジョブで行う（→ §7）

### 5.8 型ごとの組み方（区切り2・3。モックで合意した形）

区切り2・3は着手するときにこの節を値まで詰める。今は何をどの部品にするかだけを置く。

- **技術書:** タイトルの採番を小さなラベルに分ける・🎯 目的をリード文に・📶 レベルをタイトルの下の札に・
  🧪 構文と実践コードを言語つきのコード枠と実行結果に・📚 関連知識を用語集に・
  ⚠️ 注意点を黄土の面にまとめ、【件名】に番号を付け、❌ before と ✅ after を上下に並べる。
  コールアウトの色と面もこの区切りで作り、囲みの色と面は型をまたいでそろえる
- **読書ノート:** 🕓 概要の「項目：値」を本の情報カードに（ステータスは札）・📝 紹介文の `[!quote]` を紙面を渡る帯に・
  💡 要点メモを番号付きの要点カードに・🔗 関連をリンクの札に・
  ✍️ コメントを「自分の言葉」の面として分け、「第N章」を章の扉、「N.N」を番号付きの小見出しに
- **標準:** 区切り1の書式（5.2）そのもの
- **型が読み取る書き方の約束から外れた書き方は、普通の段落として描く。** 型は書き方を強いない

### 5.9 前提条件・連携・失敗

- **前提条件:** なし（AI を使わず、Nano 非対応の端末でも同じに組む）
- **保存と寿命:** 区切り1は何も保存しない。型は区切り2から解析結果と同じ寿命で持つ（→ §6）
- **他機能との連携:** 見開き（同じ書式で測る → [note_spread](note_spread.md) 判断8）・年代の紙（プレートの地 → [note_age_paper](note_age_paper.md)）・見出しを上端に置く送り（→ [note_links](note_links.md) 判断6）
- **エラー／AI非対応／キャンセル時:**

  > **該当なし:** 区切り1は非同期の処理を足さない。型の判定は区切り2から解析のジョブに載り、取り消しはそのジョブの規則に従う。

## 6. 状態とデータ

- **区切り1は状態を足さない。** `NoteUiState` に欄を足さず、契約2箇所（`cancelNoteScopedJobs()`・`withNoteScopedReset()`）への登録も無い
- 末尾の余白の直しは、画面が持つ `EndSpace` の中で閉じる（`NoteUiState` の外。寿命は今の本文の位置と同じ）
- **型は区切り2から、本文の解析結果と同じ値に載せる**（`NoteSectionModel` の側。`NoteUiState` の外 → [architecture](../system/architecture.md) の「状態が `NoteUiState` の外に出るもの」）。
  **本文と型を別々に届けない。** 別々に届くと、本文が出た後に型が届いて紙面が組み替わる
- 永続化するものは無い。型は開くたびに本文から決め直す

## 7. システム設計

```
ノートを開く
 └─ 本文の解析（Main の外。setNoteState() と applyReloadedBody() の2か所）
      ├─ ブロックの並び
      └─ 型（区切り2から。noteFormOf(frontmatter, ブロック) ← 純関数・JVMテスト）
           └─ 型ごとの書式（区切り1は標準の1つ）
                ├─ 縦の流しの描画（MarkdownRenderer）
                ├─ 見開きの計測と描画（SpreadBlocks・NoteSpread）
                └─ 右の並べ読みの本文
```

- **型は `model` の列挙、判定は `domain` の純関数に置く。** 型はノートの書き方の意味を決める判定なので `domain`（→ [architecture](../system/architecture.md) 判断5の4）。
  列挙は区切り2で解析結果に載るので、葉の `model` に置く
- **書式は描画と見開きの計測の両方へ、同じ値を引数で渡す。** 区切り1では今の `MarkdownBodyStyle` の値を替える。
  区切り2で型ごとの書式を同じ形の値として持ち、`CompositionLocal` のような暗黙の経路で片方にだけ届く形にしない（→ 判断4）
- **ノートの題の書式も書式の側へ移す。** 今は本文の紙（20sp）と見開き（`TitleStyle`）が別々に持っている
- **見開きの定数を書式と組で変える。** `SPREAD_BODY_FONT_SP`・`SPREAD_BODY_LINE_SP` は本文の段落の書式と同じ値でなければならない。行の高さを 30sp にするなら定数も 30 にする
- 型の判定はブロックの数に比例する。解析と同じく Main の外で回す（→ [architecture](../system/architecture.md) 判断3）
- **実装したら直す正本:** [markdown_rendering](../system/markdown_rendering.md) §8（引用の形）・[note_fullscreen](note_fullscreen.md)（列の 720dp）・
  [note_age_paper](note_age_paper.md)（紙が浮くプレートになる）・[dark_mode](dark_mode.md)（読む画面の紺）・[bearing_channels](../system/bearing_channels.md) §11 の持ち主の行

### 実装の区切り（区切り1の中の順）

修正1件を1コミットにする。上から順に入れる。

1. **型の判定。** `model` の列挙と `domain` の純関数、JVM テスト。画面には配線しない
2. **紙面の書式。** 題・見出し・リード文・行の高さ・字間・斜体・余白・藍の色の役割。見開きの定数を組で変える
3. **プレート。** 角・中の余白・浮き・1行の長さの上限・全画面の列
4. **ダークの夜の紺。** モックで場と部品の段を決めてから入れる
5. **最初の1枚を引く前の場と、案内の文の一本化。** モックで場の高さを決めてから入れる
6. **全画面の末尾の余白。** 画面のテストを先に落としてから直す

## 8. 設計判断と代替案

### 判断1: 型は本文から表示の前に決める。設定も AI も使わない（2026-11-26、オーナー判断）

型を選ばせる設定を作ると、ノートごとに選び直す手間が増え、選ばないノートは標準のままになる。
**分野の判定（AI）は開いた後に届くので、最初に読むときに組めず、途中で組み替えると紙面がずれる。** 分野は冊子の紙と宝石の色が持っている。
本文の骨格（見出しの語とコードの枠）は解析と同時に分かり、Obsidian の書き方の約束（`cssclasses`）で明示もできる。

### 判断2: 型で変えるのはプレートの中の組み方だけ（2026-11-26、オーナー判断）

書体と行間のチャネルはノートの型が持ち、地の色は年代、プレートの形は面の役割が持つ（→ [bearing_channels](../system/bearing_channels.md) §11・[ADR-0005](../decisions/ADR-0005-bearing-channel-allocation.md)）。
**型の違いが地の色やプレートの形へ漏れると、2つのチャネルに同じ意味が載る。** 型を足すたびにプレートの色や形も変えたくなるが、変えてよいのは中の組み方だけである。

### 判断3: 区切り1は全ノートを標準で組み、型の判定は作るが使わない（2026-11-26、オーナー判断）

白い紙面はすべてのノートに出ているので、型を待たずに一度に解消する。型ごとの組み方は、当たるノートの多い技術書から作る。
**判定を先に作っておくのは、区切り2・3で判定を変えずに組み方だけを足すため。** 判定と組み方を同じ区切りで作ると、どちらが原因で紙面が変わったかを実機で分けられない。

### 判断4: 書式は1か所に置き、描画と見開きの計測が同じ値を読む。余白は2種類だけで作る

見開きはブロックを計測してページへ割り、割った段落の残りを組み直して描く（→ [note_spread](note_spread.md) 判断5・判断8）。
**描画と計測が別の書式を読むと、ページの末尾がはみ出すか空く。** 型ごとに書式が変わっても、両方へ同じ値を渡せば計測はずれない。

- **余白は「ブロックの間の一律の間隔」と「見出しが自分の上に持つ余白」の2つだけにする。** 見開きの割り方はこの2つで高さを測っている。
  「この部品の後だけ広く」のような組み合わせごとの余白は、割り方の側に組み合わせの規則を持ち込む
- **改行の規則は `LineBreak.Simple` のまま。** 段落全体を見て改行を決める規則は、見開きが割った段落の残りを組み直すときに行の切れ目がずれる。
  禁則や行の長さの釣り合いのために変えるなら、見開きの組み直しも同じ規則で行う

### 判断5: アプリが付けた斜体をやめ、書き手の斜体は残す

日本語の斜体は、傾けただけの字になって読みにくい。引用の斜体と H6 の斜体はアプリが決めた形なので、やめる。
**書き手が `*…*` で付けた斜体は、書き手の指定なので残す。** 引用は縦線と控えめな色で見分けられ、斜体が無くても引用と分かる。

### 判断6: 1行の長さは列の最大幅（520dp）で決める

全画面の 720dp の列では、余白を除いて1行が42字を超えうる。**読みやすい1行は和文で30字台**なので、列を 520dp（16sp で約32字）に絞る。
字数ではなく dp で決めるのは、文字の倍率を上げた人の1行を広げないため（倍率を上げると1行の字数が減り、文字が大きいまま読める）。
見開きの入る条件が字数で決まる（→ [note_spread](note_spread.md) 判断9）のとは向きが逆で、あちらは「狭すぎて入らない」を、こちらは「広すぎて読みにくい」を見ている。

### 判断7: 字間は0にし、約物の詰めは題と見出しだけ

Material の本文の既定（0.5sp）は欧文のための字間で、和文では字の間が空いて見える。和文はベタで組む。
**約物の詰め（`palt`）を本文に掛けると、行ごとに字の並びが不揃いになる。** 題と見出しは短く大きいので、詰めたほうが締まる。
`palt` を持たない書体では何も起きないので、端末の書体で効き方が変わるのは害にならない。

### 判断8: 題 > H1 > … ≥ 本文の順に組む

今はノートの題（20sp）が本文の H1（24sp）より小さく、H5・H6（15sp・14sp）が本文（16sp）より小さい。
**大きさの順が役割の順と逆になると、見出しの段が読み取れない。** 題を最大にし、H5・H6 は本文と同じ大きさで太さだけで分ける。

### 判断9: 通常表示は場の上にプレートを浮かせ、全画面は画面全体を紙にする

読む画面の場（背景のグラデーション）は「読む画面は触る画面より静か」という関係を持つ（→ [dark_mode](dark_mode.md) 判断3・[note_age_paper](note_age_paper.md) 判断3）。
**場を灰色の地に替えると、その関係が読めなくなる。** モックの灰色の地は見本の台として置いたもので、プレートの見え方の合意ではあっても地の合意ではない。
全画面はそのノートに深く集中する入口（→ [note_fullscreen](note_fullscreen.md)）で、画面全体が紙になっている今の形がプレートの行き着く先に当たる。

### 判断10: ダークの夜の紺は、読む画面の場と紙に限る

アプリ全体のダークの面を夜の紺にすると、冊子の分野色（ダークの紙の床を `panel` に置いている）とほかの全画面のコントラストを組み直すことになり、読む面の変更の外へ広がる。
**読む画面だけを深くすると、読む画面が触る画面より静かという今の関係を強める側に動く。** ほかのタブとの差は場のグラデーションで既にある。
読む画面の上に乗る部品（再会カード・要約の行など）は、夜の紺に合わせて段を組み直す。

### 判断11: 案内の文は1か所に置き、題を出さない

今は読む面の空の場と本文の紙が同じ状態の案内を別々に持ち、片方だけが古いボタンの名前を指していた。**文を1か所に置けば、ボタンの名前を変えたときに片方だけ古くなることがない。**
「ノート未表示」という題は、状態を報告する事務的な言葉で、引く前の場に要らない。次の操作の1文だけで足りる。

### 判断12: 末尾の余白は窓ごとに測り直す

末尾の余白は、見出しを上端に置くのに窓の高さから決まる量である（→ [note_links](note_links.md) 判断6）。
**量を別の窓へ運ぶと、高い窓で足した余白が低い窓に残り、末尾へ送ると余白だけが見える。** 置いている見出しだけを運び、戻った窓で足りない分を測り直す。

### 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 地を年代の紙（生成り）にする3案 | 配色を選ばせることになり、年代の紙の意味（古さ）が既定の見た目に溶ける。年代の紙はオプションのまま、プレートの地に載せる |
| 太字にマーカーを敷く | 蒸留の候補を淡いマーカーで見せる案と見分けにくくなる。太字は太字のまま |
| 型を分野（AI）で決める | 判断1 |
| 等幅や本文の書体を区切り1で同梱する | APK が数百KB増える。等幅は技術書の型のコード枠と一緒に区切り2で決める |
| 余白をブロックの組み合わせごとに持つ | 判断4 |

## 9. 品質要件

- **コントラスト:** 紙の上の文字はすべて 4.5:1（→ [ui_design_principles](../system/ui_design_principles.md) §1）。
  藍のリンクは文字なので、**年代の紙の4段すべてとダークの夜の紙の上で** 4.5:1 を `AppColorContrastTest` で強制する。見出しの線と箇条の点は装飾で、見出しは大きさと太さでも見分けられる
- **色だけで伝えない:** 最初の1枚を引く前の場の失敗は、言葉で伝える（→ [ui_design_principles](../system/ui_design_principles.md) §1 の 1.4.1）
- **文字の倍率:** 1行の上限は dp で決め、倍率を上げた人の字数を減らす（→ 判断6）。見開きの入る条件は今のまま
- **性能:** 型の判定はブロックの数に比例し、解析のジョブの中で回す。書式の変更で増える処理は無い
- **アニメーション:** 足さない

## 10. 検証と受け入れ条件

- **JVMテスト:**
  - 型の判定: `cssclasses` が骨格より優先される／骨格の語は頭の記号と番号を外して照らす／2つ以上かつ多いほうに決まる／同数や1つだけでは決まらない／どれにも当たらなければコードの枠で決まる／読めない frontmatter は飛ばす
  - 書式の関係: 題 > H1 > … ≥ 本文の大きさの順／アプリの書式に斜体が無い／字間が0／**見開きの定数が本文の段落の書式と一致する**（値ではなく関係を見る）
  - 色: 藍のリンクが年代の紙の4段とダークの夜の紙で 4.5:1／ダークで地 < 紙 < 紙の上の部品の明るさの順
  - 形: 読む面の角が眺める面より大きい（`BearingChannelTest` は今のまま通る）
  - 案内の文: `「」` で指す名前が、画面にあるボタンの文字として実在する（ソース走査）
  - 末尾の余白: 窓を替えて戻すと、余白が戻った窓で要る分を超えない（`EndSpaceTest`）
- **instrumentation:**
  - 見開きの計測と描画が一致する（今のテストを新しい書式で通す）
  - 全画面を出入りした後に末尾へ送ると、最後の段落が見える（`EndSpaceUiTest` に足す。今は戻った直後の見出しの位置までしか見ていない）
- **実機確認:**
  - ライトとダーク・スマホと開いた Fold（通常表示・机・見開き・全画面・右の並べ読み）で、紙面が組まれて見える
  - 年代の紙をオンにしてプレートの地に色が載る／ダークでは載らない
  - 文字の倍率 1.3 で、1行の上限と見開きの入る条件がどちらも効く
  - 最初の1枚を引く前の場（Vault を選ぶ前・選んだ後・空の Vault）と、全画面でリンクを開いて読み込む間に古い案内が出ないこと
  - 末尾に近い見出しから開いて全画面を出入りし、末尾へ送って最後の段落が見えること
- **実機で起こせないので自動テストが持つ順序:**

  > **該当なし:** 区切り1は非同期の処理を足さない。

- **保証していないこと:**
  - 型ごとの組み方（区切り2・3）。区切り1では型の判定の結果が画面に出ない
  - 約物の詰めの効き方は端末の書体による
  - 和文と欧文の間のアキ
  - 見開きの版面（ノドと小口）

## 11. 既知の制約・未解決事項

- **和文と欧文の間のアキは入らない。** Compose の文字組みには自動で入れる手段が無く、文字列に空白を足すと本文を書き換えたのと同じになる（選択・引用・痕跡の位置がずれる）
- **区切り2で決めること:** 📶 レベルをタイトルの下へ動かすか（表示の順が Obsidian と変わり、見開きの計測も同じ並びで扱う）／
  型が読み取る書き方の約束（「項目：値」の箇条・【件名】・❌ before と ✅ after・`[!quote]`）の範囲／
  コードの言語を解析で残すこと（今のコードのブロックは言語の札を捨てている。ファイル名は Markdown のコードの枠に無いので出せない）／
  等幅の書体を同梱するか／横に長いコードの行を横に送るか折り返すか／コールアウトの色と面（見開きでページをまたぐときの面の切れ方を含む）／内側の部品の角の段

- **後の案:** 型で見出しの役割が分かれば、注意点だけを集めて読む冊子も作れる。暮らしの型は後で足す
- **右の並べ読みに型を広げるか**は区切り2で決める。区切り1では右も標準で組む
