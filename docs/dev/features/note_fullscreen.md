## 1. 概要

ノート以外を**完全に消して**読むための表示。ノートタブの ⛶ ボタンから入り、✕ で戻る。

実体は**非タブの独立ルート** `note_fullscreen` で、モードフラグではない。
この方式が「バー／レールが消える」「回転・Fold開閉で維持される」を**構造として保証**する。

## 2. ゴールと非ゴール

### ゴール
- 折り畳み前後どちらでも**ノート以外を完全に消す**
- スクロール位置を通常表示と往復で保つ
- 全画面中もAIの状態に気づける（最小化した形で）

### 非ゴール
- **全画面で編集や操作を増やさない。** 読むための面
- **AI導線を消さない**（消すのではなく最小化する → §8 判断5）

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 全画面表示 | バー・レール・システムバー・額縁がすべて消える | ノートタブの ⛶ |
| スクロール継承 | 通常表示で読んでいた位置から始まる | 進入時 |
| スクロール書き戻し | 全画面で読み進めた位置が通常表示へ戻る | ✕・システムバック・FABタップ |
| AIインジケータFAB | フラット円で状態を示し、変化時だけラベルを数秒フラッシュ | 常時 |

## 4. 現在のユーザーフロー

1. ノートタブの ⛶ を押す → `note_fullscreen` ルートへ遷移する
2. `DisposableEffect` が `systemBars()`（ナビ＋ステータス）を隠す
3. タブ側の `firstVisibleItemIndex` / `ScrollOffset` から**開始位置を継承**する
4. 読む（本文カラムは最大 **720dp** で中央寄せ、背景はノートページ色で全ブリード）
5. ✕ ・システムバック・FABタップのいずれかで離脱する
   - タブ側へスクロール位置を**書き戻す**（非suspendの `requestScrollToItem` で保留位置を積むだけ）
   - `DisposableEffect` が **`navigationBars()` だけ**を復元する（ステータスバーは隠したまま）

## 5. 機能仕様

- **前提条件:** ノートが表示されていること
- **上限:**

  | 対象 | 値 |
  |---|---|
  | 本文カラムの最大幅 | **720dp**（中央寄せ） |
  | AIインジケータFAB | **48dp**（Material 推奨のタッチ領域） |

- **システムバー:** 進入時に `systemBars()` を隠し、離脱時に `navigationBars()` だけ復元する。
  ステータスバーはアプリ全体の仕様どおり隠したままにし、既存の `onWindowFocusChanged → hideStatusBar()` と矛盾させない
- **安全インセット:** `safeDrawingPadding` は**背景ではなく本文と ✕ ボタン側にだけ**適用する
- **Snackbar:** 全画面ルート表示中は**抑制する**（`isFullscreenRoute` ガード）
- **エラー／キャンセル時:**

  > **該当なし:** この画面はAI生成もI/Oも行わない。表示中の本文をそのまま描くだけ。

## 6. 状態とデータ

**永続化しない。**

**ルート自体が状態である。** `isFullscreen` の `remember` フラグを持たないのが要点で、
**ルートは NavController の復元対象**になるため Fold開閉による Activity 再生成でも維持される。

**スクロール状態は共有しない**（→ §8 判断3）。全画面は専用の `LazyListState` を持ち、
`rememberLazyListState(index, offset)` が内部で `rememberSaveable` を使うので、
全画面中のFold開閉でも位置が復元される。

## 7. システム設計

```
NoteReaderTab（⛶）
 └─ NavHost: note_fullscreen（非タブルート）
      └─ FullscreenNoteScreen
           ├─ DisposableEffect          ← システムバーの制御をルートの生存期間に紐づける
           ├─ 専用 LazyListState        ← 進入時に継承・離脱時に書き戻し
           └─ AIインジケータFAB（48dp フラット円）
                └─ SectionChatState ＋ QuizState を合成
```

**`AppScaffold` は既に「非タブルートではバー／レールを出さない」構造を持つ**ので、
ルート化するだけで折り畳み前後どちらでも自動的に消える。

## 8. 設計判断と代替案

### 判断1: オーバーレイをやめ、非タブの独立ルートにする

**バー／レールが消えなかったのは、全画面が `AppScaffold` の `content` 内のオーバーレイだったから。**
compact では下バーと本文が別領域（`Column`）、expanded では左レールと本文が別領域（`Row`）に分かれているため、
**本文内のオーバーレイでは構造的にバー／レールを覆えない。**

**`remember` フラグ方式との差は復元性。** ルートは NavController の復元対象なので、
**Fold開閉による Activity 再生成でも全画面が維持される。**

> この判断は冊子モードの入れ方にもそのまま効いている（→ [booklet_mode](booklet_mode.md)）。

### 判断2: システムバーはルートの生存期間に紐づける

`DisposableEffect` で進入時に隠し、離脱時に復元する。
**復元をライフサイクルに紐づけることで、✕・システムバック・プロセス復元など全ての離脱経路で確実に戻る。**

### 判断3: スクロールは「共有」ではなく「継承＋書き戻し」

**NavHost の遷移アニメーション中は通常タブと全画面が同時にコンポーズされる**ため、
1つの `LazyListState` を2つの `LazyColumn` へ装着すると**例外になる**。

進入時は**読み取りのみ**（同時装着が起きない）で開始位置を継承し、離脱時に書き戻す。

> **書き戻しを suspend に直列依存させない。** 当初は離脱時に suspend の `scrollToItem` の完了を待ってから
> `popBackStack` を呼んでいたが、これは「閉じる」を**完了保証のない suspend に直列依存**させる形で、
> **Fold開閉による Activity 再生成後に `scrollToItem` が完了せず、✕もシステムバックも無反応になる**
> 不具合を生んだ。現在は非suspendの `requestScrollToItem` で保留位置を積むだけにし、閉じる処理を即実行する
> （→ [lessons/L35](../lessons/L35.md)）。

### 判断4: ノート色で全ブリードし、本文カラムだけ720dpに絞る

白カード＋グラデ額縁ではなく、**画面全体をノートページ色で塗る。**
広い展開画面でも行長を抑えつつ、「ノート以外の額縁」を排除できる。

### 判断5: AI導線は「消さず、最小化する」

全画面中もAIの状態が気になる（要約は終わったか、クイズは生成できたか）というユースケースを尊重し、
**AIインジケータFABは残す。** ただし通常FABの立体グラス（62dp・影・グラデ）は使わず**フラット円**にする。

- 状態は円の中身（スピナー／✓／!／💬）で表現し、**変化した瞬間だけ短いラベルを数秒フラッシュ**して自動で畳む
- ステータスは要約・回答（`SectionChatState` 由来）に**クイズ状態を合成**する。
  優先順位は「生成中 > 未確認エラー > 未確認完了 > 待機」
- タップは要約シートを開く。**シートは note ルートで描画されるため、全画面を閉じてからシートを開く**
