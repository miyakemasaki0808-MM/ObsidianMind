## 1. 概要

**本文の `[[ノート]]` と `[文字](ノート.md)` を押すと、そのノートを開く。**
Obsidian で書いたノートどうしのつながりを、アプリの中でも辿れるようにする。
Rediscover で引いた1冊から、書いた本人が張ったリンクを辿って、Reflect のループを広げる。

開いた Fold では補助の面で眺め、今のノートは替えない。スマホでは今のノートとして開く。
どちらにするかは端末ではなく窓で決める（→ §8 判断1）。

## 2. ゴールと非ゴール

### ゴール
- 本文のノートへのリンクを押すと、そのノートが開く。見出しつきのリンクはその見出しから開く
- 同じノートの中の見出しへのリンク（目次）を押すと、本文がその見出しまで進む
- 表の中のリンク（`[[ノート\|表示名]]`）も、表の外と同じに描いて押せる
- 長押しの文字選択・本文のスクロール・机の画面の横の払いを、リンクが邪魔しない
- 表示を重くしない。リンク先があるかは押したときに調べる

### 非ゴール
- **戻る道は作らない**（2026-10-10、オーナー判断）。スマホでリンクから開いた後の戻る操作は今どおりで、ノートタブではアプリが閉じる。
  元のノートへは、さがすタブの「今日読んだノート」から戻る。読んでいた位置は戻らない。
  並べ読みの「このノートへ移る」が戻る操作を持たないのと同じ線である（→ [margin_pane](margin_pane.md) §5.9）
- **外部URLは押せないまま**（同日、オーナー判断）。`[文字](https://…)` は今と同じ見た目で、押しても何も起きない。リンクの記法でない素のURLも同じ
- ノートでないファイル（画像・PDF・ソースファイル・`file://`）へのリンクは押せない
- **補助の面で眺めているノートの中のリンクは押せない。** 補助の面を独立して辿る形は Fold の机の契約1そのものなので、机の土台と一緒に決める（→ [fold_experience](../system/fold_experience.md) §5）
- 埋め込み `![[ノート]]` は扱わない（→ [markdown_rendering](../system/markdown_rendering.md) §7）
- まだ無いノートへのリンクを押して、ノートを作ることはしない。アプリはノートの本文を書かない（→ [ADR-0004](../decisions/ADR-0004-do-not-rewrite-vault-body.md)）
- ブロック参照（`#^id`）の位置へは送らない。そのノートの先頭から開く

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 押せるリンク | 見た目は今と同じ（リンクの色と下線）。ノートと見出しへのリンクだけが押せる | 本文と全画面の本文 |
| 補助の面で開く | ペインの中身がリンク先のノートに替わる。ペインを閉じていれば開き、本文だけを1画面にしていれば2面に戻す | 補助の面を出せる窓 |
| 今のノートとして開く | リンク先が今のノートになる。訪問の記録・要約・分野判定・結晶はふだんどおり走る | 補助の面を出せない窓と全画面 |
| 見出しへ送る | 見出しつきのリンクはその見出しから開く。同じノートの見出しなら本文をそこへ送る | 見出しつきのリンク |
| 知らせ | 見つからないときは短い知らせを出し、何も開かない | リンク先を引けなかったとき |
| 表の中のリンク | 表示名だけを出し、列がずれない | 表のセルの中の `\|` |

## 4. 現在のユーザーフロー

1. 本文のリンクを軽く押す。長く押すと文字の選択になり、リンクは開かない
2. 手元の走査結果からリンク先を引く
3. 見つかれば開く
   - **補助の面を出せる窓:** 補助の面にリンク先を出す。「← 余白へ戻る」で元の余白へ戻り、関連の一覧へは送らない。
     「このノートへ移る」で今のノートにできるのは並べ読みと同じ
   - **それ以外の窓と全画面:** リンク先を今のノートとして開く。見出しつきならその見出しから、無ければ先頭から
   - **同じノート:** 本文をその見出しまで送る。見出しの無いリンクなら先頭へ送る
4. 見つからなければ知らせを出し、何も開かない

## 5. 機能仕様

- **前提条件:** Vault を選んであり、本文が表示されている。リンク先は Vault 全体の走査結果から引く。
  走査は Rediscover・冊子・ノートを開く経路が済ませるので、本文が出ていれば通常は手元にある
- **入力と出力:** **押せるかは記法だけで決める。** 描くときにリンク先を探さない（→ §8 判断2）

  | 記法 | 押せるか | 引き方 |
  |---|---|---|
  | `[[名前]]`・`[[名前\|表示名]]` | 押せる | 名前で引く。正規化は関連ノートと同じで、大文字小文字を区別せず `.md` を外す |
  | `[[フォルダ/名前]]` | 押せる | パスの末尾が一致するノート。無ければ名前で引く |
  | `[[名前#見出し]]`・`[[#見出し]]` | 押せる | ノートを引いてから見出しへ。`[[#見出し]]` は同じノート |
  | `[文字](パス.md)` | 押せる | 今のノートのフォルダからの相対で引く。`/` で始まれば Vault の根から。見つからなければ名前で引く |
  | `[文字](#見出し)` | 押せる | 同じノートの見出し |
  | `[[画像.png]]` など、添付ファイルの拡張子を持つ名前 | 押せない | — |
  | `[文字](https://…)`・`file://` など、スキームを持つもの | 押せない | — |
  | `.kt`・`.pdf` など、`.md` 以外のパスへの `[文字](…)` | 押せない | — |

  - **同じ名前のノートが複数あるときは1つに決めて開く。** 今のノートと同じフォルダのものを先に、無ければパスの短いもの、それでも並べば辞書順（→ §8 判断3）
  - **見出しの照合は文字と数字だけを残して比べる。** 大文字小文字・空白・記号・絵文字は見ない。
    Obsidian の見出しリンク（`#見出しそのまま`）と、GitHub 形式のアンカー（`#全体入口開発規約-core--governance`）のどちらも同じ規則で当たる。
    同じ見出しが複数あれば最初のもの。`#親#子` のように重ねたものは最後の見出しで引く
  - **表のセルは、エスケープした `\|` で割らない。** 割ると `[[名前\|表示名]]` が2つのセルに分かれ、リンクとして描かれず列もずれる。
    セルの中身は `\|` のまま持ち、表示ではエスケープとして `|` を出す（→ [markdown_rendering](../system/markdown_rendering.md) §7）
- **上限:** 該当なし。1回押すたびに1件を引くだけで、量に比例する処理を持たない
- **状態遷移:** 状態を持たない（→ §6）
- **保存と寿命:** 保存しない。リンク用の索引は走査結果と同じ寿命（→ §6）
- **画面遷移:**

  | 窓 | ノートへのリンク | 同じノートの見出し |
  |---|---|---|
  | 補助の面を出せる窓（開いた Fold・広い窓） | 補助の面で開く。ペインを閉じていれば ✎ と同じく開き、設定に残る。本文だけを1画面にしていれば2面に戻す | 本文を送る |
  | 補助の面を出せない窓（スマホ・狭い分割の窓） | 今のノートとして開く | 本文を送る |
  | 全画面（⛶） | 今のノートとして開き、全画面のまま続ける。戻る操作は今どおり、まず全画面を抜ける | 本文を送る |

- **他機能との連携:**
  - 今のノートとして開くときは、関連タブと同じ `openNote` を通る。Rediscover ではないので再会カードは出ない
  - 補助の面で開くときは並べ読みの経路をそのまま使う。眺めるだけで、訪問の記録・要約・分野判定・余白メモのどれも走らない（→ [margin_pane](margin_pane.md) §5.9）
  - 続けてリンクを渡っても、自動で走る生成はノートに留まってから始まる（→ [background_ai_ux](../system/background_ai_ux.md) §7）
- **エラー／AI非対応／キャンセル時:**
  - **見つからない:** 「『名前』は見つかりませんでした」と出し、何も開かない
  - **走査結果がまだ無い:** 「ノートの一覧を読み込んでいます」と出し、何も開かない
  - **見出しが見つからない:** 別のノートなら先頭から開き、「見出し『…』が見つからないので、先頭から開きました」と出す。同じノートなら「見出し『…』が見つかりませんでした」と出し、本文を動かさない
  - **読み込みの失敗**は開いた先の扱いのまま。今のノートなら本文のエラー、補助の面なら右側だけに出る
  - AI を呼ばない。押したときに引くのは手元の走査結果だけで、待ちもキャンセルも生じない

## 6. 状態とデータ

> **該当なし（新しい状態を持たない）:** 押したときに手元の走査結果から同期で引き、結果はその場で開く操作に変わる。
> `NoteUiState` に足す欄も、契約2箇所（`cancelNoteScopedJobs()`・`withNoteScopedReset()`）に載せるものも無い。

- **引く材料はリンク用の索引である。** Vault 全体の走査結果（`NoteScanCache`）と同じ場所で持ち、走査を公開するたびに作り直し、Vault 切替で捨てる。
  中身は走査結果の写しなので、寿命は Vault 単位（→ [architecture](../system/architecture.md) 判断4の2行目）。
  索引の中の表は、初めて引いたときに組む
- **見出しへ送る依頼は画面の保存値に置く。** 「このノートへ移る」が右の位置を持ち越すのと同じ置き場で、Fold の開閉で画面が作り直されても失わない

## 7. システム設計

| 層 | 新規 | 変更 |
|---|---|---|
| `domain` | `NoteLinks.kt` — 記法からリンクを読む（`noteLinkOf`）、走査結果の索引（`NoteLinkIndex`）、引く（`resolveNoteLink`）、見出しのブロックを探す（`headingBlockIndex`）。いずれも純関数 | `domain/markdown/MarkdownBlocks.kt` — 表のセルを `\|` で割らない |
| 走査のキャッシュ | — | `NoteScanCache` — 公開と同じ1か所で索引を作り直す。Vault 世代の照合は今の公開と共有する |
| 窓口 | — | `NoteViewModel.resolveNoteLink` — 今のノートを出発点に、今の索引で引く。同期で、ジョブを持たない |
| `ui/markdown` | — | `inlineMarkdown` が押せるリンクにだけ `LinkAnnotation` を付ける。押す口を渡されなければ今と同じ文字列になる。`MarkdownNoteContent` が押す口と、長押しで開かせない見張りを持つ |
| `ui/screen` | `NoteLinkActions.kt` — 引いた結果と窓から、画面の操作を決める純関数と、知らせの文 | `NoteReaderTab` と `FullscreenNoteScreen` がリンクを受ける。`SideReadingPane` が見出しから始める |

- **押せるかは描くときに記法だけで決める。** リンク先の文字列は `scanInlineSyntax` が決めた範囲から切り出し、記法を別に解釈しない。
  解釈器が2つになると、片方の規則だけが変わったときに表示と押せる範囲が食い違う（→ [lessons L51](../lessons/L51.md)）
- **引くのは押したときに1回で、Main で同期に行う。** 索引の表はノートの数に比例して組むが、1回の走査につき1度だけで、表示の経路には乗らない
- **長押しでは開かせない。** Compose 1.7.3 のリンクは、リンクごとに押せる箱を重ねる作りで、長押しを受け取らない。
  そのため、長く押してから離しても「押した」になる（ソースで確かめた）。文字の選択は長押しで始まるので、
  そのまま使うと、リンクの上から選ぼうとした指を離した瞬間にノートが替わる。
  本文の容器が子より先に指離しを見て、長押しの時間を超えていればリンクを開かない（→ §8 判断4）
- **補助の面に押す口を渡さない。** `SideReadingPane` の本文は押せない文字列のまま描く

## 8. 設計判断と代替案

### 判断1: 開く面は窓で決め、端末で決めない

補助の面を出せる窓なら補助の面、出せない窓と全画面では今のノートとして開く。
不変条件「今のノートは主の面の1つだけ」を守るためで（→ [fold_experience](../system/fold_experience.md) §4）、
補助の面のノートを今のノートへ替えるのは「このノートへ移る」だけのまま変わらない。
全画面は面が1つなので、スマホと同じ扱いにする。

### 判断2: リンク先は押したときに引く

描くときに引くと、本文の描画が走査結果に依存し、表示の経路に乗る。
押せるかは記法だけで決め、見つからないことは押した後に知らせる。
代わりに、まだ無いノートへのリンクも押せるリンクと同じ見た目になる。Obsidian は薄く描くが、ここでは区別しない。

### 判断3: 同じ名前は1つに決めて開く

画像の解決は、候補が曖昧なら選ばない（→ [note_image_rendering](note_image_rendering.md) §4）。リンクは選ぶ。
リンクは Obsidian が解決する前提で書かれているので、同じフォルダを先に見る規則に寄せれば、書いた本人の意図に近い。
**開いた先の題名が見えるので、違っていても黙って誤らない。** 画像は違う絵が出ても気づきにくいので、同じ扱いにしない。

### 判断4: 長押しの見張りは本文の容器に1つ置く

代替案は、リンクごとに独自の押下の検出を書く形（`ClickableText` の形）。各 `Text` に配置の結果を受ける口が要るうえ、
読み上げからリンクとして押す操作を失う。`LinkAnnotation` なら TalkBack からリンクとして押せる。
見張りは指の時間だけを見るので、読み上げからの押下は止めない。

### 判断5: 外部URLと戻る道は作らない

オーナー判断（→ §2）。外部URLはブラウザへ渡すだけなら権限は要らないが、押せる対象をノートとその見出しに絞る。
戻る道は、開いた順を持つ新しい状態になる。今日読んだノートから元へ戻れるので、それで足りるとした。

## 9. 品質要件

- **性能:** 描画で増えるのはリンクごとの押せる箱だけ。リンク先は押したときに1件引く
- **プライバシー:** ネットワークに出ない。外部URLはそもそも押せない
- **アクセシビリティ:** リンクは読み上げでリンクとして押せる。文中のリンクは押せる範囲が文字の大きさになるが、WCAG 2.5.8 の文中の例外に当たる
- **オフライン・端末制約:** 該当しない。端末の中で完結する

## 10. 検証と受け入れ条件

- **JVMテスト:** `NoteLinksTest` — 記法の分け方・名前とパスの引き方・同じ名前の選び方・見出しの照合。この Vault で数えたリンクの型（表示名つき・表の中の `\|`・フォルダつき・相対の `.md`・`%20`・目次のアンカー・添付・外部URL）を写す。
  `MarkdownParserTest` — 表のセルを `\|` で割らない。`InlineMarkdownTest` — 押せるリンクだけに `LinkAnnotation` が付き、押す口が無ければ付かない。
  `NoteLinkActionsTest` — 窓ごとの開き方と知らせ
- **instrumentation:** `NoteLinkTapUiTest` — 押すと開く・長押しでは開かない・リンクの上から縦にスクロールしても開かない
- **実機確認:** 開いた Fold と閉じた外画面の両方で、目次の表のリンク・相対の `.md`・同じノートの目次を押す。
  リンクの上から長押しして文字を選べるか。スクロールの途中や横の払いで誤って開かないか
- **保証していないこと:** 走査の後に作ったノートへのリンクは、次の走査まで見つからない。
  走査が一部のフォルダを読めなかったとき、「見つかりませんでした」はノートが無いことを意味しない。
  机の画面の横の払いをリンクの上から始めたときにリンクが開かないことは、払いの判定が子より先に指を使い切ることに頼っていて、自動テストでは確かめない

## 11. 既知の制約・未解決事項

- **走査結果は古くなりうる。** 引くのは手元の走査結果で、押したときに走査し直さない。走査の後に Obsidian で作ったノートは、次の走査まで見つからない
- **まだ無いノートへのリンクも、押せるリンクと同じ見た目になる**（→ §8 判断2）
- **補助の面のノートの中のリンクは押せない。** Fold の机の土台で決める
- **走査が一度も済んでいないと、どのリンクも引けない。** 本文を出す経路が走査を済ませるので通常は起きないが、走査が失敗した後は「読み込んでいます」が続く
