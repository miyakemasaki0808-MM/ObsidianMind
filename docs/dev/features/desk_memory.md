## 1. 概要

開いた Fold の机で、今のノートの右に並べて読んだノート（**並べた相手**）を、その回の訪問の痕跡に1件だけ控える。
次にそのノートと再会したとき、再会カードに「前回は『X』と並べて読んでいました」と添え、
開いた Fold の机ならその名前を押して同じ相手を右に開き直せる。**利用者の操作は1つも増えず、カードのボタンも増えない。**

[fold_experience](../system/fold_experience.md) の契約3（並べて考えた結果を、痕跡として残せる）にあたる。
北極星の判断基準「その結果は、次の再会の材料として残るか」に、机の上の行動を載せる段である。

## 2. ゴールと非ゴール

### ゴール

- 並べ読みをしただけで、並べた相手が訪問の痕跡に残る（残す操作を足さない）
- 再会で返す。開いた Fold は名前を押して開き直せ、閉じた画面は名前で分かる
- **再会カードの枠（排他1件）を奪わず、ボタンも増やさない**（→ [reunion_card](reunion_card.md) 判断1・この文書の判断2）
- AI を使わない

### 非ゴール

- **メモに、そのとき並べていた相手を添えること。** オーナー判断で採らない（→ 判断1）
- **右のノート（補助の面）から引用すること。** 同じく採らない。引用は今のノートの本文からだけ（→ [margin_quote](margin_quote.md) 判断6）
- **再会カード・冊子に引用を出すこと**
- **右のノートの読む位置を残すこと・翌日の机を自動で戻すこと。** 戻すのは相手だけで、開き直すと先頭から出す（→ 判断8）
- **2件以上を返すこと・並べた履歴の一覧を見せること**（→ 判断5）
- **相手のノートの痕跡へ書くこと。** 右で読んでも、右のノートの訪問は記録しない（→ 判断7）

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 並べた相手を控える | 何も見えない | 開いた Fold の机で、右に資料として見えていた時間の合計が30秒以上のノートがある（→ §5） |
| 名前を添える | 再会カードの見出しの1文の下に「前回は『X』と並べて読んでいました」 | 前回の訪問に並べた相手がある。閉じた画面・開いた Fold のどちらでも |
| 名前から並べて開く | 名前が本文のリンクと同じ見た目で押せる。押すと机を開き、右に相手を先頭から出す | 上と同じ条件で、余白ペインを出せる窓。それ以外の窓では名前は文字だけ |

## 4. 現在のユーザーフロー

1. 開いた Fold の机でノートAを読み、「このノートの関連」か本文のリンクからノートBを右で開いて読む
2. Bが右に資料として見えていた時間が合わせて30秒を超えると、Bはこの回の並べた相手の候補になる。いちばん長く並べた1件が、Aの訪問に控えられる
3. 後日、Rediscover でAを引く。再会カードの見出しの1文の下に「前回は『B』と並べて読んでいました」が出る
4. 開いた Fold なら名前の『B』を押すと、机が開いて右にBが先頭から出る。閉じた画面では名前は押せず、Aを読み続ける
5. 「読んだ」でカードを畳むと、名前の行も一緒に畳まれる

## 5. 機能仕様

- **前提条件:** 痕跡の訪問が記録される読み方であること（記録の条件は [reflect_reading_trace](reflect_reading_trace.md) のまま）。
  名前の行は再会カードが出る経路だけに出る（Rediscover・冊子の「これを読む」 → [reunion_card](reunion_card.md) §5）
- **並べたとみなす時間:** 右に**資料として見えていた**時間を、相手ごとに足し算する。数えるのは次の全部が成り立つ間だけ
  - 並べ読みの右の面が資料（書きかけを出している間は数えない → [margin_quote](margin_quote.md) §5.6）
  - 右のノートが読めている（読み込み中・失敗は数えない）
  - 補助の面が画面に出ている（本文だけにしている間・窓でペインが閉じている間は数えない）
  - アプリが前面にある（背面・冊子の間は数えない。今のノートの読書の門と同じ止め方 → `ReadingPauseReason`）
- **相手の決め方:** 足し算が30秒以上の相手のうち、**いちばん長いもの1件**。同じ長さなら後から並べたもの。右で辿った先（右のノートの中のリンク）も別の相手として数える
- **今のノート自身は相手にしない**
- **入力と出力:** 入力は並べ読みの状態の移り変わりと単調な時計。出力は訪問1件につき相手1件か無し
- **上限:** 相手は訪問1件につき1件。相対パスとタイトルは痕跡の既存の上限に従う。ファイル全体の上限は §6
- **返すのは前回の訪問だけ。** 痕跡の最後の訪問に相手があるときだけ名前の行を出す。それより前の訪問の相手は返さない（カードは「前回のあなた」を伝える → [reunion_card](reunion_card.md) §1）
- **名前は控えたときのタイトル**で、後で改名されても再解決しない（訪問の見出し名と同じ歴史的記録 → `ReadingVisit`）
- **名前から並べて開く:** 名前を押せるのは余白ペインを出せる窓だけで、ほかの窓では同じ行の名前を文字だけで出す（行の並びは変えない）。
  押すと、控えた相対パスを今の Vault で引き当て、見つかれば机を開いて右で開く。右で開く口は関連の候補から開くのと同じで、今のノートは替わらない（→ [desk_foundation](desk_foundation.md)）。
  「← 余白へ戻る」では開く前の余白の位置へ戻る（本文のリンクから開いたときと同じ）。見つからなければ「『X』が見つかりません」と知らせる
- **状態遷移:** 右に資料が見えている ⇄ 見えていない、の区間ごとに足す。ノートを離れる（訪問を記録する）ときに相手を決める。背面へ回って訪問を記録する場合も同じ時点の値で決める
- **保存と寿命:** 痕跡サイドカーの訪問の欄（→ §6）。訪問の保持（30件）・孤児掃除・退避・読み戻しは訪問と一緒に扱う
- **画面遷移:** 名前を押すと机の画面へ移る（✎ で開くのと同じ）。閉じた画面には遷移が無い
- **他機能との連携:** 名前の行は、再会カードの見出しの1文と枠の間に置く。**枠の中身の選び方とボタンの列は変えない**
- **エラー／AI非対応／キャンセル時:** AI を使わないので Nano の有無に依らない。
  ノート切替・Vault 切替では足し算を捨てる（記録した訪問の分は残る）。相手を引き当てられないときは知らせるだけで、痕跡は書き換えない

## 6. 状態とデータ

- **痕跡のスキーマを v8 → v9 に上げる。** `ReadingVisit` に並べた相手（相対パスとタイトル）を任意の欄として足す。
  v1〜v8 は相手無し（null）で読む。checksum の正規形に版の分岐を足す（`READING_TRACE_SCHEMA_VERSION` の約束）。欄の登録は [reflect_reading_trace](reflect_reading_trace.md) §6 へ書く
- **ファイルの上限:** 訪問30件の全部に上限いっぱいの相手が入ると、今の 192KB を超えうる。
  区切り1で `ReadingTraceLimitsTest` の実物測定に相手を足し、超えるなら `MAX_FILE_BYTES` を上げる（読み込みと保存が同じ上限を使う）
- **足し算の置き場:** 読んでいる回（`ReadingTraceController` の読書の区間）に持つ。訪問と同じ寿命なので、
  ノート単位の状態を `NoteUiState` に足さず、契約2箇所（`cancelNoteScopedJobs()`・`withNoteScopedReset()`）への新しい登録は要らない。
  右が見えているかは画面の側が知っているので、調停側（`NoteSessionCoordinator`）を通して知らせる
- **再会カードの状態:** `ReadingTraceCard` に前回の相手（タイトルと相対パス）の欄を足す。カードと同じくノート単位で、既存のリセットに乗る
- **合流:** 相手は訪問の欄なので、別端末との合流と読み戻しは訪問の合流にそのまま乗る

## 7. システム設計

```
画面（右に資料が見えている／いない）
  → NoteViewModel → NoteSessionCoordinator
      → ReadingTraceController（読書の区間に相手ごとの足し算。単調な時計）
          → ノートを離れる・背面へ回る: 訪問に相手を載せて保存（既存の recordVisit）
Rediscover で再会
  → ReunionCardController / 痕跡の読み込み → ReadingTraceCard に前回の相手
      → 再会カード: 名前の行（全端末）。名前を押せるのはペインを出せる窓だけ
          → 名前を押す: 相対パスを引き当て → 机を開く → 右で開く（SideReadingController.open）
```

- **出す条件は純関数に切る。** 名前の行を出すか・名前を押せるか（相手があるか・ペインを出せる窓か・カードを畳んだか）
- **足し算と相手の決め方は Android 非依存に置き、時計を差し替えて JVM で確かめる**（`NoteReadGate` と同じ形）

> **未確認:** 相対パスから今の Vault のノートを引き当てる口。痕跡は相対パスで引くが、開くには文書の参照が要る。
> Rediscover の一覧かリンクの解決の口を使えるかを区切り3で確かめ、ここを書き直す。

### 実装の区切り

着手の順はロードマップが持つ。この文書は区切り方だけを決める。

1. **土台（JVM）:** スキーマ v9・旧版の読み込み・checksum の版の分岐・上限の測り直し・合流と退避。画面に出るものは変えない
2. **並べた時間を数えて訪問へ載せる:** 足し算と相手の決め方・止める条件・訪問の記録への配線。まだ画面は変えない
3. **再会カードで返す:** 名前の行・名前から並べて開く・引き当てと見つからないときの知らせ・閉じた画面

2・3は同じ実機検証に載せる（1は画面を変えないが、スキーマを上げるので [reading_trace_backup](reading_trace_backup.md) の実機ケースを全件通す）。
同じブランチの並べ読みの入口の修正（印・前回のメモ・要約の入口で並べ読みを閉じない）も、この実機検証にまとめる。

## 8. 設計判断と代替案

### 判断1: 残すのは並べた相手だけ（2026-10-31、オーナー判断）

契約3の最小の形は「机の上で何と何を並べたか」で、ほかの2つはその上に載る。
**採らなかった案:** 置いたメモに、そのとき右にあったノートを添える（メモの行に「『X』と並べて」）。
右のノートの一節を引用する（[margin_quote](margin_quote.md) 判断6で段4へ送っていた件。照らし直しを別のノートへ広げることになり、段の大きさが倍近くになる）。

### 判断2: 枠にもボタンにも入れず、押せる名前で返す（2026-10-31、オーナー判断）

枠は排他1件で（[reunion_card](reunion_card.md) 判断1）、前後の要約・当時の問い・ノートの要約は**ノートの中身**を伝える。並べた相手は**机の配置**で、種類が違う。
枠に入れると、途中まで読んだノートでは前後の要約と、読了したノートでは問いと取り合い、どちらかが毎回消える。
[fold_experience](../system/fold_experience.md) §5 の「日をまたぐ再開は契約3の痕跡を経由し、再会カードから返す」を、名前の行の中の名前で満たす。
**ボタンも足さない。** ボタンの列は最大3つ（続きから読む・前回のメモを見る・読んだ）で、4つ目を足すと開いた Fold の左のページで2段に折り返し、本文がさらに下がる。
名前の行はどのみち出すので、名前に入口を兼ねさせれば要素が増えない。見た目と動きは本文のリンクにそろえる（→ [note_links](note_links.md)）。
**採らなかった案:** 枠の候補に入れて優先順位を決める。ボタンの列に「並べて開く」を足す。

### 判断3: 閉じた画面では名前だけを添える（2026-10-31、オーナー判断）

閉じた画面には並べ読みが無い。名前を押して相手へ移れるようにすると今のノートが替わり、再会したノートから離れることになる。
契約3は「スマホでも再会から読める形を置く」なので、名前を読めれば足りる。行は開いた Fold と同じで、名前を押せないことだけが違う。
**採らなかった案:** 名前を押して相手へ移る。

### 判断4: 並べたとみなすのは、右に資料として見えていた時間の合計30秒（仮の決定）

右で開いただけ・一瞥しただけの相手を残すと、再会で返すものが偶然の寄り道になる。
**見えていた時間で決め、開いた回数やスクロールでは決めない** — 並べ読みは眺めるための形で（[margin_pane](margin_pane.md) §5.9）、読み進めなくても並べて考えていることがある。
30秒は、結晶の材料が「読んだ」とみなす線（`NoteReadGate`）にそろえた。実機で見直す余地を残す。
**書きかけを出している間は数えない** — その間は右のノートが見えていない。

### 判断5: 訪問1件につき相手1件。いちばん長く並べたもの

返すのは1件なので、控えるのも1件で足りる。並べた相手を全部控えると、上限と合流の扱いが増える割に返す先が無い。

### 判断6: 痕跡全体の欄ではなく、訪問の欄に持つ

返すのは前回の訪問の相手なので、訪問の欄なら「最後の訪問」を見るだけで決まる。
痕跡全体に1つ持つと、どの訪問の相手かを別に持たないと、別端末の合流や読み戻しで新しい訪問と古い相手が組になる。訪問の欄なら既存の訪問の合流がそのまま正しい。

### 判断7: 相手のノートの痕跡には書かない

右のノートは今のノートにしない（[fold_experience](../system/fold_experience.md) §4 の不変条件）。右で読んでも右のノートの訪問を記録しないので、相手の側へ書くと、訪問の無い痕跡に机の記録だけが現れる。
並べた事実は、並べたときに今のノートだった側にだけ残る。

### 判断8: 右のノートの位置は戻さない。翌日の机も自動では戻さない

位置まで残すと訪問ごとの欄が増え、改稿で外れる。名前は相手を思い出させる入口で、読み直す位置は利用者が決める。
机を自動で戻すと、アプリの入口が「昨日の机」になり、偶然に引く入口と取り合う（[fold_experience](../system/fold_experience.md) §5「翌日の机は契約にしない」）。

## 9. 品質要件

- **プライバシー:** 相手の相対パスとタイトルは Vault の中の痕跡サイドカーにだけ書く。端末の外へは出ない（ネットワーク権限が無い）
- **データ保護:** 旧版の痕跡を読めなくしない（v1〜v8 を相手無しで読む）。上限を上げるなら読み込みと保存を同時に上げる
- **性能:** 足し算は区間の出入りでだけ動く。再会のたびに Vault を走査しない（引き当ては押したときだけ）
- **アクセシビリティ:** 名前の行は読み上げられる文にする。押せる名前はリンクとして「『X』を並べて開く」と読み上げ、色と下線だけに頼らない。押せる範囲は名前の文字より広く取る

## 10. 検証と受け入れ条件

- **JVMテスト:**
  - 痕跡 v9 の往復・v1〜v8 を相手無しで読む・checksum の版の分岐・相手の欄の上限と弾き方。最悪の痕跡を実シリアライザで測って上限に収まること
  - 合流と読み戻し（同じ訪問の相手が残る・片側だけ v8 の退避）
  - 足し算（資料⇄書きかけの切替・片側1画面・窓でペインが閉じる・背面・読み込み中と失敗を数えない）と相手の決め方（30秒の境・いちばん長いもの・同じ長さは後のもの・今のノート自身を除く）
  - **両方向:** 右で数えている途中にノートを替える・訪問の保存中に30秒を越える。走行中の印が残らないこと
  - 名前の行を出す条件と、名前を押せる条件（前回の訪問だけ・押せるのはペインを出せる窓だけ・畳んだら出さない）
- **instrumentation:** 再会カードに名前の行が出て、ボタンの列は変わらない。開いた Fold の机で名前を押すと右に相手が出て、今のノートは替わらない。閉じた画面では名前を押せない。見つからないときに知らせる
- **実機確認:** 机で相手を30秒以上並べて離れ、Rediscover で引き当てて名前の行が出ること・名前を押すと右に出ること・押せると見て分かること。閉じた画面で名前が文字だけで出ること。
  30秒未満で離れたときに出ないこと。スキーマを上げたので [reading_trace_backup](reading_trace_backup.md) を全件
- **実機で起こせないので自動テストが持つ順序:** 訪問の保存の途中で足し算が30秒を越える順序。別端末で並べた訪問と読み戻しが合流する順序
- **保証していないこと:** 改名・移動した相手を辿り直すこと（見つからないと知らせるだけ）。30秒が「並べて考えた」の線として妥当か（体感。判断4の見直しの材料）。
  それより前の訪問の相手を返すこと
