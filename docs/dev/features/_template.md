# 機能名

**状態:** Draft / Implemented / Deprecated
**最終検証:** YYYY-MM-DD / `<commit>`
**関連コード:**
**関連テスト:**
**正本:** この文書

> **この様式の使い方。**
> - **ヘッダ5行は必ず埋める。** 特に `最終検証` — **これが無いと、文書が実装から離れたことを誰も検知できない。**
>   実装を当て直した日と、そのときのコミットを書く。読む側はこの日付以降の変更を疑ってよい。
> - **節を空のまま残さない。** 空欄は「未調査」「該当なし」「書き忘れ」の区別が付かない。
>   埋められないときは**理由を書く**（下記）。
> - **`最終検証` は実際に実装と突き合わせた文書だけ更新する。** 器を整えただけで日付を進めない。
> - **履歴を書かない。** 「1巡目で〜だったが2巡目で〜にした」は [owner/journal/](../../owner/journal/) が持つ。
>   ここには**現在有効な仕様と判断だけ**を現在形で書く。
> - **§8 に却下案を全部並べない。** 同じ議論が再発するものだけ残す。

## 空欄の代わりに書くもの

**問題はブランクではなく、未完成なのに完成済みに見えることである。** 埋められない節には理由を残す。

```markdown
## 5. 機能仕様

> **未確認:** 上限値とキャンセル条件は実装との突合が必要。
```

```markdown
## 6. 状態とデータ

> **該当なし:** この機能は状態を永続化しない。
```

| 記法 | 意味 | 次にすること |
|---|---|---|
| `> **未確認:** …` | **調べれば書ける。まだ調べていない** | 実装を読んで埋める |
| `> **該当なし:** …` | **この機能には存在しない** | 何もしない（理由が正本） |
| （空欄） | **禁止** | どちらかに倒す |

**`未確認` が残っている文書は `最終検証` を進めない。** 器だけ整えた状態と、
実装と突き合わせた状態を、日付で見分けられるようにする。
