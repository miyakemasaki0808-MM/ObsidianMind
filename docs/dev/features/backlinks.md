# このノートへのリンク — バックリンクを1文つきで出す

**状態:** 構想。知識索引の区切り2で作る
**最終検証:** 未検証（実装前）
**関連コード:** 未作成。索引は `data/KnowledgeIndexDatabase.kt`、リンクの解き方は `domain/NoteLinks.kt`（`resolveNoteLink`）を使う
**関連テスト:** 未作成（→ §10）

## 1. 概要

**今のノートへリンクしているほかのノートを、リンクを含む1文つきで並べる。**
過去の自分がこのノートをどこでどう使ったかを、題名の一覧ではなく、リンクを書いた文で読める。
開いた Fold では余白ペインに、スマホでは関連タブに出す。AI を呼ばない。

ロードマップの段5（知識索引）で、補助の面へ最初に出すもの（2026-11-14、オーナー判断）。

## 2. ゴールと非ゴール

### ゴール

- 今のノートを指すリンクを、索引が読めた範囲で漏れなく出す
- なぜリンクしたかが分かる1文を添える
- 開いた Fold では右で開いて並べ読みでき、今のノートは替わらない（→ [fold_experience](../system/fold_experience.md) 契約1）
- スマホでも読める（機能は共有する → [fold_experience](../system/fold_experience.md) §5 の線引き）

### 非ゴール

- **リンクしていない言及は扱わない。** 題名が本文に出てくるだけのノートは数えない
- **AI で選んだり並べ替えたりしない**
- **全文検索と目次は扱わない**（→ [knowledge_index](../system/knowledge_index.md) §1）
- **関連ノートの並びを変えない。** バックリンクは別の一覧で、関連に出ているノートがこちらにも出てよい
- **余白メモと引用は出さない。** 索引には載せるが、出し方は決めていない（→ [knowledge_index](../system/knowledge_index.md) §11 の区切り4）
- **押せないリンクは数えない。** コードの中・画像・外部URL・`.md` 以外のパス

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 余白ペインの節 | 「このノートの関連」の上に「このノートへのリンク」を畳んで件数だけ出す。開くと1ノート1行 | 開いた Fold で余白ペインを出している |
| 関連タブの節 | 関連の一覧の下に同じ一覧を出す | 関連タブを開いた |
| 1行の中身 | 題名と、リンクを含む最初の1文。同じノートにほかのリンクもあれば「ほか2箇所」 | — |
| 押したとき | ペインでは右で開く。関連タブでは今のノートとして開く。どちらもリンクのある節の見出しから | 行を押す |
| 作っている間 | 「索引を作っています（120 / 500）」 | その Vault の索引の最初の作成が終わっていない |

## 4. 現在のユーザーフロー

> **該当なし（構想）:** 実装前なので、作る予定の流れを書く。

1. Vault を開くと、背景で索引を作る（→ [knowledge_index](../system/knowledge_index.md) §3）
2. ノートを開くと、索引から今のノートへのリンクを引く
3. 開いた Fold で ✎ から机を開くと、余白ペインに「▸ このノートへのリンク 3」が出る
4. 開くと3行が並ぶ。押すと右で開き、「← 余白へ戻る」で戻る。「このノートへ移る」で主の面へ移る
5. スマホでは関連タブを開くと、関連の下に同じ一覧がある。押すとそのノートを開く
6. 別のノートに Obsidian でリンクを足すと、次の走査の後に一覧へ増える

## 5. 機能仕様

- **前提条件:** Vault を選んである。その Vault の索引の最初の作成を終えている。終えていなければ進み具合を出す
- **入力と出力:** 入力は今のノート。出力は出どころのノートごとに1行（題名・最初の1文・ほかの箇所の数・開く位置の見出し）
- **数え方:**
  - 本文で押せるリンクだけを数える（→ [note_links](note_links.md) §5 の表）。`[[名前]]`・`[[フォルダ/名前]]`・`[[名前#見出し]]`・`[文字](パス.md)`
  - **出どころから解いたときに、今のノートへ着くものだけ。** 同じ名前の別のノートへ着くリンクは除く（→ [note_links](note_links.md) §8 判断3 と同じ規則）
  - 今のノート自身の中のリンク（`[[#見出し]]` や自分の名前）は除く
- **並び:** 出どころのノートの更新日時が新しい順。同じなら題名の順（2026-11-14、オーナー判断）
- **件数:** 全件。絞らない（同日、オーナー判断）
- **1ノート1行:** 本文で最初に出てくるリンクの1文を添え、2つ目以降は「ほか N 箇所」と数だけ出す（同日、オーナー判断）
- **1文:** リンクを含む文。リンクは表示名（`[[名前|表示名]]` なら表示名）で出し、記法の記号は出さない。長ければ末尾を「…」で切る
- **開く位置:** リンクのある節の見出しから開く。見出しより前にあればノートの冒頭から。
  **同じ見出しが出どころに複数あるときは、何番目の見出しかで区別する。** 索引は節の見出しの文字と、同じ見出しのうち何番目か（見出しの照合と同じ規則で数える）を持つ。
  開くときに出どころの本文が変わっていて、その番目の見出しが無いか文字が合わなければ、同じ見出しの最初のものから開き、それも無ければ冒頭から開く
- **上限:** 件数は絞らない。1文の長さと、1ノートから取るリンクの数は索引の上限に従う（→ [knowledge_index](../system/knowledge_index.md) §8）
- **状態遷移:** 作っている（進み具合）→ 引いている → 出せる／読めない。**0件なら節を出さない**。
  その Vault で準備完了の走査がまだ一度も公開されていない間は、解けないので「引いている」のまま待ち、0件に畳まない（→ [knowledge_index](../system/knowledge_index.md) §3・§5）
- **保存と寿命:** 保存しない。結果はノート単位で、ノートを替えたら捨てる。索引の寿命は [knowledge_index](../system/knowledge_index.md) §4
- **画面遷移:** ペインからは右で開く（並べ読み → [margin_pane](margin_pane.md) §5.9・[desk_foundation](desk_foundation.md)）。関連タブからは今のノートとして開く（関連の行と同じ）
- **他機能との連携:**
  - 右で開いたノートは眺めるだけで、訪問を記録しない（→ [margin_pane](margin_pane.md) §5.9）。机で並べた相手としての控えは [desk_memory](desk_memory.md) の規則どおり
  - 索引が直ったとき（走査で変わったノートを読み直した）と、走査が公開されたとき（解くのに使うリンクの索引が替わった）に、今のノートの分を引き直す
- **エラー／AI非対応／キャンセル時:**
  - AI を使わないので、AI 非対応の端末でも同じに動く
  - 索引を作れない・読めないときは、節を開くと「このノートへのリンクを数えられませんでした」と出す。読書は止めない
  - ノートを替えたら引いている途中の要求を止め、遅れて届いた結果を書かない
  - 走査が一部のフォルダを読めなかったときは、読めた分で出す。読めなかったフォルダのノートからのリンクは、解かずに除く
  - 走査が読めずに空だったとき（入れ物は空の一覧を公開する）は、0件と言わず「読めない」にする。節を開くと「このノートへのリンクを数えられませんでした」と出し、次に読めた走査が届けば一覧に戻る

## 6. 状態とデータ

- **ノート単位の状態（予定）:** バックリンクの状態（作っている・引いている・出せる・読めない）と行の一覧。
  **`cancelNoteScopedJobs()` と `withNoteScopedReset()` の両方へ登録する**（→ [architecture](../system/architecture.md) 判断4 の1行目）
- **Vault 単位の状態:** 索引の進み具合。こちらは索引を作る側が持つ（→ [knowledge_index](../system/knowledge_index.md) §5）
- **畳む・開くは覚えない。** 関連の一覧と同じく、ノートを替えると畳んだ状態に戻る
- **永続化:** しない。索引は [knowledge_index](../system/knowledge_index.md) が持つ

## 7. システム設計

```
余白ペイン／関連タブ
  → NoteViewModel
    → バックリンクを引く Controller（ノート単位）
      → 索引（data のインターフェース越し）: 今のノートの名前の鍵でリンクを絞る
      → resolveNoteLink（domain）: 出どころから解き、今のノートへ着くものだけ残す
      → 出どころごとにまとめ、更新日時の順に並べる（domain の純関数）
    → 状態の Writer（照合した要求・索引の世代・走査の公開の回数が、3つとも今も同じときだけ書く）
```

- **見出しへ送る依頼に、同じ見出しの番目を任意で足す。** 今の依頼は見出しの文字だけで、開き始めの位置（`NoteStart.kt`）は `headingBlockIndex` で最初に合う見出しを選ぶ。
  バックリンクから開くときだけ番目を渡し、右で開く経路と今のノートとして開く経路の両方で同じ戻り方をする。本文のリンクは番目を渡さないので、今どおり最初の見出しから開く

## 8. 設計判断と代替案

### 判断1: 行き先は索引に持たず、引くときに解く

`[[名前]]` がどのノートを指すかは、同じ名前のノートが増減すると変わる。索引の時点で決めると、ほかのノートが増えただけで正しい行き先が古くなる。
引くときに本文のリンクと同じ規則で解けば、**バックリンクに出たノートのリンクを押すと、必ず今のノートへ戻ってくる。**

### 判断2: 1ノート1行・最初の1文

1本のノートが何度もリンクしていると、リンクごとの行では同じ題名が続いて一覧を埋める。
本文で最初に出てくるリンクは、そのノートで今のノートを持ち出した場所であることが多い。残りは「ほか N 箇所」で数だけ伝える（2026-11-14、オーナー判断）。

### 判断3: 更新が新しい順に全件

最近の自分の使い方を先に出す。畳んだ節の中に並ぶので、件数を絞るボタンは置かない。
「10件＋すべて見る」も検討したが、押す手間を1つ増やすので採らなかった（同日、オーナー判断）。

### 判断4: スマホでも関連タブで読める

バックリンクは情報であって、Fold でしか成立しない操作ではない。[fold_experience](../system/fold_experience.md) §5 の線引きに従い、機能として共有する（同日、オーナー判断）。

## 9. 品質要件

- **性能:** 引くのは今のノートの名前で絞った行だけ。DB の読みも解き方も Main の外で行う
- **プライバシー:** 端末の中で完結する。索引のバックアップの扱いは [knowledge_index](../system/knowledge_index.md) §9
- **アクセシビリティ:** 行は押せる高さを守る（→ [ui_design_principles](../system/ui_design_principles.md)）。読み上げでは題名と1文を1つの行として読む

## 10. 検証と受け入れ条件

- **JVMテスト:** 数え方（押せる記法だけ・自分自身を除く・同じ名前の別のノートへ着くものを除く）、1ノート1行と「ほか N 箇所」、並び、
  1文の切り出しと切り詰め、状態遷移、ノートを替えた後に旧い結果を書かないこと、索引が直ったら引き直すこと。
  **開く位置:** 同じ見出しの2つ目にだけリンクがあるとき2つ目を指すこと、本文が変わって番目が合わないときの戻り方、本文のリンクの見出しは今どおり最初のものを指すこと
- **instrumentation:** 余白ペインの節の畳む・開く・押すと右で開くこと。関連タブの節。同じ見出しの2つ目の節へ、ペインと関連タブの両方から開くこと
- **実機確認:** 開いた Fold とスマホで、実際の Vault でリンクを多く受けるノートを開き、件数と1文を目で見る。押して開く位置
- **実機で起こせないので自動テストが持つ順序:** ノートを替えた直後に前のノートの結果が届く。引いている途中で索引が直る（→ [knowledge_index](../system/knowledge_index.md) §10）
- **保証していないこと:** Obsidian で足したリンクは、次の走査まで出ない。1MB を超える本文の後ろにあるリンクは数えない。読めなかったフォルダのノートからのリンクは出ない
