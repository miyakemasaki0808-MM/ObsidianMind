## 1. 概要

**今のノートへリンクしている過去のノートのうち、久しく読んでいないものを3件、リンクを書いた1文つきで出す。**
最新号を読みながら「そういえば昔の号ではどうだったか」と勧められる、雑誌のバックナンバーの棚にあたる（2026-11-21、オーナー判断）。

バックリンクは、過去の自分が自分の手でこのノートと結んだ跡である。AI が意味の近さで選ぶ関連ノートとは違い、
北極星の「過去の自分の思考と再会する」に直接つながる。そこで役割を**再会の入口**に置き、
次に読むノートの道案内は、本文のリンクと関連ノートに任せる。

開いた Fold では余白ペインに、スマホでは関連タブに出す。AI を呼ばない。
ロードマップの段5（知識索引）で、補助の面へ最初に出したもの（2026-11-14、オーナー判断）。

## 2. ゴールと非ゴール

### ゴール

- 自分が結んだのに久しく読んでいないノートと、読んでいる途中で再会できる
- 1行で、そのノートでこのノートをどう使ったかが分かる
- そこで自分が余白メモを書いていれば、それが分かる
- 開いた Fold では右で開いて並べ読みでき、今のノートは替わらない（→ [fold_experience](../system/fold_experience.md) 契約1）
- スマホでも読める（機能は共有する → [fold_experience](../system/fold_experience.md) §5 の線引き）

### 非ゴール

- **次に読むノートの道案内をしない。** 本文のリンクと関連ノートが持つ。全件を一度に見せることもしない（「ほか N 件」で開ける）
- **今のノートの本文がすでにリンクしている相手を出さない。** 本文を読めば分かる（→ 判断5）
- **リンクしていない言及は扱わない。** 題名が本文に出てくるだけのノートは数えない
- **AI で選んだり並べ替えたりしない**
- **全文検索と目次は扱わない**（→ [knowledge_index](../system/knowledge_index.md) §1）
- **関連ノートの並びを変えない。** 別の一覧で、関連に出ているノートがこちらにも出てよい
- **余白メモの本文と引用は出さない。** 出すのは書いたかどうかの印だけ。メモと引用を索引に載せる案は保留している（→ [knowledge_index](../system/knowledge_index.md) §2）
- **押せないリンクは数えない。** コードの中・画像・外部URL・`.md` 以外のパス

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 余白ペインの節 | 「このノートの関連」と反証の一文の下に「このノートのバックナンバー」を畳んで件数だけ出す。開くと3件 | 開いた Fold で余白ペインを出している |
| 関連タブの節 | 関連の一覧と反証の一文の下に同じ3件を出す | 関連タブを開いた |
| 1行の中身 | 題名と、リンクを含む1文を1行ずつ。文の中の今のノートの題名は「このノート」と出す | — |
| ✎ の印 | 題名の後ろに ✎。そのノートのリンクのある節に、自分が余白メモを書いている | 痕跡にその節のメモがある |
| ほか N 件 | 3件の下に「ほか N 件」。押すと残りを同じ並びで出す | 4件以上ある |
| 押したとき | ペインでは右で開く。関連タブでは今のノートとして開く。どちらもリンクのある節の見出しから | 行を押す |
| 作っている間 | 件数の代わりに「索引を作っています（120 / 500）」。ペインでは押せない1行、関連タブでは枠の中 | その Vault の索引の最初の作成が終わっていない |
| 数えられない | 件数を出さない。ペインでは開くと、関連タブでは枠の中に「このノートのバックナンバーを数えられませんでした」。**作っている途中でもこちらを先に出す** | 走査が読めずに空・置き場が使えない・索引の最初の作成が止まった |

## 4. ユーザーフロー

1. Vault を開くと、背景で索引を作る（→ [knowledge_index](../system/knowledge_index.md) §3）
2. ノートを開くと、索引から今のノートへのリンクを引き、本文がすでにリンクしている相手を除き、相手ごとに最後に読んだ日を痕跡から引く
3. 開いた Fold で ✎ から机を開くと、余白ペインの「このノートの関連」と反証の一文の下に「▸ このノートのバックナンバー 7件」が出る
4. 開くと、久しく読んでいない3件と「ほか 4 件」が並ぶ。押すと右で開き、「← 余白へ戻る」で戻る。「このノートへ移る」で主の面へ移る
5. スマホでは関連タブを開くと、関連と反証の一文の下に同じ3件がある。押すとそのノートを、リンクのある節の見出しから開く
6. 別のノートに Obsidian でリンクを足すと、次の走査の後に増える。右で開いたノートは訪問を記録しないので、並びは変わらない

## 5. 機能仕様

- **前提条件:** Vault を選んである。その Vault の索引の最初の作成を終えている。終えていなければ進み具合を出す
- **入力と出力:** 入力は今のノート。出力は出どころのノートごとに1行（題名・最初の1文・✎ の有無・開く位置の見出し）と、4件目以降の数
- **数え方:**
  - 本文で押せるリンクだけを数える（→ [note_links](note_links.md) §5 の表）。`[[名前]]`・`[[フォルダ/名前]]`・`[[名前#見出し]]`・`[文字](パス.md)`
  - **出どころから解いたときに、今のノートへ着くものだけ。** 同じ名前の別のノートへ着くリンクは除く（→ [note_links](note_links.md) §8 判断3 と同じ規則）
  - 今のノート自身の中のリンク（`[[#見出し]]` や自分の名前）は除く
  - **今のノートの本文がリンクしている相手は除く。** 今のノートから出るリンクを索引から引き、今のノートから同じ規則で解いて、着いた先の出どころを除く。件数にも数えない。
    全部が除かれたら0件で、節を出さない（→ 判断5）
- **並び:** 最後に読んだ日が古い順（→ 判断3）
  - 最後に読んだ日は、出どころのノートの痕跡にある訪問の最新の日時。このアプリで読んだときにしか残らない
  - **読んだ記録が無いノートを最も古いとして先に出す。** 痕跡が無い・壊れている・読めないときも同じ
  - 記録が無いもの同士と、同じ日時のもの同士は、出どころのノートの更新日時が古い順。それも同じなら題名の順
- **件数:** 3件を出し、残りは「ほか N 件」に畳む。押すと残りを同じ並びで出す。ノートを替えると畳んだ状態に戻る（→ 判断3）
- **1ノート1行:** 本文で最初に出てくるリンクの1文を添える。同じノートのほかのリンクの数は出さない（→ 判断2）
- **1文:** リンクを含む文を1行で出し、はみ出す分は「…」で切る。
  - **リンクが1行に入るように切り出す。** 文頭から1行に収まらないときは、リンクの手前を少し残して前を「…」で切る
  - **別名の無いリンクは、名前の部分を「このノート」と出す。** 見える文字が書かれたリンクそのもの（`[[名前]]`・`[[名前#見出し]]`、パスの末尾の名前と同じ文字の `[文字](パス.md)`）のときだけで、見出しは書かれたまま残す。別名（`[[名前|表示名]]`・題名と違う `[文字](パス.md)`）は利用者の言葉なので替えない（→ 判断6）
  - 記法の記号は出さない
- **✎ の印:** 出どころのノートの痕跡に、最初のリンクのある節と同じ見出しの余白メモが1件以上あれば付ける。見出しは見出しの照合と同じ規則（`headingMatchKey`）で比べる。
  **リンクが最初の見出しより前にあるときは付けない。** メモの見出しが空なのは、見出しより前で書いたときと、見出しを控えていない古いメモのときがあり、区別できない。
  メモの本文は出さない。押した先は行と同じ（リンクのある節の見出しから開くので、そのメモの節に着く）（→ 判断7）
- **開く位置:** リンクのある節の見出しから開く。見出しより前にあればノートの冒頭から。
  **同じ見出しが出どころに複数あるときは、何番目の見出しかで区別する。** 索引は節の見出しの文字と、同じ見出しのうち何番目か（見出しの照合と同じ規則で数える）を持つ。
  開くときに出どころの本文が変わっていて、その番目の見出しが無いか文字が合わなければ、同じ見出しの最初のものから開き、それも無ければ冒頭から開く。
  **見出しは本文の最初の行に置く。** 見出しから後ろが画面より短いときも、本文の末尾に余白を足して見出しを上端へ送る（→ [note_links](note_links.md) 判断6）
- **上限:** 画面に出すのは3件。1文の長さと、1ノートから取るリンクの数は索引の上限に従う（→ [knowledge_index](../system/knowledge_index.md) §8）
- **状態遷移:** 作っている（進み具合）→ 引いている → 出せる／読めない。**0件なら節を出さない**。
  並びには痕跡が要るので、痕跡を読み終えるまで「引いている」のまま待つ（前に引けた行があれば残す）。
  **索引が今のノートをまだ読んでいないときも「引いている」のまま待つ。** 出るリンクが分からず互いのリンクを除けないので、判定済みの一覧として出さない。
  索引が読み終えたときの知らせで引き直す（索引が読めた上で出るリンクが無いノートとは分ける）
  その Vault で準備完了の走査がまだ一度も公開されていない間は、解けないので「引いている」のまま待ち、0件に畳まない（→ [knowledge_index](../system/knowledge_index.md) §3・§5）
- **保存と寿命:** 保存しない。結果はノート単位で、ノートを替えたら捨てる。索引の寿命は [knowledge_index](../system/knowledge_index.md) §4
- **画面遷移:** ペインからは右で開く（並べ読み → [margin_pane](margin_pane.md) §5.9・[desk_foundation](desk_foundation.md)）。関連タブからは今のノートとして開く（関連の行と同じ）
- **他機能との連携:**
  - 右で開いたノートは眺めるだけで、訪問を記録しない（→ [margin_pane](margin_pane.md) §5.9）。机で並べた相手としての控えは [desk_memory](desk_memory.md) の規則どおり
  - 関連タブから今のノートとして開いて読めば訪問が残り、次に同じノートを開いたときは後ろへ下がる
  - 索引が直ったとき（走査で変わったノートを読み直した）と、走査が公開されたとき（解くのに使うリンクの索引が替わった）に、今のノートの分を引き直す
- **エラー／AI非対応／キャンセル時:**
  - AI を使わないので、AI 非対応の端末でも同じに動く
  - 索引を作れない・読めないときは、節を開くと「このノートのバックナンバーを数えられませんでした」と出す。読書は止めない
  - 痕跡のフォルダを読めないときは、全部を記録なしとして並べ、✎ を付けない。節は出す
  - ノートを替えたら引いている途中の要求を止め、遅れて届いた結果を書かない
  - 走査が一部のフォルダを読めなかったときは、読めた分で出す。読めなかったフォルダのノートからのリンクは、解かずに除く
  - 走査が読めずに空だったとき（入れ物は空の一覧を公開する）は、0件と言わず「読めない」にする。節を開くと「数えられませんでした」と出し、次に読めた走査が届けば一覧に戻る

## 6. 状態とデータ

- **ノート単位の状態:** `BacklinksState`（引いていない・引いている・出せる・読めない）と行の一覧。行は並べ終えた全件を持ち、3件で切るのは画面の側。
  **`cancelNoteScopedJobs()` と `withNoteScopedReset()` の両方へ登録してある**（→ [architecture](../system/architecture.md) 判断4 の1行目）
- **Vault 単位の状態:** 索引の進み具合（`KnowledgeIndexProgress`）。こちらは索引を作る側が書く（→ [knowledge_index](../system/knowledge_index.md) §5）。
  節の出し方は2つを合わせて純関数 `backlinksSectionFor` が決める（数えられない → 作っている → 1件以上の行 → 出さない、の順）
- **畳む・開くは覚えない。** 節の開閉と「ほか N 件」の開閉は、関連の一覧と同じく、ノートを替えると畳んだ状態に戻る。
  開いたときの**ノートの表示の番号**（`NoteUiState.noteLoadId`、ノートを開くたびに進む）を画面の保存値に持って比べる。
  ノートの参照で比べると A→B→A で同じ値に戻り、ノートの画面が組まれていない間（全画面）の切り替えを見逃すため。
  **番号は発行した Store の印（`NoteLoadId.issuer`）ごと比べる。** 画面の保存値はプロセスの作り直しをまたいで戻るが、
  Store は作り直されて数え直すので、数だけで比べると前のプロセスの A で開いた値が新しいプロセスの B と一致して開く。
  印は Store を作るたびに乱数で決める（同じ Store のまま画面を作り直したときは同じ印なので、開いたまま）
- **索引に足すもの:** リンクの表に、1文の中のリンクの位置（始まりと終わり）。1行の切り出しと「このノート」への置き換えに使う。
  索引の版が上がるので、更新した後の最初の起動で索引を作り直す（→ [knowledge_index](../system/knowledge_index.md) §6）
- **永続化:** しない。索引は [knowledge_index](../system/knowledge_index.md) が持つ。痕跡は読むだけで書かない

## 7. システム設計

```
余白ペイン／関連タブ
  → NoteViewModel
    → バックリンクを引く Controller（ノート単位）
      → 索引（data のインターフェース越し）: 今のノートの名前の鍵で絞ったリンクと、今のノートから出るリンクを、1つの読み取りで一組に引く
      → resolveNoteLink（domain）: 出どころから解き、今のノートへ着くものだけ残す。今のノートから出るリンクも解き、着いた先を除く
      → 痕跡（data のインターフェース越し、I/O）: 出どころごとに最後に読んだ日時と、メモを書いた節の見出しを引く
      → 出どころごとにまとめ、最後に読んだ日の古い順に並べる（domain の純関数）
    → 状態の Writer（その照会がまだ取り消されていないときだけ書く。ノートの切替・索引の直し・公開のたびに前の照会を取り消す → knowledge_index §5）
```

- **痕跡は読むだけなので、痕跡の錠を取らない。** 錠は同じファイルの読み書きを守るもので（→ [architecture](../system/architecture.md) の並行処理の規約）、
  ここは書かない。書き込みの途中を読んで壊れて見えたら記録なしとして並べ、次に引き直したときに直る
- **見出しへ送る依頼は、同じ見出しの番目を任意で持つ**（`PendingNoteStart`・`SideLinkStart` の `headingOccurrence`）。開き始めの位置は `headingBlockIndex` がその番目を選び、無ければ最初の見出しへ戻る。
  バックリンクから開くときだけ番目を渡し、右で開く経路と今のノートとして開く経路の両方で同じ戻り方をする。本文のリンクは番目を渡さないので、今どおり最初の見出しから開く
- **関連タブから開くときは、ノートの画面がまだ組まれていない。** 本文の位置と同じ `MainActivity` のスコープで `rememberNoteStart` を持ち、解析が届いたら見出しへ送る。
  経路は先頭から開く境界（`openNoteFromTop`）と対の `openNoteAt` を通し、経路の検査（`NoteOpenRouteContractTest`）が両方を認める
- **ペインから右で開いたときの入口は「余白の一覧」**（関連の候補と同じ）。「← 余白へ戻る」は一覧の始まりまで面を送る。関連の見出しがあればそこ、無ければバックナンバーの見出しが行き先（→ 判断8）

## 8. 設計判断と代替案

### 判断1: 行き先は索引に持たず、引くときに解く

`[[名前]]` がどのノートを指すかは、同じ名前のノートが増減すると変わる。索引の時点で決めると、ほかのノートが増えただけで正しい行き先が古くなる。
引くときに本文のリンクと同じ規則で解けば、**バックナンバーに出たノートのリンクを押すと、必ず今のノートへ戻ってくる。**

### 判断2: 1ノート1行・最初の1文を1行で

1本のノートが何度もリンクしていると、リンクごとの行では同じ題名が続いて一覧を埋める。
本文で最初に出てくるリンクは、そのノートで今のノートを持ち出した場所であることが多い（2026-11-14、オーナー判断）。
**1文は1行に収め、ほかの箇所の数は出さない**（2026-11-21、オーナー判断）。題名・最大3行の文・箇所の数を読み解くのが重かった。
再会の入口に要るのは「どう使ったか」の手掛かりで、何箇所で使ったかではない。

### 判断3: 久しく読んでいない順に3件

**再会の入口なので、忘れかけている相手を上に出す**（2026-11-21、オーナー判断）。更新の新しい順では最近触ったノートが上に来て、
本文や関連ノートで目に入りやすいものと重なる。全件を並べるとどれが大事か分からず重かったので、3件に絞り、残りは「ほか N 件」で開く。
読んだ記録はこのアプリの痕跡にしか無いので、Obsidian でしか開いていないノートは記録なしとして先に出る。記録なし同士を更新の古い順にするのは、古い号ほど忘れている見立てによる。

### 判断4: スマホでも関連タブで読める

バックリンクは情報であって、Fold でしか成立しない操作ではない。[fold_experience](../system/fold_experience.md) §5 の線引きに従い、機能として共有する（2026-11-14、オーナー判断）。

### 判断5: 今のノートの本文がリンクしている相手を除く

互いにリンクしているノートは、今のノートの本文を読めばそこへ行ける。バックナンバーに並べても新しく分かることが少なく、本文のリンクと役割が重なる（2026-11-21、オーナー判断）。
判定は索引にある今のノートのリンクで行い、表示中の本文の解析は使わない。**入るリンクと出るリンクは1つの読み取り（トランザクション）で一組に引く。**
別々に引くと、間に索引の突き合わせが入ったとき、入るリンクは旧く出るリンクは新しいという、どの時点の索引にも無い組み合わせになり、互いのリンクの相手が出る。

### 判断6: 文の中の今のノートの題名を「このノート」と出す

リンクを含む文には、必ず今のノートの題名が入る。題名が長いと1行を食い、相手が何を言ったかが読めない（2026-11-21、オーナー判断）。
**別名は替えない。** `[[名前|表示名]]` の表示名は、そのとき自分が選んだ言葉だからである。
**題名の正規化で照らさない。** 正規化は `|`・`#`・`^`・フォルダを落とすので、`習慣#ではない`・`習慣^2`・`悪い/習慣` のような別名まで題名に見える。
この行のリンクは今のノートへ着くと解いてあるので、見える文字が書かれたリンクそのものかどうかだけで別名の有無を見分け、名前の部分だけを替える

### 判断7: 余白メモは本文を出さず、✎ の印だけ

そこで自分が何か書いたと分かれば、開いて読むかを選べる。本文まで出すと1行が重くなり、メモと引用を補助の面に出す案（保留中）を先取りすることになる（2026-11-21、オーナー判断）。
痕跡のメモは見出し名だけを控えるので、同じ見出しが複数ある出どころでは、別の節のメモで印が付くことがある（→ §11）。

### 判断8: 関連と反証の一文の後に置く

**並びは、関連ノート → AI推薦 → 反証の一文 → バックナンバー。余白ペインと関連タブで揃える**（2026-11-21、オーナー判断）。
バックナンバーは過去への入口で、今のノートから読み進める関連ノートより大事なものではない。
置き場ごとに役割が違うので順を変えてよい（机では再会を先に）という案もあったが、採らなかった。

## 9. 品質要件

- **性能:** 引くのは今のノートの名前で絞った行と、今のノートから出るリンクだけ。DB の読みも解き方も Main の外で行う。
  痕跡は出どころのノート1本につき1回読む（I/O）。リンクを多く受けるノートでは読む数が増えるので、節が出るまでの時間を実機で測る
- **プライバシー:** 端末の中で完結する。索引のバックアップの扱いは [knowledge_index](../system/knowledge_index.md) §9
- **アクセシビリティ:** 行は押せる高さを守る（→ [ui_design_principles](../system/ui_design_principles.md)）。読み上げでは題名と1文を1つの行として読み、✎ は「余白メモあり」と読む。「ほか N 件」は押せる行として読む

## 10. 検証と受け入れ条件

- **JVMテスト:** 数え方（押せる記法だけ・自分自身を除く・同じ名前の別のノートへ着くものを除く）、**今のノートの本文がリンクしている相手を除くこと**
  （今のノートの本文のリンクが同じ名前の別のノートへ着くなら、その相手は除かない）、1ノート1行、
  **並び**（記録なしが先・記録なし同士は更新の古い順・同じ日時は更新の古い順・それも同じなら題名の順・壊れた痕跡は記録なし）、
  **索引が今のノートをまだ読んでいないときは出さずに待ち、読み終えたら除くこと**、**3件と残りの数**、**✎ の判定**（同じ見出しのメモで付く・別の節のメモと、リンクが見出しより前のときは付かない）、
  **1文の切り出し**（リンクが文の後ろにあっても1行目に入る）と**「このノート」への置き換え**（別名は、正規化で題名に見えるものも替えない。見出しは後ろの空白や窓で切れたものも残す）、
  状態遷移、ノートを替えた後に旧い結果を書かないこと、索引が直ったら引き直すこと。
  **開く位置:** 同じ見出しの2つ目にだけリンクがあるとき2つ目を指すこと、本文が変わって番目が合わないときの戻り方、本文のリンクの見出しは今どおり最初のものを指すこと
- **instrumentation:** 余白ペインの節の畳む・開く・押すと右で開くこと。「ほか N 件」を押すと残りが出て、ノートを替えると畳まれること。関連タブの節。
  同じ見出しの2つ目の節へ、ペインと関連タブの両方から開くこと。2つ目の節が末尾に近くても、右と今のノートの両方で見出しが最初の行に来ること。
  `KnowledgeIndexDaoTest` で今のノートから出るリンクを引けること
- **実機確認**（[実機ケース](../../review/device_validation/knowledge_index.md)）**:** 開いた Fold とスマホで、実際の Vault でリンクを多く受けるノートを開き、3件の並びと1行と ✎ を目で見る。
  互いにリンクしているノートが出ないこと。関連タブから開いて読んだノートが次に後ろへ下がること。節が出るまでの時間
- **実機で起こせないので自動テストが持つ順序:** ノートを替えた直後に前のノートの結果が届く。引いている途中で索引が直る。痕跡を読んでいる途中でノートを替える（→ [knowledge_index](../system/knowledge_index.md) §10）
- **保証していないこと:** Obsidian で足したリンクは、次の走査まで出ない。1MB を超える本文の後ろにあるリンクは数えない。読めなかったフォルダのノートからのリンクは出ない。
  Obsidian で読んだことは並びに効かない

## 11. 既知の制約・未解決事項

- **1行に収まるかは文字数の目安で決める。** 画面の幅は測らず、リンクが文頭から20文字より後ろにあるときだけ、手前を8文字残して前を切る。幅の広い画面では切らなくても入る文を切ることがある
- **リンクの数が多いノートほど、節が出るまで待つ。** 並べるのに出どころごとの痕跡を読むため。リンクを多く受けるノートで実機で測る
- **✎ は見出し名で照らす。** 痕跡のメモは同じ見出しのうち何番目かを控えないので、同じ見出しが複数ある出どころでは、別の節に書いたメモでも印が付く
- **末尾に近い見出しから開いた後に末尾まで読むと、最後の段落の下に余白が見える。** 見出しを最初の行に置くための余白で、先頭から開き直したノートには残らない（→ [note_links](note_links.md) 判断6）
- 読み上げは、作り直す前の形（題名と1文と「ほか N 箇所」が1つの押せる行にまとまる）までを画面の構造で確かめた。✎ の「余白メモあり」を含め、音声で聞いた判定はしていない
- 大きな Vault の最初の作成の時間と DB の大きさは [knowledge_index](../system/knowledge_index.md) §8 が持つ
