## 1. 概要

**開いた Fold を本の形（縦の折り目）で持ち、余白ペインを閉じて読むとき、本文を左右2ページに組む。** 行が折り目をまたがない。
横に払うと次の見開きへ進む。読む位置は、机・全画面・閉じた外画面の縦の流しと行き来しても失わない。

**直したいのは今の縦積みである。** ペインを閉じると [`readerLayoutFor`](../../../app/src/main/java/com/example/newproject/ui/screen/ReaderLayout.kt) は縦積みを返し、
本文は1段のまま窓いっぱいに流れる。平らに開いた Pixel 10 Pro Fold（窓 約852dp）では1行が約40字になり、その中ほどを折り目が通る。
Google が開いた Fold の用途として名指しする「本の形で長文を読む」と、このアプリの本業（ノートを読む）が重なる（→ [fold_experience](../system/fold_experience.md) §7）。

**冊子の見開き（10枚を2枚ずつ並べる案）ではなく、本文の見開きを選んだ（2026-10-18、オーナー判断）。** 冊子は扉の1行と「これを読む」の紙で、長文を読む場所ではない。
天綴じ（上へ送る）の冊子を左右に並べても、本の見開きの形にならない（→ [booklet_mode](booklet_mode.md) 判断10）。冊子の見開きは、未着手の案として残している。

**体験であって機能ではない。** 保存するデータは増えず、閉じても何も失わない（→ [fold_experience](../system/fold_experience.md) §5 の線引き）。スマホに同じものは置かない。
**どこから導くか:** fold_experience §6 の姿勢の割り当ての「縦の折り目」の行（契約での行き先に見開きを書いてある）。
**契約1〜4からは導かない** — 補助の面を使わない、主の面だけの体験である。§5 の「契約から導けないものは机の外」との関係は §11 でオーナーに確かめる。

## 2. ゴールと非ゴール

### ゴール
- 本の形でペインを閉じて読むとき、**行が折り目をまたがない**
- 読む位置を、縦の流し（机の左・全画面・閉じた外画面・横持ち）と行き来しても見失わない。**ブロックは一致させ、ブロックの中はおおよそ**で受け渡す
- 読書の記録・「この部分」の節・リンクの送り・続きから読む・ノートの始まりの位置が、見開きでも今と同じ意味で効く
- めくりは指に追従し、指を離した所で決まる

### 非ゴール
- **本らしさのために書体・行間・紙の色を変えない。** 書体と行間は何も表さず、読む面の紙の色は年代が持つ（→ [bearing_channels](../system/bearing_channels.md) §2）
- **紙の重なりや残りの厚みで進み具合を見せない。** 重なりは冊子の面の形の一部で「眺める」を表す。読む面の栞も取り下げている（同 §2・§5）
- **冊子のめくり（紙の反り・折り目の影）を借りない**（→ §8 判断7）
- 縦書き・右開き。ページをまたぐ文字の選択
- 卓上の形（横の折り目）・折り目の無い大きな窓・閉じた外画面での見開き。姿勢の割り当ての別の行で、今の並べ方のまま
- 全画面（⛶）と、机の「本文を1画面に」での見開き。どちらも本文が折り目をまたぐが、この段では扱わない（→ §11）
- AI を呼ばない。保存するデータを増やさない

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 見開きで組む | 本文が左右2ページに出る。行は折り目をまたがない | 本の形・ペインを閉じている・ページの幅が下限以上（→ §5） |
| めくる | 横に払うと、指に追従して次（左へ払う）・前（右へ払う）の見開きへ滑る。読み上げからは見開きを送る操作 | 見開きの間 |
| 位置の受け渡し | ✎ で机へ、閉じて外画面へ、横に持って縦積みへ、⛶ で全画面へ移っても、左ページの先頭のブロックから読める。戻ると、そのブロックを含む見開き | 並べ方が替わった |
| 送り先の見開き | リンク・続きから読む・節へ飛ぶ・ノートの始まりは、送り先のブロックを含む見開きを開く | 本文を送る操作 |
| 読書の記録 | 右ページの終わりまでを読んだ位置として記録する | めくり終えて止まった |

## 4. 現在のユーザーフロー

> **該当なし（構想）:** 実装後に、入口から終了・再開までを書く。想定の流れは次のとおり。

1. 開いた Fold を本の形で持ち、ペインを閉じたまま Rediscover でノートを引く。本文が先頭の見開きで出る
2. 左へ払って読み進める。右へ払うと戻る
3. ✎ でペインを開くと机の画面になり、左の本文は見開きの左ページの先頭のブロックから始まる。✎ でしまうと、机の左で読んでいたブロックを含む見開きに戻る
4. Fold を閉じると、外画面はスマホと同じ縦の流しで同じブロックから。開き直すと、そのブロックを含む見開きに戻る
5. 次のノートを引くと、先頭の見開きから

## 5. 機能仕様

- **入る条件（`readerLayoutFor` に1行足す）:** ペインを閉じている、縦の折り目が本文領域の中にある、2ページのどちらの幅も下限以上、
  高さの足りない横長ではない（左右2列の判定が先に当たる）。**下限は本文の下限（300dp）と同じ** — 下限を割る窓（文字の大きさを上げて細くなった分割窓など）は縦積みのまま。
  ノートが無いときは縦積み（空の案内を見開きにしない）
- **並べ方:** 折り目で左右に割り、**2ページを同じ大きさにする**。どちらも読む面で、紙の色（年代）と形は今の読む面のまま（→ [bearing_channels](../system/bearing_channels.md) §9）。
  操作とレールの置き方は §8 判断3（オーナー判断待ち）
- **ページの割り方:** ブロックを本文の順に、左ページ・右ページ・次の見開きの左ページ…と詰める（→ §8 判断4）

  | ブロック | 割り方 |
  |---|---|
  | 段落・見出し・リストの項目・引用の行・コード | 行の境目で割る。割った残りは次のページの頭から |
  | 見出し | **ページの末尾に見出しだけを残さない。** 次のブロックの最初の1行と一緒に送る |
  | 画像 | 割らない。ページの高さに収まらなければ、ページに収まる大きさへ縮める |
  | 表 | 行の境目で割る |
  | 水平線 | 割らない |

- **めくり:** 横に払う。**指に追従して滑らせるだけで、冊子の紙の反りは借りない**（→ §8 判断7）。
  ページはスクロールしないので、縦の払いでは何も動かない。長押しは文字の選択、リンクは押せる、画面の端の戻る操作はシステムのまま。
  決める距離と速さはページャの既定に任せる（机の片側を広げる払い 56dp・400dp/秒 とは別の操作）
- **位置:** 見開きの位置は「左ページの先頭のブロック番号と、そのブロックの何文字目から始まるか」で持つ。
  **正本は本文の一覧の状態（ブロック番号＋オフセット）のまま**で、めくるたびにブロック番号を書き戻す（→ §8 判断6）。
  縦の流しへ渡すときはブロックの中の割合で渡し、**画素の一致は保証しない**（全画面と同じ水準 → [note_fullscreen](note_fullscreen.md) §10）
- **上限:** 本文は最大1MB（既存）。ページを組むための計測は Main で時間を区切って進める（→ §9）。総ページ数とページ番号は、この段では出さない（→ §11）
- **状態遷移:** 縦積み ⇄ 見開き ⇄ 机 は、窓とペインの設定から `readerLayoutFor` が決める。見開きの側から並べ方を変える操作は持たない
- **保存と寿命:** 見開きの位置はノートの画面の保存値に置き、ノートの URI を鍵にする。組んだページは覚えるだけで保存しない。
  ノート・ページの大きさ・文字の大きさ・本文の解析結果・画像の寸法のどれかが変われば組み直し、**組み直しても左ページの先頭（ブロックと文字の位置）は保つ**
- **画面遷移:** ✎ で机へ、⛶ で全画面へ（今のまま）。どちらから戻っても、送り出した位置を含む見開き
- **他機能との連携:**

  | 機能 | 見開きでの扱い |
  |---|---|
  | 読書の記録（[reflect_reading_trace](reflect_reading_trace.md)） | 右ページの最後の切れ端のブロックと、そのブロックをどこまで出したか（文字の割合）を、今の報告と同じ口へ送る。**めくり終えて止まったときだけ**。寸法の届いていない画像より後ろは報告しない（今の規則のまま） |
  | 「この部分」の節（[margin_pane](margin_pane.md) §5.3） | 左ページの先頭のブロックの節。めくり終えてから決める（流している途中で入れ替えない、と同じ） |
  | 本文のリンク（[note_links](note_links.md)） | 同じノートの見出しなら、その見出しを含む見開きを開く。別のノートは今どおり |
  | 続きから読む（[reunion_card](reunion_card.md)）・ノートの始まり | 送り先のブロックを含む見開きを開く |
  | 再会カード | 引いた直後だけ、左ページの上に出る。出ている間は左ページが短くなり、閉じたら組み直す（机の左と同じ扱い） |
  | 見出しの印（余白メモの件数） | 見出しの脇に今どおり出る |
  | 蒸留の太字・リンクの装飾 | 本文の装飾のまま描く |
  | 余白のシート | 今の縦積みと同じ。見開きの上に出る（折り目をまたぐのは今の縦積みと同じで、この段では変えない） |

- **エラー／AI非対応／キャンセル時:** AI を呼ばない。画像の寸法が届く前は、ページいっぱいの高さを取って組み（誤るなら大きい側 → [note_image_rendering](note_image_rendering.md)）、
  届いたら組み直す。組んでいる途中でノートが替われば、その組版は捨てる

## 6. 状態とデータ

> **保存するデータは増えない。** `NoteUiState` の欄も、契約2箇所（`cancelNoteScopedJobs()`・`withNoteScopedReset()`）への登録も増えない。
> 見開きの位置と組んだページは**ノートの画面の中**（保存値と `remember`）にあり、ノートの URI を鍵にして替われば捨てる。机の広げ方（`deskSpread`）と同じ置き方である。

- **位置の正本は Activity で共有している本文の一覧の状態（`noteListState`）のまま。** 見開きはそこからブロックを読み、めくるたびに書き戻す。
  一覧の状態を読み書きする口は、主なものだけで6つある（`rememberMarginFaceInputs`・`ReadingProgressReporter`・`rememberNoteStart`・続きから読む・同じノートへのリンク・`openNoteFromTop`）。ほかに全画面の継承と書き戻しがある。
  正本を移すとそのすべてを書き換えることになり、最後の1本を取り残しやすい（→ [lessons L14](../lessons.md#l14-横展開は最後の1本を取り残す)）
- **見開きの側で持つのは、ブロックの中の文字の位置だけ。** ブロック番号が一覧の状態と一致している間だけ有効で、外から一覧の状態が書き換わったら（リンク・続きから読む等）捨てて、送り先のブロックの先頭から開く
- **世代の三層目は要らない。** 組版の計測は画面のスコープで走り、ノート・大きさが変われば鍵の変化で取り消される（→ [architecture](../system/architecture.md) 判断4）

- **置き場所は `ui`。** ページの割り方は画面の形を決める判定なので、純関数でも `domain` に置かない（→ [architecture](../system/architecture.md) 判断5の4）
- **計測は Compose の `TextMeasurer`。** 使う口（`measure`、行ごとの `getLineStart`・`getLineEnd`・`getLineTop`・`getLineBottom`）は Compose 1.7.3 の ui-text のバイナリにあることを確かめた

### 実装の区切り

着手の順はロードマップが持つ。この文書は区切り方だけを決める。

1. **組版の土台（JVM）:** ページの割り方・位置の対応・入る条件の純関数とテスト。画面は変えない
2. **見開きを出す:** 計測・2ページの描画・めくり・入る条件・操作とレールの置き方（判断3）・縦の流しとの位置の受け渡し
3. **つなぐ:** 読書の記録・節・リンク・続きから読む・見出しの印・再会カード
4. **仕上げ:** 見出しを残さない・表とコードの分割・画像の縮小・読み上げ・アニメーションの設定

2と3は同じ実機検証に載せる（1は画面を変えないので載せない）。

## 8. 設計判断と代替案

### 判断1: 冊子の見開きではなく、本文の見開き

オーナー判断（2026-10-18、→ §1）。対話型の図で今の縦積み・冊子の見開き・本文の見開きを比べて決めた。
冊子の見開きは冊子を使うときだけ効き、本文の見開きはペインを閉じて読むたびに効く。

### 判断2: 見開きは条件がそろえば自動で入る。入る・出るボタンを足さない

ボタンは増やさない方針である（2026-10-03、オーナー判断）。条件は窓とペインの設定で決まり、机の画面と同じ決め方になる。
**代わりに、縦の流しで読みたい人の道が無い。** 文字の大きさを上げてページが下限を割れば縦積みになるが、それを道とは呼べない。要望が出たら設定で足す。

### 判断3: 操作とレールの置き方 — オーナーの判断待ち

**ページの幅を取るか、タブへの道を取るかの選択である。** 平らに開いた Pixel 10 Pro Fold（窓 約852dp、折り目は中央）での見込み（実測ではない）：

| | (A) 机と同じ形（推奨） | (B) 縦積みの延長 |
|---|---|---|
| レール | 畳む | 残す |
| 操作（Rediscover・💬・✎・⛶・別のノート・冊子） | 左ページの上のつまみを下へ払うと帯で出る（[margin_pane](margin_pane.md) §5.1 の机と同じ） | 左ページの上に今の行で出る。右ページの上には今の節の名前（柱）を置く |
| 1ページの幅 | 約398dp（机の面と同じ）。本文の幅 約360dp、**1行 約22字** | 約318dp（左はレールの分だけ狭く、右も同じ幅にそろえる）。本文の幅 約280dp、**1行 約17字** |
| 1見開きの字数 | 約1,200字 | 約900字（操作の行の分だけ行も減る） |
| タブを替える道 | **無い** — 帯に1つ足すか、つまみで帯を出すとレールも重ねて出す形が要る。机の「タブは帯に入れない」（2026-10-06）を見直すことになる | 今と同じ |

**推奨は (A)。** (B) のページは本文の下限（300dp）ぎりぎりで、コードと表が窮屈になり、1行17字は新聞の段組みに近い。
読む場所を良くするための段なので、読む幅を優先する。タブへの道は「つまみで帯を出すとレールも重ねて出す」を推す — ボタンを増やさず、机にもそのまま効く。
**見た目に触る判断なので、実装の前に図で合意する**（→ [ui_design_principles](../system/ui_design_principles.md) §4）。

### 判断4: 先頭から全体を組む。今の位置から局所に組まない

ページの境目が入り方（先頭・続きから読む・リンク）で変わらず、前の見開きへ戻るのも単純で、ページ番号を後から足せる。
**代わりに、先頭から測るので、深い位置から入ると組み上がるまで待つ。** 計測を時間で区切り、組めた所から見開きを出す。1MB の本文で待つ時間は区切り2で測る（→ §9）。
今の位置から局所に組む案は、前へ戻るたびに後ろ向きに組む規則が要り、同じノートでも入り方でページの境目が変わるので採らない。

### 判断5: 割った段落は、残りの文字を同じ幅で組み直して描く。全文を描いて切り取らない

全文を描いてページの窓で切り取ると、読み上げが隠れた行まで読み、選択とリンクが見えない行にも効く。
**組み直すと、改行が段落の頭から決まる規則でなければずれる。** 段落全体を見て改行を決める規則だと、残りだけを組み直したときに行の切れ目が変わり、
ページの下に1行はみ出す・空く。そこで**見開きの本文は改行の規則を「行の頭から決まる」もの（`LineBreak.Simple`）にそろえ、計測と描画で同じ規則を使う。**
今の本文の既定がどちらかは確かめていない（→ §11）。

### 判断6: 位置の正本は本文の一覧の状態のまま

§6 のとおり、読み書きする口が6つある。正本を見開き専用の型へ移すと、6つすべてと全画面の継承を書き換える。
見開きはブロック番号だけを一覧の状態と往復させ、ブロックの中の文字の位置だけを自分で持つ。**見開きの間は一覧が組まれていない**ので、一覧の見えている範囲を読む口（読書の記録）は見開き用に1本足す。

### 判断7: めくりは横に滑らせるだけ。冊子の紙の反りを借りない

冊子のめくり（折り目が斜めに走る紙の反り・影）は冊子の面の手触りで、天綴じの紙1枚を繰る形として作った（→ [booklet_mode](booklet_mode.md) 判断10・判断11）。
読む面へ借りると、動きが面の役割（眺める／読む）まで運び始める（→ [bearing_channels](../system/bearing_channels.md) §8「手触りの側には意味を運ばせない」）。
**指に追従する動きの行は、載る面を読む面へも広げることになる。** 意味は同じ（何を繰っているかの手触り）なので行は割らないが、
実装するときに bearing_channels §2 の「載る面」を書き換える。時間で進むめくり（読み上げからの送り）は OS のアニメーションの設定に従い、指で進めるめくりは従わない（冊子と同じ線 → [booklet_mode](booklet_mode.md) 判断10）。

### 判断8: 計測は描画と同じ書式から取り、ずれは描画の側で検査する

計測（`TextMeasurer`）と描画（`Text`）が別の書式を読むと、ページの末尾がはみ出すか空く。書式を1か所に切り出して両方が読み、
**組んだページを実際に描いて、はみ出さないことを instrumentation で確かめる**（JVM では文字を組めない → [lessons L53](../lessons/L53.md)）。

## 9. 品質要件

- **性能:** 計測は Main で行い、1回あたり約4ms で区切って次のフレームへ譲る（区切らないと、長いノートでめくりと入力が止まる → [lessons L13](../lessons.md#l13-純粋と軽いは別)）。
  ページへ割る純関数は寸法の配列を1回なめるだけで軽い。**目安（仮）:** 20KB の本文で最初の見開きまで100ms以内。1MB の本文でかかる時間は未測定で、区切り2で測ってから目安を決める
- **アクセシビリティ:** 読み上げはページの文字を順に読む。見開きを送る操作を読み上げから使える。文字の大きさを上げてページが下限を割れば縦積みになる
- **プライバシー:** ネットワークに出ない。AI を呼ばない

## 10. 検証と受け入れ条件

- **JVMテスト:** `SpreadPaginationTest` — 割り方の各行（行で割る・見出しを末尾に残さない・画像を縮める・表を行で割る・空のノート）、
  見開きの位置とページの対応（組み直しても左ページの先頭を保つ）、読書の記録へ送る位置、**要素数が最大になる入力**（→ [lessons L52](../lessons/L52.md)）。
  `ReaderLayoutTest` — 入る条件（縦の折り目・ペインを閉じている・下限・卓上の形・折り目の無い Expanded・高さの足りない横長）
- **instrumentation:** 組んだページを描いてはみ出さないこと（段落・リスト・引用・コード・表・画像を含む本文で）。めくり。
  ✎ で机へ・閉じた外画面へ替えて戻す・横持ちへ替えて戻すで、同じブロックが出ること。同じノートの見出しへのリンク、続きから読む、読書の記録
- **実機確認:** 本の形でペインを閉じて読み、めくる。開閉・✎・全画面との往復で位置を失わない。長いノート・画像・表・コードを含むノート。文字の大きさを上げたとき縦積みになる
- **実機で起こせないので自動テストが持つ順序:**
  - 組版の途中でノートが替わる（組版は短く、ノートの切替と重ねられない）→ 古い組版の結果が新しいノートのページにならないことを instrumentation で固定する
  - 画像の寸法が、組版の途中やめくりの途中に届く → 組み直しても左ページの先頭を保つことを `SpreadPaginationTest` で固定する
  - 文字の大きさの変更が組版の途中に来る → 鍵の変化で組み直すことを instrumentation で固定する
- **保証していないこと:** 縦の流しとの往復でのブロックの中の画素の一致。1MB の本文で組み上がるまでの時間（区切り2で測るまで）。ページをまたぐ文字の選択
