## 1. 概要

Vigilith を**ポイントを要求するペットではなく**、既存のAI操作と読書痕跡へ身体を与える
**寡黙な読書相手**として常駐させる。

**主役は常にノート。** 新しい会話人格やキャラクター用の永続状態は作らない。

## 2. ゴールと非ゴール

### ゴール
- 既存の状態（AI生成中・蒸留の工程・痕跡カードの有無）を**身体表現**する
- 通常5タブで**同一個体**として常駐する
- 本文・カード・操作ボタンを**覆わない**

### 非ゴール
- **自動で文章を発話しない。** 既存データを身体で表すだけ
- **催促表現を持たない**（ストリーク・空腹・報酬要求）
- **キャラクター専用の状態を ViewModel へ足さない**
- **エラー・モデル取得待ち・復旧要求を感情として演じない**（→ §8 判断2）

## 3. 詳細機能一覧

| 詳細機能 | ユーザーから見える挙動 | 起動条件 |
|---|---|---|
| 常駐 | 通常5タブで同じ個体が右下に居る | 常時（シート表示中は非表示） |
| タップ | 現在のセクションを対象に要約・質問シートを開く | ノートタブ |
| ドラッグ | 画面内を移動できる（四辺へclamp） | 常時 |
| 4表示状態 | 姿勢とモーションが変わる | 既存状態から導出（→ §5） |
| 退避 | Snackbar・IME を避けて位置を変える | それらが表示されたとき |

## 4. 現在のユーザーフロー

1. アプリを開くと `AppScaffold` 直下の `VigilithHost` が Vigilith を描く（**通常5タブで一体だけ**）
2. 既存状態から表示状態を導出する（`resolveVigilithPresentation` — **純関数**）
3. タップするとセクション要約・質問シートが開く
4. ドラッグで移動できる。**位置は px ではなく配置可能領域内の相対座標（0〜1）で保持**する
5. Fold開閉・回転・ラベル寸法の変更があると、**同じ相対位置から安全な座標を再計算**する
6. ボトムシート表示中は**非表示**、全画面読書中は**最小AIインジケータへ委ねる**

## 5. 機能仕様

- **4つの表示状態**（3つの基本姿勢）:

  | 状態 | 導出元 | 表示・モーション |
  |---|---|---|
  | `Idle` | 下記以外 | 正面で翼を畳み、レンズとコアだけが**4.8秒周期**で弱く呼吸する |
  | `Summarizing` | 全体要約またはセクション要約の生成中 | 胴体を三分の二横向きにし、外側の片翼を開いて結果を案内する |
  | `Distilling` | 蒸留の `Analyzing` / `Saving`、AIタブ上の `Candidates` | 正面で両翼を胸元へ寄せ、断片の収集・保持・下線確定を工程別に描く |
  | `Messenger` | ノートタブで未dismissの `ReadingTraceCard` がある | 下から静かに着地し、痕跡カプセルが登場中に**一度だけ**明滅する |

- **優先順位:** `Distilling` > 明示的なセクション要約 > `Messenger` > バックグラウンド要約 > `Idle`
- **配置:**

  | 対象 | 値 |
  |---|---|
  | 表示枠 | **76×93dp** |
  | ラベル表示中の予約枠 | **260×132dp**（状態ラベルを出すときだけ広がる） |
  | Snackbar 表示中の退避 | **72dp 上方** |
  | IME 表示中の下限 | **キーボード上端＋16dp**（Snackbar より優先） |

  予約領域には Compact の `NavigationBar`・展開時の `NavigationRail` を含め、
  システムバーは `WindowInsets.safeDrawing` から**実測**する
- **素材:** 4状態それぞれが専用の**透過ロスレスWebP**（高さ936px・幅749〜802px）。
  起動OPも専用WebP、ランチャーは Adaptive Icon 用 VectorDrawable
- **目の統一:** 全表示で「明るい機械枠／Aqua虹彩／濃色瞳孔／左上キャッチライト」
- **エラー／AI非対応時:**

  > **該当なし:** エラーは `Idle` へ戻して既存UIの説明に任せる（→ §8 判断2）。

## 6. 状態とデータ

**永続化しない。**

> **該当なし:** キャラクター専用の状態を持たない。表示状態は既存の
> `SectionChatState` / `DistillState` / `QuizState` / `ReadingTraceCard` から**導出するだけ**で、
> `NoteUiState` にキャラクター用のフィールドを足していない。

**ドラッグ位置だけが例外的にUI側の状態**だが、これも相対座標（0〜1）で持ち、画面変更のたび再計算する。

## 7. システム設計

```
AppScaffold
 └─ VigilithHost（通常5タブ共通・一体だけ）
      ├─ resolveVigilithPresentation()   ← 純関数。既存状態 → 表示状態
      ├─ VigilithMascotMotion            ← 純関数。工程の分離・出力範囲・一度だけの発光・着地
      └─ 配置計算                         ← 純関数。clamp・Fold再配置・Snackbar/IME退避
```

**表示判断・モーション・配置のすべてを純関数へ集約する。** Compose や Android 型を含めないので、
JVMテストで固定できる（→ §10）。

## 8. 設計判断と代替案

### 判断1: 吹き出しの操作責務を Vigilith へ移す

ノート画面右下には、セクション要約と質問シートを開く**ドラッグ可能な吹き出しが既にあった。**
Vigilith を別要素として追加すると**操作対象と表示領域が競合する**ので、置き換える。

タップとドラッグの振る舞いは従来どおり維持する。

### 判断2: エラーを感情として演じない

エラー・モデル取得待ち・復旧要求は `Idle` へ戻し、**既存UIの説明に任せる。**

**マスコットが困った顔をしても、ユーザーは何をすればいいか分からない。**
説明はテキストの仕事で、身体表現の仕事ではない。

### 判断3: 既存状態を唯一の真実にする

`resolveVigilithPresentation` は既存状態を読むだけで、**ViewModel へキャラクター専用状態を足さない。**

足すと「マスコットの状態」と「機能の状態」の2つが生まれ、必ずずれる。

### 判断4: ドラッグ位置は px ではなく相対座標で持つ

**Fold開閉・回転・状態ラベルの寸法変更で、px の位置は意味を失う。**
配置可能領域内の相対座標（0〜1）で保持し、変更後に同じ相対位置から安全な座標を再計算して四辺へ clamp する。

### 判断5: 反復アニメーションを低強度に限定する

低強度の発光・候補探索・翼の動きだけにし、**回転・バウンドは使わない。**
**非表示中は動かさない。**

状態遷移も短い Crossfade ＋小さな移動に留める。

> **Animator duration scale 0倍でも最終ポーズが成立する構成を維持する。**
> Compose の遷移が即時完了しても、姿勢が崩れない。

### ガードレール（守り続けるもの）

1. 本文・読書痕跡カード・操作ボタンを**覆わない**
2. 自動で文章を**発話しない**。既存データを身体表現するだけ
3. ストリーク・空腹・報酬要求などの**催促表現を持たせない**
4. 反復アニメーションは低強度に限定し、**非表示中は動かさない**

## 9. 品質要件

- **アクセシビリティ:** ノートタブでは**1つの Button semantics へ状態・操作・対象節を集約**し、
  可視ラベルは読み上げ対象から外して**TalkBack の二重フォーカスを防ぐ**。タッチ領域は 76×93dp
- **性能:** 表示判断・モーション・配置がすべて純関数で、再コンポーズの範囲が閉じている
- **プライバシー:**

  > **該当なし:** ユーザーデータに触れない。
