## 1. 概要

読んできたノートの要約から、**別々のノートに共通する筋**をAIが選び、1文に総括して Vault に溜める。
✨ Reflect タブの要約の下に、**いま開いているノートが根拠に入っている結晶だけ**を出す。

Reflect を作り直す3本目である。北極星の2つ目の基準「その結果は、次の再会の材料として残るか」に、
いまの Reflect はどれも答えていない — 要約は端末に溜まるが読む面が無く、蒸留は Obsidian 側にしか残らない。
**結晶は溜まることそのものが役目**で、溜まった件数がそのまま Reflect の利用実績になる。

**総括するのは「あなたの思考」ではなく「読んできたもの」である**（→ 判断1）。
ユーザーには何も要求しない。読むだけで材料が控えられ、条件がそろえば裏で1文ができる。

## 2. ゴールと非ゴール

### ゴール
- **読むだけで溜まる。** 書く・押す・選ぶ操作を1つも要求しない
- **根拠を総括の横に並べる。** どのノートのどの要約から作ったかが常に見え、後から検算できる
- **追記だけで、上書きしない。** 一度書いた結晶は書き換えも自動削除もしない
- **Vault に残る。** 端末を替えても、Vault と一緒に持ち歩ける

### 非ゴール
- **本人の考えとして総括しない。** 材料は読んだノートの要約であって、本人の言葉ではない（→ 判断1）
- **助言・問い・評価を足さない。** 選んだ要約に書かれていないことは書かせない
- **Rediscover の画面と再会カードには出さない。** 情報過多を避ける（2026-09-26、オーナー判断）
- **通知しない。** Snackbar もバッジも出さない。自動で走る機能なので、失敗は黙って諦める（→ 判断8）
- **結晶を消す・直す導線は持たない。** 最初の版では Vault のファイルを消せば消える、までに留める
- **読書痕跡の退避と復元には載せない**（→ §11）
- **余白メモは、最初の版では材料にしない**（→ §11）

## 4. 現在のユーザーフロー

1. ノートを開き、本文が出る。この Vault の結晶をまだ読み込んでいなければ、読み込みを始める（AIを呼ばない）
2. ノートに3秒留まり、要約が出ている → そのノートの要約を、材料として端末に控える
3. 試す条件（→ 判断5）を満たせば、このノートの再会カードの照合が終わるのを待ち（→ 判断10）、
   **今のノートと、最近見た他のノート最大5件**を候補にして、生成を1回だけ呼ぶ
4. AI は、今のノートと筋を共有するノートを他の候補から1〜3件選び、選んだ要約だけを材料に1文で総括する。
   Vault に1ファイルとして書き、一覧へ足す。**筋が無ければ何も書かない**
5. ✨タブを開くと、要約の下に、今のノートを根拠に含む結晶が出る
6. 「結晶の一覧」から、これまでの結晶を新しい順に見る。根拠のノート名を押すとそのノートが開く

**中断:** ノートを切り替えると、門番待ち・要約待ち・生成中の試行は取り消され、**試行として数えない。**
**保存に入った結晶は、切り替えても止めずに書き終え、同じ Vault なら一覧へ足す**（→ 判断9）。
Vault を切り替えると、読み込み中の一覧と生成中の試行を捨てる。保存は要求した Vault へ書き終えるが、新しい Vault の一覧には足さない。

## 5. 機能仕様

- **前提条件:** Vault が選ばれ、ノートの相対パスが確定していること。**相対パスが確定しないノートは控えない**
  （関連ノートから開いた直後など。根拠をパスで持つため）
- **入力と出力:** 入力は候補のノート名と要約。出力は選んだ候補のIDと1文
- **状態遷移:** 一覧は 未読込 → 読込中 → 読込済み。生成は状態を持たない（→ 判断8）
- **保存と寿命:** 結晶は Vault 内に1件1ファイルで、消さない。控えは端末内で、上限を超えた古いものから押し出す
- **画面遷移:** ✨タブ → 結晶の一覧（新しいルート）→ 根拠のノート（既存のノートを開く経路。Rediscover 経路ではないので再会カードは出ない）
- **他機能との連携:** 要約の結果を読むだけで、要約の生成・保存・表示は変えない。置き場は読書痕跡のフォルダを共有する（→ 判断7）
- **エラー／AI非対応／キャンセル時:** 失敗・非対応・モデル未取得では黙って何もしない。**モデルのダウンロードを始めない。**
  `CancellationException` は再throwし、試行として数えない。保存が失敗したら一覧に何も足さない（試行は数えたまま）

### 上限

| 対象 | 値 | 理由 |
|---|---|---|
| 候補 | **今のノートを含めて最大6件** | 完成プロンプトを小さく保つ（下の予算） |
| 断片（候補1件の要約） | **240字**。超えたら文の区切りまで手前へ寄せ、区切りが無ければ切って `…` | 要約は2〜4文。全文を渡す厚みは要るが、6件並べても予算に収める |
| ノート名 | `PromptLimits.LABEL_CHARACTERS` | 既存のラベル上限をそのまま使う |
| 根拠 | **今のノート＋他の1〜3件**（2〜4件） | 1件では「共通する筋」にならない。5件以上は1文で総括できない |
| 結晶の文 | **1文・10〜120字** | 一覧で1〜2行に収まる長さ |
| 控え | **1 Vault あたり12件**。同じノートは1件にまとめ、開き直したら最後に見た時刻だけを進める | 使うのは直近5件なので、重複を除いても足りる厚み |
| 渡した材料の記録 | **直近60件**（1回の試行で最大6件 × 10回分） | 同じ材料で作り直さないため（→ 判断5）。溢れた古い記録の材料は、また新しい材料として数える |
| 試行 | **端末の暦日で1日1回まで**、かつ**実際にAIへ渡す候補の中に**、まだ渡していない材料が3件以上 | → 判断5 |
| 結晶1件のファイル | 16KB。超えるものは書かず、読み込みでも飛ばす | 想定は1〜2KB。壊れた巨大ファイルで一覧を止めない |
| 生成 | 出力256トークン・60秒・`generateMutex` 直列 | `AiClient` の既存値 |

**完成プロンプトは最大でも約3,400字**（指示文 約700字＋6件 ×（ノート名200＋断片240））で、
`MAX_PROMPT_CHARACTERS` の6,000字を変えずに収まる（→ [ai_input_excerpt](../system/ai_input_excerpt.md) §13）。
**実トークンの余裕は `PromptTokenBudgetTest` に用途を1つ足して実機で測ってから確定する。**

### プロンプト

`PromptBuilder.buildCrystalPrompt` を12本目の完成プロンプトとして足し、`PromptBudget.assemble` を通す。

- 指示文で**「これは読んだノートの要約で、読み手自身の考えではない」**と明示する
- 候補は `N1`〜`N6` のIDで渡す。**`N1` は今のノート**。照合キーはIDで、ノート名を照合に使わない
  （→ [ai_input_excerpt](../system/ai_input_excerpt.md) §13 判断10）
- 求めること: `N1` と共通する筋を持つ候補を他から1〜3件選び、**選んだ要約だけを材料に**、共通する筋を1文で書く。
  要約に無いこと・助言・問い・評価は書かない。筋が無ければ `NONE` とだけ答える
- 出力形式は2行 — `選択: N1, N3` と `結晶: 〜。`
- 材料（候補一覧）が予算を超えたら、**古い候補から行ごと落とす。`N1` は落とさない**。落とした候補は許可集合からも外す。
  **試す条件の判定と渡した材料の記録も、落とした後の集合（以下「渡す候補」）で行う**（→ 判断5）

### 応答の検証（`parseCrystalResponse`・純関数）

| 応答 | 扱い |
|---|---|
| `NONE`（前後の空白・句点は許す） | 空振り。何も書かない |
| 選択に `N1` が無い／他が0件か4件以上／提示していないID | 不正。何も書かない |
| 結晶が2文以上／疑問文（`？` や「か。」で終わる）／10字未満か120字超／本文にIDが漏れている（**選択欄が読むのと同じ表記すべて** — 大小文字・全角・空白付き） | 不正。何も書かない |
| 上のどれでもない | 採用。選んだ候補の断片をそのまま根拠として書く |

コロンの全角・半角、IDの大小文字・全角・空白、2行の前後の余計な行は許す。**IDの表記の正規化は照合にだけ使い、保存する文は均さない。****空振りと不正は区別して記録しない** — どちらも「書かない」で、試行としては数える（→ 判断5）。

### 表示

- ✨タブ: 要約（`SummaryPanel`）の直下。**このノートを根拠に含む結晶**を新しい順に最大3件、その下に一覧への入口
- 絞り込みは純関数 `crystalsForNote(crystals, path)` が決める。**UIに条件を書かない**
- **今のノートの相対パスは `NoteState` が持たない**ので、結晶を試す契機（`crystallize`）で `crystalNotePath` に置く。
  相対パスが確定しないノートでは置かないので、そのノートの✨タブには結晶が出ない（入口は出る）
- 根拠のノート名は、結晶を作った時点のものを出す。改名・移動には追従しない
- 一覧: 新しい順。根拠のノート名は、**今の走査結果に同じ相対パスがあれば押せる**。無ければ押せない表示にする
- 一覧を開いたときの走査は **Vault単位の Job** として持ち、Vault切替で取り消す。取り消しに加えて、走査キャッシュが
  公開の直前に Vault の世代を照合するので、切替の前に始まった走査が後から返っても**切替後のキャッシュ・開けるパス・分野の索引へ戻らない**
  （→ [note_field_color](note_field_color.md) の「別Vaultの遅れて届いた結果を現Vaultへ合成しない」）
- 見た目は [ui_design_principles](../system/ui_design_principles.md) と [bearing_channels](../system/bearing_channels.md) に従い、
  **新しい色・形の意味を足さない**。面は要約と同じパネルを使う

## 6. 状態とデータ

**UI状態:** 書き手は結晶の Controller だけで、寿命の違う2欄を1つのスライス（`CrystalSlice`）で持つ。

| 欄 | 中身 | 寿命 |
|---|---|---|
| `crystalLog` | `CrystalLogState` — `NotLoaded` / `Loading` / `Loaded(crystals)`。`crystals` は新しい順 | **Vault単位** |
| `crystalNotePath` | ✨タブの絞り込みに使う今のノートの相対パス。`NoteState` が相対パスを持たないため、ここに置く | **ノート単位** |

✨タブの表示は、この2欄から純関数で導く。

**契約への登録（→ 判断8）:**

| 契約 | 登録 | 理由 |
|---|---|---|
| `cancelNoteScopedJobs()` | **載せる** — `crystal.cancelAndClear()` は生成ジョブだけを止め、requestId を進める。**保存に入った結晶と一覧には触らない**（→ 判断9） | 試行はノートを開いた契機で走る |
| `withNoteScopedReset()` | **`crystalNotePath` だけ載せる。一覧は載せない** | 一覧は Vault 全体のもの。ノートを切り替えただけで一覧が消えるのは誤り。パスを残すと次のノートの✨タブに前のノートの結晶が出る |
| `withVaultScopedReset()` | **載せる** — `crystalLog = NotLoaded`。`clearVaultScoped()` が読み込みと生成を止めて requestId を進める。**保存は止めないが、その完了を新しい Vault の一覧へ足さない**（→ 判断9） | 別 Vault の結晶を出さない |

**結晶（Vault 内・1件1ファイル）:** `_ReadingTraces/crystals/<作成時刻のエポックミリ秒>.json`

| 欄 | 中身 |
|---|---|
| `schemaVersion` | 1 |
| `createdAt` | 作成時刻（エポックミリ秒）。**並べ替えはこの欄で行い、ファイル名に意味を持たせない** |
| `sentence` | 結晶の1文 |
| `sources` | 2〜4件。各件は `vaultRelativePath`・`noteTitle`・`fragment`（**AIへ渡した断片そのもの**） |
| `checksum` | 他の欄の正規形の SHA-256。読書痕跡と同じ作法（→ [reflect_reading_trace](reflect_reading_trace.md) §6） |

**控え（端末内）:** `noBackupFilesDir/crystal_material/<Vault の名前空間のSHA-256>.json`。名前空間は分野判定と同じもの
（→ [note_field_color](note_field_color.md) 判断9）。自動バックアップにも退避にも載らない。

| 欄 | 中身 |
|---|---|
| `schemaVersion` | 1 |
| `lastAttemptAt` | 前回の試行の時刻。null は未試行。暦日の条件にだけ使う |
| `entries` | 最大12件。各件は `vaultRelativePath`・`noteTitle`・`fragment`・`lastSeenAt`（最後に見た時刻。候補の並びにだけ使う） |
| `presented` | これまでの試行でAIへ渡した材料の指紋。直近60件 |

**不変条件:**

- **既存の結晶ファイルを書き換えない。** 書くのは新しいファイルを作るときだけ
- **保存は、依頼した時点の Vault へだけ書く。** 保存の依頼は Vault の名前空間を持ち、書き込みの直前に現在の Vault と照合して、
  違えば書かない（読書痕跡の保存と同じ契約）。書き込みに入った後は、Vault を切り替えても依頼した Vault のファイルとして書き終わる
- **一覧へ足すのは、保存が成功し、一覧が依頼と同じ Vault のものであるときだけ。** 照合するのはノートの requestId ではなく
  Vault の世代（`vaultGeneration`）。保存が失敗したら何も足さない
- **足すのは1回だけ。** 作ったファイル名で重ねる。一覧が読込中なら、読み込みの完了時に重ねる（列挙より後に書いたファイルは列挙に現れない）。
  未読込なら足さない — 次の読み込みがファイルから読む
- **一覧の読み込みは、その Vault へ走っている保存が終わるのを待ってから列挙する。**
  Vault を A→B→A と選び直した直後でも、A への保存が一覧から漏れない
- **読めない結晶は、その1件だけ飛ばす。** checksum 不一致・パース失敗・未知の `schemaVersion`・16KB超。一覧全体は止めない
- **材料の同一性は「相対パス＋断片」で決める。** 指紋はその2つの SHA-256。**開き直しは材料を増やさない** —
  断片が同じなら `lastSeenAt` を進めるだけで、指紋も「まだ渡していない」かどうかも変わらない。断片が変われば別の材料になる
- **控えが壊れていたら空から始める。** 読むだけで作り直せるので、壊れた控えを直そうとしない。書くときは一時ファイルから置き換える
- **`crystals/` フォルダは、`_ReadingTraces` の列挙が完全で、かつ無いと確かめたときだけ作る。**
  読めなかったことを不在とみなすと2つ目を作る（→ [reflect_reading_trace](reflect_reading_trace.md) §5）

## 7. システム設計

```
本文を出す（setNoteState の Success）→ 相対パスが確定
 └─ NoteSessionCoordinator
      ├─ crystal.ensureLogLoaded()                 ← Vault単位・未読込なら1回・AIを呼ばない
      │    ├─ awaitCrystalSaves(vaultKey)          ← その Vault への保存が終わるのを待つ
      │    └─ CrystalStore.readAll(vaultKey)  @Dispatchers.IO
      └─ crystal.onNoteShown(path, title)          ← requestId を採番し、crystalNotePath を置き、vaultKey をこの時点で決める
           │ ── 生成（ノート単位。切り替えたら取り消す）──
           ├─ awaitDwell()                          ← 3秒（→ background_ai_ux §7）
           ├─ 要約が Success になるのを待つ          ← Error・AiUnavailable なら終わる
           ├─ fragmentOf(summary)                   ← 純関数・240字
           ├─ CrystalMaterialStore.record()         ← 端末内
           ├─ 今日すでに試していたら終わる          ← 暦日だけの前段。候補を作る前に抜ける
           ├─ selectCrystalCandidates(...)          ← 純関数・今のノート＋直近5件
           ├─ PromptBuilder.buildCrystalPrompt()    ← 予算で落とした後の「渡す候補」も返す
           ├─ shouldAttemptCrystal(渡す候補, ...)    ← 純関数。渡す候補の中に未提示が3件以上（→ 判断5）
           ├─ awaitReunionSettled()                 ← このノートの再会カードの照合が終わるまで（→ 判断10）
           ├─ checkAvailability()                   ← Ready 以外は終わる。DLは始めない
           ├─ AiClient.generate()  @generateMutex   ← 60秒
           ├─ CrystalMaterialStore.markAttempted(渡す候補)  ← 返ったら数え、同じ集合の指紋を記録する
           ├─ parseCrystalResponse()                ← 純関数
           └─ isCurrent(requestId) を照合して保存を依頼する   ← ここより前の取消では何も書かない
                │ ── 保存（Vault単位。ノートを切り替えても止めない）──
                ├─ CrystalStore.append(crystal, vaultKey)  @Dispatchers.IO   ← 書き込み直前に Vault を照合
                └─ 成功し、vaultGeneration が依頼時と同じなら一覧へ1回だけ足す
```

- **呼ぶのは窓口（`NoteViewModel`）で、再会カードの照合より後。** Rediscover・冊子は `presentDrawnNote`、
  関連・さがす・結晶の一覧は `openNote` から、相対パスが確定した後に `crystallize` を呼ぶ（順序は `CrystalWiringOrderTest`）
- **要約と再会カードの結果は待つだけ。** Coordinator が「このノートの要約の終わりを待つ関数」と「再会カードの照合の終わりを待つ関数」を渡し、
  Controller どうしは呼び合わない
- **照合は2つあり、守るものが違う。** requestId は「この生成を保存へ渡してよいか」、`vaultGeneration` は「この保存を今の一覧へ足してよいか」。
  どちらも使う直前の1箇所で行う（→ [architecture](../system/architecture.md) 判断4）
- `controller` は Android 非依存のまま保つ。2つの保存は `data` 側の実装を注入する

## 8. 設計判断と代替案

### 判断1: 総括するのは「読んできたもの」（2026-09-27、オーナー判断）

当初は「読んだノートの本文から規則で抜いた**本人の文**」を材料に、本人の思考を総括する形だった。
オーナーの Vault（2026-09-27 に置き直した最新の写し）で測ると、**本人の文の層が薄かった** — 痕跡のある読んだノート225本のうち73%が本の読書メモで、
問いの候補が抜けた34本もほぼ本人の問いではなかった（試験問題の「Q:」、AIの解説文、写したチェックリスト、リポジトリ文書の写し）。
**そのまま作ると、他人の言葉を「あなたの思考」として出す。**

そこで総括の対象を「読んできたもの」へ言い直した。**主語を変えれば、材料が他人の言葉であることは誤りではなくなる。**
プロンプトでも画面でも、本人の考えとして語らせない。

### 判断2: 材料は保存済みの要約。扉の代表文と問いの候補は使わない

- **要約は読むだけで溜まる。** 開いたノートで必ず作られ、ユーザーに何も要求しない。材料の条件と一致する
- **扉の代表文は弱い。** 冊子の扉は「最初に読める1文」を40字で選ぶ規則で、読んだノートの測定では
  本の索引ノートの「開始日：2025/05/23」、表の見出し行、ラベル行が選ばれていた。総括の材料には内容が足りない
- **問いの候補の抽出器は使わない。** 上の測定どおり他人の言葉が主で、引用ブロックを見分けても残る
- **代償:** 要約はAIの出力なので、結晶は**AIの出力を材料にしたAIの出力**になる。誤りは乗算される
  （→ [ai_input_excerpt](../system/ai_input_excerpt.md) §10）。根拠の断片を必ず横に並べるのはこのため

### 判断3: 核は今読んでいるノート

AIに候補の中から自由に組を選ばせず、**今のノート（`N1`）を必ず根拠に含める。**

- ✨タブは「このノートを根拠に含む結晶」だけを出すので、核を今のノートにすれば**できた結晶がその場の画面に出る**
- 「どれとどれが似ているか」を全組み合わせから探させるより、1件を軸に選ばせるほうが指示が単純で、応答の検証も書ける
- **無理につなげさせない。** 筋が無ければ `NONE` を返してよく、空振りは何も書かない

### 判断4: 控えるのは門番を通ったとき（読書痕跡の門番ではない）

材料を控える線は、自動生成の門番（ノートに3秒留まる → [background_ai_ux](../system/background_ai_ux.md) §7）にする。
読書痕跡の記録の門番（能動読書10秒）のほうが「読んだ」の定義としては正しいが、
**訪問はノートを離れたときに保存される** — その時点では要約はノート単位の状態としてもう消えている。
読書中に「10秒に達した」を知らせる経路を痕跡セッションへ足すのは、離脱・背面化・メモの預かりの契約を持つ部品への新しい入口になる。
**3秒は「このノートに Nano を使ってよい」とアプリが既に決めている線**なので、それに揃えた。
代償として、3秒だけ見たノートも「読んできたもの」に入る（→ §10）。

### 判断5: 試すのは1日1回まで、まだ渡していない材料が3件たまってから

- **1日1回。** 結晶は一つずつ意味を持ってほしい。毎回のノート表示で作ると一覧が似た文で埋まり、Nano の錠も取り合う。
  端末の暦日で数えるので、2台で読めば1日2つまでできうる
- **数えるのは「まだAIへ渡していない材料」であって、「最近見たノート」ではない。** この2つを分ける。
  - **材料**は「相対パス＋断片」で同一とみなす。要約は完成プロンプトを鍵に保存されて同じ入力なら同じ文を返すので、
    開き直しただけでは断片は変わらない。**時刻で数えると、同じノートを読み返すだけで同じ材料から作り直す**
  - **最近見た順**（`lastSeenAt`）は、候補のどれを選ぶかにだけ使う。開き直せば進むが、材料の数には効かない
  - 試行のたびに、**AIへ渡した候補すべての指紋**を記録する。選ばれなかった候補も含める — 渡した組で結晶ができなかったなら、
    同じ組をもう一度渡しても同じ結果になる（生成は決定的）
  - **「まだ渡していない材料が3件」は、実際に渡す候補の中で数える。控え全体では数えない。**
    控えは12件、渡すのは直近の6件なので、控え全体で数えると、候補の外に残った未提示の材料を理由に**昨日と同じ6件を渡しうる**。
    判定・送信・記録を、予算で落とした後の同じ集合（渡す候補）に結び付ける。
    候補の外にある未提示の材料は、読み直して直近に上がれば候補に入り、そのとき数える
  - したがって、同じ1件を3回開いても1件、昨日渡した3件を今日読み返しても0件である。
    本文を直して要約が変われば、そのノートは新しい材料として1件に数える
- **初回は、異なる材料が3件そろった時点で試す**
- **生成が返ったら試行として数え、渡した材料を記録する** — 成功・空振り・不正・失敗のいずれも。
  失敗を数えないと、壊れた状態でノートを開くたびに Nano を呼ぶ。
  **キャンセルでは数えない**（ノートを切り替えただけで、その日の1回を失わない）。
  `Ready` でなかった回は生成を呼んでいないので数えない
- **記録は直近60件で溢れる。** 10回ほど前の試行で渡した材料は、また新しい材料として数えうる。
  そのころには候補の他の5件が入れ替わっているので、同じ組にはならない
- **件数と間隔の値は実機で見て決め直してよい。** 溜まる速さの体感で決めるものである

### 判断6: 1結晶1ファイル。書き換えない

- **追記を字義どおりに守れる。** 新しいファイルを作るだけなので、既存の結晶に触れる経路が1本も無い
- **壊れても1件で済む。** 痕跡の書き込みは `"wt"` の直接上書きで原子性が無い（→ [reflect_reading_trace](reflect_reading_trace.md) §5）。
  全件を1ファイルに追記すると、書き込み中の中断で**全部の結晶を失う**
- **端末間で衝突しない。** 2台が同じ Vault に書いても別のファイルになる。同じミリ秒の衝突は SAF が別名にし、読む側は名前に意味を持たせない
- **代償:** 一覧の読み込みが件数に比例する（→ §11）

### 判断7: 置き場は `_ReadingTraces/crystals/`、控えは端末内

- **結晶は Vault に置く。** 溜まったものは Vault と一緒に持ち歩けるべきで、端末を替えたら消える置き場では目的に合わない
- **新しいルートフォルダを作らない。** アプリの記憶は `_ReadingTraces` に集まっているので、その下のフォルダにする。
  ノート収集の3箇所の除外（→ [reflect_reading_trace](reflect_reading_trace.md) §5）をそのまま受け継ぐ
- **痕跡の索引に載らないことを検査で固定する。** 索引は `_ReadingTraces` の子の名前の先頭64文字をキーとして読み、
  64文字未満は載せない。`crystals` はこれで外れる。**この前提に頼る経路（索引・孤児掃除・退避・読み戻しの下見）はすべて
  同じ索引を通るので、判定を `readingTraceKeyOf` に出してテストで固定した**（`ReadingTraceKeyTest` → [L14](../lessons.md#l14-横展開は最後の1本を取り残す)）
- **控えは Vault に書かない。** 書くとノートを開くたびに Vault への書き込みが1回増える。控えは失っても読めば溜まり直すので、
  端末内で足りる

### 判断8: 失敗を見せず、状態は Vault 単位の一覧だけ持つ

- **自動で走る機能は黙って劣化する**（→ [background_ai_ux](../system/background_ai_ux.md) §6 判断1）。生成中の表示も、失敗の表示も持たない。
  結晶は Vault に残って一覧からいつでも辿れるので、**未確認管理も要らない**（→ [background_ai_ux](../system/background_ai_ux.md) §4）
- **生成のジョブはノート単位、結果は Vault 単位**（保存を Vault 単位に分ける理由は判断9）。これは分野判定と同じ形で、architecture が「例外は分野判定だけ」と書き、
  **「同じ形が2件目に現れたら、そのとき表を組み直す」**と決めている形の2件目にあたる。
  **[architecture](../system/architecture.md) 判断4 の表の3行目「ジョブはノート単位・結果はVault単位」として並べた**
- **Controller を共通化しない。** 見せ方は分野判定と同じ（進捗も失敗も出さない）だが、材料・保存・表示がすべて違う。
  共通化の再検討の条件（未確認管理と Snackbar を持つ Controller の3つ目）にも当たらない

### 判断9: 生成の取消と、始まった保存の完了を分ける

生成はノート単位で、ノートを切り替えたら止める（錠を空けるため）。**保存は Vault 単位で、ノートを切り替えても止めない。**

- **SAF の書き込みはブロッキングI/Oで、取消を付けても書き終わりうる**（→ [L49](../lessons/L49.md)）。
  生成と同じ Job で保存すると、ファイルはできたのに一覧へ足す手前で止まり、**その日の1回を使った結晶が再起動まで見えない**
- **境目は「保存を依頼した時点」である。** それより前の取消では何も書かない。後の取消は保存を止めず、完了を一覧へ反映する
- **宛先は依頼の時点で固定する。** 書き込みの時点の現在の Vault から解決すると、切り替えた後の Vault へ書く。読書痕跡の保存が要求に Vault を持たせるのと同じ形である
- **一覧への反映は Vault の世代で照合する。** ノートの requestId で照合すると、同じ Vault の中でノートを切り替えただけで反映を落とす。
  逆に照合しないと、Vault を切り替えた後の一覧に前の Vault の結晶が混ざる
- **採らなかった案:** 保存を止めて書きかけを消す — SAF の削除は失敗しうるので、消せなかったファイルが黙って残る。
  取消を無視して一覧へ足す — Vault を切り替えた後の一覧に混ざる

### 判断10: 結晶は、再会カードの生成より先に錠を取らない

**要約の完了を待つだけでは、再会カードより先に走りうる。** 再会カードは Rediscover で本文を出した直後に照合を始めるが、
訪問の保存待ち・痕跡の読み込み・本文の解析を経てから生成を呼ぶ。要約が保存済みで即座に出れば、
3秒の門番を抜けた結晶のほうが先に `generateMutex` を取る。**錠は先に並んだ順で、後から来た要求は追い越せない。**
60秒の計測も錠を取った後に始まるので、カードの枠は結晶の生成時間だけ遅れる。

- **結晶は、生成を呼ぶ直前に、このノートの再会カードの照合が終わるのを待つ。** 照合の Job が無ければすぐ進む。
  待つのは試す条件を満たしたときだけで、材料を控えるのは待たない
- **照合は結晶より先に要求されている。** Rediscover では本文を出した直後に照合を要求し、結晶はその後で門番を待ち始めるので、
  待つ時点で照合の Job は既に走っている。**この順序を `NoteSessionCoordinatorTest` で固定する**。
  照合が入れ替わったら新しいほうも待つ
- **永久には待たない。** 照合の Job はどの枝でも終わる — Rediscover 以外の経路（Job が無い）、痕跡が無い・読めない、
  保存済みの前後の要約や選別結果で済んだ、生成が成功・失敗・空振りした、AIが使えない。ノートを切り替えれば両方とも取り消される。
  照合が保存待ちで止まり続けたら、結晶はそのノートでは試さない（試行として数えない）
- **関連ノートのAI推薦と分野判定は待たない。** どちらも既存の自動生成どうしで錠を取り合っている
  （→ [background_ai_ux](../system/background_ai_ux.md) §7）。結晶は1日に多くて1回なので、それらを遅らせるのは多くて1日1回である。
  **本文と同じ画面に出る再会カードだけを、結晶より先にする**

### 採らなかった案

| 案 | 採らない理由 |
|---|---|
| 一覧を開いたときに生成する | 押して使う機能になり、開くたびに待たせる。「読むだけで溜まる」を落とす |
| 読んだノートの本文から規則で本人の文を抜く | 判断1の測定で、本人の文の層が薄い |
| 余白メモだけを材料にする | いまの Vault には書ける版で読まれた記録が無く、メモが0件。溜まるまで何もできない |
| 要約の先頭1文だけを渡す | 再会カードの枠には足りるが、筋を見つけるには薄い。240字までの全文を渡す |
| 候補をランダムに選ぶ | 同じ状態から同じ候補にならず、テストで固定できない。直近の順で足りる |
| 全結晶を1ファイルに追記する | 判断6 |

## 9. 品質要件

- **性能:** 生成はノート表示あたり多くて1回、1日多くて1回。要約と再会カードの照合が終わってから錠を取るので、その2つの表示を遅らせない
  （→ 判断10）。関連ノートのAI推薦と分野判定とは錠を取り合う。
  一覧の読み込みは `Dispatchers.IO` で、件数に比例する
- **プライバシー:** 結晶ファイルには読んだノートの名前と要約が入り、Vault の同期先へそのまま出る。読書痕跡が要約を持つのと同じ扱いである。
  控えは `noBackupFilesDir` に置き、端末の外へ出ない
- **データ保護:** 既存の結晶ファイルを書き換えない。読めない1件は飛ばすだけで、消さない
- **アクセシビリティ:** 根拠の開閉は開いている状態を読み上げで伝え、押せる範囲は 48dp を確保する（→ [ui_design_principles](../system/ui_design_principles.md)）
- **オフライン・端末制約:** すべて端末内の Nano で完結する。Nano 非対応端末では何も出ず、既存の画面は変わらない

## 10. 検証と受け入れ条件

- **JVMテスト:**
  - `parseCrystalResponse` — §5 の表の各行。`NONE` の揺れ、`N1` 抜け、提示外ID、2文、疑問文、長さの両端、IDの漏れ
  - `shouldAttemptCrystal` と材料の記録 — 異なる3件で初回1回。**同じ内容の3件を翌日・再起動後に開き直しても0回**。
    同じ1件を3回開いても1件。まだ渡していない材料が2件なら0回、3件で暦日も満たせば1回。
    前回の結果が成功・空振り・不正・失敗のどれでも同じ規則になること。キャンセルでは数えず記録もしないこと。
    断片が変わったノートを1件として数えること。
    **判定を渡す候補に結び付けること** — 1日目にA→B→Cで試し、同じ日にD〜Lを控え、2日目にLを開くとL〜Gの6件で試す。
    3日目・4日目にLだけを開くと、控えには未提示のD・E・Fが残るが、渡す候補は同じL〜Gなので0回。
    控えに未提示が3件あっても渡す候補の中が0〜2件なら0回、3件で暦日も満たせば1回。予算で候補を落とした後の集合でも同じ
  - `selectCrystalCandidates` と断片の切り方 — 同じノートの重複、直近順、6件の上限、文の区切りへの寄せ、区切りの無い長文
  - `crystalsForNote` — 根拠に含むものだけ、新しい順、3件で打ち切り
  - `CrystalJson` — 往復、checksum 不一致・未知の版・16KB超をその1件だけ飛ばすこと
  - `CrystalController` の**両方向** — 門番待ち・要約待ち・生成中にノートを切り替えると書かず数えない／
    生成中に Vault を切り替えると新しい Vault に書かない／走行フラグが残らない
  - **保存の途中で止める**（→ 判断9）。偽 Store を**書き込みの開始後・完了前**で止め、実スレッドで交錯させる
    （単一スレッドのスケジューラではこの交錯を作れない → [L49](../lessons/L49.md)）。
    同じ Vault でノートを切り替えてから解放すると、保存した1件が再起動なしで一覧に**1回だけ**出る／
    Vault を A→B、A→B→A と切り替えてから解放すると、B へは書かず B の一覧にも出ない。A へ戻った後の一覧は A の実ファイルと一致する／
    保存が失敗したら一覧に足さない／保存を依頼する前の取消（生成中を含む）では保存0件／
    一覧の読込中に保存が終わっても、読み込みの完了後に1回だけ出る
  - `NoteSessionCoordinator` — ノート切替で一覧は残り、絞り込みのパスは消えること。Vault切替では両方消えること
  - **再会カードとの順序**（→ 判断10）。要約を保存済みにして、再会カードの訪問の保存待ちか解析を3秒より後まで止める。
    結晶の試す条件を満たしていても先に錠を取らず、止めを解くとカードの生成が先に走る／
    逆向き（カードの生成中に結晶が待つ）／カードの無い経路・保存済みで済んだカード・生成が失敗したカードの後では結晶が進む／
    待っている間にノートを切り替えると、両方の旧い要求が残らない／照合は結晶が待ち始める前に要求されていること
  - 痕跡の索引・孤児掃除・退避・読み戻しの下見が `crystals/` を無視すること（→ 判断7）
  - 走査キャッシュ — Aの走査を止めたままBへ切り替え、Bの後にAが返っても、キャッシュ・開けるパス・分野の索引はBのまま。
    A→B→A でも最初のAの走査が今の走査を上書きしない（`NoteScanCacheTest`）
  - `PromptBudgetTest` / `PromptIndentationTest` / `PromptGenerationCoverageTest` に12本目を足す
- **instrumentation:** `PromptTokenBudgetTest` に結晶の最大構成（6件・断片240字・ノート名200字）を足した。
  実機（Pixel 10 Pro Fold）の余裕は日本語・英語の2プロファイルで 1,894／1,972 トークン（上限4,352・出力予約256）。
  `OnDeviceGenerationTest` に結晶を1件足し、実Nanoの応答を本番のパーサへ通した結果を logcat へ出す（形の一致は assert しない）
- **実機確認:** ケースは [結晶の実機ケース](../../review/device_validation/reflect_crystal.md)（`CRYSTAL-01`〜`07`）。
  初回生成・保存・✨と一覧・根拠のノートへの遷移・同じ日の2回目を試さないこと・実SAFの A→B→A・実Nanoの応答を確かめた
- **保証していないこと:**
  - **結晶の中身の正しさ。** 要約に無いことを書かない・本人の考えとして語らない、はプロンプトで頼んでいるだけで、機械では検査していない。
    根拠の断片を並べて、読む人が検算できるようにしている
  - 3秒だけ見たノートも材料に入る（→ 判断4）
  - 関連ノートのAI推薦と分野判定より先に錠を取ることはある（→ 判断10）
  - 他の端末が作った結晶は、次に Vault を選んだときかアプリを起動し直したときに見える。その場では届かない
  - 根拠のノート名は作った時点のもの。改名・移動したノートは一覧から押せなくなる
  - **切替前に始まった走査が遅れて返る瞬間は、実機で観測していない。** アプリはローカルの Vault を読む前提で走査が速く、
    遅い置き場（Google ドライブ等）は前提の外なので、実機での再現は求めない（2026-09-29、オーナー判断）。判定は `NoteScanCacheTest` が固定する
  - Nano 非対応端末で何も出ないこと・保存の途中での切替は、実機で確かめていない（JVMの `CrystalControllerTest`・`CrystalSaveInterleavingTest` が見る）

## 11. 既知の制約・未解決事項

- **余白メモを材料に足す時期は決めていない。** いまの Vault には、メモを書ける版で読まれた記録がまだ無い。
  溜まってきたらオーナーが決める。**足すときは「本人の言葉」と「読んだものの要約」を分けて渡し、総括の主語を混ぜない**
- **読書痕跡の退避と復元に結晶は載らない。** 退避の形式の版を上げる作業になるので、最初の版では入れない。
  結晶は Vault に置くので、Vault が残る限り失われない
- **一覧の読み込みは件数に比例する。** 1日1件なら年に約365件。遅さが体感できたら、端末内に索引を持つ
- **結晶を消す・直す導線が無い。** 実機で困ったら足す
- **文言は実機で見て決め直す。** 見出し・入口・「〇〇・△△ から」・一覧の見出し
