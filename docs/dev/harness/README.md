## 1. コミット前のゲート

**CLAUDE.md の「コード変更後は必ずゲートを通してからコミットする」を、Claude のコミットについて機械が照らす。**
PR の CI だけでは、失敗を含むコミットがブランチに混ざっても PR まで気づけない。
実際に、ゲートとコミットを `;` でつないで、テストの失敗を含むコミットを作ったことがある（push の前に直した）。

| 部品 | 役割 |
|---|---|
| `.claude/gate/gate.sh` | ゲート（`testDebugUnitTest lintDebug --offline`、引数で Gradle のタスクを足せる）を流す。**成功したときだけ**、文書を除く作業ツリーのハッシュを通過の記録として残す |
| `.claude/gate/pre_commit_hook.sh` | Claude Code の PreToolUse（Bash）。`git commit` を含むコマンドなら、作業ツリーのハッシュと記録を照らし、合わなければ終了コード 2 で止めて理由を Claude へ返す |
| `.claude/gate/lib.sh` | 「コード」の定義とハッシュの取り方。両方が同じものを読む |
| `.claude/settings.json` | フックの登録。追跡するので、このリポジトリで動く Claude Code すべてに効く |

### 1.1 契約

- **照らすのは作業ツリー全体と索引の両方である。** 作業ツリーのコードが記録と一致し、索引のコードが作業ツリーと一致したときだけ通す。
  ゲートが見たのは作業ツリーなので、作業ツリーだけを照らすと、作業ファイルと違う内容をステージして
  作業ファイルを戻すだけで、ゲートを通していないコードがコミットに入る
- **`git add` は単独のコマンドで流す。** 同じコマンドの中で `git add` すると、フックの時点では索引が揃っていないので止まる。
  ステージしていないコードの変更や未追跡のコードが残っていても止まる。
  コードの書きかけを残したまま文書だけをコミットしたいときは、コードの変更を退避する
- **コマンドを走らせる前に照らす。** ゲートとコミットを `;` や `&&` でつないでも、ゲートはまだ走っていないので止まる
- **照らすのはコミットする worktree である。** `git -C <道>` は解いて（空白を含むパスの引用符も外す）、その worktree の記録と照らす。
  記録は worktree ごとに分かれているので、呼び出し元の記録を別の worktree へ流用しない。
  コミットより前の `cd`・`pushd`、`GIT_DIR` などの環境変数、`--git-dir`・`--work-tree`、変数や展開の入った `-C` は、
  対象を決められないので、変更の有無にかかわらず止める。対象の worktree を作業ディレクトリにして単独で流す
- **コマンドの文字列だけを見る。** 引用符や heredoc の中に `git commit` と書いてあっても当たる（`bash -c "git commit"` も当たる）。
  コードの変更が残っている間にその語を含む文書を Bash で書くと止まるので、文書は編集の道具で書く
- **文書だけの変更は止めない。** 文書は `docs/`・最上位の `*.md`・`.claude/skills/` で、ゲートの後に足しても記録は無効にならない。
  `docs/` はテストの入力なので、止めると変更履歴を1行足すたびにテストが走り直す。
  最上位以外の `*.md`（`androidTest` の資料など）はコードとして数える
- **未追跡のファイルも数える。** `.gitignore` の外にある新しいファイルはコードの変更である。無視されるファイルは数えない
- **ゲートを始めた時点で前の記録を消す。** 失敗・中断・実行中のコード変更では記録が残らない
- **記録は git ディレクトリの中に置く。** 追跡されず、worktree ごとに分かれる

### 1.2 防げないもの

- ゲートが見ていない不具合（実機でしか出ないもの、`assembleDebugAndroidTest` を足し忘れた androidTest の破損）
- Claude 以外が作るコミット（オーナーの手作業・Codex）
- `git commit` を経ないコミット（`git commit-tree` など）。照合の形は `pre_commit_hook.sh` の正規表現が持つ
- パスを指定したコミット（`git commit <パス>`）。索引と作業ツリーが揃っていても、入るのはその一部なので、
  ゲートが見た組み合わせと違うことがある
- 同じコマンドの中で、照らした後にコードを書き換えてからコミットする形
- 列挙した形の外で作業ディレクトリを変える手段（`env` のオプション、スクリプトの中のコミットなど）。
  シェルの構文と Git のオプションを網羅して解いてはいない
- フックを読み込んでいないセッション。設定はセッションの開始時に読まれる

### 1.3 検査

`CommitGateHookTest` が一時のリポジトリに偽の `gradlew` を置き、本物のスクリプトを走らせる。
止まる形（記録なし・ゲート後のコード変更・失敗・つないだコマンド・未追跡のコード・作業ツリーと違う索引・
`git -C` で頼んだ別の worktree の未検証のコード・対象を決められない形）と、
止まらない形（文書だけ・ゲート後の文書・コミット以外のコマンド）、フックの登録、CLAUDE.md の手順を固定する。
スクリプトとフックの登録は Gradle のテスト入力に足してある — 文書と同じく、既定ではテストの入力に数えられないため。
テストは UTF-8 のロケールで流す。macOS の bash 3.2 は UTF-8 のとき `$after）` の全角文字を変数名の続きと読むので、
全角文字に隣り合う変数は `${after}` と囲む。

## 2. 手順の置き場（Skill）

**ひと続きで行う作業手順は `.claude/skills/<名前>/SKILL.md` に置く。** CLAUDE.md は毎回読み込まれる憲法なので、
原則・禁止事項・完了条件だけを持ち、手順はその場面が来たときに Skill として読む。

| 置き場 | 持つもの |
|---|---|
| CLAUDE.md | 常に効かせる原則・禁止事項・完了条件 |
| `docs/dev/` | 判断と理由。この文書もここにある |
| `.claude/skills/` | ひと続きの手順。規則の正本へリンクし、**順序だけ**を持つ |
| [device_validation](../../review/device_validation/README.md) | 実機検証の手順。端末とリポジトリを一体で扱い、Codex も読むので例外としてここに置く |

- **完了条件は Skill へ移さない。** Skill は場面が来たときにしか読まれないので、毎回効かせたい条件を移すと、読まれなかったときに黙って抜ける
- **Skill に規則の写しを置かない。** 写すと2箇所のどちらかが古くなる。規則は正本へリンクする
- **Skill の名前は CLAUDE.md から「Skill `名前`」の形で名指す。** 名指しが実在するかを検査が見る

| Skill | いつ使うか |
|---|---|
| Skill `fetch-branch` | オーナーに「フェッチして」と言われたとき |
| Skill `review-intake` | 外部レビューを受け取り、対応に着手する前 |
| Skill `review-loop` | 実装をコミットしてゲートを通した後、Codex のレビューと修正を往復するとき |

### 2.1 検査

`ProjectSkillShapeTest` が、各 Skill の `name` がフォルダ名と同じで `description` があること、
Skill の中のリンクが実在すること、CLAUDE.md とこの文書が名指す Skill が実在することを固定する。
Skill `review-intake` については、一覧への転記・受付簿の検査・本文の削除と再検査の順序も固定する。
受付簿の検査は本文のファイル名が一覧にあるかも見るので、転記より先に流すと手順どおりの受付が必ず落ちる。
ただし固定するのは手順の文の並びまでで、受付を実際にその順で行ったかは見ない。

## 3. レビューの往復

**Claude が Codex をコマンドで呼び、レビューと修正を往復する。** P1・P2 が0件になるか、同じシリーズで3回に達したら止めてオーナーへ渡す。
以前はオーナーが Claude の差分と観点を Codex へ渡し、結果を Claude へ伝えていた。判断の要らない受け渡しにも手が要り、
オーナーが離れている間は往復が止まった。**試行中**で、続けるかはオーナーが記録を見て決める（→ §3.4）。

**変えていないもの:** 完了の線を引くのはオーナーである（→ [L64](../lessons.md#l64-検証の限界をそのまま完了条件にしない)）。
実装した側は自分の diff を判定せず、サブエージェントで代えない。レビュー本文は `docs/review/` に置き、受付簿の検査に載せる。

| 部品 | 役割 |
|---|---|
| `.claude/review/codex_review.sh` | 1回分のレビューを頼む。プロンプトを組み、`codex exec` を流し、最後のメッセージを本文として `docs/review/<日付>-<シリーズ>-r<回>.md` に置く |
| Skill `review-loop` | 往復の順序。観点の書き方、受付、直す・止める・渡すの分かれ目 |
| `.git/vigilith-review/<シリーズ>` | シリーズの回数・閉じたか・前回見た HEAD・前回の本文のファイル名・次に判定させる指摘・前回残った指摘・堂々巡りで止めたか。追跡しない |
| `.git/vigilith-review/log.tsv` | 1回ごとの時刻・範囲・モデル・推論の強さ・秒数・トークン・P1〜P3 の件数・前回の残りの件数・終了コード。試行の記録の材料 |

### 3.1 契約（スクリプトが機械的に守るもの）

- **同じシリーズは最大3回。** 4回目は Codex を呼ぶ前に断る
- **新しい P1・P2 が0件で、前回までの P1・P2 も残っていない回でシリーズを閉じる。** 閉じたシリーズは断る。
  新しい指摘は本文の `### P1-1.` の形の見出しで数える。前回までの指摘は §1 の表の判定の列（`解消`・`部分解消`・`未解消`）で読み、
  `解消` 以外と読めない行を残りとして数える。レビュアーには判定が変わらない指摘を §2 へ再掲しないよう頼んでいるので、
  見出しだけを数えると、直っていない指摘が残ったまま「0件」で閉じる
- **§1 で同じ指摘が2回続けて未解消か部分解消と判定されたら、回数が残っていても断る**（堂々巡り）
- **前の本文が `docs/review/` に残っていたら断る。** 受付と転記を済ませないまま次の本文を置くと、本文は最大1本の規則が崩れる
- **追跡しているファイルに未コミットの変更があれば断る。** レビューの対象はコミットした状態に限る
- **Codex が追跡しているファイルを変えたら、本文を残したまま終了コード 5 で止まる。** Codex は製品コードを変えない。
  コミットや checkout で HEAD を動かした場合も同じに扱う（差分が空になるので、作業ツリーだけを見ると見逃す）。
  Codex が失敗した回でも、変えたことのほうを先に知らせる。
  未追跡の残し物（一時のテストなど）は知らせるだけで消さない
- **Codex が失敗したら回数に数えず、本文も残さない**
- **2回目からは、前回見た HEAD から今の HEAD までを、前回の受付行と合わせて判定させる。**
  受付ID は本文のファイル名全体から作るので（→ Skill `review-intake`）、前回の受付行は状態に残した前回の本文のファイル名で名指す。
  頼み直す日の日付から組み直すと、日をまたいだ再レビューで一致しなくなる

### 3.2 Codex の実行環境

`codex exec` を `workspace-write` のサンドボックスで流し、`~/.gradle` と `~/.android` への書き込みと、サンドボックス内のネットワークを開ける。
Gradle はロックの調停にローカルのソケットを使うので、ネットワークを閉じたままだとテストを1本も流せない（2026-11-07 実測）。
読み取り専用にしないのは、Codex がこれまでのレビューで一時のテストを書いて反例を作り、それが指摘の根拠になってきたため。
**モデルと推論の強さは毎回指定する。** 1回目は `gpt-6-astra` の `xhigh`、修正後の再レビューは同じモデルの `high` で、
オーナーがアプリで使い分けてきた形に合わせた（2026-11-07、オーナー判断）。`~/.codex/config.toml` はアプリと共有で、
既定は実機検証用の `gpt-6.1-sol`・`medium` なので、指定しないとレビューが弱いモデルで走る。共有の既定は変えない。
使ったモデルと推論の強さは `log.tsv` に残る。

**実機検証は CLI に載せず、アプリで回す**（2026-11-07、オーナー判断）。Fold を開く・閉じる、端末をつなぐ・外す、
端末設定の変更を許可するといった物理の操作と判断にオーナーが要るので、CLI にしても中継は外れない。
外せるのは、オーナーの手が要らないレビューの中継である。

### 3.3 防げないもの

- Codex の判定の誤り。見落としも、誤った指摘もありうる。完了の線をオーナーが引くのはこのため
- Codex のトークン切れ。失敗は数えないが、2回続いたら止める（Skill `review-loop` の6）
- 同じ指摘の堂々巡りのうち、§1 で判定されないもの。スクリプトが見るのは §1 の判定の列だけで、
  言い換えて §2 に新しい指摘として出し直された指摘は同じものと見分けられない（Skill `review-loop` の6で止める）

### 3.4 試行の記録

試行の間は、往復を1つ終えるたびに [experiments/](experiments/) へ1本ずつ記録を置く。
書くのは、何を変えたか、各回の結果、かかった時間とトークン、人の手が要った場面。続けるか戻すかは、記録を見てオーナーが決める。

### 3.5 検査

`CodexReviewScriptTest` が一時のリポジトリで本物のスクリプトを走らせ、`codex` を偽物に差し替えて §3.1 の各項を固定する。
