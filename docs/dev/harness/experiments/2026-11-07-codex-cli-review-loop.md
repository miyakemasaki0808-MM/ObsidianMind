## 人の手が要った場面

- **往復の間は無かった。** 3回の依頼・受付・修正・再依頼を、オーナーの中継なしで回した
- 上限の3回目で P1・P2 が残ったので、決まりどおり直さずにオーナーへ渡した（続けるか、直し方をどうするかの判断が要る）

## 分かったこと

- **中継が外れることは確かめられた。** 本文が `docs/review/` に置かれ、受付簿の検査に載る形も保たれた
- **指摘の質は、アプリ経由と見分けがつかない水準だった。** 一時テストで反例を作って根拠にし、Claude の修正が入れた回帰を2回とも捕まえた
- **同じ形の問題が回をまたいで細かくなる場面では、3回の上限が先に来る。** frontmatter の一覧のように、手で書いた解析を直すたびに次の形が見つかる問題は、束2のコマンドの文字列の解析と同じ型だった。この型は、直し方そのもの（解析を手で書くか、範囲を絞るか、別の手段に替えるか）をオーナーと決める必要がある
- 続けるか戻すかの判断はオーナーが書く
