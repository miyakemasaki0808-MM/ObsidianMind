## 変えたこと

過去の修正コミットを過去問にして Claude Code（`claude -p`、Opus）に解かせ、その修正で足したテストで採点する足場を置いた（§4）。
本番の問題数を決める前に、1回あたりの時間とトークンを測るため、3題を2つの条件で1回ずつ解かせた。
比べた仕組みは CLAUDE.md の有無（オーナー判断）。

| 題 | 修正 | 中身 |
|---|---|---|
| `trace11-match-controls` | `06532701` | 照らし直しの整え方に U+001C〜U+001F が残る |
| `ai5-frontmatter-null` | `71adebaf` | frontmatter の引用符なしの null をタグや別名として読む |
| `ai6-zero-padded` | `82d5ed5b` | 0で埋めた開始番号1の箇条の中の引用を見落とす |

## 比べ方

同じ題を、親コミットのまま（`as-is`）と CLAUDE.md を外した状態（`no-claude-md`）で1回ずつ解かせた。
各条件1回なので、差がばらつきか効き目かは言えない。

**解かせた場所に欠陥が2つあり、比べた結果は割り引いて読む必要がある**（どちらも直した → 「分かったこと」）。

- 書き出したリポジトリに履歴が無く、設計文書が名指すコミットの実在を確かめる `AdrShapeTest` が、解く前から落ちていた
- `no-claude-md` は CLAUDE.md のファイルを消したので、それを読む文書の検査がさらに落ちていた（解く側の報告では、単体テスト全体で18件）

## 時間とトークン

`claude -p` の JSON 出力（`modelUsage`）から。トークンは入力・出力・キャッシュの作成・キャッシュの読み出しの合計。費用は CLI が出す API 料金での換算で、実際はオーナーの Pro プランの利用枠から出た。

| 条件 | 平均の秒 | 平均のトークン | 平均の費用 | 平均のターン |
|---|---|---|---|---|
| as-is | 218 | 936,112 | $0.66 | 25.3 |
| no-claude-md | 134 | 467,266 | $0.41 | 18.7 |
| 6回の計 | 1,054 | 4,210,132 | $3.21 | |

- トークンの92〜96%はキャッシュの読み出しで、出力は1回あたり4,500〜8,200
- 実時間のうちモデルの応答は約4割で、残りは Gradle のテストとゲートだった
- 6回の間に利用上限には当たらなかった

## 分かったこと

- **合格率では2つの条件を見分けられなかった。** 課題文が求める振る舞いを具体的に書いており、直す箇所も1〜5行だった。
  本番では、このリポジトリの規約（契約2箇所への登録、取り消しの再送出、要求の世代の照合など）を守らないと隠しテストが落ちる修正を選ぶ必要がある
- **CLAUDE.md ありは、トークンが約2倍だった。** 増えた分は主に、ゲートを流すことと変更履歴・設計書の更新に使われた。
  これは隠しテストでは測れないので、合否のほかに、何を触ったか（変更履歴・設計書・ゲート）を数える必要がある。
  1回ごとの差分は `.git/vigilith-eval/runs/` に残すようにした
- **解かせる場所は、解く前に既存のテストがすべて通っていなければならない。** 落ちていると、解く側は無関係な失敗の調査にターンを使い、条件の差に混ざる。
  直した点は3つ:
  - 書き出したリポジトリに、親とその祖先の履歴を持たせた（修正より後の履歴は持たない）
  - CLAUDE.md はファイルを消さず、CLI の設定（`CLAUDE_CODE_DISABLE_CLAUDE_MDS`）で読ませないようにした
  - `check` で、親で既存のテストがすべて通ることも確かめるようにした
- 本番の規模の目安: 10題を2条件で1回ずつ流すと20回で、この平均なら約1,400万トークン（換算 約$11）、約1時間
- 続けるか、本番の規模をどうするかはオーナーが決める
