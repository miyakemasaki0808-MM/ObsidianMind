# L31. 件数は「そろそろやるべきか」のトリガーにならない

**教訓:** 件数は**作った量**であって、**困っている度合い**ではない。
「N件を超えたら面倒になるはず」という**予測**を閾値に埋め込んでいるだけで、
実際に面倒になったかは何も語らない。しかも閾値は**必ずいつか超える**ので、
発火そのものが「やるべき理由」に見えてしまう。

**いつ当てるか:** 再検討の条件を書きたくなったとき。
**それが観測なのか予測なのかを先に問う。** 代わりに置くのは実害か状況の変化 —

- 実行忘れで**実害が一度出た**
- 開発者が**複数人になった**
- 頻度が上がって**明確に苦痛になった**
- **配布のゲート**が要るようになった

いずれも「起きたかどうか」を後から確認でき、予測を含まない。
