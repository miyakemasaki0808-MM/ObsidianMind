# L56. **1つの受け入れ条件を複数の状態で満たすなら、寿命を揃える**

**いつ当てるか:** 「◯◯すると△△が残る」という条件を、2つ以上の状態で実現するとき
**検査:** [`BookletNavigationTest`](../../../app/src/androidTest/java/com/example/newproject/ui/BookletNavigationTest.kt)（往復を実NavHostで通す）

---

冊子の受け入れ条件は「**戻れば同じ10枚が同じページ位置で残る**」だった。これを

- **束** → `NoteUiState`（Vault単位。ノート切替でも消えない）
- **ページ位置** → 画面ローカルの `rememberPagerState`

の2箇所で満たしていた。机上では両方とも「残る」と説明でき、テストも通った。
**実機では束だけが残り、ページ位置は1枚目へ戻った。**

**1つの条件を2つの寿命で持つと、短いほうが条件を決める。** しかも失われるのは
条件の一部だけなので、**壊れ方が半端で気づきにくい**（束は正しく残っているので
「残っている」ようにも見える）。

**直し方は、置き場所を短いほうへ合わせるのではなく、条件と同じ寿命の場所へ集めること。**
ページ位置を束と同じ `BookletState.Open` へ移すと、引き直し・Vault切替・プロセス復元で
**束と一緒に消える**ことまで自動的に揃う。

**書くときの手順:** 受け入れ条件を1つ選び、**それを構成する状態を全部数え、寿命を並べて書く。**
1つでも違えば、そこが壊れる場所である。
