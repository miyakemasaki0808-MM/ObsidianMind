# L19. 設計書に「処方」だけ書くと、効果の見積もりが検証されないまま残る

**教訓:** 設計書には処方（何をするか）に加えて、**効果の検算（それで何が変わるか）を1つ書く。**
検算が書けないなら、その処方はまだ効果を測っていない。

**いつ当てるか:** 設計書に「〜すべき」と書いたとき。
**「これで何が書けるようになるか」を具体的に1件挙げる。**

**再発の証拠:**
- **2026-08-01** — `model` から `Uri` を追い出す設計で「不透明化してもテスト容易性は1ミリも上がらない。
  controller の引数から消すべき」と書いた。結論は正しかったが**理由が誤りで、処方の範囲が足りていなかった。**
  着手前に測ると、Vaultスコープの経路をJVMで検証できない壁は**3つ**あった —
  ①`vaultUri(): Uri?` が非nullで要る ②`NoteRepository` が具象クラス ③全公開メソッドが `ContentResolver` を取る。
  **処方が崩すのは1つ目だけで、そのとおりに実装しても新しく書けるテストは0件**だった。
  3つ同時に外して初めて21件書けた → [saf_boundary_gateway](../system/saf_boundary_gateway.md)
