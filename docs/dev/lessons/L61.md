# L61. **前提を共有した検査は、前提ごと間違える。** 符号の*意味*は値では観測できない

**いつ当てるか:** 符号・向き・順序など、**値そのものではなく値の解釈**が正しさを決めるとき
**検査:** `BookletSheetPerspectiveTest`（描いた画素を数える）

---

冊子の紙は「上端を蝶番に、下端が手前へ持ち上がる」。`sheetAngleDegrees` は負の角度を返し、
KDoc・設計書・27件のJVM検査がそろって「**負なら手前**」と書いていた。**全部が同じ思い込みを写していた。**

実機では逆で、**紙は下端が細くなって束の中へ沈んでいた**（2026-09-05 の実機レビュー `P2-1`）。
27件は1件も落ちない。**検査は前提を固定しただけで、前提そのものは一度も確かめていなかった。**

## 向きは2つの事実の積で、片方は値に現れない

| 何を | どこで確かめられるか |
|---|---|
| 正の角度が蝶番より下の点を +Z へ送る | **値。** Compose の `Matrix.rotateX` の実装を観測できる |
| **+Z が画面の手前である** | **画素。** 描いて幅を測るまで、どこにも現れない |

前者だけを検査して「向きを固定した」と書いたのが誤りだった。
**同じ形は `sheetShowsFace`（表裏）にもあった** — 符号を共有しているので、一緒に裏返っていた。

## 当て方

- **「この符号はどちらが手前／先／上か」を検査が答えているか**を問う。答えていなければ、その検査は*一貫性*しか見ていない
- **解釈を外から持ってくる。** 自分で書いた定数と比べるのではなく、**SDKの実装**か**描いた結果**を観測する
- **描画・向き・順序は、1本だけ画素か実測を見る検査を置く。** 値の検査を何十本足しても代わりにならない
