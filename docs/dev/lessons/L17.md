# L17. 「ゲートに載せる」か「黙らせる」かの二択に見えたら、選択肢を数え直す

**教訓:** 二択に見えるのは、たいてい**強度の軸を2値だと思い込んでいるとき**。
仕組みの側が中間の強度を用意していることがある。Lint の severity は
`error` / `warning` / `informational` / `ignore` の4段階で、`informational`（hint）は
`warningsAsErrors` の昇格対象にならない — **「落とさないが、見えている」**が最初から存在していた。

**いつ当てるか:** 「有効/無効」「載せる/外す」「手動/自動」で考え始めたとき。
**強度の軸と時間の軸の両方**を疑う（「今は A、条件を満たしたら B」は片方を選ぶより強いことが多い）。

**扱いは指摘の出どころで変える。**

| 種類 | 終わりが来るか | 扱い |
|---|---|---|
| 自分のコードの欠陥（未使用変数・コントラスト不足） | **来る**（直せば消える） | ゲートに載せる |
| 外界の変化（上流が新版を出した） | **来ない**（次の版がまた出る） | **報告だけさせる** |

後者をゲートに載せると、こちらが1行も触っていないのにある日赤くなり、CIの赤から意味が失われる。
かといって消せば催促も消える（下記 2026-07-31 の吸収分）。

**再発の証拠:**
- **2026-07-31（1度目・強度の軸）** — Lint警告0のために依存更新系3チェックを `disable` にしたら、
  黙らせた瞬間から誰も更新を促さなくなった。**抑制は「やらない」ではなく「いつやるか決める」とセット**にしないと静かな放置に変わる。
  なお理由と代替案をコード内へ書いた抑制（`@Suppress` にコメント）はこの型に当たらない —
  **抑制の理由が読める場所に残っているか**が分かれ目。※旧 L15 を統合した
- **2026-08-01（2度目・時間の軸）** — 読書痕跡の孤児掃除で「手動か自動か」で詰まり、
  「判定が信用できないから手動しかない」と結論。見落としていたのは
  **「今は手動、実績が出たら自動」という段階の軸**だった
  → [reflect_reading_trace](../features/reflect_reading_trace.md)（孤児掃除）
