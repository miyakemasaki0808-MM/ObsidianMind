# L41. 単位を細かく割ると、その値を読む既存箇所が古い単位のまま取り残される

**いつ当てるか:** 候補・状態・表示の**単位を細かく割った**（1件が複数件になる変更）

---

蒸留の候補を「文」から「句」「語句」へ割った1機能の中で、**同じ形の欠陥が3度**出た。

| 取り残された読み手 | 症状 | 正しい単位 |
|---|---|---|
| 入力上限（160字） | 句長で判定するため、読点のある超過文だけが分割後に復活した | 親文 |
| 候補カードの文脈欄 | 直前候補の `text` を読むため、直前が分割文だと最後の句へ縮んだ | 親文 |
| 画面の文言と状態名 | 「N文を太字にします」のまま、句・語句を「文」と説明した | 単位に依存しない語 |

**3度とも既存テストは緑のまま通り抜け、3度とも実機レビューが見つけた。**
新しい単位と既存の読み手が**交差する入力**を通していなかったため
（超過文テストは読点が無く句へ割れない、文脈テストは「割れた句自身」の片側だけ、など）。

**割る側の実装は正しく書けている。落ちるのは常に「その値を読む側」である。**
分割そのものに気を取られ、読み手を数え直さない。

**対策は、割った直後にその値を読む箇所を列挙し、演算ごとに親と子のどちらを使うか決めること。**
関数名ではなく**その型を読む全箇所**で引く（→ [L14](../lessons.md#l14)）。
**文言と名前も読み手に含める** — 型では守れないので走査へ載せる。

**検査:** `DistillCandidateUnitCopyTest`（文言のみ。値の単位はレビューで拾う）
