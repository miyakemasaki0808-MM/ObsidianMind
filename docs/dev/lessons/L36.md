# L36. 防御的パースは全分岐で対称にする。緩くしすぎると別種の誤りを生む

**教訓:** 片方の分岐だけ「崩れた出力」を許容し、もう片方を完全一致にすると、
**同じモデルの同じ崩れ方で片方だけ落ちる。**
守ろうとしている相手（＝指示に完全には従わない小型モデル）は分岐を選ばない。

**同時に、緩くしすぎると別種の誤りを生む。** 単純な文字包含は自由文の中の文字を誤検出する。
**境界（`\b`／トークン単位）を持たせて「意図した1つ」だけを取る。**

**いつ当てるか:** AI応答のパースを書く／緩めるとき。
**正常系で動くことを合格にせず、モデルが崩す代表パターン**（末尾記号・括弧・余計な語・前置き）
**を必ずテストに入れる。**

**再発の証拠:**
- **2026-07-22** — ○×・3択・4択の適応出題でエラーを減らした直後の版で、**多択だけ**が
  「Q&Aの生成結果を読み取れませんでした。」で失敗した。○×パスは末尾記号除去＋同義語許容と
  防御的だったのに、多択パスは `indexOf(answer.trim().uppercase())` の**完全一致のまま**で、
  `ANSWER: B.` `ANSWER: (B)` `ANSWER: B) 選択肢文` が全部落ちていた。
  **「クイズ生成エラーを減らす」という当初の狙いを、非対称が自ら削いでいた**
- **同件・実装中の自己修正** — 初版の救済策 `firstOrNull { it in 'A'..'D' }` は
  `The answer is B` で先頭の `ANSWER` の **A を拾い、不正解を正解扱いする silent bug** を生む。
  **パース失敗（エラー）より悪い**ため、単語境界 `\b[A-$maxLabel]\b` へ切り替えた
