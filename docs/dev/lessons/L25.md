# L25. 「網羅テストがある」と「そのフィールドが網羅されている」は別

**教訓:** リフレクションで「全部見る」テストは、**フィクスチャ側にも同じ数だけ足さないと
初期値と初期値を突き合わせるだけ**になる。登録が正しくても間違っても通る。
**「網羅している」という設計意図は、網羅の材料が揃って初めて実現する。**

**いつ当てるか:** 契約テストへ新しいフィールド／項目を足したとき。
足した直後に**変異を1回当てる**（→ [L11](../lessons.md#l11-テストが効いているかは変異させて確かめる)）。

**同じ構造は系統図・一覧・チェックリストにも現れる。**
共通するのは、**更新すべき場所が「書いてある場所」と一致しない**こと —
フィクスチャは契約テストの中に、系統図は設計書の中に、再掲表は憲法の中にある。
**「ここを直せ」と書いてある文書自体が、直す場所を全部数えているとは限らない。**
コピーが1つでもあるなら、**コピー元に「コピーがある」と書く。**
