# L25. 「網羅テストがある」と「そのフィールドが網羅されている」は別

**教訓:** **「ここを直せ」と書いてある文書や検査自体が、直す場所を全部数えているとは限らない。**
更新すべき場所が「書いてある場所」と一致しない — フィクスチャは契約テストの中に、
系統図は設計書の中に、再掲表は憲法の中にある。
コピーが1つでもあるなら、**コピー元に「コピーがある」と書く。**

**いつ当てるか:** 契約テスト・一覧・系統図へ項目を足したとき。
足した直後に**変異を1回当てる**（→ [L11](../lessons.md#l11-テストが効いているかは変異させて確かめる)）。

**再発の形（4例）:**
- 全欄を見るリセット検査が、フィクスチャへ欄を足さなかったので新しい欄を素通りした
  （入力そのものの検査は [L46](L46.md) と、そこが案内するテストの KDoc が持つ）
- Controller の系統図が追加のときに更新されず、件数が古いまま残った。
  **「機能追加の定型」に数えていない場所は、定型を守っても漏れる**
- `document_map` §5 の逆引き表が CLAUDE.md にも再掲されていることがどこにも書かれず、片方にだけ載った
- 実機確認を終えたのに課題台帳の本文末尾だけを直し、一覧・見出し・`roadmap` が古いまま残った

**検査:** `WipIssueReferenceTest`（`_wip/` の課題IDが台帳に実在する — 4例目の一番痛い形だけを数える）
