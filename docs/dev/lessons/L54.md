# L54. **原状回復より先に、実データへ再進入しない終了地点を探す**

**いつ当てるか:** 実データを持つ環境を検証に使う手順を書いたとき／後処理に「元へ戻す」を置いたとき
**検査:** —（手順の正本は [device_validation](../../review/device_validation/README.md)）

---

実機検証の共通手順は「一時Vaultで検証し、元Vaultへ戻す」だった。ところがVaultを選び直す操作は
必ず `loadRandomNote()` を呼ぶので、**戻すたびに読書痕跡と履歴が増える**。
X-11の検証では、元Vaultのノート3件に訪問が1件ずつ増えた。

**「元へ戻す」は、戻す操作自体に副作用が無いことを暗黙の前提にしている。**
前提が崩れると、原状回復を丁寧にやるほど元データを汚す。開始前にバイト基準線を取って
復元する案もあったが、**復元にも元データを書き換える許可が要る**ので権限境界と両立しなかった。

**解いた形は「戻さない」だった。** 常設の検証用Vaultを開始・終了地点に固定し、元Vaultへ再進入しない。
**回復の精度を上げるのではなく、回復が要らない地点を選ぶ。**

**「元へ戻した」の判定は、画面ではなく永続面の集合で行う。** 今回は画面もVault選択も戻っていた。
増えていたのはサイドカーとアプリ設定で、**見ていた面には出なかった**。

**当て方:** 手順へ「元へ戻す」を書く前に、**その操作が何を書くか**を数える。1つでも書くなら、
戻さずに済む終了地点（専用領域・破棄可能データ）を先に探す。
通常操作が元データを変える型は [L43](L43.md) と同じで、これが2度目である。
