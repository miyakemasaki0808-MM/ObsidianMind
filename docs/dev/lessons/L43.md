# L43. 破壊性はコマンド名ではなく、実際のinstall/uninstall境界で判断する

**いつ当てるか:** 実データのある実機で、ビルドツールのタスクを走らせるとき。

---

X-4の実機検証で `connectedDebugAndroidTest` を使ったところ、22件を成功させた後に
**対象アプリ本体までアンインストールし、アプリデータを消した**。実機検証の権限範囲は
「`adb install -r`（アプリデータを維持する上書き）」までで、アンインストールは
**明示的に範囲外**と書いてあったが、**タスク名が「テストを実行する」としか言っていない**ため
読み取り側の操作として扱われた。

**「読み取りに見えるコマンド」を許可範囲の判定に使わない。** 判定材料はタスク名ではなく、
そのタスクが実際に踏む install / uninstall / clear の境界である。同じ形は
`gradlew clean`・`pm clear`・キャッシュ削除つきの再ビルドにもある。

Vault内のファイルは無傷で、失ったのはアプリ内設定と履歴だった。
**被害が小さかったのは対象の性質による偶然**で、判断の誤りとは独立している。

**恒久手順の正本は [device_validation/README](../../review/device_validation/README.md)。**
実機では `assembleDebugAndroidTest` までをGradleで行い、対象APKとtest APKを
`adb install -r` したうえで `am instrument` を直接実行する。connectedタスクは
破棄前提のエミュレータに限定する。
