# L32. 「自分を評価する」と宣言した仕組みは、評価する規則自体が守られない

**2026-08-10、旧 §0「diffができたら当てる5問」を廃止した記録。**

**教訓:** 仕組みに自分の廃止条件を書いても、**その判定を実行する規則もまた規則である**。
検査に載っていなければ、判定は行われない。**旧 §0 は「3回で評価し、2回目・3回目も同じ結果なら廃止を検討」と
自ら書きながら、17件のコード変更が走るあいだ一度も判定されなかった。**
[L29](L29.md)「規則は検査へ変えるまで守られない」が、**L29 から作られた仕組み自身に当たった。**

**いつ当てるか:** 「様子を見て後で判断する」「N回試して駄目なら見直す」と書きたくなったとき。
**その判定を誰がいつ実行するのかを、同じコミットで検査に載せる。** 載せられないなら、
その見直しは**行われない**前提で設計する。

**経緯:**

| 日付 | できごと |
|---|---|
| 2026-08-02 | §0 導入。「次の3回のコード変更で評価する」と宣言 |
| 2026-08-05 | **1回目の判定＝発火しなかった。** 画像表示で毎回当てて報告に1行残したのに、外部レビューのP1「確保した高さを成功経路へ渡していない」は問4がそのまま当たる形だった。**当てたつもりで当たっていなかった** |
| 2026-08-06〜09 | **17件の変更。2回目・3回目の判定は一度も記録されず** |
| 2026-08-10 | 文書の再編中に期限超過が発覚し、宣言どおり**廃止** |

**廃止の決め手は3つ。**

1. **1回目の判定が「発火しなかった」で、その後改善する手が打たれていない。**
   §0 自身が「文書を足すことを主な対策にしない」と書いていたのに、対策は文書のままだった
2. **文書だけの変更をすり抜ける。** [L29](L29.md) が2026-08-05に記録した
   「自分の変更に見えない作業では発火しない」がそのまま残っており、
   **2026-08-10 の change_history 圧縮・roadmap 削除でも `§0適用` が残されなかった**（3度目）
3. **5問のうち検査へ移せるものは既に移っている。** 問1はコンパイラ（sealed の網羅 `when`）、
   問2・問3は変異確認の運用、問4・問5は grep。**文書の表として並べる価値が残っていなかった**

**代わりに置いたもの:** [lessons.md](../lessons.md) の索引に **「検査」列**を設けた。
検査を持つ教訓と持たない教訓を**同じ見出しで並べない** — 前者は規約、後者は参考である。
[L29](L29.md) の実績（守られたのは検査に載せたときだけ）を、索引の形として毎回見えるようにした。
