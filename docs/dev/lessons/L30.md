# L30. 失敗が「赤」ではなく「件数の減少」として出ると、誰も気づけない

**教訓:** **期待していた件数が出ていないことは、期待値を持っていない限り分からない。**
これまでの気づけなさは「落ちるテストが無い」（[L11](../lessons.md#l11-テストが効いているかは変異させて確かめる)）や
「検査が一度も走らない」（[L29](L29.md)）だったが、
今回は**検査は走っており、赤も出ている**。それでも消えた件数はどこにも数えられない。

**いつ当てるか:** テストを足したとき。**足した数だけ増えたかを見る。**
緑/赤ではなく件数で確かめる。合わなければ、走らなかったものがある。

**再発の証拠:**
- **2026-08-08** — instrumentation を4件足して実機で走らせたら**そのクラスが1件も起動していなかった。**
  見え方は **「1 failed, 30 passed」** — 失敗1件に見え、**消えた3件はどこにも数えられない。**
  原因は JUnit4 の `@Test` が `void` を要求すること。Kotlin の `fun x() = runBlocking { ... }` は
  **ブロック末尾の式の型がそのまま戻り値になる**ので、末尾を `Log.i()`（`Int` を返す）にした
  1メソッドだけが `void` でなくなり、`InvalidTestClassError` で**クラス全件が起動しなかった**

**構造上の対処:** 「末尾に値を返す式を置かない」は規約にできない（1行足すだけで破れ、破れたことが見えない）。
**書き方のほうを縛る** — 式本体の `runBlocking` は `runBlocking<Unit>` にする。
**コンパイルが通ることは、テストが起動することを意味しない。**

**検査:** `InstrumentationTestShapeTest`（ソース走査で固定）
