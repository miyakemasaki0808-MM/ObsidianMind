# L48. 不可逆操作の承認は、**見せた瞬間と書く直前の状態を突き合わせて**初めて意味を持つ

**いつ当てるか:** 「実行前に内容を確認させる」画面を作るとき
**検査:** `ReadingTraceBackupControllerTest`（下見のあとに端末側が変わったら最初の確定では書かない）

---

痕跡の読み戻しは、下見（何件増え、どの返事が失われるか）を見せてから確定させる設計にした。
確定時には**端末側を読み直す**ところまで作ってあった — 下見と確定のあいだに
訪問が書き出されうるので、古い値で上書きしないためである。

**そこで止まっていたのが穴だった。** 読み直しても、**下見との差を照合していなかった**。
下見で「失われる返事はありません」と見せた後に同じノートへ返事が保存されると、
確定は規則どおりマージし、**利用者が承認していない損失**が起きる。
読み直しは*訪問を守る*ためのもので、*承認を守る*ものではなかった。

**「最新の値で処理する」と「見せた内容を実行する」は別の要求である。** 前者だけを満たすと、
確認画面は「実行前に一度止まる」以上の意味を持たなくなる。

**当て方:** 確認画面を作ったら、**見せた材料そのものを保持し、書く直前に突き合わせる。**
差があれば1件も書かずに作り直して出し直す。このとき **「まだ何も書いていない」を先に伝える** —
二度目の確認を求められた利用者が最初に知りたいのは、押した操作がどこまで進んだのかである。
**件数ではなく中身で比べる**（件数が同じでも別のものが変わっていれば承認内容ではない）。
