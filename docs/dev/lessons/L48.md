# L48. 不可逆操作の承認は、**見せた瞬間と書く直前の状態を突き合わせて**初めて意味を持つ

**いつ当てるか:** 「実行前に内容を確認させる」画面を作るとき
**検査:** `ReadingTraceBackupControllerTest`（下見のあとに端末側が変わったら最初の確定では書かない）。
確定時の読み直しだけでは承認を守れない理由と、件数ではなく中身で照合する理由は、このテストの KDoc が持つ

---

**「最新の値で処理する」と「見せた内容を実行する」は別の要求である。** 前者だけを満たすと、
確認画面は「実行前に一度止まる」以上の意味を持たなくなる。

**当て方:** 確認画面を作ったら、**見せた材料そのものを保持し、書く直前に中身で突き合わせる。**
差があれば1件も書かずに作り直して出し直し、**「まだ何も書いていない」を先に伝える**。
二度目の確認を求められた利用者が最初に知りたいのは、押した操作がどこまで進んだのかである。

読み戻しの規則（メモは両方を残して合流する）は [reading_trace_backup](../features/reading_trace_backup.md) が持つ。
