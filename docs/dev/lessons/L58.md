# L58. **中間状態は届くとは限らない — 契機を「通ったか」に置かない**

**いつ当てるか:** 状態の**移り変わり**を検出して何かを始めようとしたとき（演出・通知・記録の起動）
**検査:** [`BookletRestackTest`](../../../app/src/test/java/com/example/newproject/BookletRestackTest.kt)（同期と遅延の引き直しを対で通す）。
キャッシュで `Loading` が届かなかった経緯と、1回の操作につき最終状態だけを渡す理由は、このテストの KDoc が持つ

---

**`StateFlow` も Compose の状態も、保持するのは最新の値だけである。** 途中の値は「速く通り過ぎれば無かったのと同じ」で、
**中間状態はイベントではない。** 冊子の積み直りを「`Loading` を観測したか」で決めていたため、
キャッシュが同期で返る通常経路では演出が一度も出なかった。

**症状の場所を塞ぐと、同型が別の入口から出る。** 実装中に初回だけ再生が揺れることに気づき、初回を抑止して直ったつもりになったが、
原因は中間状態への依存だったので、引き直し側に同じ形が残った。

**解き方は、最終状態だけで見分けられるようにすること。** 単調増加のID（世代）を状態へ載せれば、
待ちの有無に関係なく「別のものが届いた」と言える。**中身の比較では代用できない** — 引き直した束が同じ並びになることがある。
検査は**同期完了と遅延完了を対で書く**。片方だけなら、どちらの実装でも緑になる。

**2度目（同じ機能の中で）:** 再生の判定を世代へ直した後も、ページャの位置合わせは `Loading` で画面から一度外れることを当てにしていた。
**中間状態に依存している箇所は機能ごとに1つとは限らない。** 演出・位置・寿命は別々に依存しうるので、
直すときは**同じ経路を使う状態を全部数える**（→ [L14](../lessons.md#l14-横展開は最後の1本を取り残す)）。
