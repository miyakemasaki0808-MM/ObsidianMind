# L58. **中間状態は届くとは限らない — 契機を「通ったか」に置かない**

**いつ当てるか:** 状態の**移り変わり**を検出して何かを始めようとしたとき（演出・通知・記録の起動）
**検査:** [`BookletRestackTest`](../../../app/src/test/java/com/example/newproject/BookletRestackTest.kt)

---

冊子の積み直り（新しい束が届いたときの演出）を、**「`Loading` を観測したか」**で決めていた。
ノート一覧が60秒キャッシュから同期で返ると、`Loading` は次の `Open` に上書きされ、
**購読側には一度も届かない。** つまり**キャッシュが効いている通常経路では演出が出なかった。**

**`StateFlow` も Compose の状態も、保持するのは最新の値だけである。**
途中の値は「速く通り過ぎれば無かったのと同じ」で、**中間状態はイベントではない。**

**同じ根に一度気づきながら、対症で止めていた。** 実装中に「初回だけ再生されたりされなかったりする」
ことに気づき、**初回を抑止して直ったつもりになった。** 非決定性の原因は初回であることではなく
**中間状態に依存していること**だったので、引き直し側に同じ形がそのまま残った。
**症状の場所を塞ぐと、同型が別の入口から出る。**

**解き方は、最終状態だけで見分けられるようにすること。** 単調増加のID（世代）を状態へ載せれば、
待ちの有無に関係なく「別のものが届いた」と言える。
**中身の比較では代用できない** — 引き直した束が同じ並びになることが実際にある。

**検査は同期完了と遅延完了を対で書く。** 片方だけなら、どちらの実装でも緑になる。

**関連:** [L11](../lessons.md#l11-テストが効いているかは変異させて確かめる)（変異させて確かめる）・[L56](L56.md)（1つの条件を複数の状態で満たすなら寿命を揃える）

## 2度目（2026-09-03、同じ機能の中で）— **直したのは判定だけだった**

世代で再生を決める形に直した後も、**ページャの位置合わせは中間状態に依存したまま**だった。
`rememberPagerState` は `Loading` で画面から一度外れることを当てにしており、
その `Loading` が届かない引き直しでは、**束は新しいのに旧い終端のページが残った。**

**同じ経路（`Open → Open`）で観測が必要なものを、1つしか数えていなかった**
（→ [L14](../lessons.md#l14-横展開は最後の1本を取り残す)）。
**「中間状態に依存している箇所」は機能ごとに1つとは限らない。** 演出・位置・寿命は別々に依存しうるので、
直すときは**同じ経路を使う状態を全部数える。**
