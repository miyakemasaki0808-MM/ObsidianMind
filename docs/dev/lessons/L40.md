# L40. 改名した型は、正本の機能仕様まで同じPRで当て直す

**いつ当てるか:** 状態・列挙の値を改名／削除するとき
**検査:** `DesignDocStateNameTest`（`features/` `system/` が、実在しない値や消した名前を現役のように書かない）
**正本:** 状態の名前と意味は [background_ai_ux](../system/background_ai_ux.md) §6。
検査の対象と対象外、消した名前の一覧、歴史として書くときの形は検査の KDoc が持つ

---

**コンパイラが挙げる範囲を、直すべき範囲だと思わない。** コードの改名は全箇所がコンパイルエラーになるが、文書は何も言わない。
2026-08-12 の `AiAvailability` の改名では、独立レビューに3回続けて正本のずれを指摘された。

**検査を置いたら、指摘された実例で本当に落ちるかを確かめる。** 2回目に入れた検査は書いた時点で緑だったが、
それは修飾つきの名前しか見ず、指摘された箇所を1つも数えていなかったからだった。

**当て方:** 改名・削除したら、消した名前を検査の一覧へ足す（足し忘れは検査できない）。
`owner/` は検査の対象外のままにする。更新はオーナーの依頼のときだけである（→ [owner/README](../../owner/README.md)）。
