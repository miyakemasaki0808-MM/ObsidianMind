# L34. AIが混入させるバグは「通常フローでは表面化しない」。型ごとに検証の勘所が違う

**教訓:** 最新モデルが混入させる潜在バグには3つの型があり、**共通DNAは「通常フローでは表面化しない」こと。**
だから**「通常フローで動く」を合格にしてはいけない。**

| 型 | 何が起きるか | 検証の勘所 |
|---|---|---|
| **(A) 状態遷移型** | 別画面へ遷移して戻る／折り畳む・展開すると**ボタンが無反応**になる | **遷移をまたいだ後**に主要導線を1回叩く |
| **(B) 応答解釈型** | AIの出力が正常系から崩れると解釈が破綻する | **モデルが崩す代表パターン**（末尾記号・括弧・余計な語・前置き）をテストに入れる → [L36](L36.md) |
| **(C) 並行状態型** | 確認した値と使う値がズレ、**稀なタイミングでだけ別の対象へ書く** | **外部の可変状態を何回読んでいるか**を数える。2回以上なら間で変わる前提で読む → [L26](L26.md) |

**いつ当てるか:** AIが書いたdiffをレビューするとき。型を決めてから、上表の勘所を当てる。

**(A) の発火条件が独特。** 「別画面へ遷移して戻る」とセッション**生存中に**画面が再生成され、
そこで固定されたクロージャが悪い状態を抱き込む。`android:configChanges` の無いActivityでは
**Fold開閉・回転も再生成**を伴うので、状態遷移バグの検証項目に必ず入れる。
対処は `rememberUpdatedState`（→ CLAUDE.md 禁止事項）。

**再発の証拠 — 旧 `bugfix_reports.md` の4件（2026-08-10 に本カードへ統合し、同文書は廃止）:**

| # | 症状 | 型 | 混入者 | 発見者 |
|---|---|---|---|---|
| 1 | 吹き出しタップが完全無反応（stale closure）。クイズ画面へ遷移して戻ると発火 | A | Claude Fable 5 | **ユーザー** |
| 2 | ✕もバックも無反応で全画面を解除できない。Fold開閉で発火 → [L35](L35.md) | A | Claude Opus | **ユーザー** |
| 3 | 多択クイズだけ「読み取れません」で失敗 → [L36](L36.md) | B | Codex | Claude（レビュー） |
| 4 | 旧ノートの痕跡が切替後の新Vaultへ書かれる → [L26](L26.md)・[L6](../lessons.md#l6-修正の主張は修正コードを別の目で読むまで確定させない) | C | Claude Opus | Codex（レビュー） |

**混入は Fable 5・Opus・Codex と横断的で、特定モデルの癖ではない。**
**発見は「ユーザーが踏む」2件と「別モデルのレビュー」2件で、自己レビューによる発見はゼロ。**
これが CLAUDE.md の「**別の目は、実装したのとは別のモデル／エージェントがdiffをレビューすること**」の実証データである。

**(C) には固有の危うさがある** — 対策を入れた本人（＝AI）が「解消済み」と書けてしまう。
方針が正しいと、実装が効いていなくても文書・コミットメッセージは通る（→ [L6](../lessons.md#l6-修正の主張は修正コードを別の目で読むまで確定させない)）。
