# L37: 文書の誤りを直すとき、直した先で新しい誤りを作る

**当てるとき:** 実装と食い違う記述を見つけて、書き直そうとしている。

## 何が起きたか

「ひとことの結果はAIタブのパネルへ直接出る」という記述が実装と逆だった。
**訂正の1回目は「起点と結果が同じ画面で閉じるから」と書いたが、これも誤りだった** —
生成開始時にノートタブへ自動で戻るので、閉じていない。**同じ箇所を2度間違えた。**

## なぜ起きたか

1回目の訂正で確かめたのは**「結果がどこに出るか」だけ**だった。
`RemarkPanel` がボタン1つであることは確認したが、**そこから先の導線**
（生成開始 → ノートタブへ戻る → Snackbar で呼び戻す）を追っていない。

**誤りの周りには、その誤りを支えていた説明が必ず付いている。**
記述を1行直しても、**その記述が理由になっていた判断は古いまま残る。**

## どうするか

- **訂正するときは、その記述に依存している文まで読む。** 1行の事実ではなく、
  その事実が支えている判断ごと当て直す
- **同じ誤りは1箇所で終わらない。** 今回は文書2本＋ソースのKDoc2箇所へ伝播していた。
  訂正したら**同じ文言をリポジトリ全体で検索する**
- **判定軸そのものを疑う。** 2度間違えたのは、軸（結果がどこに出るか）が
  実際の分かれ目（後から辿り着けるか）とずれていたため
