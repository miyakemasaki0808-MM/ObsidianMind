# L18. 段階移行の単位は「型の大きさ」ではなく「同じ変換関数に手が届く範囲」で切る

**教訓:** 移行の単位を決めるのはサイズではない。見るべきは
①その型がどの層で組み立てられるか ②その層は変換関数に手が届くか、の2つ。
**手が届かない層で組み立てられる型どうしは、同時に移すしかない。**
「小さいところから」は安全に見えるが、**小ささは移行の独立性を意味しない。**

**いつ当てるか:** 型の置き換えを段階に分ける段取りを引くとき。
着手前に、型ごとの構築箇所を層で塗り分けると単位が自然に決まる。

**再発の証拠:**
- **2026-08-01** — `model` から `android.net.Uri` を追い出すとき「最小の型から順に」で段取りを組み、
  1段目で詰まった。`ui` が `HistoryEntry` から `RelatedNote` を作り `domain` が `NoteFile` から作るため、
  片方だけ新型にすると新旧の変換が要る。ところが変換関数は `data` にあり、
  `ui` と `domain` は依存規約上 `data` を import できない。
  **「変換を境界に閉じる」という設計判断そのものが部分移行を禁じていた。**
  3型を同時に移すと変換は1つも要らず、正しい単位は最初から「3型まとめて」だった
