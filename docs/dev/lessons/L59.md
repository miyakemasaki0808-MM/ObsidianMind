# L59. **実装から書いた受け入れ条件は、実装が狙いを外していることを検出できない**

**いつ当てるか:** 見え方・体感の受け入れ条件を書いたとき（とくに**実装した後に**書いたとき）
**検査:** なし（**参考**。条件の書きぶりなので機械では判定できない）

---

冊子の「繰る手触り」に、送っている最中だけ紙が2%縮んで影が深くなる演出を入れた。
実機ケース `BOOK-31`〜`BOOK-40` を書き、**10件すべて成功した**。倍率1での追従、TalkBackのカスタム操作、
倍率0で指追従だけが残ること、積み直りの再生条件 — **書いてあることはすべて出ていた。**

**それでもオーナーの体感は「思ってたのとなんか違う」だった。**

ケースは*実装した演出が出ているか*を書いていて、*繰れているか*を書いていなかった。
**「紙がわずかに縮んで影が深くなる」は実装の記述で、「めくった感じがする」は狙いの記述である。**
前者だけを並べると、**実装が狙いを外していても全件が緑になる。**

## なぜ起きるか

受け入れ条件を**実装の後に**書くと、目の前にある挙動をそのまま条件に写してしまう。
写した条件は必ず通る。**通ることが分かっている条件は、何も検証していない。**

## 当て方

- **狙いの言葉で1件書いてから、実装の言葉のケースを足す。** 冊子なら「10枚を通しでめくって、
  紙をめくった感じがするか」が先で、角度や影はその内訳である
- **「このケースが全部通っても狙いを外しうるか」を自分に問う。** 外しうるなら、外し方を書いたケースが足りない
- **仕様の分岐を決めるケースには、そう書いておく**（→ [booklet_mode](../features/booklet_mode.md) の `BOOK-45`）。
  判定の場所が決まっていれば、緊張は消えなくても迷子にならない

**値で観測できるものは実機へ預けない**（→ [L53](L53.md)）。今回も*向き*はJVMへ引き出せた —
実機に残すのは**重さ・速さ・気持ちよさ**だけでよい。**預ける範囲が広いほど、この失敗は起きやすい。**
