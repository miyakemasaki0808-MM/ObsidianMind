# L53. **実機でしか走らないテストは、効いているかを確かめる機会が端末のあるときに限られる**

**いつ当てるか:** 描画・レイアウト・タップの契約を `androidTest` で守ろうとしたとき
**検査:** `DistillRangeHighlightTest`・`DistillRangeNoticeTest`（JVMへ引き出した観測点）

---

太字範囲の調整シートは「確定範囲を太字＋下線で示す（色だけの手がかりにしない）」を契約に持ち、
`androidTest` で親文が表示されることを見ていた。**強調を丸ごと外してもこのテストは緑のまま通る。**
テスト名とコメントには太字と書いてあり、**主張だけが検査の顔をしていた**（外部レビューで発見）。

根は観測点の誤りだけではない。検査が効いていると言えるのは変異させて落としたときだけ
（→ [L11](../lessons.md#l11-テストが効いているかは変異させて確かめる)）だが、`androidTest` の変異確認は**端末をつないだときにしか回らない**。
机上ゲートも CI も `androidTest` を組み立てるだけで走らせないので、**実機側へ置いた契約は変異確認を省かれやすい。**
原理的にできないのではない — 冊子の紙の画素検査（`BookletSheetPerspectiveTest`）は、端末で切り抜きを落とす変異を当てて確かめている。

**当て方:** 実機テストへ契約を置く前に、**値として観測できる部分をJVMへ引き出す**。
調整シートでは `highlightedParent`（AnnotatedStringのspan）と `overlapNotice`（文言の主語）を
`internal` の純関数にし、JVM側で変異確認した。実機側には「そのspanが実際に描かれる」ことだけを残す。

**残すものと引き出すものの線引き:** 実測（レイアウト・可視判定・再コンポーズ・タップの届き先・画素）は実機に残す。
**値の組み立ては引き出す。** 引き出せない契約は、端末で変異を当てない限り、効いているかが分からないまま残る。
