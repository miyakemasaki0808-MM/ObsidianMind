# L50. **外から見える契約は、外から見える形で検査する。** decode した意味は形の欠落を通す

**いつ当てるか:** アプリの管理外へ出すファイル形式・利用者へ見せる文言を決めたとき
**検査:** `ReadingTraceBackupJsonTest`（生のJSONに `documentId` のキーが1つも無い／
非退避ファイルは入力形式によらず同じ文言）

---

退避ファイルの契約は2つとも「外から見た形」で書かれていた —
**`documentId` がどこにも無いこと**と、**退避ファイルでないものを断る文言**。
どちらもJVMテストを持っていたが、**内部表現で書かれていた**ため実機まで残った。

- `documentId`: テストは decode した `trace.documentId` が null であることを見ていた。
  実装は値を null にしただけなので、生のJSONには `"documentId": null` が残る。
  **意味は満たし、形は満たしていない。**
- 拒否文言: テストは `Unusable` という**型**しか見ていなかった。
  非JSONは parse例外の枝、別形式は format照合の枝へ入り、
  同じ「選んだファイルが違う」に二通りの文言が出ていた。

**どちらも「テストがある」ことが安心の根拠になっていた。** 1,110件が緑のまま、
契約が要求している当のもの（生バイト列と画面の文字列）を誰も見ていなかった。

**当て方:** 受入条件が「外から見て何が見えるか」で書かれているなら、
検査もその粒度で書く — **生の文字列を検査し、文言は等値で比べる**。
型や復元後の値は、その手前の性質でしかない（→ [L25](L25.md)）。
