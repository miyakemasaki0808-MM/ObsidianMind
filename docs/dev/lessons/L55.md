# L55. **走査テストは呼び出しの存在しか見ない。受理条件は結果で書く**

**いつ当てるか:** ソースを文字列で走査するテストを、振る舞いの担保として置いたとき／変異を「その行を消す」で作ったとき／検査の受理条件を緩めたとき
**検査:** [`BookletRouteContractTest`](../../../app/src/test/java/com/example/newproject/architecture/BookletRouteContractTest.kt)（役割を構造だけに限定した例。同じ契約を結果で見るテストの対応表を KDoc に持つ）・[`BearingChannelTest`](../../../app/src/test/java/com/example/newproject/architecture/BearingChannelTest.kt)（走査対象と受理条件を狭めた例）。
具体的な代入箇所と引数の境界は、両テストが持つ

---

**走査が確かめられるのは「書いてあること」までで、「そう動くこと」ではない。** 同じ穴を4度、別の形で踏んだ。

| 回 | 走査が通したもの | 解き方 |
|---|---|---|
| 1（冊子ルートの3契約） | 呼び出し先を空にする・届かない分岐へ移す・順序を入れ替える | 観測できる場所まで境界を動かし、結果を見るテストを置いた |
| 2（面の形の役割） | 代入を戻しても、KDoc・import 行・別の面の代入に名前が残る | 受理条件を「名前がある」から「どの面のどの代入か」へ変え、走査対象を関数の本体へ絞った |
| 3（紙の引数） | 前方一致へ緩めた受理条件が、定数の後ろに条件を足した形を通した | 定数の直後が引数の区切り（`,` か `)`）であることまで見る |
| 4（見開きのめくり） | 「アプリが倍率を上書きしていない」は通ったまま、依存の内側が倍率を1に固定していた | 倍率0を注入し、途中のフレームを数える（→ [note_spread](../features/note_spread.md) 判断7） |

**当て方:**

- **観測対象:** 走査を置くときは、同じ契約を結果で見るテストがどこにあるかを KDoc へ書く。
  書けないなら、その契約は観測できる場所へ動かす合図である。**不在の走査は「自分が書いていない」までしか言えない**
- **最小の変異:** 変異は本番で起こりうる最小の形（1行の書き換えだけ）で作る。
  「その行を消す」と付随する import や兄弟の代入も一緒に消え、実際には空いている面を塞いだと錯覚する
- **緩めた範囲の明示:** 受理条件を緩めるときは、何を諦めたかをその場で言葉にする
  （「引数の総数」を諦めるつもりで、「定数であること」まで一緒に諦めていた）
