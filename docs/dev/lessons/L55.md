# L55. **走査テストは呼び出しの存在しか見ない。受理条件は結果で書く**

**いつ当てるか:** ソースを文字列で走査するテストを、振る舞いの担保として置いたとき
**検査:** [`BookletRouteContractTest`](../../../app/src/test/java/com/example/newproject/architecture/BookletRouteContractTest.kt)（役割を構造だけに限定した例）・[`BearingChannelTest`](../../../app/src/test/java/com/example/newproject/architecture/BearingChannelTest.kt)（走査対象と受理条件を狭めた例）

---

冊子ルートの3つの契約（読書時間を止める・読込中の要求を取り消す・本文を先頭から開く）は
`MainActivity` のルート定義にあり、**`NoteViewModel` が `AndroidViewModel` なので素のJVMから触れない**。
そこでソース走査で「その呼び出しが書いてあるか」を固定し、4通りの変異で落ちることまで確かめた。

**それでも保証にならなかった。** 呼び出し先の本体を空にする・到達しない分岐へ移す・
順序を入れ替える、のいずれも走査は通る。**変異確認をしても、変異させた場所が
「呼び出しの有無」だけなら、確かめたのは呼び出しの有無でしかない。**

**解いた形は、観測できる場所まで境界を動かすことだった。**

| 契約 | 動かした先 | 観測するもの |
|---|---|---|
| 読込の取り消し | `NoteSessionCoordinator`（JVMで組み立てられる） | 履歴・ノート状態・要約が始まらないこと |
| 先頭から開く | `openFromBooklet`（Composableの外の純粋な関数） | 実際の `LazyListState` の位置 |
| 読書時間の停止 | `ReadingTraceController`（停止理由つき） | fake clock で積算された時間 |

走査は残したが、**役割を「境界を通っているか」だけに書き下げた**。
**走査を置くときは、同じ契約を結果で見るテストがどこにあるかをKDocへ書く。**
書けないなら、その契約は観測できる場所へ動かす合図である。

## 2度目（2026-09-02）— **名前の在処が実装の証拠に化ける**

冊子の紙と本文パネルが「面の形の役割」を引いていることを走査で固定したが、
**同じ穴を3通りの形で踏んだ。** いずれも**ビルドが通ったまま検査も通る**。

| 名前が残った場所 | 見つかり方 |
|---|---|
| **KDoc** — 代入を直書きへ戻しても、説明文に役割名が残る | 自分の変異確認で発見 |
| **import 行** — 代入を戻しても import は残る。**Kotlin も Android Lint も未使用 import を報告しない** | **外部レビューが発見**（自分の変異確認は import ごと消していたので、この面が空いていた） |
| **別の面の代入** — 紙の形を戻しても、縁が同じ役割を引いているのでファイル全体では残る | import を落とした後も残っていた |

**教訓は「コメントを落とせ」ではない。** 落とす対象を1つずつ足しても、
名前が残りうる場所は次々に出てくる。**受理条件を「名前があること」から
「どの面の、どの代入・どの呼び出しか」へ変える**のが解き方だった
（走査対象を関数の本体へ絞った）。

**変異確認の作り方にも同じ穴があった。** 変異を「その行を消す」で作ると、
**付随する import や兄弟の代入も一緒に消してしまい、実際には空いている面を塞いだと錯覚する。**
変異は**本番で起こりうる最小の形**（＝1行の書き換えだけ）で作る。
