# L47. 不在を破壊的処理の根拠にするなら、**不在を返しうる全境界で「不能」と分ける**

**いつ当てるか:** 「見つからない」を根拠に、上書き・削除・新規作成を決めるとき
**検査:** `ReadingTraceBackupControllerTest`（端末側を読めない痕跡を新規扱いにしない／置き場を列挙できないときは読み戻さない）。
読取失敗の作り方と、保留・書き込み0件で観測する理由はテストの KDoc が持つ

---

痕跡の孤児掃除は、この規則を**一覧の境界**で守っていた（列挙できなかったことを `ReadingTraceKeyListing` の型で分ける）。
**それでも読み戻しは同じ穴を踏んだ。** 1件を読む境界（点読込）は例外を「無い」へ畳んだままで、
SAF の一時的な読取失敗で退避側を新規として丸ごと書き、**端末側のメモが警告も保留もなく消える**形になっていた。

**規則が適用済みに見えることが、見落としの原因になる。** 一覧側の型と KDoc が立派であるほど
「この論点は閉じている」と読めてしまう。**閉じているのは境界1つぶんである。**

**当て方:** 破壊的な分岐を書くとき、その判断材料が通ってきた境界を**すべて**列挙し、
どこかで「失敗」が「不在」に化けていないかを見る。片方だけ型で分かれていたら、
それは残りが未対応であることの合図であって、対応済みの証拠ではない（→ [L14](../lessons.md#l14-横展開は最後の1本を取り残す)）。
