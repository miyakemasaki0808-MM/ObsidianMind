# L51. **書き込み側の保護集合は、表示側の解釈集合から決める**

**いつ当てるか:** 本文へ記号を挿す処理を書いたとき／描画側が解釈するインライン記法を増やしたとき
**検査:** なし（**参考**）。蒸留の保護不足を直すときに、両者の集合を突き合わせる走査テストへ載せる

---

蒸留は原文へ `**` を挿す。壊さないための保護範囲は**コードスパンとリンク**で始まり、
そこで固定された。一方で描画側の `inlineMarkdown` は、その後も解釈できる記法を増やし、
いまは `*…*`・`***…***`・`~~…~~` も読む。**同じ文字列を2つの解釈器が別の規則で読んでいる。**

結果、装飾の内側で文・句が割れ、保存すると装飾の対応が変わった。
文字は1つも消えていないので、**「装飾記号の挿入のみ・既存文字を削除しない」という契約は満たしたまま壊れる。**

**片方だけを見て正しさを判断できない。** 保護集合の正しさは、書き込み側のコードをいくら読んでも決まらない。
決めているのは**読む側が何を構文と見なすか**である。

**当て方:** 本文へ記号を挿す処理の保護集合を書くときは、**その本文を解釈する側の一覧を先に開く**。
片方に記法を足したら、もう片方も同時に数え直す（→ [L14](../lessons.md#l14-横展開は最後の1本を取り残す)）。
**集合が一致していることを検査に載せるまで、規則としては数えない**（→ [L29](L29.md)）。
