# L51. **同じ文字列を2つが読むなら、解釈器を共有する**

**いつ当てるか:** 本文へ記号を挿す処理を書いたとき／描画側が解釈するインライン記法を増やしたとき
**検査:** `InlineSyntaxTest`（解釈規則）・`InlineMarkdownTest`（表示が同じ答えを使う）・`DistillSourceModelTest`（境界と保存）
**正本:** [reflect_distill](../features/reflect_distill.md) の「候補の対象と除外」

---

蒸留は原文へ `**` を挿す。壊さないための保護範囲は**コードスパンとリンク**で始まって固定され、
一方で表示側は解釈できる記法を増やし続けた。**同じ文字列を2つが別の規則で読んでいた。**
文字は1つも消えないので、**「装飾記号の挿入のみ」という契約を満たしたまま壊れる。**

**一覧を揃えるだけでは足りなかった。** 記法の種類を合わせた次のレビューで、
バッククォートの数え方・エスケープ・リンクの消費・ブロックの単位という解釈規則の食い違いが4件出た。
**一覧の同期をやめて、解釈器そのものを1つにした**（`domain/markdown/InlineSyntax.kt`）。

**当て方:** 本文へ記号を挿すなら、**その本文を解釈する側の関数を呼ぶ**。写して持つと次の追加でまたずれる
（→ [L14](../lessons.md#l14-横展開は最後の1本を取り残す)）。保護集合の正しさは書き込み側をいくら読んでも決まらず、
決めているのは**読む側が何を構文と見なすか**である。
**過剰保護は過小保護と同じ検査では捕まらない** — 守りすぎを見るテストは、
偽の対が文境界を飲み込む入力でないと効かない（→ [L11](../lessons.md#l11-テストが効いているかは変異させて確かめる)）。
