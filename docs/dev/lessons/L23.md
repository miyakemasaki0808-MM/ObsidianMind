# L23. 台帳に長く残った課題ほど、着手時には前提が古くなっている

**教訓:** 課題は**書かれた時点の情報**で書かれる。時間が経つとコードは変わらなくても
**周辺の理解が進み、測る手段が増える**。台帳の記述は書き直されないので、
**古い前提のまま優先度だけが積み上がる。**
「2回連続で指摘された」ことは前提の正しさを補強しない — **同じ古い前提を2回読んだだけ**である。

**いつ当てるか:** 台帳の課題に着手するとき。**まず前提そのものを測り直す。**
特に「規模感」「影響」「対応候補」は書かれた当時の推測であることが多い。
最初の30分を前提の検算に使うと、**施策ごと不要と分かることがある。**

**「変わらなかった」は必ず記録する。** 書き残さないと、次に同じ課題が新鮮な顔で立ち上がる。

**再発の証拠:**
- **2026-08-01** — AI-1（関連ノートの抜粋予算）は最優先の改善候補だったが、**前提が2つとも誤っていた** —
  ①注意書きが予算の38% → 実測**1.7%**（→ [L22](L22.md)）
  ②予算が小さいことが品質を抑えている → **600→800 にしても体感は変わらない**。
  結果、この課題は**対応候補として書かれていた施策を両方とも捨てる**形で閉じた
  → [ai_input_excerpt](../system/ai_input_excerpt.md)（予算調整）
