# L44. 出力を丸ごと固定する回帰テストは、誤った出力も同じ強さで固定する

**いつ当てるか:** 生成した文字列を**期待値ごと**比較するテストを書く／その期待値を更新する

---

プロンプトの `trimIndent()` は**補間後の文字列**に効くため、複数行の値を埋めると
テンプレート側の字下げ（12スペース）が全行に残っていた。実運用ではほぼ常に起きていた。

**回帰テストは11本のうち7本のプロンプトを文字列で固定しており、緑だった。**
そのうち**2本は、字下げが残った出力を期待値として書いていた**。

```kotlin
"            You are a study assistant. ...",   // ← 12スペースごと期待値になっていた
"Keep each statement within 50 characters ...", // ← 補間した値の2行目だけ字下げ無し
```

行ごとの `listOf(...).joinToString("\n")` という書き方が、**不揃いを不自然に見せなかった。**
`trimIndent()` の raw string で書いていれば、期待値の側が書けずに気づけた。

**なぜ他の5本が通ったか。** 値を**単一行**（`"本文"`）でしか渡していなかったため。
不具合は値が複数行のときだけ出る。**「どの入力で通したか」を書いていないテストは、
通していない入力について何も言っていない。**

**対策は2つ。**

1. **期待値は、出力の形を保つ書き方で書く**（raw string ＋ `trimIndent()`）。
   行の配列へ潰すと、人が読んで気づける不揃いが消える。
2. **値は形を変えて2通り渡す。** 長さではなく**形**（単一行/複数行・空/非空・1件/複数件）を振る。
   実際の欠陥は「長い値」ではなく「改行を含む値」で出た。

**検査:** `PromptIndentationTest`（全 builder を複数行の値で組み立て、静的な行が変わらないことを固定）
