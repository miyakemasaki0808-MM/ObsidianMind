# L44. 出力を丸ごと固定する回帰テストは、誤った出力も同じ強さで固定する

**いつ当てるか:** 生成した文字列を**期待値ごと**比較するテストを書く／その期待値を更新する
**検査:** `PromptIndentationTest`（全 builder を複数行の値で組み立て、字下げが漏れないことと静的な行が変わらないことを固定）。
`trimIndent()` が効かなかった原因と、既存の回帰テストが緑のまま通った理由は、この検査の KDoc が持つ

---

**期待値を出力から写すと、誤った出力がそのまま正解になる。** プロンプトの字下げ漏れでは、
文字列を固定していた回帰テストのうち2本が、字下げの残った出力を期待値に書いて緑だった。

**当て方は2つ。**

1. **期待値は出力の形を保つ書き方で書く**（raw string ＋ `trimIndent()`）。
   行の配列へ潰すと、人が読んで気づける不揃いが消える
2. **値は長さではなく形を振る**（単一行/複数行・空/非空・1件/複数件）。
   実際の欠陥は長い値ではなく、改行を含む値で出た。
   **「どの入力で通したか」を書いていないテストは、通していない入力について何も言っていない**
