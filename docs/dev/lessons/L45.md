# L45. 「必ず収まる」を保証する最後の砦は、何を残すべきかを知らない

**いつ当てるか:** 全経路へ効く**共通のクランプ・切り詰め・打ち切り**を1箇所に置いた
**検査:** `PromptBudgetTest`（どの入力でも上限を超えない／指示文と締めは残る／意図する最大構成では切り詰めが起きない／
結晶の候補は古い側から落ちて今のノートは残る）

---

完成プロンプトの上限を1箇所（`PromptBudget`）で強制したとき、長さの不変条件は全経路で緑だったのに、
**有効な入力が意味を壊された。** 当時の読書痕跡の俯瞰要約（いまは撤去済み）は訪問を古い順に並べていたので、
**末尾＝最新の訪問**が共通の切り詰めに当たり、最新の到達率だけが落ちた。

**共通の砦は「どこを削っても等価」を暗黙に仮定している。** 実際には経路ごとに「絶対に残す側」が違う
（会話なら直近の質問、結晶なら今のノート、ピッカーなら照合キーのタイトル）。**その知識は砦の側には無い。**

**対策は2段にする。**

1. **用途ごとの予算で、意味の単位（行・候補・往復）を保ったまま先に閉じる。**
   落とすなら**要らない側から丸ごと**落とし、切るなら**構造を壊さない部分だけ**を切る
2. **共通の砦は、そこへ到達したこと自体を異常とみなす。** 意図する最大構成で切り詰めが起きないことを固定する

**長さだけの検査では見えない。** 用途ごとに「残す側」を境界テストで固定する
（→ [L44](L44.md) と同じ形 — 検査が見ている性質が、守りたい性質より狭かった）。
