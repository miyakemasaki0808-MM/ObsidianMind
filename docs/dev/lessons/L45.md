# L45. 「必ず収まる」を保証する最後の砦は、何を残すべきかを知らない

**いつ当てるか:** 全経路へ効く**共通のクランプ・切り詰め・打ち切り**を1箇所に置いた

---

完成プロンプトの上限を1箇所（`PromptBudget`）で強制した。長さの不変条件としては正しく、
`PromptBudgetTest` は「どんな入力でも6,000字以内」を全11経路で緑にした。

**それでも、有効な入力が意味を壊された。** 読書痕跡の俯瞰要約は訪問を古い順に並べるので、
**末尾＝最新の訪問**が共通クランプに当たる。保存契約で許された512バイトの見出しが10件そろうと、

```
- stopped at section "SSS…SSS
(truncated)
```

となり、**閉じ引用符と `(100% of the note)` が消えた。**
「どこで止まりがちか」を答えるプロンプトで、最新の到達率だけが落ちる — 意味の逆転である。

**共通の砦は「どこを削っても等価」を暗黙に仮定している。** 実際には経路ごとに
「絶対に残す側」が違う（会話なら直近の質問、痕跡なら最新の到達率、ピッカーなら照合キーのタイトル）。
**その知識は砦の側には無い。**

**対策は2段にする。**

1. **用途ごとの予算で、意味の単位（行・候補・往復）を保ったまま先に閉じる。**
   落とすなら**要らない側から丸ごと**落とし、切るなら**構造を壊さない部分だけ**を切る。
2. **共通の砦は、そこへ到達したこと自体を異常とみなす。**
   `PromptBudgetTest` は「意図する最大構成で切り詰めが起きない」ことも固定している。

**長さだけの検査では見えない。** 6,000字以内は満たしていた。
**用途ごとに「残す側」を境界テストで固定する**（→ [L44](L44.md) と同じ形 — 検査が見ている性質が、
守りたい性質より狭かった）。

**検査:** `PromptBudgetTest`（最新行が完全な1行として残る／古い側から落ちる）
