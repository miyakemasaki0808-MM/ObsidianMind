# L20. 端末AIを呼ぶテストは、フォアグラウンドのActivityが前提条件そのもの

**教訓:** 端末AIのテストでは **Activity の有無が環境ではなく前提条件**である。
`ActivityScenarioRule` を定型に含める。あわせて、
**エラーメッセージの品質は経路ごとに違い、同じ原因が別の顔で出る。**

**いつ当てるか:** 端末AIを呼ぶ instrumentation を書くとき。
SDKのエラーコードが表に載っていないときは、メッセージだけを頼りに原因を決めない。

**再発の証拠:**
- **2026-08-01** — `countTokens()` が `[ErrorCode 10003] Tokenization failed` で落ちた。
  `FeatureStatus` は `AVAILABLE`、`baseModelName` は `nano-v3`、公式対応端末で生成は普段どおり動く。
  **材料だけ見ると「beta2 の計測APIが Android 17 と非互換」という読みになり**、
  実際に beta4 への更新（既定値 256→4096 の動作非互換を抱える重い変更）を検討しかけた。
  正解は **AICore がバックグラウンドからの利用を拒否していた**だけで、`ActivityScenarioRule` を足したら 6/6 緑

同じ「バックグラウンド拒否」が経路によって2通りに見えていた。

| 呼び出し | メッセージ |
|---|---|
| `generate()` / `warmup()` | `[ErrorCode 30] Background usage is blocked.`（原因を言う） |
| `countTokens()` | `[ErrorCode 10003] Tokenization failed.`（**原因を示さない**） |

**先に見たのが `countTokens()` だったせいで、計測API固有の不具合だと誤読した。**
