# L57. **製品判断を、適合必須の基準で補強しない**

**いつ当てるか:** 好みで決めた設計に「WCAG ◯.◯.◯ の対象になる」「規約上こうしないといけない」と理由を足したとき
**検査:** なし（**参考**。文言の性質なので機械では判定できない）

---

冊子の紙の背後に出す「縁」を、束の全10枚へ位置によらず出すと決めた。
理由として**「最後の1枚で縁が消えると残数を形で数えることになり、WCAG 1.4.1 の対象になる」**と書いた。

**1.4.1 は色だけで情報を伝えることを禁じる基準で、形はむしろその代替手段として挙げられている側**である。
形で残数を表すこと自体は 1.4.1 に触れない。**基準の適用対象を取り違えたまま正本化していた。**

**製品判断としては正しかった。** 形は「面の役割」を運ぶチャネルだと決めてあるので、
残数まで兼ねさせれば割り当てが崩れる — これだけで結論は変わらない。
**足した基準は、結論を1ミリも支えていなかった。**

## なぜ危ないか

| 起きること | 具体 |
|---|---|
| **議論が閉じる** | 好みなら「別の見せ方はどうか」と言えるが、適合必須だと言われると誰も反論しない |
| **基準の意味が壊れる** | 次に 1.4.1 を引く人が、色ではなく形の話だと思って読む |
| **本当の理由が失われる** | 補強のほうが強く見えるので、チャネル割り当てという実際の根拠が後ろへ下がる |

## 当て方

**「その基準を外しても結論は変わるか」を先に問う。** 変わらないなら、それは根拠ではなく飾りなので書かない。
変わるなら、**基準番号ではなく原文の適用対象**を確かめてから書く。

**好みは好みと書いてよい。** このリポジトリは
[ui_design_principles](../system/ui_design_principles.md) §2・§3 で
「このアプリの好み」を基準と分けて持っており、**分けてあることが両方を守っている。**
