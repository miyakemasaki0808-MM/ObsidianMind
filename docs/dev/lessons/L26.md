# L26. 非同期の要求は「今」を読み直さない。要求時点の対象を要求自身に持たせる

**教訓:**

1. **非同期操作が「対象スコープ」を必要とするなら、開始時に1つ取って最後まで使う。**
   途中でも次の操作でも読み直さない
2. **世代照合とスコープ固定は別物。** 世代は「走行中に無効化されたか」を見る。
   スコープ固定は「そもそもどれに対する要求か」を決める。**片方だけでは足りない**
3. **状態リセットを安全装置に数えない。** リセットを1つ書き忘れた瞬間に消える防御は防御ではない

**内容から導く識別子（ハッシュ・スラッグ・正規化名）は、スコープをまたぐと衝突する。**

**いつ当てるか:** 非同期処理が Vault／ノートなどのスコープを参照するとき。
「この要求は**どれに対する**ものか」を要求自身が持っているか確かめる。

**再発の証拠:**
- **2026-07-25（1度目・保存経路）** — 書き込み時点で `vaultUri()` を読み直すと、
  旧ノートの痕跡が切替後の新Vaultへ書かれる。要求時点のVault識別子を要求へ添えて運ぶ形にした（判断10）
- **2026-08-01（2度目・削除経路）** — 孤児の洗い出しと削除のあいだにVaultが切り替わると、
  削除時に `currentVaultKey()` を読み直す実装では**新Vaultへ旧Vaultの候補キーを適用**する。
  世代照合（`vaultGeneration`）は置いていたが、**それが見るのは「操作中の切替」だけで
  「操作と操作のあいだの切替」は見ない。**
  危険を跳ね上げたのは識別子が `sha256(相対パス)` だったこと —
  **別Vaultに同じ相対パスのノートがあればキーも一致する**
  → [reflect_reading_trace](../features/reflect_reading_trace.md)（孤児掃除）
