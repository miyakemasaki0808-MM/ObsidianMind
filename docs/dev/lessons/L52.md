# L52. **上限テストは、長さだけでなく処理対象の要素数も最大化する**

**いつ当てるか:** 入力サイズの上限を決めたとき／全文を走査する処理を足したとき
**検査:** `DistillSourceModelTest`（リンク密・既存太字密・装飾文密の最大サイズ入力）・
`DistillProtectedScanTest`（時間で捕まらない二乗の書き方をソース走査で禁じる）。
入力の作り方と閾値の根拠、時間ではなく形で縛る理由は、両テストのコメントが持つ

---

蒸留は 256KB の最大サイズ入力で一段目を計測していたが、中身は `x` の反復で**記法spanが1つも無かった**。
リンクが密な合法入力では段階1が 7.9秒かかっていたのを、上限テストが緑のまま通した。
**長さだけを最大化した入力は、長さに比例する経路しか踏まない。** 効いていたのは文字数ではなく記法の数だった。

**種類を増やしても足りなかった。** 次の巡では、リンク密・太字密の2本を持ちながら
「候補数×保護範囲数」の経路を両方とも通っていなかった。**掛け合わさる2つの量を同時に最大化する。**

**当て方:** 上限を決めたら、**その上限の中で「処理対象の要素」が最大になる入力**を別に作る。
種類ごとに通る経路が違うので1本にまとめない。**閾値が置けないほど差が小さい経路は、時間ではなく形で縛る。**
