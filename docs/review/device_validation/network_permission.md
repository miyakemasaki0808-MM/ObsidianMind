# ネットワーク権限除去の実機検証ケース

## 正本

- 権限を持たない判断: [ADR-0002](../../dev/decisions/ADR-0002-on-device-ai-only.md)
- 除去の方法・検査・安全と見た根拠: [dependency_policy](../../dev/system/dependency_policy.md) 判断5
- 共通の準備と後処理: [Codex実機検証手順](README.md)

## 適用条件

`AndroidManifest.xml` の権限・`app/build.gradle.kts` の依存を触ったときに使う。

**机上では代えが利かない。** マージ後マニフェストに権限が無いことは
`verify<Variant>ManifestPermissions` が保証するが、
**権限を失った状態でML Kitが動くか**は端末でしか分からない。
計測の送信経路（`Uploader`）が `ConnectivityManager` を呼ぶことは確認済みで、
**例外がログに落ちるだけだという見立てを確かめるのがこのケースの目的**である。

**release APKは対象外。** 未署名で実機に入れられず、署名方針も未決である。
release 成果物の権限は `verifyReleaseManifestPermissions` が静的に見ているので、
ここで見るのは debug のランタイム挙動だけでよい。

## 検証前

- **Vaultの状態に依存しない。** 常設検証用Vaultのままでよく、一時領域も fixture も要らない。
- **モデル未DLの端末が1台要る**（`PERM-02` のため）。既にDL済みの端末しか無い場合は
  `PERM-02` を「対象外」と記録し、他を実施する。**DLをやり直させるために端末設定を触らない。**
  これは端末が無いときの妥協ではなく方針である（2026-09-12・オーナー判断）。
  [background_ai_ux](background_ai_ux.md) の「ダウンロード済みモデルは検証のために削除しない」と同じ線で、
  **未DL状態は作りにいかず、契機（端末初期化・2台目の入手）が来たときに消化する。**
- 上書きインストールの前に、旧版の権限を数えておく。**差は2件とは限らない** —
  マニフェストで除いたのは2件だが、**端末の要求権限では3件減ることがある**
  （OSが足す分。→ `PERM-01`）。**合否に使うのは差ではなく、新版が2件になること。**

  ```text
  adb -s <serial> shell dumpsys package com.vigilith.ai | grep -A20 "requested permissions"
  ```

- logcat をクリアしてから始める。`PERM-04` は「出ていないこと」を見るため。

  ```text
  adb -s <serial> logcat -c
  ```

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `PERM-01` | 新しいAPKを `adb install -r` し、**上書き前後**の要求権限を数える | 新版は `BIND_SERVICE` と `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` の**2件だけ**。設定→アプリ→権限に「インターネット」が出ない。**旧版との差は3件になりうる** — 2026-09-12 の実機では、除いた2件に加えて `ACCESS_LOCAL_NETWORK` も消えた（マニフェストには無く、OSが足していた分） |
| `PERM-02` | モデル未DLの端末でAI機能を開き、DLを最後まで走らせる | **完走する**。進捗が止まらない（DLはAICoreアプリが行うので権限の影響を受けないはず） |
| `PERM-03` | AI 9経路を一巡する（要約・補記・クイズ・関連ノート・セクションチャット・蒸留・読書痕跡・検索ピッカー・分野判定） | **すべて従来どおり結果が出る**。失敗表示・無応答・待ち時間の悪化が無い |
| `PERM-04` | `PERM-03` の直後にアプリを前面のまま5分放置し、続けて背面で5分置く | **クラッシュしない**。`SecurityException` がlogcatに出ること自体は許容する（`TransportRuntime` の計測がログに落ちるのは想定どおり） |
| `PERM-05` | 端末を機内モードにして `PERM-03` から3経路を選び直す | 機内モードでも**同じ結果が出る**。オンデバイス生成が外部接続に依存していないことの確認 |

**`PERM-04` が本体である。** 権限を失った計測経路がアプリを巻き込まないかは、ここでしか分からない。
落ちる場合はプロセスごと死ぬので、**アプリが消えたら不合格**と判定できる。

**`PERM-01` も机上の検査の焼き直しではない。** `verify<Variant>ManifestPermissions` が見るのは
マージ後マニフェストまでで、**OSがインストール時に足す分は入っていない**
（2026-09-12 の `ACCESS_LOCAL_NETWORK` が実例）。端末に入った後の要求権限はここでしか数えられない。

**`PERM-04` で不合格なら、`ACCESS_NETWORK_STATE` だけ戻す。**
ユーザーに見える権限は `INTERNET` のほうで、ADR-0002 が守りたい線もそちらにある。
2件を1つの塊として扱わない。

## 後処理

- 一時領域を作らないケースなので、Vaultの後始末は無い。**常設検証用Vaultのまま終える。**
- test APK を入れた場合のみアンインストールする。対象アプリ本体には触れない。
- logcat の抜粋を取った場合は、**端末を特定する値（シリアル・Vault URI・端末内パス）を落としてから**記録へ貼る。

## 記録

- 合否はケースIDで返す。`PERM-02` を実施できなかった場合は「対象外」と理由を書く。
- **不合格が1件でも出たら、`INTERNET` の除去自体を保留にするか判断を仰ぐ。**
  権限を戻す判断はオーナーのものである（ADR-0002 の線に触れるため）。
- 合格の範囲を [dependency_policy](../../dev/system/dependency_policy.md) 判断5 の状態行へ写す。
  **この行が「確認待ち」を含む限り未確定である。**
- **`PERM-02` が対象外で終わったときは、状態行に「モデルDLは確認待ち」を残す。**
  他が全部合格していても、DL成功を生成成功から推定しない。
  **待ち方は決まっている** — 上の「検証前」のとおり契機待ちにする。**期限は置かない。**
- **権限除去より前に行ったDLの確認は使えない。** `AIUX-05`・`AIUX-06` は
  ネットワーク権限を持つビルドでの結果なので、**いまの問い（権限が無くてもDLできるか）には答えていない**。
  過去の合格を根拠に `PERM-02` を閉じない。
