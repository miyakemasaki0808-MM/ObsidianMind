## 適用条件

要約の保存（`SummaryCache`・`FileSummaryCache`）、要約のプロンプト・抜粋、`SummarizeUseCase` の状態分岐、
回数制限の判定（`isAiCoreBusy`）、要約の生成の記録（`GenerationRecordingAiClient`）を変えたときに使う。
初回は新しい保証を足した変更なので通し版とする。

### 当たりは「要約の生成の記録」の行数で判定する

**保存のファイル名と更新時刻では判定しない。** 同じプロンプトで生成し直しても、同じ名前のファイルが
置き換わって更新時刻が進むので、**毎回生成する回帰でも「当たった」ように見える。**

Debug APK は、要約のために生成を呼ぶたびに logcat へ `VigilithSummaryGen: generate` を1行出す
（本文もタイトルも載らない。分野判定・痕跡の要約など**他の機能の生成は出ない**）。
**試行ごとに、その操作の直前（前の画面の要約が出きった後）に端末の時刻を採り**、
要約欄に要約かエラーが出きった後で、その時刻以降の行を数える。
**再起動の試行（`SUMCACHE-05`）だけは、起動の前に時刻を採る。** 起動直後に出たノートの生成を数えの外に置くと、
失われた保存をその生成が補った後から数えることになる。

```text
adb -s <serial> shell date '+%m-%d %H:%M:%S.000'
adb -s <serial> logcat -d -T '<採った時刻>' -s VigilithSummaryGen:I | grep -c 'VigilithSummaryGen: generate'
```

| 判定 | 条件 |
|---|---|
| **当たった** | 記録が**0行**で、要約欄に要約が出る |
| **生成した** | 記録が**1行**（失敗した生成も1行に数える） |
| **観測不成立** | 初めて開いたノートの試行が**1行にならない**（0行＝記録が出ていない、2行以上＝他の生成を数え込んでいるか要約が2回走った）。**その回の `SUMCACHE-01`〜`06` は合格にしない** |

**0行だけでは合格にしない。** 同じ回の中で、初めて開いたノートの試行が1行になったこと（記録が動いていることの対照）と組にして判定する。
観測できなかった試行（時刻を採り損ねた・logcat を読めなかった）は未実施として記録し、合格に数えない。

**ファイルは補助の観測に留める。** 保存の有無と置き場を確かめるときだけ、読み取りで見る。

```text
adb -s <serial> shell run-as com.vigilith.ai ls -l --full-time no_backup/summary_cache
```

## 検証前

- **Debug APK であること**を確認する（記録は Debug APK でしか出ない）。
- AIが `Ready` であることを開始前に記録する。モデル未取得・非対応の端末では `SUMCACHE-01`〜`06` を実行できないので、未実施として記録する。
- ケース別一時Vaultへ次の4本を置く。
  - **短いノートA** — 抜粋されない長さ（1200文字以下）
  - **長いノートB** — 1200文字を大きく超え、冒頭と末尾に見出しを持ち、真ん中の段落だけが長いもの
  - **ノートC** — Aと同じ本文で、ファイル名だけが違うもの
  - **短いノートD** — A〜Cと違う本文のもの（生成中の切り替え用）
- 開始前に `summary_cache` の一覧を採っておく。**既存の保存は消さない**（元Vaultの要約も入りうる。消すのは権限範囲の外）。
- 要約・分野判定・痕跡の要約が同じ錠を取り合うので、1試行ごとに要約が出きってから次の操作へ進む。
- **自動の生成は、ノートに続けて3秒留まってから始まる**（→ [background_ai_ux](../../dev/system/background_ai_ux.md) §7）。
  3秒以内にノートを移ると生成そのものが走らず、記録が0行になる。**初めて開いたノートの試行では3秒以上留まる。**

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `SUMCACHE-01` | ノートAを初めて開き、要約が出るまで待つ。別ノートへ移ってからAを開き直す | 初回は記録**1行**（観測の対照）。開き直しは記録**0行**で同じ要約が出る。補助: ファイル名の集合が変わらない |
| `SUMCACHE-02` | ノートCを開く（Aと本文が同じでファイル名が違う） | 記録**1行**。ファイルが1件増える（タイトルはプロンプトに載るため） |
| `SUMCACHE-03` | ノートBを初めて開いて要約を待つ。一時Vault内でBの**真ん中の段落だけ**を書き換え、別ノートへ移ってからBを開き直す | 初回は記録**1行**。開き直しは記録**0行**（抜粋に載らないため） |
| `SUMCACHE-04` | 一時Vault内でノートBの**冒頭**を書き換え、別ノートへ移ってからBを開き直す | 記録**1行**。ファイルが1件増え、**書き換える前の要約は出ない** |
| `SUMCACHE-05` | **`SUMCACHE-06` の後に行う。** ①一時Vaultの全ノート（A〜D）をそれぞれ開き直し、どれも記録0行であることを確かめる。②`am force-stop` する。③**起動の前に**時刻を採る。④起動し、起動直後にノートが出ていればその要約が出きるのを待つ。⑤ノートAを開いて要約を待つ（起動直後にAが出ていれば開き直さない）。③の時刻から⑤までの行を数える | 記録が合計**0行**で、Aの要約が出る（再起動をまたいで保存が残る）。**1行でも出たら不合格** — ①で全ノートを保存済みにしてあるので、起動から数えた行は**どのノートのものでも**保存が再起動をまたがなかったことを示す。**③の時刻を起動の後に採った試行は無効**（起動直後の生成が失われた保存を補った後から数えることになり、開き直したAが当たって0行になる） |
| `SUMCACHE-06` | 時刻を採り、ノートDを開いて**5秒以上待ち、要約欄が生成中のうちに**ノートAへ切り替え、Aの要約が出てからDを開き直して要約を待つ | 記録は合計**2行**（Dの1回目と開き直し。Aは0行）。Aの画面にDの要約が出ない。補助: Dを開き直す直前にファイルが増えていない（途中の要約は保存されない）。**切り替える前にDの要約が出ていたら、この試行は観測不成立** |
| `SUMCACHE-07` | 検証の前後で一時Vaultのファイル一覧を比べる | 要約の保存のためにVault内へファイルが増えていない |
| `SUMCACHE-08` | 要約の生成が AICore に `ErrorCode 9 / BUSY` で断られた場面を観測できたときだけ、要約欄の文言を読む | 「端末のAIが混み合っています。少し待ってからノートを開き直してください。」が出て、SDKの英文が出ない。**BUSY を起こすために短時間に生成を投げ続けない**（窓の長さは特定しない判断 → 正本）。観測できなければ未実施とし、`SummarizeUseCaseTest` で代える |

## 後処理

- 生成中Jobを残さず、常設検証用Vaultへ切り替えてケース別一時Vaultを削除する。元Vaultへは戻さない。
- `summary_cache` の中身は消さない。検証で増えた要約は端末内の導出値で、上限で古い順に消える。

## 記録

- 試行ごとの開始時刻と、生成の記録の行数（**0行の試行は、同じ回の対照の1行と並べて書く**）
- 補助に見た `summary_cache` のファイル名と更新時刻（**要約の本文は記録しない** — 元Vaultの要約が混ざりうる）
- 要約欄に出た文言（`SUMCACHE-08` を観測できた場合）
- 実行できなかった試行と、その理由（AIの状態・時刻の採り損ね・BUSY を観測できなかった等）
