# ノート要約の保存と混雑時の実機検証ケース

## 正本

- 保存の鍵・置き場・上限・作り直さない判断・混雑時の文言: [note_summary](../../dev/features/note_summary.md) 判断6〜判断9
- 自動AI機能の見せ方: [background_ai_ux](../../dev/system/background_ai_ux.md) §6
- 共通の準備と後処理: [Codex実機検証手順](README.md)

## 適用条件

要約の保存（`SummaryCache`・`FileSummaryCache`）、要約のプロンプト・抜粋、`SummarizeUseCase` の状態分岐、
回数制限の判定（`isAiCoreBusy`）を変えたときに使う。
初回は新しい保証を足した変更なので通し版とする。

**「生成しなかった」は画面の速さで判定しない。** 保存はファイル1件ずつなので、
アプリの `no_backup/summary_cache/` のファイル名と更新時刻を前後で比べて判定する（読み取りだけ）。

```text
adb -s <serial> shell run-as com.vigilith.ai ls -l --full-time no_backup/summary_cache
```

- **当たった** — ファイル名の集合が変わらず、対応する1件の更新時刻だけが進む
- **生成し直した** — 要約が出たあとにファイルが1件増える（または上限で古い1件と入れ替わる）

## 検証前

- AIが `Ready` であることを開始前に記録する。モデル未取得・非対応の端末では `SUMCACHE-01`〜`05` を実行できないので、未実施として記録する。
- ケース別一時Vaultへ次の3本を置く。
  - **短いノートA** — 抜粋されない長さ（1200文字以下）
  - **長いノートB** — 1200文字を大きく超え、冒頭と末尾に見出しを持ち、真ん中の段落だけが長いもの
  - **ノートC** — Aと同じ本文で、ファイル名だけが違うもの
- 開始前に `summary_cache` の一覧を採っておく。**既存の保存は消さない**（元Vaultの要約も入りうる。消すのは権限範囲の外）。
- 要約・分野判定・痕跡の要約が同じ錠を取り合うので、1ケースごとに要約が出きってから次の操作へ進む。

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `SUMCACHE-01` | ノートAを開いて要約が出るまで待ち、別ノートへ移ってからAを開き直す | 2回目は同じ要約が出る。**ファイル名の集合が変わらず、Aの1件の更新時刻だけが進む** |
| `SUMCACHE-02` | ノートCを開く（Aと本文が同じでファイル名が違う） | 生成し直し、ファイルが1件増える（タイトルはプロンプトに載るため） |
| `SUMCACHE-03` | 一時Vault内でノートBの**真ん中の段落だけ**を書き換えてから開き直す | 生成し直さない（抜粋に載らないため）。`SUMCACHE-01` と同じ判定 |
| `SUMCACHE-04` | 一時Vault内でノートBの**冒頭**を書き換えてから開き直す | 生成し直し、ファイルが1件増える。**書き換える前の要約は出ない** |
| `SUMCACHE-05` | `am force-stop` してから起動し、ノートAを開く | 生成し直さず要約が出る（再起動をまたいで残る） |
| `SUMCACHE-06` | ノートAの要約の生成中に別ノートへ切り替え、生成が止まってから戻る | 切り替え先へAの要約が出ない。途中の要約は保存されず、戻ったときに生成し直す |
| `SUMCACHE-07` | 検証の前後で一時Vaultのファイル一覧を比べる | 要約の保存のためにVault内へファイルが増えていない |
| `SUMCACHE-08` | 要約の生成が AICore に `ErrorCode 9 / BUSY` で断られた場面を観測できたときだけ、要約欄の文言を読む | 「端末のAIが混み合っています。少し待ってからノートを開き直してください。」が出て、SDKの英文が出ない。**BUSY を起こすために短時間に生成を投げ続けない**（窓の長さは特定しない判断 → 正本）。観測できなければ未実施とし、`SummarizeUseCaseTest` で代える |

## 後処理

- 生成中Jobを残さず、常設検証用Vaultへ切り替えてケース別一時Vaultを削除する。元Vaultへは戻さない。
- `summary_cache` の中身は消さない。検証で増えた要約は端末内の導出値で、上限で古い順に消える。

## 記録

- 各ケースの前後の `summary_cache` のファイル名と更新時刻（**要約の本文は記録しない** — 元Vaultの要約が混ざりうる）
- 要約欄に出た文言（`SUMCACHE-08` を観測できた場合）
- 実行できなかったケースと、その理由（AIの状態・BUSY を観測できなかった等）
