# AI入力予算の実機検証ケース

## 正本

- 本文の切り出し方: [ai_input_excerpt](../../dev/system/ai_input_excerpt.md)
- 完成プロンプトの上限: `model/PromptLimits.kt` と `ai/PromptBudget.kt`
- 共通の準備と後処理: [Codex実機検証手順](README.md)

## 適用条件

プロンプトの文面・用途別の抜粋上限・完成プロンプトの上限・候補ブロックの予算・
会話履歴の取り分を変えたときに使う。**計測の基準線を取り直す作業もここに含む。**

計測は端末AI（Gemini Nano）へ問い合わせるので、Nano非対応端末では
`PromptTokenBudgetTest` が `Assume` で skip する。**skip を「通った」と読まない。**

## 検証前

- `PromptTokenBudgetTest` は Activity を立てる（AICore はバックグラウンド利用を拒否する）。
  他アプリを前面に出さずに走らせる。
- 直前に採った計測値があるなら、**それがどの版で採られたか**を確認する。
  プロンプト文面を変えた後の値は、変える前の値と直接は比べられない。

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `BUDGET-01` | `PromptTokenBudgetTest` の `トークンAPIの最小疎通を確かめる` を実行する | `getTokenLimit()` と `countTokens("hello")` が値を返す |
| `BUDGET-02` | `端末AIのどの能力が使えるかを切り分ける` を実行する | 全プローブが成功する。失敗があれば欠けている能力を名指しできる |
| `BUDGET-03` | `全計測ケースが入力と出力予約の合計を上限内に収める` を実行する | 12ケース × 2プロファイルすべてで余裕が0以上。**表を logcat から採って残す**（これが新しい基準線） |
| `BUDGET-04` | `抜粋の注意書きが占めるトークン数を差分で測る` を実行する | 注意書きの実コストが正の値で、関連ノートの余裕が0以上 |
| `BUDGET-05` | `関連ノートの予算候補ごとの余裕を測る` を実行する | 掃引表が採れ、限界費用が読み取れる |
| `BUDGET-06` | 長いノートでセクションチャットを10往復以上続ける | 会話が伸びても回答が返り続ける。生成時間が往復ごとに伸び続けない |
| `BUDGET-07` | 見出しが極端に長いノートでセクションAIを開く | 見出しだけで抜粋が押し出されず、要約・質問候補が返る |
| `BUDGET-08` | タイトルの長いノートが多数あるVaultでノートを開く | 関連ノートのAI推薦が返り、候補が0件にならない |
| `BUDGET-09` | 同じVaultでAIピッカーに自然文で問い合わせる | 候補が返る。タイトルが途中で切れた候補が結果へ混ざらない |

## 後処理

- 一時Vaultを削除し、元Vaultへ戻す。
- **採った計測表は、予算を判断するときの材料としてレビュー本文へ置く。**
  この手順書へ日付つきの結果を書き戻さない。

## 記録

ケースIDごとに入力・操作・期待・実測を対応させ、レビュー本文へ残す。
