# 「別のひとこと」が別の一文かを確かめるケース

## 正本

- ひとことの仕様（1文・候補の与え方・保存先）: [reflect_remark](../../dev/features/reflect_remark.md)
- ひとことと返事の保存: [reflect_reading_trace](../../dev/features/reflect_reading_trace.md)
- 同じ入力なら出力は決定的であること: [ai_quality_measurement](../../dev/system/ai_quality_measurement.md) 判断8
- 自動生成が3秒留まってから始まること: [background_ai_ux](../../dev/system/background_ai_ux.md) §7
- 共通の準備と後処理: [Codex実機検証手順](README.md)

## 適用条件

**このケース表は保証を確かめるものではなく、欠陥が実在するかを確かめるものである。**
「別のひとことをもらう」は同じ材料で生成を呼び直すだけで、乱数も前回の一文を避ける指示も持たない。
生成は決定的なので、**材料が変わっていなければ同じ一文が返るはず**という読みがあるが、
**実機では一度も観測していない。** 直し方を決める前に、まず起きるかどうかを見る。

ひとことの生成・候補の選び方・生成設定を変えたときにも使う。

## 検証前

- **Gemini Nano が使える端末であること。** 使えないと全ケースが成立しない。
- **一時Vaultに、関連ノートの候補が付くノートを用意する。** 候補が0件だと材料が痩せ、
  観測が「候補なしのときの挙動」に寄る。
  - 共通の語を含むノートを**5件以上**置き、そのうち1件を対象にする
  - 対象ノートは**本文が数百字以上**あるもの（抜粋が空だと比較の意味が薄い）
- **材料が固まってから押す。** 自動生成は本文表示から続けて3秒留まってから始まるので、
  ノートを開いたら**関連ノートの一覧が出きるまで待つ**。候補は押した瞬間の
  関連ノートの結果から作られるため、**出る前と後では入力そのものが違う**。
- **1回目と2回目のあいだでノートを切り替えない。** 切り替えると候補も痕跡も変わる。

## ケース

| ID | 入力・操作 | 観測・期待 |
|---|---|---|
| `REMARK-01` | 関連ノートが出きった状態で「ひとことをもらう」→ 結果を控える → 専用画面で「別のひとことをもらう」→ 2つ目を控える | **2つの全文を比較して記録する。** 一致すれば課題は実在、異なれば実在しない。**どちらでも合否にしない — これは観測である** |
| `REMARK-02` | `REMARK-01` の後、返事を書いて保存 → もう一度「別のひとことをもらう」 | 「返事が消えます」の確認が出て、「もらう」で返事が置き換わる。**このときのひとことが `REMARK-01` と同じかを記録する。** 同じなら、同じ問いのために返事だけが失われたことになる |
| `REMARK-03` | アプリを `force-stop` してから同じノートを開き直し、関連ノートを待って1回もらう | `REMARK-01` の1つ目と**同じ文字列かどうか**を記録する。同じならセッション内の再利用ではなく生成そのものが決定的、違うなら別の要因がある |
| `REMARK-04` | **別のノート**で1回もらう | `REMARK-01` と違う一文が出る。**対照** — 材料が変われば出力も変わることを示し、「AIが常に同じことを言う」と読み違えるのを防ぐ |
| `REMARK-05` | 生成中（「考えています…」の表示中）にボタンを連打する | 生成は1回しか走らない（既存の保証）。二重に走った痕跡が残らない |

## 後処理

- 常設検証用Vaultへ切り替えてから、ケース別一時Vaultだけを削除する。元Vaultへは戻さない。
- **一時Vaultの `_ReadingTraces/` にはひとことと返事が平文で残る。** 一時Vaultごと消す。
- 元Vaultのノートでは試さない。ひとことと返事は痕跡へ書き込まれるため、読書痕跡が増える。

## 記録

- **ひとことの全文を、ケースごとにそのまま残す。** 文字列の一致・不一致が観測の中身なので、
  「同じだった」という要約では次の判断に使えない。
- 候補の件数（関連ノートの表示件数）と、1回目・2回目の所要時間も控える。
  **候補が0件だったときは、その旨を明記する** — 材料が痩せた状態の観測になる。
- 結果がどちらでも**新規起票はしない。** 判断材料として最新のレビュー本文へ残し、
  直すかどうかはオーナーが決める。
