# 全節の要約の実機検証ケース

## 正本

- 全節の要約: [section_ai_chat](../../dev/features/section_ai_chat.md)（§3〜§5・判断7）
- 入口と面の遷移: [margin_pane](../../dev/features/margin_pane.md) §5.4・§5.8
- 上限の根拠の計測: [background_ai_ux](../../dev/system/background_ai_ux.md) §6 の 2026-11-03 の記録
- 共通の準備・観測・後処理: [README](README.md)。UI変更なので**通し版**で行う

## 適用条件

見出しの要約ボタン、全節の作る節の順番と上限、作る節の線、断られたときの扱い、面の要約の行を変えたときに使う。

**所要時間は判定ではなく記録する。** 上限の15節は素のテストの実測から安全側に決めた値なので、実アプリの値がそれを支えるかをここで確かめる（→ `SBATCH-13`）。

## 検証前

- **一時Vaultに次のノートを置く。** 生成した原本とマニフェストは証跡へ残す
  - **節の多いノート:** `全節_20節.md`（H2 が20個、各節に200字以上の本文）
  - **対象より多いノート:** `全節_34節.md`（H2 が34個、各節に200字以上の本文）
  - **短い節と親の混ざったノート:** `全節_混在.md`（H1 の直後に本文の無い H2、その下に200字の H3 が2つ、50字の H2 が1つ、続けて200字の H2 が10個。対象は12節）
  - **短い節が先頭のノート:** `全節_短い先頭.md`（50字の H2「A」、200字の H2「B」。対象は1節）
  - **全部短いノート:** `全節_短い.md`（H2 が3個、各節20字）
  - **見出しの無いノート:** `全節_見出しなし.md`（本文500字）
  - **本文の上限いっぱいの節:** `全節_長い節.md`（H2 が5個、各節に2,000字）
- 開いた Fold と閉じた画面（スマホの形）の両方で行う。Nano が使える端末で行い、使えなければ生成のケースは未保証とする

## ケース

**狙いのケースを先に置く**（→ [L59](../../dev/lessons/L59.md)）。

| ID | 入力・操作 | 期待 |
|---|---|---|
| `SBATCH-01` | **狙い：節を読み進めるたびに押して待たずに済む。** 閉じた画面で `全節_20節.md` の先頭を開き、💬 を押して、面を出さずに記号を見る。✎ でシートを出したまま本文を節3まで送る | 面は出ず、記号が ⏳ の数字で進む。シートを出すと、止まった節の要約が押さずに出る。上限で 💬 15/20 になって止まる |
| `SBATCH-02` | `SBATCH-01` の続きで、✎ でシートをしまってから 💬 15/20 を押す | 面を出さず、残りの5節を作る。記号が ✓ になる。作った15節を作り直さない |
| `SBATCH-03` | **狙い：読む位置を待たせない。** `全節_34節.md` の先頭で 💬 を押し、すぐ ⏳ を押してシートを出し、シートを出したまま本文を節30まで送って止める | 面に「次に作ります」が出て、その節の要約が次にできる。生成中だった節は取り消されず要約が残る。その後は列の残りへ戻る |
| `SBATCH-04` | `全節_混在.md` で 💬 を押して作り終え、✓ を押してシートを出し、見出しだけの親と50字の節へ本文を送る | 分母が12。見出しだけの親と50字の節は作らない。その節の面には「この節を要約」のボタンが残り、押すとその節を作る |
| `SBATCH-05` | `全節_混在.md` の全節の生成中に ⏳ を押してシートを出し、作らない節（50字の節）まで本文を送って面の「この節を要約」を押す | 走っている生成を取り消さず次に作る。押した直後から「次に作ります」が出る。できたら列の残りへ戻る |
| `SBATCH-06` | 全節を頼む前に面の「この節を要約」で1節を頼み、生成中に 💬 を押す | その節を取り消さず、作り直さず、残りの節を作る |
| `SBATCH-07` | `全節_短い.md` の節2で 💬 を押す | 押して何も起きない形にならない。節2だけを作り、記号が ✓ になる |
| `SBATCH-08` | `全節_見出しなし.md` で 💬 を押す | ノート全体を1節として作る。記号に数を添えない |
| `SBATCH-09` | **狙い：止められる。** `全節_34節.md` の生成中に ⏳ を押して面を出し、「全節の生成を止める」を押す。次に 💬 を押す | 面が出て要約の行まで送る。止めるとできた要約は残り、記号が 💬 の数字になる。「生成を中止」は全節の間は出ない。押し直すと続きから作る |
| `SBATCH-10` | 全節の生成中に (a) 別のノートを開く (b) Vault を選び直す (c) 蒸留で本文を差し替える | どれも全節が止まる。要約は消え、記号が 💬 に戻る。次のノートに前のノートの要約が出ない |
| `SBATCH-11` | **狙い：背面で全部 ! にならない。** `全節_34節.md` の生成中にホームへ戻り、30秒待って戻る | 記号が ! にならず、節に理由が残らない。戻ると ⏳ のまま続きを作る。戻った直後に要求が通るかを記録する（2026-11-03 の計測では見ていない） |
| `SBATCH-12` | `全節_34節.md` で 💬 を押して15節を作り、終わったらすぐ押し直す、を作り終えるまで繰り返す | 断られても節が ! にならず、待って進む。止まったら面に混み合いの文言が出て、押し直すと続きから作る。断られなかったらその旨を記録する |
| `SBATCH-13` | **狙い：上限の根拠を実アプリで確かめる。** (a) `全節_20節.md` と `全節_長い節.md` の所要時間 (b) ノートを開いて3秒以内に 💬 を押したときの、要約と関連ノートが出るまでの時間 (c) 全節が終わった直後に別のノートを開いて、要約に混み合いの文言が出るか | (a)(b) は実測を記録する（合否にしない）。(c) 混み合いの文言が出ないこと。出たら上限の見直しとしてオーナーへ返す |
| `SBATCH-14` | 閉じた画面・開いた Fold の帯・文字サイズ最大で、記号が 💬 15/34 のときの見出しを見る | ✎ と ⛶ の位置が動かない。数字が切れない。題名が読める。外観の判定に代表1枚を撮ってよい |
| `SBATCH-15` | TalkBack で記号を各状態で読む（💬・⏳・💬 の数字・✓・!） | 全節の要約であることと進み具合が言葉で分かる。押した結果の違いが分かる |
| `SBATCH-16` | `全節_短い先頭.md` の A に居て 💬 を押し、✓ まで待って ✓ を押す。続けて本文を B へ送る | 節は1つなので数を添えない。✓ を押すとシートが出て、**A の行は「この節を要約」のまま**（対象でないので不具合ではない）。B へ送ると B の要約が出る |
| `SBATCH-17` | `全節_混在.md` の生成中に、50字の節で「この節を要約」を押し、すぐ「全節の生成を止める」を押す。次に 💬 を押して作り終える | 止めた後の分母が13のまま残る。押し直すと足した節も作り、✓ の後にその節の要約が読める |

## 射程外（自動テストが持つ順序）

[section_ai_chat](../../dev/features/section_ai_chat.md) §10 の「実機で起こせないので自動テストが持つ順序」は試さない。進行チェックリストへ射程外として1行置く。

## 後処理

- 共通手順の後処理に従う。一時Vaultを消す。
- **元Vaultへは戻さず、常設の検証用Vaultで終える。**

## 記録

- 通したケースIDと結果、`SBATCH-13` の実測、`SBATCH-11` の戻った直後の結果、`SBATCH-12` で断られた回数。
- オーナーの体感（15節で足りるか、数字が読めるか）は合否と分けて残す。
- 測っていないもの: 要約の質、ほかの端末での所要時間。
