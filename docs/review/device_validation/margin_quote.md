# 面を越える引用の実機検証ケース

## 正本

- 機能の規則・操作・並べ読み中の面・受け入れ条件: [margin_quote](../../dev/features/margin_quote.md)（§5・§5.6・§10）
- 余白の面・シートと窓の扱い: [margin_pane](../../dev/features/margin_pane.md) §5.4
- 余白メモそのもの: [reflect_margin_memo](../../dev/features/reflect_margin_memo.md)・既存ケース [margin_memo](margin_memo.md)
- 共通の準備・観測・後処理: [README](README.md)。UI・新しい保証・痕跡スキーマ v8 なので**通し版**で行う。スキーマを上げたので [reading_trace_backup](reading_trace_backup.md) も全件通す

## 適用条件

本文の一節を余白メモへ移す操作（選択メニューの「引用して書く」・机の札）、引用つきのメモの表示と照らし直し、書き始めの位置の控え、
並べ読み中の右の面の出し分け（書きかけ｜資料）、余白メモの入力欄を変えたときに使う。

## 検証前

- **一時Vaultに次のノートを置く。** 生成した原本とマニフェストは証跡へ残す。旧版の痕跡は本番と同じ正規形（checksum）で作らないと破損扱いになるので、
  本番のエンコーダを使う一時テストで作り、本番のデコーダで読めることを確かめてから置く
  - **引用の基本:** 冒頭で「並べ読みの相手」「並べ読みの別の相手」へ wikilink する（関連に決定的に並ぶ）。次の節を持つ —
    「同じ文の節」（「結論として、この方法は有効である。ただし条件Aでは使わない。」と、同じ形の条件Bの段落）、
    「入らない長さの一節」（約340字・1,024バイトを超える1段落）、「形のいろいろ」（箇条・引用の行・表・コード）、
    同名の「同名の見出し」2つ（同じ一文）、「長い同じ段落（一）」と「（二）」（画面より長いまったく同じ段落）、その間に読み進める節を12
  - **引用の基本（差し替え用）:** 条件Bの段落だけを消した版。一時Vaultの外に置き、`QUOTE-16` で差し替える
  - **並べ読みの相手:** 10節・各3段落。右で位置を確かめられる長さ。**並べ読みの別の相手:** 1節だけの短いノート
  - **大きな本文:** 1万節のどの節にも同じ一節だけの段落。痕跡に、その一節を前後を控えずに引用したメモを20件（節を分けて）持たせる
  - **旧版の痕跡v7:** v7 の痕跡（訪問2件・引用を持たないメモ2件）。**旧版の痕跡v6:** v6 の痕跡（訪問3件・ひとこと・返事・映し返し）
  - **見出しのないノート:** 段落だけ
- **開いた Fold（机・並べ読み・札・見開き）と、閉じた画面（スマホのシート）の両方で行う。**
- 日本語のキーボードを使える状態にする。Ctrl つきのキーは、ハードウェアキーボードが無ければ `adb shell input keycombination` で送る（Android 13 以降）
- **端末AIは関係しない。** Nano が使えなくても全ケースが通ること自体が確認項目（関連は wikilink で並ぶ）
- 保存の確認には `_ReadingTraces/*.json` を pull して比べる。置く前に控える

## 射程外（自動テストが持つ順序）

正本 §10 が「実機で起こせない」と宣言した順序は、選抜の射程外とする（→ [README](README.md) 準備1）。

- 引用を付けた直後の保存の結果と、右の候補の替えが同時に届く順序
- 照合を Main の外で作っている間に、メモか解析結果が替わる順序
- 窓が変わって机が組み直される途中で、札を離す順序

## 後処理

- 共通手順の後処理に従う。一時Vaultと控えた JSON を消す。差し替え用の版を端末へ置いたなら一緒に消す。
- **元Vaultへは戻さず、常設の検証用Vaultで終える。**

## 記録

- 通したケースIDと結果、`QUOTE-18`・`QUOTE-19` で pull した JSON の差分（版・引用と控え・残った訪問数）。
- オーナーの体感（`QUOTE-01`・`QUOTE-17`・`QUOTE-25`・`QUOTE-36`）は合否と分けて残す。
- 測っていないもの: 長く使ったときの控えの当たり方、札の手触りの好み、IME ごとの違い。
