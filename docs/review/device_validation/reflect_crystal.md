# 結晶の実機ケース

## 正本

正本は [reflect_crystal](../../dev/features/reflect_crystal.md) §10。準備・観測・後処理は [共通手順](README.md)。
AI の自由文や特定の候補 ID は合否条件にしない。生成が `NONE` または不正応答なら、ファイルが増えないことを確認し、表示系は未判定とする。

## 適用条件

新しい保存（Vault 内 `_ReadingTraces/crystals/`・端末内の控え）と画面（✨タブの結晶・一覧）を含むので、初回は通し版とする。

## 検証前

- 一時 Vault を3つ用意する。A は筋を共有しうる複数のノートと無関係なノート、B と同じ相対パスのノート、A にだけあるノート。
  B は A と同じ相対パスのノートを別の本文で持つ。予備の C は、同じ日に2回目の生成を確かめるときに使う（控えは Vault ごと）
- 生成の有無は `_ReadingTraces/crystals/*.json` の件数、控えは `run-as com.vigilith.ai` で `no_backup/crystal_material/` を見る

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `CRYSTAL-01` | 一時 Vault A の要約が出た異なる3ノートを各3秒以上開く。3本目の後、生成完了を待ち、`_ReadingTraces/crystals/` と端末内の材料を調べる | 3件目より前は生成を試さない。材料は異なる相対パス3件。実Nanoが有効な結晶を返したときだけ新規 JSON が1件保存され、既存ノートは変わらない |
| `CRYSTAL-02` | A で3本目の ✨ を開き、結晶・根拠を展開する | 成功時、要約の下に現在ノートを根拠に含む結晶だけが出る。根拠にノート名と渡した要約が出る。成功・空振りのどちらでも結晶の Snackbar やバッジは出ない |
| `CRYSTAL-03` | 成功した結晶から一覧を開き、根拠のノート名を押す | 件数が実ファイルと一致し、一覧から現 Vault の根拠ノートを開ける |
| `CRYSTAL-04` | A の別の要約済みノートを同じ日に控える。A の JSON 件数と既存ファイルの SHA を比較する | 同日の2回目の生成・既存 JSON の上書きはない |
| `CRYSTAL-05` | A の結晶一覧を開いた後に B へ切り替え、B の同名相対パスを開く。A→B→A も行う | 一覧・根拠・ランダム表示が選択中 Vault に限られる。同名パスは B の本文になり、別 Vault の読書痕跡・結晶材料が混ざらない（切替前の走査の結果を切替後へ持ち込まない） |
| `CRYSTAL-06` | 実Nanoで結晶を生成し、保存 JSON・✨・一覧を照合する | 自然文に候補 ID が漏れず、生成・保存・表示の通常経路が一貫する（本文へ漏れた候補IDの検査を通常経路で通す）。特定の ID 表記を Nano が出すことは要求しない |
| `CRYSTAL-07` | `OnDeviceGenerationTest` の結晶ケースと `PromptTokenBudgetTest` の全計測ケースを実機で直接実行する | 前者は生成が空でなく、パーサを例外なく通る。後者の結晶最大構成は入力と出力予約が端末の上限内。実出力の形とトークン値を記録する |

非対応端末の無表示と、保存途中の人工的な交錯は今回の Pixel 10 Pro Fold だけでは再現条件が揃わないため、別環境の対象とする。
**走査途中の交錯（切替前に始まった走査が遅れて返る）は求めない** — アプリはローカルの Vault を読む前提で走査が速く、遅い置き場は前提の外である（2026-09-29、オーナー判断）。判定は JVM の `NoteScanCacheTest` が固定する。

## 後処理

共通手順に従い、常設検証用Vaultの待機ノートへ戻す。一時 Vault A・B・C、UIダンプ、今回入れた `com.vigilith.ai.test` を削除する。
本体 `com.vigilith.ai` と常設 Vault は消さない。

## 記録

ケースIDごとに入力・操作・期待・実測・判定を最新レビューへ残す。生成された文と根拠、保存 JSON の件数と SHA、トークンの余裕を記録し、
実Nanoの自由文の意味上の正しさは判定しない。
