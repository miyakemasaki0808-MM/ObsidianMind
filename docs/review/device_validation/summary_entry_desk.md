# 要約の入口とFoldの机の実機検証ケース

## 正本

- [margin_pane](../../dev/features/margin_pane.md) §5.1・§5.4
- [section_ai_chat](../../dev/features/section_ai_chat.md) §4
- 共通の準備・観測・後処理は [README](README.md)。UI変更なので通し版で行う。

## 適用条件

見出しの要約入口、机の操作帯、余白ペインと外殻の連携を変更したときに使う。

## 検証前

共通手順に従い、常設検証用Vaultで開始する。ケース別一時Vaultへ見出しのある長いノートと見出しの無いノートを配置し、原本のマニフェストを残す。実Nanoが使えるかを記録し、自然に作れない状態の扱いをオーナーと決める。

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `RM00-01` | カバー画面で、未要求の節の💬を押し、生成を待ち、完成した記号を押す | 最初は面が出ず生成中・完成の記号になる。完成後に押すとシートが開き、対象の要約が読める |
| `RM00-02` | 未要求の別の節へ読み進め、元の節へ戻る | 記号は今の節の状態を映す。持っている元の要約を作り直さない |
| `RM00-03` | 開いたFoldでペインをしまい、未要求の節の💬を押す | 面を出さず裏で始め、ペインを閉じた設定は変わらない。完成後に押すとシートで見せる |
| `RM00-04` | 開いたFoldでペインを出し、部分要約を頼む | ペインの要約の行で進行・結果を返す。シートを重ねない |
| `RM00-05` | 再会カードを閉じ、開いたFoldの机の画面を見る | レール・見出し・操作の行は出ず、本文とペインの幅と高さがほぼ等しい。折り目をまたがない。外観判定用の代表画像1枚を共用する |
| `RM00-06` | つまみをタップ、下へスワイプ、短い下向きフリック、上の余白から下へ払う | タップでは開かず、縦の払いでは帯が開く。本文とペインの寸法は変わらない |
| `RM00-07` | 帯の見出しとボタンの上から上へ払う。下端のつまみを押す | 帯がしまう。ボタン上の払いでボタンの操作は実行されない |
| `RM00-08` | 閉じた帯・開いた帯で横120dp・縦±30dpの横寄りの払いを行う | 帯は開閉しない。縦20dp / 40msのフリックは開閉する |
| `RM00-09` | 帯が出ている間に本文へ触れる、または戻る操作 | 帯がしまう。最初の本文への一触れで本文の位置は動かない |
| `RM00-10` | 帯の✎で机をしまい、再度✎で開く | レールと操作が戻り、再度開くと机になり帯はしまっている |
| `RM00-11` | 帯から全画面・冊子へ移り、本文へ戻る。アプリを停止・再起動する | ペインが出る設定なら机へ戻り、帯はしまった状態から始まる |
| `RM00-12` | ユーザーの手でFoldを閉じ、開く。必要なら続行操作を行う | 幅に合うシート・ペインへ移り、レールの開閉が循環しない。ノートと書きかけを保つ。端末設定を変更しない |
| `RM00-13` | 見出しの無いノートで💬を押す | ノート全体を対象に、面を出さず生成を始める |
| `RM00-14` | 利用不可理由が届く順序、別の節、再構成、シート入力中を自動UIテストで実行する | 対象の節だけで理由を見せ、行が無い間は未通知を保持し、行が出てから一度だけ消費する。注入した状態と実SDKの自然状態を区別する |

TalkBackは端末で有効な場合に実操作で確認する。有効でなければ設定を変えず、既存UIテストのsemantics操作による確認と区別して未確認を残す。
保存を行う場合はケース別一時Vault内だけで行い、原本ノートのハッシュと保存された痕跡を比較する。

## 後処理

共通手順の後処理を行う。証跡を取得して常設検証用Vaultへ戻し、待機ノートを確認する。ケース別一時物の削除と記録の確定は担当へ引き渡す。

## 記録

ケースごとの条件番号・実測・合否・未保証の範囲をprogress.mdへ記録する。実SDKと注入したUI状態、物理開閉と状態復元テストを区別する。面の寸法、本文位置、メモの保存原文と原本ハッシュの比較を証跡へ残す。
