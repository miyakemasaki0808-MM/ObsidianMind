# 要約の入口とFoldの机の実機検証ケース

## 正本

- [margin_pane](../../dev/features/margin_pane.md) §5.1・§5.4
- [fold_experience](../../dev/system/fold_experience.md) §6 の初期状態・[note_spread](../../dev/features/note_spread.md) §5「見開きのタブ」（`RM02-*`）
- [note_spread](../../dev/features/note_spread.md) §5「めくり」・§8 判断7・§9 のアクセシビリティ（`RM03-*`。帯の幅は [margin_pane](../../dev/features/margin_pane.md) §5.1）
- [section_ai_chat](../../dev/features/section_ai_chat.md) §4
- 共通の準備・観測・後処理は [README](README.md)。UI変更なので通し版で行う。

## 適用条件

見出しの要約入口、机の操作帯、片側を1画面にする払い、余白ペインと外殻の連携、開いた直後の初期状態と見開きのタブ（入り方）、見開きのめくりと読み上げからの送り、重ねたレールと帯の幅を変更したときに使う。

## 検証前

共通手順に従い、常設検証用Vaultで開始する。ケース別一時Vaultへ見出しのある長いノートと見出しの無いノートを配置し、原本のマニフェストを残す。`RM03-*` には、見開きで何度もめくれる長いノート（短い段落が多数）と、1つの見開きに収まる短いノートを置く。`RM03-03`・`RM03-05` は端末の設定（アニメーションの削除・文字サイズ）を変えるので、始める前にオーナーの許可を取り、終わったら元へ戻す。許可が無ければ設定を変えず未確認を残す。実Nanoが使えるかを記録し、自然に作れない状態の扱いをオーナーと決める。

| `RM00-12` | ユーザーの手でFoldを閉じ、開く。必要なら続行操作を行う | 閉じると書きかけがあればシートへ移り、開くとふだんの画面から始まって机は自分から出ない（シートで書いていればシートのまま）。✎ で机が戻る。レールの開閉が循環しない。ノートと書きかけを保つ。端末設定を変更しない |
| `RM00-13` | 見出しの無いノートで💬を押す | ノート全体を対象に、面を出さず生成を始める |
| `RM00-14` | 利用不可理由が届く順序、別の節、再構成、シート入力中を自動UIテストで実行する | 対象の節だけで理由を見せ、行が無い間は未通知を保持し、行が出てから一度だけ消費する。注入した状態と実SDKの自然状態を区別する |
| `RM01-01` | 開いたFoldの2面で、本文・余白それぞれの中央から左右へ200dp / 300ms払う。1画面で同方向へもう一度払い、逆へ払って戻す | 左払いで余白、右払いで本文が1画面になる。1回で1段だけ動き、端で止まる。逆払いで2面へ戻る。隠した面の操作はUI階層から消える |
| `RM01-02` | 2面の余白で右へ30dp / 40msの短いフリック。戻る操作。本文から左へ同様にフリックし、戻る操作 | 距離56dp未満でも速さ400dp/秒以上なら広がる。戻る操作はノートを替えず2面へ戻す |
| `RM01-03` | 長い本文・並べ読みを縦300dp / 300ms、横30dpずれる縦寄り、45度の斜めへ払う。長押し成立後に横へ動かす | 縦寄りは本文をスクロールし、斜め・長押しで片側は広がらない。文字選択を妨げない |
| `RM01-04` | 帯を出して本文へ横払い。帯を出し直して戻る。1画面へ広げて画面の端からシステムの戻るジェスチャー | 帯がある間は広がらず、本文の一触れで帯だけしまう。戻る優先順は帯→1画面→並べ読み。端の操作をアプリが取り返さない |
| `RM01-05` | 長い本文の途中の先頭段落と位置を記録。余白の関連一覧までスクロールし記録。両方向に広げて2面へ戻す | 本文のブロックとオフセット、余白のスクロールを保つ。幅変更で折り返しが変わる間と、2面へ戻った後を区別する |
| `RM01-06` | 起点ノートから長い関連ノートを並べ読みし、右を途中まで読む。左右の1画面と2面を往復する | 右のノートと読みかけが残る。余白だけにしても今のノートは起点のまま。「このノートへ移る」を押すまで替わらない |
| `RM01-07` | 並べ読みを隠して本文だけにし、未要求の節を帯から背景要約。そのまま結果または利用不可理由を待ち、2面へ戻す | 要求は1回、面を出さず、隠した並べ読みを閉じない。利用不可理由も隠している間は面を戻さない。2面へ戻すと同じ右のノートと読みかけが残る。実Nanoと注入した状態を区別する |
| `RM01-08` | 2面と本文1画面でつまみ・帯を確認。代表画像1枚をRM00-05と共用し、寸法をUI階層と比較 | つまみと帯が折り目にかからず、本文の上の縁に収まる。余白1画面では本文側のつまみが隠れる。画像はこの外観判定に必要な場合だけ取得する |
| `RM01-09` | 帯を出し入れする。`NoteReadingFlowTest`の時計を止めた途中座標の検証も実行する | 出る途中・しまう途中の見出しは全開位置より上、終了後に帯が消える。実窓の上の余白へはみ出さない。250msで降り、200msで巻き上がる手触りはオーナーの目視結果を別に記録し、自動時計の座標結果で代替しない |
| `RM01-10` | `NoteReadingFlowTest`を端末で直接実行し、払い・帯・背景要約・並べ読みの関連テストを照合 | 対象テストが成功し、失敗・skipを成功に数えない。固定960dp幅の注入UI結果と、実窓・実プロバイダの操作結果を区別する |
| `RM02-01` | 閉じた画面でノートを読み、Foldを開く。開いたままアプリを停止・再起動する | どちらもふだんの画面（見出しの操作の行・題名・縦積み）から始まり、机も見開きも自分から出ない。左のレールの「ノート」のすぐ下に📖「見開き」がある。閉じた画面の下のバーは5つのまま |
| `RM02-02` | レールの「見開き」を押して読む。つまみで帯を出し、重なったレールの「ノート」を押す。もう一度「見開き」で入り、戻る操作 | 見開きは、ふだんの画面で読んでいたブロックを含む見開きから始まりレールは畳まれる。「ノート」と戻る操作はどちらもふだんの画面へ戻し、見開きで読んでいたブロックから始まる。帯が出ていれば戻る操作は帯が先 |
| `RM02-03` | 見開きの帯の✎で机を開き、机の帯の✎でしまう。机で重なったレールの「ノート」を押す | ✎ でしまうと見開きへ戻る（入った元）。机でレールの「ノート」を押すと机をしまってふだんの画面へ移る |
| `RM02-04` | 机で関連ノートを右で開いて途中まで読み、Foldを閉じて開く。✎ で机を開く | 開き直した直後はふだんの画面。✎ で右に同じノートが同じ位置で出る（並べ読みは終わっていない） |
| `RM02-05` | 文字の倍率を上げて（またはブロックの長いノートで）見開きを選ぶ | 見開きのタブは選んだまま、縦の流しで出て「このノートは見開きにできません（理由）」の1行が出る。条件を満たすノートへ替えると見開きに戻る |
| `RM02-06` | 見開きで読み、さがすへ移り、レールの「ノート」で戻って指で先まで読み進めてから「見開き」を押す | 前の見開きの位置ではなく、読み進めたブロックを含む見開きから始まる |
| `RM02-07` | 机を開いてから分割窓で高さだけを下げて戻す（ノートの画面と、さがすの画面の両方で） | 下げた時点で机が閉じ、戻しても机は出ない。✎ で机が戻る |
| `RM03-01` | 見開きで、右ページの中ほどを左へ4分の1ほどゆっくり引いて止める（離さない）。そのまま左へ払いきる。右へ払って前の見開きへ戻る。最後にレールの「ノート」でふだんの画面へ戻る | めくる1枚が綴じ目（折り目の溝の中央）を軸に手前へ立ち上がり、90度を越えると裏に次の見開きの左ページが文字の読める向きで出て、左へ倒れる。回らないページと、めくった紙の下から現れるページは動かない。前へは左ページが立ち上がって右へ倒れる。紙の色・透明度は変わらず、止まった瞬間に跳ばない。ふだんの画面は止まった見開きの左ページの先頭のブロックから始まる。外観判定用の代表画像1枚（めくり途中）。遠近の強さと影の見え方は正本で未決なので、オーナーの目視を別に記録し合否に数えない |
| `RM03-02` | 見開きで、半分より手前まで引いて止めてから離す。続けて速く左へ払って離す | 止めてから離すと元の見開きへ、速く払うと払った向きの見開きへ寄って止まる。寄せの途中もめくる紙は綴じ目を軸に回る |
| `RM03-03` | 端末の「アニメーションを削除」を有効にし、`RM03-01`・`RM03-02` の引く・止める・離す・速く払う操作と、読み上げからの送り（`RM03-04` の操作。TalkBack が無ければ意味情報の操作で代える）を行う。終わったら設定を元へ戻し、同じ速い払いをもう一度行う | 指で引いている間は紙が途中の角度で回る。離すと途中の回転を省き、行き先の見開きへすぐ移る（次へ・前へ・元の見開きへのどれでも）。読み上げからの送りも途中の回転を省く。行き着く見開きは設定を戻した後の同じ払いと同じ。設定を戻すと寄せの途中の動きが戻る |
| `RM03-04` | TalkBack で見開きの面にフォーカスし、操作から「次の見開きへ」「前の見開きへ」を選ぶ。最初の見開きと最後の見開き、1つの見開きに収まる短いノートで操作の一覧を見る | 選ぶと見開きが送られ、送った後に「n番目の見開き」と読み上げる。総数は言わない。最初の見開きに「前の見開きへ」が無く、最後の見開きに「次の見開きへ」が無い（短いノートではどちらも無い）。止まった見開きの位置はふだんの画面へ戻っても保たれる |
| `RM03-05` | 端末の文字サイズを最大にして、机の帯を出す。見開きに入れる中で最も大きい文字サイズで見開きの帯を出す（入れた段階と、そのときのレールの幅を記録）。元の文字サイズへ戻して、机と見開きの帯を出す | 重ねて出たレールが帯の左端（題名「Rediscover」とボタン）を隠さず、帯の中身はレールの右端から始まる。元の文字サイズでは帯の見た目が変わらない。見開きに入れる段階でレールが最小幅より広がらなければ、そう記録する（見開きの側は踏めていない） |
| `RM03-06` | `NoteReadingFlowTest` の見開き・重ねたレールと帯のテストと、`SpreadReducedMotionTest` を端末で直接実行する | 対象テストが成功し、失敗・skipを成功に数えない。`SpreadReducedMotionTest` の倍率0は Compose の実行コンテキストへの注入で、端末の設定からの経路（`RM03-03`）と区別する |

TalkBackは端末で有効な場合に実操作で確認する。有効でなければ設定を変えず、既存UIテストのsemantics操作による確認と区別して未確認を残す。
保存を行う場合はケース別一時Vault内だけで行い、原本ノートのハッシュと保存された痕跡を比較する。

## 後処理

共通手順の後処理を行う。証跡を取得して常設検証用Vaultへ戻し、待機ノートを確認する。ケース別一時物の削除と記録の確定は担当へ引き渡す。

## 記録

ケースごとの条件番号・実測・合否・未保証の範囲をprogress.mdへ記録する。実SDKと注入したUI状態、物理開閉と状態復元テストを区別する。面の寸法、本文位置、メモの保存原文と原本ハッシュの比較を証跡へ残す。
