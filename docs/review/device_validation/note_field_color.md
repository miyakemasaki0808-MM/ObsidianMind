# 分野色と復元の実機検証ケース

## 正本

正本: [note_field_color](../../dev/features/note_field_color.md)。準備・観測・後処理は [共通手順](README.md)。

## 適用条件

分野色の初回確認はUI・新しい保存契約を含むため通し版とする。以下を変更面として選び、
起動は `LAUNCH-01`〜`LAUNCH-04`、既存の冊子instrumentationも併用する。

## 検証前

- ケース別一時Vault A・Bへ、同じ相対パスのノート、ヒントあり、ヒントなしを置く。
- 決定的な復元確認では、本番SharedNoteFieldStoreへ分野あり／NONEを保存してよい。
  この入力はテスト注入であり、実AIの判定成功とは区別する。
- 遅延・失敗の注入は一時DeviceProbeTestで行い、本番Controller・保存実装・Composeへ通す。
- 色は本番冊子の画素とラベルを照合する。外観の目視が必要なら代表の明暗各1枚を共用する。

## ケース

| ID | 操作 | 期待 |
|---|---|---|
| `FIELDDEV-01` | 一時Vaultを選択し、本文を開く前に冊子へ入る | フォルダのヒントで色・ラベルが出る。ヒントなしは無彩色 |
| `FIELDDEV-02` | 実Nanoで分野判定を生成し、本番パーサへ渡す | 固定IDまたはNONEとして読める。分類の主観的な正しさは保証しない |
| `FIELDDEV-03` | 本番ストアへ分野あり・NONEを保存し、force-stop後に起動して冊子を開く | 再判定を待たずに分野ありの色・ラベルとNONEの無彩色が復元される |
| `FIELDDEV-04` | 同じパスに異なる確定を持つA→B→AをSAFで選択する | Vaultごとの確定を表示し、他Vaultの分類が混ざらない |
| `FIELDDEV-05` | H1確定→H2→AI利用不可→降格→再走査を本番Controllerと冊子で行う | ヒントありは暫定、なしは無彩色を維持し、旧色・ラベルが復活しない |
| `FIELDDEV-06` | FIELDDEV-05後にAIを回復させ、引く束と編む束を往復する | 最新の色・ラベルが両方へ届き、束の並びとページ位置を維持する |
| `FIELDDEV-07` | 明暗それぞれで6分野とNONEを本番冊子へ描画する | 紙の画素が対応するパレットを使い、ラベルが見える。NONEに分野名が出ない |
| `FIELDDEV-08` | H1→H2確定→H1と、H2確定→B破棄・永続復元→H1を比較する | 同一セッションのH1差し戻しは追加生成0回。永続にもH1が残らない再構成後は再生成する |

## 後処理

共通手順に従い、常設検証用Vaultの待機ノートへ戻す。一時Vaultの保存内容を読み戻して確認し、
一時Vault・一時テスト・test APKを削除する。本番SharedPreferencesの一時Vault用分類キーも削除する。
