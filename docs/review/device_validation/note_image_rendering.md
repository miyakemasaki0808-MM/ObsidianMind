# ノート内画像の実機検証ケース

## 正本

- 解決・復号・表示・制約: [note_image_rendering](../../dev/features/note_image_rendering.md)
- 共通の準備と後処理: [Codex実機検証手順](README.md)

## 適用条件

Markdown画像解析、Vault索引、パス解決、画像復号、キャッシュ、プレースホルダ、失敗表示、
読書進捗、全画面表示を変更したときに使う。画像機能は読み取り専用なので、元Vaultへ書き込まない。

## 検証前

- 一時Vaultへ、縦長・横長・透過・大寸法・破損のfixtureをファイル名が識別できる形で置く。
- 同名解決ケースは別フォルダに同名画像を2枚置き、通常ケースとVaultを分ける。
- 期待する失敗理由と、正本が意図的に非対応としている形式を分ける。

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `IMAGE-01` | 単独行の `![[image.png]]` を表示する | Vault内の画像を解決し、本文幅内で表示する |
| `IMAGE-02` | 単独行の `![alt](path/to/image.png)` を表示する | パスを正規化して表示し、altをアクセシビリティ用の説明に使う |
| `IMAGE-03` | 空白・日本語・percent encodingを含むパスを使う | 正本の正規化規則どおり同じ実体へ解決する |
| `IMAGE-04` | 存在しない画像を参照する | 枠・記号・ファイル名・理由を表示し、色だけで失敗を伝えない |
| `IMAGE-05` | Vault内に同名画像を2件置き、basenameだけで参照する | どちらかを黙って選ばず、曖昧であることと候補数を表示する |
| `IMAGE-06` | SVG、アニメーション、拡張子なし埋め込み、段落途中の画像を書く | 正本の非対応契約どおり。誤って通常画像として解決しない |
| `IMAGE-07` | 縦長・横長・透過画像を連続して表示し、上下へスクロールする | placeholder・成功表示で幅と高さが不自然に跳ねず、本文を読み続けられる |
| `IMAGE-08` | 画像の直前まで読み、復号待ち・成功・失敗を順に観測する | 画像の状態だけで読書進捗が100%へ水増しされない |
| `IMAGE-09` | ファイルサイズ・画素数・辺長・デコード予算の各上限を別fixtureで越える | 上限ごとの理由で安全に失敗し、巨大Bitmapを確保しない |
| `IMAGE-10` | 同じ画像を同じ画面へ複数回置き、通常表示と全画面表示でも開く | single-flightとキャッシュが効き、表示内容は一致する |
| `IMAGE-11` | TTL内外で新しい画像を追加し、リンク切れも同時に置く | 必要な契機で索引を更新し、再コンポーズごとに全Vault走査を繰り返さない |
| `IMAGE-12` | 同じ参照先を外部から上書きし、TTL後に再表示する | 世代更新対応を変更した場合のみ実行。新しい内容を復号し、古いBitmapへ固定しない |
| `IMAGE-13` | compact／expandedの両画面幅で画像を表示する | 本文幅に収まり、ナビゲーションや全画面読書のレイアウトを壊さない |

`IMAGE-12` は正本に未解決と書かれている間は合格必須ケースではなく、修正時の再現・受理ケースとして扱う。
未解決を「既知だから成功」と判定しない。

## 後処理

- 元Vaultへ戻し、fixture画像・一時ノート・一時Vault・UIダンプを削除する。
- 端末の画像キャッシュやアプリデータを検証目的で全消去しない。
- 元Vaultの画像を上書きして鮮度確認を行わない。

## 記録

- fixtureの形式、寸法、ファイルサイズ、参照記法
- 成功画像の表示寸法と、失敗時のファイル名・理由
- スクロール前後の読書進捗と画面幅
- 索引更新ケースの経過時間、外部変更、再走査回数の観測方法
- 既知未解決として実行したケースと合否判定から外した理由
