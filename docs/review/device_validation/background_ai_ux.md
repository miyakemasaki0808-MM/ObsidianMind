# AI状態UXの実機検証ケース

## 正本

- 起動契機・状態・表示契約: [background_ai_ux](../../dev/system/background_ai_ux.md)
- 共通の準備と後処理: [Codex実機検証手順](README.md)

## 適用条件

`AiAvailability`、状態確認、モデルダウンロード、再試行、AIタブのバッジ、Snackbar、
クイズシート、ノート切替キャンセル、手動／自動AI機能の表示を変更したときに使う。

実端末で自然に作れないSDK状態は、既存の明示的なテスト経路がある場合だけ使う。
端末設定やアカウントを変えて状態を捏造しない。作れない状態は未保証としてレビューへ書く。

## 検証前

- AIがReadyか、ダウンロード待ちか、利用不可かを開始前に記録する。
- 自動起動する要約・関連と、タップ起動する機能を同じノートで観測できるfixtureを用意する。
- Nanoの直列待ちを踏むケースでは、先に動かす機能と後から押す機能を決めておく。

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `AIUX-01` | Ready端末で要約の自動生成と、手動AI機能を1件実行する | 自動機能は通常表示、手動機能は押した場所で進行・結果を返す |
| `AIUX-02` | 自動機能の状態確認がUnsupportedまたは一時不可になる状態を観測する | 要約・関連は「使えません」と常設表示せず、黙って劣化する |
| `AIUX-03` | 手動機能をUnsupported状態で押す | 押した機能自身の場所に理由を表示し、無意味な再試行を出さない |
| `AIUX-04` | 手動機能を一時不可・未知状態で押す | 理由と再試行を同じ場所に表示し、例外本文をユーザーへ出さない |
| `AIUX-05` | DOWNLOADABLE状態で手動機能を押す | モデル準備の説明後にダウンロードを開始できる |
| `AIUX-06` | DOWNLOADING状態で同じ／別の手動機能を押す | 重複ダウンロードを開始せず、進行中であることを矛盾なく示す |
| `AIUX-07` | AI生成中に別ノートへ切り替え、完了まで待つ | 旧ノートの結果・エラー・Snackbarが新ノートへ出ない。走行表示が残らない |
| `AIUX-08` | 1機能の生成中または失敗中に別の手動機能を操作する | Nano直列化の待ちがあっても各機能の状態を取り違えない |
| `AIUX-09` | クイズを開き、クイズだけが利用不可／一時不可になる状態を観測する | 要約側と無関係に、クイズ欄自身へ理由と正しい操作を表示する |
| `AIUX-10` | クイズを生成し、AIタブを開かず完了させ、次にAIタブを開く | 生成中・未確認完了・エラーの優先順どおりにバッジが1状態だけ出て、確認後に消える |
| `AIUX-11` | Snackbar表示中にActivity再生成または画面再進入を行う | 同じ完了イベントを重複表示せず、次回生成では再び通知できる |

## 後処理

- 実機のAI状態を変えるために一時fixture以外を変更していないことを確認する。
- 生成中Jobを残さず、常設検証用Vaultへ切り替えてケース別一時Vaultを削除する。元Vaultへは戻さない。
- ダウンロード済みモデルは検証のために削除しない。

## 記録

- 実行時の `FeatureStatus` と、画面へ出た文言・操作
- 自動機能が黙ったこと、手動機能が押した場所へ説明したこと
- ノート切替前後のノート名、バッジ、Snackbar、走行状態
- 自然に作れず省略したSDK状態と、その代わりに通した自動テスト
