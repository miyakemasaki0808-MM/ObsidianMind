# 読書痕跡の退避（書き出し・読み戻し）の実機検証ケース

## 正本

- 退避の規則・突き合わせ・上限: [reading_trace_backup](../../dev/features/reading_trace_backup.md)
- 痕跡そのもの（欄・保存・寿命）: [reflect_reading_trace](../../dev/features/reflect_reading_trace.md)
- ひとことと返事: [reflect_remark](../../dev/features/reflect_remark.md)
- 共通の準備と後処理: [Codex実機検証手順](README.md)

## 適用条件

退避形式・突き合わせ規則・上限・データ管理画面を変えたときに使う。
**痕跡スキーマを上げたときも必ず通す**（退避ファイルは版ごとの中身をそのまま運ぶ）。

## 検証前

- **一時Vaultに痕跡を作る。** 退避できるものが無いと大半のケースが動かない。
  少なくとも次の3種類をそろえる。
  - **返事まで書いたノート**（ひとことを生成 → 返事を保存）。**この機能が守る当のもの。**
  - **訪問だけのノート**（2回以上開く。AI俯瞰要約が付く）
  - **「まだ考えたい」の印を付けたノート**
- **壊れた痕跡を1つ用意する。** `_ReadingTraces/` のJSONを1つ選び、`noteTitle` を書き換える
  （checksum が守っている欄なので破損扱いになる）。
- 読み戻しの衝突を作るため、**書き出した後で同じノートに別の返事を書く**手順を含める。
- 保存先は**Vault外**（ダウンロード等）を既定とし、Vault内も1回試す。

## ケース

| ID | 入力・操作 | 期待 |
|---|---|---|
| `BACKUP-01` | オプション →「データ管理」を開く | 退避の2ボタンと、その下に「読書痕跡を整理」「AI補記メモを削除」がある。オプション直下に片付け系の項目は無い |
| `BACKUP-02` | 「書き出す」→ Vault外へ保存 | 既定名は `vigilith_traces_yyyyMMdd.json`。「N件を書き出しました」。件数が痕跡ファイル数と一致する |
| `BACKUP-03` | 書き出したファイルを取り出して中身を見る | 人が読めるJSON。**`documentId` がどこにも無い**（端末内のパスが漏れていない）。返事と映し返しは平文で入っている |
| `BACKUP-04` | 壊れた痕跡がある状態で書き出す | 「M件は壊れていて読み取れなかった」と出て、`_ReadingTraces/<64桁>.json` の形でファイル名が示される。**その1件は退避ファイルに入らない** |
| `BACKUP-05` | 痕跡が1件も無いVaultで書き出す | 書き出さずに理由を示す。**空のファイルが作られない** |
| `BACKUP-06` | 書き出したファイルをそのまま「読み戻す」で選ぶ | 下見が出て「失われる返事はありません／新しく増える0件・合わせるN件」。**この時点でファイルは書き換わっていない** |
| `BACKUP-07` | `BACKUP-06` の下見で「やめる」 | 何も適用されない。痕跡の更新日時が変わらない |
| `BACKUP-08` | 書き出した後で同じノートに別の返事を書き、退避ファイルを読み戻す | 下見に「1件のノートで返事が置き換わります」が**件数より先に**出る |
| `BACKUP-09` | `BACKUP-08` で確定する | 退避側の返事に置き換わり、**訪問履歴は両方が結合されている**（回数が減っていない） |
| `BACKUP-10` | 印を付けたノートの痕跡を、印の無い状態へ戻してから読み戻す | 印が復元される（`markedSummary` / `markedKind` / `markedAt` が3つとも戻る） |
| `BACKUP-11` | アプリを再インストールし、同じVaultを選んで読み戻す | 訪問・要約・ひとこと・返事が戻る。**戻したノートを開いても引き当てが壊れない**（旧端末の `documentId` を持ち込んでいない） |
| `BACKUP-12` | 退避ファイルの `backupVersion` を大きい値へ書き換えて読み戻す | 「新しい版で作られています」と出て**1件も適用されない** |
| `BACKUP-13` | 退避ファイルでない `.md` や無関係なJSONを選ぶ | 「読書痕跡の退避ファイルではありません」。何も書き換わらない |
| `BACKUP-14` | 退避ファイル内の1件の `noteTitle` を書き換えて読み戻す | その1件だけが保留になり、**残りは適用される** |
| `BACKUP-15` | 書き出し／読み戻しの走行中に「中止」を押す | 書き出しは何も保存されない。読み戻しは「途中で中止しました」＋**ここまでに適用した件数**が出る |
| `BACKUP-16` | 下見を出した状態でVaultを切り替え、戻ってから確定を押す | 確定できない（下見が消えている）。**別Vaultの痕跡が書き換わらない** |
| `BACKUP-17` | 退避ファイルを Vault内の `_ReadingTraces/` へ既定名のまま保存し、「読書痕跡を整理」を開く | **退避ファイルが削除候補に出ない**（ファイル名が64文字未満なので痕跡として索引に載らない） |
| `BACKUP-18` | 遠いプロバイダ（Google Drive 等）のVaultで書き出す | 進捗の件数が進み、画面が固まらない |

## 後処理

- 一時Vaultを削除し、元Vaultへ戻す。
- **書き出した退避ファイルを端末から削除する。** 読書履歴と返事が平文で入っている。
- 再インストールを試した場合は、元Vaultの権限を取り直す。

## 記録

ケースIDごとに入力・操作・期待・実測を対応させ、レビュー本文へ残す。
**`BACKUP-03` は中身の抜粋を控える**（`documentId` の不在は目視でしか確かめられない）。
**返事が関わるケース（`BACKUP-08`〜`11`）は、操作前後の返事の文面をそのまま控える** —
突き合わせ規則が守っているのは「どの文が残るか」なので、件数だけでは検証にならない。
