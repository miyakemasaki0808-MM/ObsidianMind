# 関連ノートの実機検証ケース

## 正本

- AI推薦の根拠の1行: [related_notes_ai](../../dev/features/related_notes_ai.md)（§5「根拠の1行」・§8 判断12）
- 共通の準備・観測・後処理: [README](README.md)

## 適用条件

関連ノートの候補の選び方・本文による再ランク・関連タブの行の表示を変えたときに使う。

**AI推薦は Nano が選ぶので、どの候補が出るかは操作で決められない。** 根拠の1行は「出た行の根拠が、そのノートとの実際の関係と食い違わないか」で判定する。
どの根拠を選ぶかの規則（重みの比較・同点の順・弱い重なりで出さないこと）は `RelatedContextScoringTest` が持つ。
Nano が使えない端末では AI推薦が出ないので、未実施とする。

## 検証前

- **一時Vaultに次のノートを置く。** 生成した原本とマニフェストは証跡へ残す
  - **今のノート:** `本の記録.md`。frontmatter の `tags` に `読書` を持ち、本文の書き出しを「毎朝の読書を続けている。」にする
  - **タグが共通:** `献立の工夫.md`（`tags: 読書`、書き出しは料理の話）
  - **書き出しが近い:** `朝の時間.md`（タグなし、書き出しを「毎朝の読書を続けたい。」にする）
  - **題名が近い:** `本の記録の振り返り.md`（タグなし、書き出しは無関係）
  - **リンクで結ぶ:** `リンク先.md`。今のノートの本文に `[[リンク先]]` を書く
  - **無関係:** `天気.md`（タグなし、題名も書き出しも重ならない）
- 開いた Fold と閉じた画面（スマホの形）の両方で行う

## ケース

**狙いのケースを先に置く**（→ [L59](../../dev/lessons/L59.md)）。

| ID | 入力・操作 | 期待 |
|---|---|---|
| `RELATED-01` | **狙い：AI推薦がなぜ並んだか分かる。** `本の記録.md` を開いて関連タブを開き、AI推薦が出るまで待つ | AI推薦の行の題名の下に、数字を含まない根拠が1つ出る（「タグ #読書 が共通」「書き出しが近い」「題名が近い」のどれか）。行を押すとそのノートへ移る |
| `RELATED-02` | `RELATED-01` で出た各行について、根拠と、検証前に置いたノートの関係を突き合わせる | 根拠が実際の関係と食い違わない（例: `献立の工夫.md` に「題名が近い」が出ない）。根拠の出ない行があってもよい（弱い重なりしか無いとき） |
| `RELATED-03` | 同じ画面で、決定的な関連（`linked` の付いた行）を見る | `リンク先.md` の行に根拠の1行は出ず、`linked` だけが出る |
| `RELATED-04` | ダークとライトで、根拠の1行と更新日の行を見る | 文字が読め、題名と区別がつく。行の高さが揃い、根拠のある行と無い行が混ざっても崩れない |

## 後処理

- 共通手順の後処理に従う。一時Vaultを消す。
- **元Vaultへは戻さず、常設の検証用Vaultで終える。**

## 記録

- 通したケースIDと結果、`RELATED-01` で出た AI推薦の題名と根拠の文言の組、Nano が使えたか。
- 根拠が食い違った行があれば、そのノートのタグ・書き出し・題名を添える。
- オーナーの体感（根拠で納得が増えたか、気になる言い方）は合否と分けて残す。
