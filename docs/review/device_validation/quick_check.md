# 実機検証（簡易版）

**この文書が答える問い:** 実機で見る面を落とさずに、**1回の検証で通すケースを減らす**にはどれを選ぶか。

**共通の準備と後処理は [Codex実機検証手順](README.md) が持つ。** ここが決めるのは**選抜と観測手段だけ**である。
機能ごとの再現手順と期待は各ケース表（正本）から動かさない。

---

## 使う場面

**使ってよい:**

- 既存機能へ変更を入れた後の**回帰確認**（新しい保証を足していない）
- 直前の指摘対応が効いていることの確認
- 実機でしか踏めない経路を含むが、**見た目と手触りには触っていない**変更

**使ってはいけない:**

- **UI（`ui/theme/`・紙面・演出・レイアウト）を触った**とき → 通し版。佇まいと手触りのケースは簡易版の射程外
- 機能の正本へ**新しい保証を足した**とき → その保証を見るケースは必ず通す
- **スキーマ版を上げた**とき → `reading_trace_backup.md` を全件
- 仕様の分岐を決めるケース（`BOOK-45`・`BOOK-57` のようなオーナー判断）を含むとき

> **簡易版は「異常が見つからなかった」までしか言えない。** 機能の完了報告には使えない。
> **1件でも不合格が出たら、その機能は通し版へ回す**（周辺が同じ形で壊れている前提で数え直す）。
> PR本文へ「確認完了」と書けるのは通し版を通したときだけである。

## 選抜規則

**スモークセットは思いつきで決めない。** 次の4つに当たるケースだけを入れる。

| 規則 | なぜ |
|---|---|
| **入口** — そこが壊れたら他の全ケースが無意味になる1件 | 落ちたと分かった時点で残りを打ち切れる |
| **契約2箇所をまたぐ** — ノート切替・Vault切替の前後 | このコードベースの事故はここに集まる（→ [architecture](../../dev/system/architecture.md) 判断2・判断4） |
| **不可逆な書き込み** — 元データを変える経路を持つ機能の1件 | 誤ると取り返せない。蒸留の太字化と退避の読み戻しだけが該当する |
| **実機でしか見えなかった欠陥の再発面** — [レビュー一覧](../README.md#レビュー一覧新しい順)の実機指摘に対応するケース | 一度実機で出た型は、JVM側に観測点が無いまま残っていることが多い |

**変更面から引いた分を足す。** diff が触った Controller・画面に対応するケースを
[document_map](../../dev/document_map.md) §5 の逆引きで引き、スモークへ足す。**足すのは足りない側だけで、減らさない。**

スモークに入っていなくても対象機能のものは全部走らせる。** 1コマンドで合否が1行返るので、絞る対象にしない。

## 観測手段

**簡易版は正常時のスクリーンショットを撮らない。** 見た目が判定の手段になるのは佇まいのケースだけで、
そこは簡易版の射程外にしてある。状態や文字の確認に画像を使うと、**同じことを高い道具で見る**ことになる。

| 見たいもの | 使う道具 | 使わない道具 |
|---|---|---|
| 画面の文字 | `uiautomator dump` して **`text=` と `content-desc=` だけ抽出** | **生のXMLを読まない**（同じ画面で約50倍） |
| 押せるか | 対象とクリックを受ける親ノードの `enabled`・`clickable` を抽出。必要ならタップ後の状態も確認 | 文字ノードの `enabled` だけで判定しない |
| 状態の遷移 | 抽出したテキストの前後比較 | 連続スクリーンショット |
| 永続化 | 端末上の実ファイル（件数・pullして差分） | 画面の見え方 |
| 遅延・失敗・走行中の切替 | **一時テスト**（下記） | 端末のネットワーク設定を手で変える |

```bash
adb -s <serial> shell uiautomator dump /sdcard/ui.xml >/dev/null && adb -s <serial> shell cat /sdcard/ui.xml | tr '>' '>\n' | grep -oE 'text="[^"]+"|content-desc="[^"]+"' | sort -u
```

**期待と違い、画像が原因説明に役立つときだけ代表1枚を撮る。**
撮影条件と途中再開時の結果再利用は、通し版と共通の
[観測とスクリーンショット](README.md#観測とスクリーンショット)を正とする。

## 一時テスト

遅延・失敗・走行中の切替を端末設定を変えずに作るときは、本番のControllerと画面を実Composeへ繋いだ
使い捨てテストを書いてよい。**ファイル名は `*DeviceProbeTest.kt` にする。**

```text
app/src/androidTest/java/com/example/newproject/ui/<機能>DeviceProbeTest.kt
```

**検証が終わったら削除する。** 残っていると `DeviceProbeResidueTest` が落ちるので、
共通手順の最後にある台帳検査（`--rerun-tasks`）を通せない。**消し忘れたまま完了報告できない**ようにしてある。

**恒久の回帰検査として残さない。** 残すべき保証が見つかったなら、それは一時テストではなく
`androidTest` の正規のテストか、JVM側の観測点として設計し直す対象である。

## 後処理

**共通手順の「実機検証後」をそのまま行う。** 簡易版だからといって省く項目は無い。
一時テストを書いた場合は、削除を**そこへ足す**。

## 記録

共通手順の記録表に加えて、簡易版では次を明記する。

| 項目 | 内容 |
|---|---|
| 版 | **簡易版であること**と、対象機能 |
| 通したID | スモークのどれと、変更面から足したどれを通したか |
| **通していないID** | 射程外にした佇まい・手触りのケースを**IDで**書く（「その他」と書かない） |
| 判定 | 合否。**1件でも不合格なら「通し版へ回す」と書く** |

**「簡易版で確認済み」とだけ書かない。** 何を見ていないかが書かれていない記録は、
次に読む人が通し版と区別できない。
