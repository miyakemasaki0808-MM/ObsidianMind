# 知識索引とバックリンクの実機検証ケース

## 正本

- 索引の作り方・寿命・置き場・性能: [knowledge_index](../../dev/system/knowledge_index.md)（§3・§4・§8・§9・§10）
- バックナンバー（バックリンク）の数え方・互いのリンクの除外・並び・1行・✎・3件と「ほか N 件」・開く位置・開閉: [backlinks](../../dev/features/backlinks.md)（§3・§5・§6・§10、判断2・3・5〜8）
- 同じ名前のノートの解き方: [note_links](../../dev/features/note_links.md) §5・§8 判断3
- 末尾に近い見出しを最初の行に置く余白（`BACKLINK-02`・`04`・`11`〜`14`）: [note_links](../../dev/features/note_links.md) §6・§8 判断6
- 共通の準備・観測・後処理: [README](README.md)。UI と新しい保証を足したので通し版で行う

## 適用条件

索引の表・突き合わせ・走査との繋ぎ・置き場を変えたとき、バックナンバーの引き方・並び・節の出し方・開く位置・開閉を変えたときに使う。
見出しへ送る位置（末尾の余白）を変えたときは `BACKLINK-02`・`04`・`11`〜`14` を通す。

**AI を使わない。** Nano の可否はどのケースの前提にも入らない。
**正本 §10 が「実機で起こせないので自動テストが持つ順序」に挙げた交錯は射程外とする**（→ [README](README.md) 準備1）。

## 検証前

- **バックリンクの一時Vault** に次のノートを置く。生成した原本とマニフェストは証跡へ残す。更新日時は置いた後に端末で揃える（並びの判定に使う）
  - **今のノート `目的地.md`**（2026-11-10）: 本文に自分へのリンク `[[目的地]]`・`[[#二つ目の節]]` と、`[[出どころ_新しい]]` への行き先のリンクを置く。見出し `## 二つ目の節` を持つ。
    `出どころ_新しい` は `目的地` へもリンクするので互いのリンクになり、バックナンバーには出ない
  - **`出どころ_新しい.md`**（2026-11-20 09:00）: 見出しより前の2文目に `[[目的地]]`、後の段落に `[[目的地|もう一度目的地]]`。1文目にはリンクを置かない
  - **`出どころ_見出し.md`**（2026-11-19 09:00）: `## メモ` を2つ持つ。1つ目の直後に「印は「一つ目のメモ」。」と、画面1枚を越える長さの段落。2つ目の直後に「印は「二つ目のメモ」。」と、その次の文に `[[目的地|表示名の目的地]]`。リンクは2つ目の節にだけある
  - **`出どころ_パス.md`**（2026-11-18 09:00）: `[目的地の説明](目的地.md)` のパスのリンクだけ。見出しを持たない
  - **`出どころ_古い.md`**（2026-11-01 09:00）: 「昨日[[目的地]]を読んで考えが変わった。」の1段落だけ
  - **`出どころ_更に古い.md`**（2026-10-01 09:00）: 「この段落はとても長い前置きで、リンクが文の後ろのほうに来るように書いてあり、最後に[[目的地]]へ触れる。」の1段落だけ
  - **`出どころ_コード.md`**（2026-11-20 18:00、最も新しい）: コードの囲みの中とインラインのコードの中にだけ `[[目的地]]` を書く
  - **同じ名前の別のノート `別の場所/目的地.md`** と、同じフォルダから `[[目的地]]` へリンクする **`別の場所/出どころ_同じフォルダ.md`**（2026-11-20 12:00）
  - **`後から足す.md`**（2026-11-10）: リンクを持たない。`BACKLINK-07` で、末尾に「[[目的地]]を後から足した。」を足した版へ置き換える（足した版は Vault の外に用意しておく）
  - **画像の後ろが短い節**（`BACKLINK-14`。どれも 2026-11-10）: `画像の目的地.md`（リンクを持たない）と、`出どころ_画像.md`。
    `出どころ_画像.md` は、画面1枚を越える長さの1つ目の節の後に `## 画像の節` を置き、その直後に「印は「画像の節」。」と「[[画像の目的地]]をここで使った。」、続けて横長の画像 `![[横長.png]]` と短い段落1つで終わる。
    `横長.png` は横1600・縦400の PNG。`目的地.md` へのリンクは持たないので、`BACKLINK-01` の件数は変わらない
- **リンクを多く受けるノート**（`BACKLINK-18`）: `集まる先.md`（2026-11-10、リンクを持たない）と、フォルダ `多くのリンク/` に「[[集まる先]]を使った。」だけのノートを200本。更新日時は問わない
- **出どころのノートは、`BACKLINK-01` を終えるまで今のノートとして開かない。** 並びはこのアプリで読んだ記録で変わる。右で開くのは記録に残らないので構わない
- **合成 Vault（500本・3,000本）** を別々の一時Vaultに置く。[生成手順](scale_vault_fixture.py)で作り、ハッシュの一致を確かめる（ノートの無いフォルダも含む。`adb push` が空のフォルダを落とすことがあるので、端末側のフォルダの数も突き合わせる）
- ノートは Explore で題名を打って開く。同じ題名が2つ出たら、フォルダで見分けて選ぶ
- DB の確認には `run-as com.vigilith.ai` を使う（Debug APK だけで使える）。索引の DB は `knowledge_index.db` で、`-wal`・`-shm` が並ぶことがある
- 走査の時刻は logcat の `VigilithNoteScan: started` / `published` で採る（→ [explore](explore.md) の走査の記録）
- 開いた Fold（机と余白ペイン）と、閉じた画面（スマホの形、関連タブ）の両方で行う

## 後処理

- 共通手順の後処理に従う。一時Vault（バックリンク・500本・3,000本。画像のノートはバックリンクの一時Vaultに置く）を消す
- **元Vaultへは戻さず、常設の検証用Vaultで終える。** 終わった時点で索引は常設の検証用Vaultの分に作り直される

## 記録

- ケースごとの条件番号・実測・合否。`BACKLINK-01` の行の題名・1文・「ほか N 箇所」の文言と並び
- `INDEX-04`・`INDEX-05` の時間（測り方と、1回の取得にかかった時間を添える）と DB の大きさ。正本 §8 の未確認へ書く値はここから取る
- `INDEX-06` の各回の値と中央値、比べた今の値
- 端末の設定を変えたケース（回転・TalkBack）は、許可の有無と戻したことを書く
