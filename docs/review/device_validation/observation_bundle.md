# 実機で見れば決まる観測のケース

**使い捨てのケース表である。** 議論ではなく端末で一度見れば扱いが決まる5件を、1回の実機検証に束ねる。
5件の扱いがすべて決まったら、このファイルと [簡易版](quick_check.md) のスモーク行を一緒に削除する。

| 束 | 何を見るか | ケース |
|---|---|---|
| 読む位置 | 関連・さがす・ランダムでノートを開くと、本文が前のノートで読んでいた位置から始まる疑い | `OBS-01`〜`OBS-05` |
| 見出しの霞 | 左右2列と余白ペインのライトで、見出しの霞が左の列から溝へはみ出している疑い | `OBS-06`〜`OBS-07` |
| 大きな Vault | 走査と起動の時間（未計測） | `OBS-08`〜`OBS-10` |
| ダークの見やすさ | 2026-07-26 の実機確認より後に足した面の、実機での見やすさ | `OBS-11`〜`OBS-13` |
| 読み上げ | 蒸留などの画面の TalkBack 読み上げ | `OBS-14`〜`OBS-15` |

## 適用条件

**この5件を見る1回の実機検証だけに使う。** ほかの機能の実機検証には束ねない。

**期待と、見た結果から扱いを決める線は、このファイルに書いていない。** ケース表の「期待」欄は空けてあり、
**Codex が着手前に書き込む**（実装した側が期待を決めない → [L59](../../dev/lessons/L59.md)）。
**数値の線（`OBS-08`〜`OBS-10`）は着手前に置かない。** 測った値を記録し、オーナーがその値を見て線を引く。

見た結果の行き先は、束で分かれる。

- **読む位置・見出しの霞（疑い2件）:** 課題として残すか消すかを決める。課題台帳（`_wip/current_issues.md`）の該当項目の受理条件は、期待を書くときの材料にしてよい
- **大きな Vault・ダーク・読み上げ（検討枠の3件）:** 課題候補の検討枠（`_wip/fable51_triage.md`）の扱いを「未検討」以外にする。直す必要があれば課題台帳へ起票する

**射程外:** 読書痕跡の索引作成の時間（痕跡の置き場の列挙）。大きな Vault の束と同じ fixture では測れるが、5件に入っていないので測らない。

## 検証前

**組み立てと配置は Claude、それ以外は Codex**（→ [実機検証手順](README.md) の「誰が行うか」）。

- **端末は Fold を使う。** 見出しの霞の束が、カバー画面の横向き（左右2列）と、開いた内画面（余白ペイン）の両方を要する。
  ほかの束はどちらの画面でもよい
- **回転・Fold の開閉・TalkBack の有効化は人の手で行う。** 回転と TalkBack は端末設定に当たり、依頼の権限範囲の外である
  （→ [実機検証手順](README.md) の「権限範囲」）。**端末の前に人がいる時間を、`OBS-06`・`OBS-07`・`OBS-11`〜`OBS-15` にまとめる**。
  `OBS-01`〜`OBS-05` と `OBS-08`〜`OBS-10` は人がいなくても進められるので先に済ませる
- **一時Vaultは2つ作る。** 束ごとに中身の性質が違うので混ぜない
  - `VigilithDeviceReview_observation_<YYYYMMDD>`（読む位置・見出しの霞・ダーク・読み上げ用）:
    **どのノートも数画面ぶんの長さ**にし、各ノートの1行目に、そのノートだけの印になる文を置く（例: `冒頭の印 A`）。
    ランダムでどのノートを引いても、先頭が見えているかを文字で判定できるようにするためである。
    **関連タブに候補が出るよう、同じタグを持つノートを複数置く。** 見出しを持つノートと、蒸留にかけられる長さのノートを含める
  - `VigilithDeviceReview_observation_scale_<YYYYMMDD>`（大きな Vault 用）:
    生成した `.md` を置く。**本数は Codex が着手前に決める**（手元の Vault は約500本で、その数倍まで測る範囲を見込む）。
    **SAF の走査はフォルダごとに IPC が発生する**ので、1フォルダへ平らに置かず、実際の Vault に近いフォルダの深さと数で置く。
    生成の手順と本数・フォルダの数は `evidence/<検証名>/` に残す
- **ダークへの切り替えはアプリのオプションで行う**（端末設定ではない）。検証前の値を控え、後処理で戻す
- **端末AIは読み上げの束で使う**（蒸留）。Nano が使えない端末なら、`OBS-14` は未確認として返す

## ケース

### 読む位置

先に本文を下へ送ってから別のノートを開き、新しいノートの本文がどこから始まるかを見る。
**見るのは画面の文字だけで、画像は撮らない。**

```bash
adb -s <serial> shell uiautomator dump /sdcard/ui.xml >/dev/null && adb -s <serial> shell cat /sdcard/ui.xml | tr '>' '>\n' | grep -oE 'text="[^"]+"|content-desc="[^"]+"' | sort -u
```

| ID | 入力・操作 | 観測するもの | 期待（Codex が着手前に書く） |
|---|---|---|---|
| `OBS-01` | ノートを開き、本文を数画面ぶん下へ送る。ノートタブの「ランダム表示」で次のノートを開く | 新しいノートの1行目の印が画面の文字にあるか。無いなら、画面の最初に見えている文 | |
| `OBS-02` | `OBS-01` と同じく送ってから、さがすタブの「🎰 ランダムに引く」で出た候補を開く | 同上 | |
| `OBS-03` | 同じく送ってから、関連タブの候補を開く | 同上 | |
| `OBS-04` | **対照。** 同じく送ってから、冊子を開き「これを読む」で本文へ渡る | 同上（先頭へ戻す処理があるので、ここが先頭から始まらなければ観測の方法を疑う） | |
| `OBS-05` | **対照。** 開いた内画面の余白ペインで、関連ノートを右に開き、右の本文を数画面ぶん送ってから「このノートへ移る」を押す | 左の本文が、右で読んでいた位置から始まるか | |

**さがすのキーワードは使わない。** Nano が候補を選ぶので、引く候補が一定しない。
**送る量は3つの経路で同じにする。** 開いた先のノートが送った量より短いと、位置が残っていても末尾に着いて見分けにくい。

### 見出しの霞

**画像が判定の手段になるケースである**（→ [実機検証手順](README.md) の「観測とスクリーンショット」の例外）。
撮るのは各ケース1枚で、見出しの帯の右端と、左の列の右端の位置関係が写っていればよい。

| ID | 入力・操作 | 観測するもの | 期待（Codex が着手前に書く） |
|---|---|---|---|
| `OBS-06` | ライトで、カバー画面を横向きにして左右2列にする。見出しのあるノートを開き、見出しを画面に入れる | 見出しの帯の右端が、左の列の右端とそろうか、溝へはみ出すか | |
| `OBS-07` | ライトで、内画面を開いて余白ペインを出す。見出しのあるノートを開き、見出しを画面に入れる | 同上（右にあるのは画面の端ではなく折り目の溝） | |

**ダークと縦積み（1列）は撮らない。** ダークは霞を敷かず、縦積みは左右とも画面の端なので、作りの上で起きない。

### 大きな Vault

**起動時に走査は走らない。** 走査は最初の「ランダム表示」（冊子・関連の補填も同じ走査キャッシュ）で起き、
結果は60秒保持される（→ [rediscover](../../dev/features/rediscover.md) 判断2）。
そのため起動の時間と、最初の走査の時間を分けて測る。

| ID | 入力・操作 | 観測するもの | 期待（数値の線は置かない） |
|---|---|---|---|
| `OBS-08` | 大きな Vault を選んだ状態で `am force-stop` し、`am start -W` で起動する | `TotalTime`。3回測る | 値を記録する |
| `OBS-09` | `OBS-08` の直後（走査キャッシュが空）に、ノートタブの「ランダム表示」を押す | 押した時刻から、ノートの本文が画面の文字に出るまでの時間。3回（各回の前に `am force-stop`）。応答なしの表示が出たかどうか | 値を記録する |
| `OBS-10` | `OBS-09` の後、60秒以内にもう一度「ランダム表示」を押す | 同上（走査キャッシュを使う側の時間）。`OBS-09` との差が、走査そのものにかかる時間の目安になる | 値を記録する |

**時間は、画面の文字を繰り返し読み取って測る。** 押した時刻と、本文が出たと分かった時刻を書く。
`uiautomator dump` は1回に1秒前後かかるので、**それより細かい差は言えない**ことを記録に添える。
細かく測る必要が出たら、一時テスト（→ [簡易版](quick_check.md) の「一時テスト」）に切り替えてよい。**製品コードにログを足さない。**

**本数を変えて同じ3ケースを繰り返す。** 本数ごとに条件を分けて記録する（→ [実機検証手順](README.md) の「進行チェックリスト」）。

### ダークの見やすさ

**2026-07-26 の実機確認は、5タブ・全画面読書・ボトムシート・Vigilith 4状態・暗所での実読・システムバーの浮きを見ている**
（→ [dark_mode](../../dev/features/dark_mode.md)）。ここで見るのはそれより後に足した面だけである。
冊子は [冊子のケース](booklet_mode.md) にダークのケースがあるので含めない。

**判定には人の目が要る。** 画像が判定の手段になるケースなので、各面1枚まで撮ってよい。
オーナーが端末で見られるなら、7月と同じく**暗い部屋で実際に読む**ことを優先する。

| ID | 入力・操作 | 観測するもの | 期待（Codex が着手前に書く） |
|---|---|---|---|
| `OBS-11` | ダークで、開いた内画面に余白ペインを出す。ペインの各段（この部分のメモ・このノートの関連など）と、並べ読みの右の本文を見る | 文字・印・押せるものが背景に沈んでいないか。押せるものと押せないものが見分けられるか | |
| `OBS-12` | ダークで、カバー画面の横向き（左右2列）にし、操作と再会カードの列と本文の列を見る | 同上 | |
| `OBS-13` | ダークで、7月より後に足した残りの面を見る。**どの面を見るかは Codex が着手前に選び、ケース行へ書き足す**（候補: 結晶の一覧、反証の一文、余白メモのシート、要約の入口と机の操作帯、全画面のシート） | 同上 | |

### 読み上げ

**先に画面の文字の抽出で、読み上げ名の欠けを拾う。** これは端末設定を変えずに済む。
**そのうえで人が TalkBack を有効にし、実際の読み上げを聞く。** 冊子の `BOOK-16` と同じく、
TalkBack のメニューは ADB の入力では開けないので人が操作する。検証が終わったら TalkBack を無効へ戻す。

| ID | 入力・操作 | 観測するもの | 期待（Codex が着手前に書く） |
|---|---|---|---|
| `OBS-14` | 蒸留の画面を開き、蒸留の開始から結果の表示、微調整、確定までを TalkBack で操作する（蒸留の書き込みは一時Vaultの中だけで行う） | 押せるもの・状態の表示がそれぞれ何と読み上げられるか。読み上げられない、または意味が通らないもの | |
| `OBS-15` | 蒸留のほかに読み上げを見る面。**どの面を見るかは Codex が着手前に選び、ケース行へ書き足す** | 同上 | |

## 後処理

- 共通手順の後処理に従う。一時Vault（2つ）・UIダンプ・一時テストを書いたならそれも削除する
- **アプリのダーク設定を検証前の値へ戻す。** TalkBack を無効へ戻したことも確かめる（戻すのは人の手）
- **元Vaultへは戻さず、常設の検証用Vaultで終える**（戻す操作自体が読書痕跡を増やすため）
- 大きな Vault の生成の手順と本数は `evidence/<検証名>/` に残す。消すかどうかはオーナーが決める
