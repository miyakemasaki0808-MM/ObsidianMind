# レビュー

**このフォルダが持つもの:** 外部レビューの成果物と、その**追跡**。

**各レビューは独立したスナップショット。** 対象コミット時点の評価であり、後から書き換えない。

> **不変にするのは「評価・指摘・根拠・結論」。** こちら側の運用手順を指す記述だけは、
> **レビュアーの合意があるときに限り**直す。合意なく直すのは不可。
>
> **実績（2026-08-05 時点で1件）:** `2026-08-03-image-n3.md` の
> 「修正完了時は本書の判定表を更新し…」を、
> **「本書は書き換えない。完了は新しい確認レビューと受付簿で記録する」**へ直した。
> 元の文が本書の不変規約と矛盾していたためで、
> **レビュアー自身の指摘（2026-08-05）に基づく**。
> 分割時のメタ記述の最小修正（「上に保存」「ここから下」「本節」→ 別ファイル・本書）も
> 同じ扱いで、いずれも**評価・指摘・根拠・結論は1行も変えていない**。
したがって**古いレビューに残る「未解決」は当時の評価**であって、現在の状態ではない。
現在の状態は最新のレビューと [_wip/current_issues.md](../_wip/current_issues.md) を正とする。

## ファイルの役割

| ファイル | 役割 | 誰が書くか |
|---|---|---|
| `2026-*.md` | レビューの成果物 | **レビュアー（Codex）。こちらは書き換えない** |
| [review_template.md](review_template.md) | レビューに書く内容の様式 | こちらが持ち、レビュアーへ渡す |
| [findings.md](findings.md) | **指摘の受付簿** — 全件と、その処遇 | こちらが書く |

**受付簿が要る理由。** 「総評で問題と書いたものは課題台帳へ起票する」という規則は
[CLAUDE.md](../../CLAUDE.md) と [document_map](../dev/document_map.md) の2箇所に以前からあり、
**それでも 2026-08-01 の総評の指摘4件が2日間どこにも追跡されなかった**。
規則を増やしても直らないので、**全指摘の処遇を1枚で見えるようにし、機械検査で取りこぼしを検出する**形にした。

> **受付簿の内容は薄く保つ。** 受付簿が持つのは「存在と処遇」だけで、
> **指摘の根拠と詳細は日付別のレビューが、進行中の対応内容は
> [_wip/current_issues.md](../_wip/current_issues.md) が持つ。**
> 両方に内容を書くと必ず片方が古くなる。
>
> **解消して `current_issues` から削除しても、根拠はレビューに残る。**
> だから受付簿は「どのレビューの何番か」を指せれば足りる。
