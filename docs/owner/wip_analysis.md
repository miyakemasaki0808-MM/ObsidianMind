## 3. ロードマップ — 物差しは効いている。Now が薄い

**構造は良い。** 北極星 → 昇格の物差し（頻度と重さのOR）→ Now／Next／Later の順で、
物差しが順序を動かした実績（2026-09-09、重さ側で初めて昇格）まで記録している。
完了項目を取り消し線で残さず消す運用も守られ、Now に完了品が溜まっていない。

### Now の3件は、いずれも「着手中」ではない

| Now の項目 | 状態 |
|---|---|
| ランチャー再タップの積み重なり | 実装済み。実機は5ケース中4つ済み、残るは回転とFold開閉の1つ |
| AIピッカーのID契約 | 机上で閉じられる小さな修正。既存部品を流用できると台帳が書いている |
| 再会の演出 | **2026-07-22 の初版から Now にいる。** 主役の座は佇まいへ渡り、残る設計は頻度と強度だけ。実装は始まっていない |

「直近で着手」の段に**8週間いる設計項目**があると、Now の意味が「次にやる」から「いつかやる」へ薄まる。
設計が決まっていないものは Now の項目ではなく、Now の**入口の前**にある。

### Reflect 側が Now／Next にゼロ

北極星は Rediscover と Reflect のループを濃くすることだが、Now／Next の5件は
起動の入口・AI契約の取り残し・演出・要約キャッシュ・読む面の栞で、**すべて Rediscover 側か待ち時間の側**にある。
Fable 5.1 の評価が書いた「ループの片側だけが濃くなっている」懸念は、ロードマップの並びでも裏付けられる。

Reflect 側の候補は機能アイデアにある。読了後に本文の対比を並べる案、蒸留の「読み直す観点」、
但し書きを落とさない要約、前回止まった周辺から1つ選ぶ案。**どれも物差しでは上がらない** —
頻度は読了時や蒸留時に限られ、重さは違和感どまりである。物差しは「困る度合い」を測るので、
「ループを濃くする」側の価値を測れない。**ここは物差しの外でオーナーが線を引く場所**である。

### Later は「引き金が別」の器

Later の4件はいずれも「実際に困ったら」「配布の意思が固まったら」「測る道具が入ったら」で動く。
物差しで昇格しないと明記してあるので矛盾は無いが、**Later と呼ぶより「条件付き」と呼ぶほうが正確**である。
測る道具は 2026-09-13 に物差しだけ先に入ったので、フォーカス文脈の関連ノートは条件の半分を満たした。
ロードマップの最終更新は 09-12 で、この変化を反映していない。

## 4. 機能アイデア — 型は効いている。候補の年齢が見えない

### 27候補の出どころ

| 出どころ | 候補 |
|---|---|
| 2026-07-22 の初期整理（オーナーの志向を選択式で確定） | 見出し単位のミニ要約・蒸留の観点・ピッカーの1行要約・称号・再会の演出・ウィジェット |
| オーナーの実感 | 二度書きの発見・読む面の栞・ローカルDB |
| 外部壁打ち Antigravity（08-02） | 暗黙タグ・余白メモ・放置ノートフィルター・セクションフォーカス |
| 外部壁打ち Codex（08-05・08-15） | 但し書き保全要約・通じない箇所の検出・AI結果キャッシュ・優先度と計測・回帰再生器・カバレッジ検査・太字範囲の調整 |
| 外部壁打ち Gemini（09-08） | 読了後の二項対立・前回止まった周辺・スリープ防止・見出しリンクのコピー・めくり終わりの触覚 |
| その他 | 埋め込みと数式・プロンプトログ |

**3つの型が候補を横断して効いている。** 「非AIで候補を出しAIは選別だけ」「測る道具が先に要る」「本文は触らず示すまで」。
各候補が型を参照するだけで済んでおり、同じ話の書き直しが無い。資料としての質は高い。

**実装に至ったのはオーナーの実感由来が多い。** 冊子・編む冊子・分野色・痕跡の退避・範囲調整は
いずれも実機を触ったオーナーの一言から始まっている。外部壁打ち由来で実装まで行ったのは太字範囲の調整だけで、
残りは資料の中にいる。**壁打ちは候補を増やすが、実装の引き金にはなっていない。**

### 初期候補が8週間動いていない

07-22 の初期候補6件は、演出を除いて本文がほぼ動いていない。動いたのは実装に至った候補と、
外部壁打ちで足された候補である。**古い候補は「まだ有効か」を誰も問い直していない**が、
資料の運用規則は「着手前に実装を当て直す」としか書いておらず、着手されない候補は当て直されない。

### 「足場」行の鮮度は守られない

各候補の「足場」行が実装確認の正だが、実装は毎週変わる。今週は分野判定が AI結果キャッシュの鍵設計を先取りし、
資料もそれを反映した。**反映されたのは着手が近い候補だけ**で、他の候補の足場行がいまも正しいかは分からない。
`owner/` と同じ「古びてよい」側にあると割り切るか、着手判定のたびに1件ずつ当て直すかのどちらかになる。

### 小さな不整合

ヘッダの最終更新は 2026-09-12 だが、カバレッジ検査の項に「2026-09-13、物差しだけ先に入った」とある。
本文の更新にヘッダが追いついていない。

## 6. 横断して見えたこと

1. **「待っている」が見えない。** 4本とも項目の状態は「未対応」か「完了して削除」の2値で、その間にある
   「実装済み・実機待ち」「契機待ち」「別の目のレビュー待ち」は本文を読まないと分からない。
   数えると、台帳11件のうち8件、検討枠21件のうち10件が何かを待っている。
2. **Reflect の空白。** 北極星の片側が Now／Next に1件も無い。物差しが測れない価値なので、放っておくと埋まらない。
3. **入力は3系統ある。** オーナーの実感・外部レビュー・外部壁打ち。実装まで至るのは実感由来が多く、
   壁打ち由来は資料に溜まる。溜まること自体は悪くないが、寿命の管理が無い。
4. **自動起動AIが3本になった影響は、台帳の1件にしか現れていない。** ノートを開くたびに要約・分野判定・痕跡要約が
   走り、同じ錠を取り合い、AICoreの短期回数制限にも当たる。要約キャッシュは呼び出しを減らすが、
   **開いた瞬間に3本走る構造そのものは変えない。**

## 7. 提案

**Fable 5.1 が独自に出した案を含む。** 採否はオーナーが決める。費用は文書だけで済むものから並べた。
