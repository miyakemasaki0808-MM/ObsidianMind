# アプリ俯瞰

**プロジェクト:** Vigilith AI（旧 Obsidian Mind）
**最終更新:** 2026-09-08

**位置づけ:** **この文書は2つの役割を兼ねている。**
**①`owner/` フォルダの入口**（下の一覧）と、**②このアプリが何をするかを一望する1枚**（後半の機能表）である。
**継続的に同期する台帳ではない**ので、指示があったときに通しで見直す。細部が実装より古いことは仕様の範囲。

> **他のフォルダの README は案内に徹しているが、ここだけ内容も持っている。**
> 分けるかどうかは保留にしてある（→ [readme_map](readme_map.md) §4）。
> **入口を探して開いた人が、そのまま機能を読める**ことを優先している。

> ## `owner/` の更新はオーナーが指示したときだけ（不変）
>
> **本フォルダ全体に効く。** 実装を変えたついでに直さない。オーナーが読むための俯瞰であり、
> **更新の契機はオーナーの依頼だけ**である。細部が実装より古いことは仕様の範囲。
>
> **だから検査にも載せない。** ゲートへ載せると、**古びてよいと決めた文書が
> 無関係な変更を止める**ことになる（2026-08-22、解析書の目次で実際にやってしまい撤去した）。
> 型を改名した・スキーマ版を上げた等で俯瞰がずれても、**それはCIで止める種類のずれではない。**
> 次の通し見直しで直す。
>
> **検査で守るのは `dev/`（判断の正本）と `_wip/`・`review/`（追跡）まで。**
> そちらは古くなると実害が出る。**同じ「複製が古びる」形でも、文書の役割で対処が変わる。**

## アプリの機能（俯瞰）

> **Vigilith AI は「過去の自分の思考と再会し、もう一段深める、オンデバイスAIの読書相手」。**
> Obsidian の Vault（`.md` 群）を SAF 経由で読み書きし、**AIは全て端末内の Gemini Nano**（ネットワーク権限なし）。

画面は**5つのタブ**（ノート／さがす／関連／AI／オプション）と、**全画面ルート7つ**
（冊子・全画面ノート・クイズ・ひとこと・データ管理・補記メモ管理・読書痕跡の整理）。

| 機能 | できること |
|---|---|
| **Rediscover（ランダム表示）** | 過去ノートを偶然引く。アプリの入口であり心臓 |
| **ReadingTrace（読書痕跡）** | 読書位置を自動記録し、同じノートを引いた時だけ「前回の読み方」を再会カードで出す |
| **再会カード** | 枠に1件だけ出す。本文にあった**当時の問い**／**古びうる記述**／読み方の俯瞰要約のいずれかで、「まだ考えたい」と印を付けると次の再会で最優先に再掲する |
| **ノート要約** | 開いたノートの要約を自動生成する |
| **関連ノート** | 現ノートに近い候補をAIが選び、タップで切り替える |
| **さがす（AIピッカー）** | キーワード検索・フォルダ絞り込み・当日の閲覧履歴・AIによる候補提示 |
| **セクションAI** | 見出し単位で要約・質問候補・Q&Aを出す |
| **適応出題クイズ** | 入力量に応じて ○× / 3択 / 4択 を自動選択して出題する |
| **ノートへのひとこと** | AIが**1文の問いか接続**を返し、ユーザーが**返事**を書ける。返事にはAIが「映し返し」を1文添える。すべて読書痕跡のサイドカーへ保存する |
| **蒸留（Distill）** | AIが重要文を**選び**、ユーザーが確認した文だけを元ノートで `**太字**` にする |
| **冊子モード** | ランダムを1回押して**10枚の束**を作り、ZINEのようにめくる独立画面。各ページには本文から抽出した代表文1行（扉）が出る。**冊子ではAIも訪問記録も走らせない** — 始まるのは「これを読む」で通常表示へ渡ったときだけ |
| **編む冊子** | 開いているノートを種にして、**済んだAI推薦から2つ目の束**を作る。冊子の中のトグルで引く束と行き来し、**それぞれのページ位置が残る**（実機検証中） |
| **読書痕跡の退避** | 訪問記録・AI要約・ひとこと・**ユーザーが書いた返事**を1ファイルへ書き出し、読み戻せる（オプション →データ管理） |
| **ノート内画像の表示** | wikilink 埋め込み（`![[...]]`）をVault横断の画像索引で解決して表示する |
| **Vigilith** | 画面に常駐する梟のマスコット。AIの状態を身体で示し、タップで操作へ入る |
| **ダークモード** | オプションのトグルで切替（OS設定には追従しない） |
| **後片付け** | 旧「AI補記メモ」ファイルの削除と、孤児になった読書痕跡の整理（どちらもオプションから） |

> **「AI補記メモ」は 2026-08-09 に「ノートへのひとこと」へ作り直した。**
> 出力が1文になり、**結果は専用画面（上の全画面ルートの1つ）で読む。**
> AIタブにあるのは入口のボタンだけで、押すとその画面へ渡る。
> `_AI補記` フォルダへ書く旧機能は無くなり、**既存ファイルの削除だけ**がオプションに残っている。
> → [reflect_remark](../dev/features/reflect_remark.md)

**ノート本文へ書き込むのは蒸留の太字化だけ。** ひとこと・返事・読書痕跡はすべてサイドカー（別ファイル）へ逃がしてある。
機能ごとのデータフローは [source_code_analysis.md](source_code_analysis.md) §5〜§6、
なぜそう作ったかは [features/](../dev/features/)・[system/](../dev/system/) が持つ。

## この俯瞰が答えないこと

**機能表は「何ができるか」までで、次の3つは持たない。**

| 知りたいこと | 見る先 |
|---|---|
| いまコードがどうなっているか（構成・規模・検証状態） | [source_code_analysis.md](source_code_analysis.md) |
| **なぜそう作ったか／何を試して駄目だったか** | [dev/features/](../dev/features/)・[dev/system/](../dev/system/)・[dev/lessons/](../dev/lessons/) |
| いま何が壊れている・足りないか | [_wip/current_issues.md](../_wip/current_issues.md)（`owner/` は課題を持たない） |

**実装が進んでも本書は自動では追いつかない。** 検査に載せていないので、
**ずれていることをCIは教えない**（それは意図した設計である → 冒頭の枠）。
**通しの見直しはオーナーの依頼があったときだけ**行い、そのつど最終更新日を入れ替える。
