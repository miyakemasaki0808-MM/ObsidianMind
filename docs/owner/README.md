# アプリ俯瞰

**プロジェクト:** Vigilith AI（旧 Obsidian Mind）
**最終更新:** 2026-09-20

**位置づけ:** この文書は2つの役割を兼ねている。**`owner/` フォルダの入口**が前半の一覧、
**このアプリが何をするかを一望する1枚**が後半の機能表である。
継続的に同期する台帳ではない。指示があったときに通しで見直す。細部が実装より古いことは仕様の範囲。

> 他のフォルダの README は案内に徹しているが、ここだけ内容も持っている。
> 分けるかどうかは保留にしてある → [readme_map](04_readme_map.md) §4。
> 入口を探して開いた人が、そのまま機能を読めることを優先している。

> ## `owner/` の更新はオーナーが指示したときだけ（不変）
>
> 本フォルダ全体に効く。実装を変えたついでに直さない。オーナーが読むための俯瞰であり、
> 更新の契機はオーナーの依頼だけである。
>
> だから検査にも載せない。ゲートへ載せると、**古びてよいと決めた文書が無関係な変更を止める**。
> 2026-08-22 に解析書の目次で実際にそうなり、撤去した。
> 型を改名した、スキーマ版を上げた、といったずれは CI で止める種類のものではない。次の通し見直しで直す。
>
> 検査で守るのは `dev/` の判断の正本と、`_wip/`・`review/` の追跡まで。そちらは古くなると実害が出る。
> 同じ「複製が古びる」形でも、文書の役割で対処が変わる。

**欠番は詰めない。** 文書が消えたらその番号を空けたままにする。詰め直すと、既存の参照が別の文書を指す。

**ここは非エンジニア向けの平易版ではない。** オーナーはコード構成や設計を読んで学ぶので、技術的な内容を薄めない。

## アプリの機能（俯瞰）

> **Vigilith AI は「過去の自分の思考と再会し、もう一段深める、オンデバイスAIの読書相手」。**
> Obsidian の Vault、つまり `.md` の群れを SAF 経由で読み書きし、AIは全て端末内の Gemini Nano で動く。
> ネットワーク権限は持たない。推移依存が持ち込む権限もビルドで除き、成果物の権限を数える検査で守っている。

画面は**5つのタブ**。ノート・さがす・関連・AI・オプション。
加えて**全画面ルートが6つ**ある。冊子・全画面ノート・クイズ・データ管理・補記メモ管理・読書痕跡の整理。

| 機能 | できること |
|---|---|
| **Rediscover** | 過去ノートを偶然引く。アプリの入口であり心臓 |
| **読書痕跡** | 読書位置を自動記録し、同じノートを引いた時だけ「前回の読み方」を再会カードで出す |
| **再会カード** | 枠に1件だけ出す。本文にあった当時の問い、古びうる記述、読み方の俯瞰要約のいずれか。「まだ考えたい」と印を付けると次の再会で最優先に再掲する |
| **ノート要約** | 開いたノートの要約を自動生成する。**同じ入力の要約は端末に残してあり、開き直したときは作り直さない** |
| **関連ノート** | 現ノートに近い候補をAIが選び、タップで切り替える |
| **さがす** | キーワード検索・フォルダ絞り込み・当日の閲覧履歴・AIによる候補提示 |
| **セクションAI** | 見出し単位で要約・質問候補・Q&Aを出す |
| **適応出題クイズ** | 入力量に応じて ○×・3択・4択を自動選択して出題する |
| **余白メモ** | 読んでいる最中に浮かんだ短い断片を、本文ヘッダの `✎` から何度でも置ける。**AIを1回も呼ばない。** 読書痕跡のサイドカーへ溜まり、次に同じノートと再会したとき自分の言葉として戻ってくる |
| **蒸留** | AIが重要文を**選び**、ユーザーが確認した文だけを元ノートで `**太字**` にする。太字にする範囲は3段のプリセットか、端のつまみを引く自由範囲で選び直せる |
| **冊子** | ランダムを1回押して10枚の束を作り、ZINEのように上へ繰る独立画面。各ページには本文から抽出した代表文1行が扉として出る。冊子ではAIも訪問記録も走らせず、始まるのは「これを読む」で通常表示へ渡ったときだけ |
| **編む冊子** | 開いていたノートを種にして、済んだAI推薦から2つ目の束を作る。冊子の中のトグルで引く束と行き来し、それぞれのページ位置が残る。追加のAI呼び出しは無い |
| **冊子の分野色** | 紙の地色でノートの分野を伝える。フォルダ名を手がかりに暫定の色を付け、ノートを開いたときにAIが固定リストから分野を1つ選んで確定へ昇格する。確定は端末に残る |
| **読書痕跡の退避** | 訪問記録・AI要約・ユーザーが書いた余白メモを1ファイルへ書き出し、読み戻せる。オプションのデータ管理から |
| **ノート内画像** | wikilink 埋め込み `![[...]]` を Vault 横断の画像索引で解決して表示する |
| **年代の紙色** | 放置期間を紙の地色の段階で伝える。既定オフ |
| **Vigilith** | 画面に常駐する梟のマスコット。AIの状態を身体で示し、タップで操作へ入る |
| **ダークモード** | オプションのトグルで切り替える。OS設定には追従しない |
| **後片付け** | 旧「AI補記メモ」ファイルの削除と、孤児になった読書痕跡の整理。どちらもオプションから |

**自動で走るAIは、ノートに続けて3秒留まってから始まる。** 要約・分野判定・再会カードの要約・関連ノートの推薦の4本が対象で、
冊子から開いてすぐ閉じたノートでは Nano を呼ばない。**保存済みの要約と前回の記録は待たずに出る。**

> **Reflect の系譜は3代目である。** 「AI補記メモ」を 2026-08-09 に「ノートへのひとこと」へ作り直し、
> そのひとことを 2026-09-20 に撤去して「余白メモ」へ置き換えた。
> ひとことはAIが問いを投げてユーザーが答える形で、Reflect のなかでユーザーへの要求が最も重く、
> しかも1ノート1件・上書きなので溜まらなかった。余白メモはその要求を全部外している。
> 判断の記録は [reflect_margin_memo](../dev/features/reflect_margin_memo.md) と
> [reflect_remark](../dev/features/reflect_remark.md) が持ち、`_AI補記` フォルダの既存ファイルの削除だけがオプションに残っている。

**見た目のチャネルには持ち主が決まっている。** 色は年代と分野、形は面の役割、動きは出来事の強度。
書体と行間は何も表さない。装飾を足す前に [bearing_channels](../dev/system/bearing_channels.md) を読む。

**ノート本文へ書き込むのは蒸留の太字化だけ。** 余白メモも読書痕跡もサイドカーへ逃がしてある。
分野の確定と閲覧履歴は端末内に置き、バックアップからは除外している。
機能ごとのデータフローは [01_source_code_analysis.md](01_source_code_analysis.md) §5〜§6、
なぜそう作ったかは [features/](../dev/features/)・[system/](../dev/system/) が持つ。

## この俯瞰が答えないこと

**機能表は「何ができるか」までで、次の3つは持たない。**

| 知りたいこと | 見る先 |
|---|---|
| いまコードがどうなっているか。構成・規模・検証状態 | [01_source_code_analysis.md](01_source_code_analysis.md) |
| なぜそう作ったか、何を試して駄目だったか | [dev/features/](../dev/features/)・[dev/system/](../dev/system/)・[dev/lessons/](../dev/lessons/) |
| いま何が壊れている・足りないか | [_wip/current_issues.md](../_wip/current_issues.md)。`owner/` は課題を持たない。外から見た分析だけを [wip_analysis](07_wip_analysis.md) が持つ |

**実装が進んでも本書は自動では追いつかない。** 検査に載せていないので、ずれていることを CI は教えない。
それは意図した設計である。通しの見直しはオーナーの依頼があったときだけ行い、そのつど最終更新日を入れ替える。
