# デザインの持ち帰り帳 — 装飾と手触り

ペルソナはノート専門の UX デザイナー・読書愛好家・書籍編集者である。報告書の本体は `.agents/` にあり、git の管理外。

## 1. なぜ持ち帰るのか

> **オーナーの見方（2026-10-08）:** ストイックすぎるアプリは、どうしても飽きる。
> ある程度の装飾は要り、見た目にもこだわりが要る。

このアプリの文書は削る力が強い。物差し、手段の割り当て表、差し戻した実物の記録がそろっていて、
足す案はたいていどこかの行で止まる。止まること自体は正しいが、削るだけでは上の見方に応えられない。

**結晶がその例だった。** 規則はどれも守っていた。AI は選ぶだけ、1日1件まで、通知しない。
それでも一覧が文字の札の縦並びでは、溜まった実感が出なかった。結晶は溜まることそのものが役目なので、
見え方は飾りではなく機能の一部だった。宝石の陳列の案はそこから出た。

外部の3人は規約を読まずに書いたので、出す力だけがあって削る力が無い。
ここには、こちらの物差しで削った残りだけを置く。

## 2. 外した物差し

次に当たる案は載せていない。

- **書く・推敲する・製本する。** 汎用エディタはロードマップでやらないことに入っている。本文へ書くのは蒸留の太字だけ
- **AI に自由に書かせる、人格を持たせる。** 台帳の方向は選ぶ AI で、記憶も人格も持たせない
- **夜間や裏で AI を走らせる。** 同梱の SDK は、前面にいないアプリからの推論を `BACKGROUND_USE_BLOCKED` で止める
- **偶然の引きに意図を混ぜる。** 積読が問いに反応して光る、のような形
- **カメラで視線を追う**
- **取り下げ済みの装飾。** 紙の銘柄や書体の切り替え、栞、冊子の残り枚数を形で見せること
- **結晶ができたことを知らせる。** 結晶は通知もバッジも出さず、Rediscover の画面にも出さないと決めてある

## 3. 考え方として持ち帰るもの

**飾りは、もう在るものに形を与えるときに効く。** 冊子の束の縁は、状態が持っている10枚のうち9枚を
見せていなかったから足した。年代の紙色は最終更新からの経過を、宝石の棚は溜まった件数を見せる。
報告書の製本・積読・余白の地層も同じ動きをしている。反対に、何も運ばない飾りは試すたびに外れてきた。

**擬物化は、部品が小さいか多いと崩れる。** UX デザイナーが仲間の案に出した批評がそのまま当たる。
3D の積読タワーは冊数が増えると触れる場所が重なり、常に広い余白は本文を細くする。
[ui_design_principles](../dev/system/ui_design_principles.md) §3 の、大きい部品で成立した手を小さい部品へ移した失敗と同じ形である。

**1つの画面で手段を全部鳴らさない。** 報告書の融合案は、色・紙・光・音・触覚・動きを同時に使う。
こちらは手段ごとに意味を1つにしている → [bearing_channels](../dev/system/bearing_channels.md)。
持ち帰るときは、その案がどの行に載るかを先に決める。

## 4. 形として持ち帰るもの

各カードは「報告書では」「このアプリでは」「乗せる先」「先に決めること」の順に書く。

### 4.1 意味で縮むピンチ

**報告書では。** 2本指で縮めると、文字が小さくなるのではなく、例や修飾が引いて見出しと要点だけが残る。
もう一段縮めると概念の地図になる。段の境で、カメラの絞り環のような小さな手応えが返る。

**このアプリでは。** 地図の段は AI と埋め込みが要るので外し、3段に留める。全文、見出しと各節の最初の1文、見出しだけ。
どれも節の構造から AI なしで作れる。見出しだけの段で見出しを押すと、そこで全文へ戻る。
長いノートの全体を一目で掴み、目的の節へ跳ぶ道になる。

**乗せる先.** 台帳には「見出しごとのミニ要約」と「今の節以外を薄くするフォーカス」が、同じ節の構造に乗る2つの見出し UI として並んでいる。
先に作る側が両者の関係を決める、と書かれたまま止まっている。ピンチの段として1つの UI にまとめれば、2つは同じ UI の段になる。
ミニ要約ができたら、中の段の「最初の1文」をそれに差し替える。

**先に決めること.**
- 指に追従する動きの行は、今は冊子の面にだけ載っている。読む面へ広げる判断が要る
- ピンチは文字の拡大と取り違えられやすい。何が起きたかが見て分かる形にする
- 段は画面の中だけで持ち、ノートを替えたら全文へ戻す。今のノートの状態へ足すなら、契約2箇所への登録が要る

### 4.2 余白メモの地層

**報告書では。** 本の余白に、書いた年ごとに違う色のインクで注釈が積もる。
2022年の青、2024年のセピア、2026年の墨が並び、自分の読み方が育ってきたことと向き合える。

**このアプリでは。** 余白メモは書いた時刻と節を持ってサイドカーにあり、「この部分」には今の節のメモが新しい順に並ぶ。
これを書いた日で層に分け、層の境に日付を置くと、同じ節に何度立ち止まったかが見える。データは増えない。
北極星の「前回の自分の読み方と再会する」に一番近い。

**乗せる先.** 「この部分」のメモの並び → [margin_pane](../dev/features/margin_pane.md)。並び順は実機で調整してよいと設計書にある。
再会カードの「前回のメモを見る」で開いたときは、前回の層が上に来る。

**先に決めること.**
- **年を色で分けない。** 古さを色で言うのは読む面の紙の役目で、ペインで別の色の約束を作ると、同じ古さを2通りの色で言うことになる。
  古い層を薄くするのも採れない。文字の 4.5:1 と、文字色を透かさない検査の両方に当たる。
  層は区切りと日付と、重ねた紙の縁のような形で見せる
- **層をどの単位で切るか。** 日・読書1回・年。年に1度しか開かないノートと毎日開くノートで、効く単位が違う

### 4.3 結晶の棚の形

**報告書では。** 書き上げた原稿が、中身の量に応じた背幅の本になり、書棚の最上段に収まる。
積読タワーは冊数で高くなる。UX デザイナーは、冊数が増えると触れる場所が重なると批判した。

**このアプリでは。** 書く案は外すが、溜まったものを物として棚に並べる感覚は、結晶の一覧を宝石の陳列にする案と同じ向きにある。
台帳に残っている問いのうち2つに、答えの候補を出せる。

- **宝石の見た目を何で変えるか。** 結晶の根拠は2〜4本のノートである。根拠の本数で宝石の形を3種類に分けると、
  色を使わずに「何本をつないだ結晶か」が見える。色の持ち主は読む面が年代、冊子が分野なので、一覧へ色を持ち込まずに済む
- **件数が増えたときの棚。** 1年で最大365個ほどになる。月で棚板を区切り、宝石は格子に並べて重ねない。
  触れる大きさは1個ずつ確保する。3D の山のように積むと、タワーへの批判がそのまま当たる

**乗せる先.** 結晶の一覧を宝石の陳列にする案。台帳にあり、ロードマップでは Now に入っている。

**先に決めること.** 宝石の形に本数の意味を持たせることを、佇まいの割り当て表にどう書くか。
一覧の画面は、表にある読む面にも冊子の面にも当たらない。

### 4.4 見開きのノド

**報告書では。** 開いた Fold の見開きで、中央の綴じ代に影が落ち、紙がわずかに湾曲して見える。

**このアプリでは。** 見開きの冊子を作るときの、形の材料になる。冊子の紙は「束の一番上の1枚」の形で、
角を落とし、背後に縁を見せ、下に地を残している。見開きでは2枚が折り目で綴じられた形になり、ノドの影はその綴じを静止画で言う。
画面で最大の部品なので、小さい部品に装飾を移す失敗にも当たらない。

**乗せる先.** Fold の机の2段目、見開きの冊子 → [booklet_mode](../dev/features/booklet_mode.md) 判断9・[fold_experience](../dev/system/fold_experience.md)。

**先に決めること.**
- 影は形の一部で、残り枚数を運ばない。束の縁と同じ規則
- 端末の傾きに合わせて影を動かす案は採らない。センサーが要り、OS の「アニメーションを減らす」とも当たる
- 影は折り目に落ちるが、操作は折り目に置かない

### 4.5 面を越える紙片

**報告書では。** 左の面の文を右の面へはじくと、紙片が机の上を滑るように移り、着いたところで結合する。

**このアプリでは。** Fold の机の契約2「本文の一節を補助の面へ移すと、引用つきの余白メモになる」の、移す操作の手触りになる。
選んだ一節が指の下で短冊のような紙片になり、補助の面に落ちると余白メモの欄に収まる。
移した結果は余白メモなのでスマホと共有し、紙片の見た目と動きだけが Fold 専用の体験になる。

**乗せる先.** Fold の机の3段目、面を越える引用 → [fold_experience](../dev/system/fold_experience.md) §5。

**先に決めること.** 落とし先を折り目から離す。指に追従する動きの行を補助の面へ広げる判断は、4.1 と同じものになる。

### 4.6 触覚は1種類を、指で送る操作の終わりに

**報告書では。** 小口をめくる細かい振動、段を越える絞り環のクリック、カードがはまる磁石の手応え、製本プレスの重い衝撃。
周波数まで書き分けてある。

**このアプリでは。** 書き分けは持ち帰らない。触覚の強弱を出来事で変えると、出来事の強さを運ぶ別の行へはみ出す。
持ち帰るのは「指で送った操作が止まった瞬間に、1種類だけ返す」ことである。
冊子のめくり終わり、4.1 の段の切り替わり、4.5 の紙片が収まった瞬間が当たる。アプリは今、触覚を1か所も使っていない。

**乗せる先.** 台帳にある「めくり終わりの微細な触覚」。手触りは 2026-09-07 に問題なしと決着していて、
足りないと感じるかがそのまま採否になる、と台帳に書かれている。§1 のオーナーの見方は、その採否を開け直す理由になる。

**先に決めること.** OS の触覚の設定に従うこと。オプションで切れる口を置くか。

## 5. 持ち帰るときの手順

1件ずつ台帳へ移す。移すときは台帳の様式で、出所・適合理由・足場・懸念・規模感を書き直し、ここのカードを消す。
どれも見た目に触る案なので、着手前にモックで合意する → [ui_design_principles](../dev/system/ui_design_principles.md) §4。
