## 6. 横断して見えたこと

1. **撤去してから足すと、足す側の設計が軽くなる。** 「この部分」の設計は、常駐マスコットと質問・クイズが無い前提で書けた。
   入口の取り合いや、浮くものと面の重なりを考えずに済んだ。撤去は 09-30 の1日で終わり、その翌日から段1に入った
2. **段に切ると、実機の役割がはっきりする。** 画面の作り直し・キーボード・フォーカスは実機でしか出ず、データの照合は机上で閉じる。
   段2は実機で6件、段3は実機で0件だった。段の中身で、実機を厚くするか薄くするかを先に決められる
3. **検証側が止まっても、条件の記録があれば戻れる。** 段3の実機検証は、検証側のトークン切れで1度止まった。
   条件を中身のハッシュで書いてあったので、同じ条件のまま再開でき、それまでの成功を引き継げた
4. **検証側の回避は、手順書に戻らない。** 起動のケースの手順書にある数え方は、1枚の画面を10と数える。
   検証側は手順を変えて正しく数えたが、手順書は変わっていない。回避した記録は進行表に残るのに、直す契機が来ない
