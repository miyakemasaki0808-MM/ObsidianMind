## 0. 北極星 — このアプリは何であろうとしているか

> **Vigilith AI は「過去の自分の思考と再会し、もう一段深める、オンデバイスAIの読書相手」である。**

このアプリの心臓は **Rediscover（ランダムに過去ノートを引く）**。単なるVaultビューアではなく、「たまたま引いた過去のノート」を起点に、**AIが読書相手として思考を深める手伝いをする**ことに独自性がある。

### 3つのコア価値（ぶらさない軸）

1. **再発見（Rediscover）** — 偶然を"再会"へ変える。アプリの入口であり心臓。
2. **省察（Reflect）** — ノートの中身を育てる（蒸留）／前回の自分の読み方と再会する（ReadingTrace）。
3. **オンデバイス完結** — 全AIは端末内Gemini Nano。クラウド送信ゼロ＝プライバシーが差別化の土台。この制約は弱点ではなく設計哲学。

### 判断基準（機能を足すかどうかの物差し）

- **Rediscover→Reflectのループを濃くするか？** YESなら優先。単独で便利なだけの機能は後回し。
- **オンデバイスNanoの制約（出力256トークン・Mutex直列・60秒）の中で成立するか？**
- **機能ごとに堅牢性レベルを意図的に選べているか？**（蒸留＝重厚 / ReadingTrace＝ベストエフォート）
- **本質（ノートを読む）を妨げないか？** AIは主役ではなく相手役。
- **ユーザーに意識させる必要があるか？** ReadingTrace で分かったのは、**AIの役割を「創作」から「要約」に落とすと、ユーザーの操作を増やさずに価値を出せる**ことだった（→ [reflect_reading_trace](../dev/features/reflect_reading_trace.md) の「採らなかった案 — TimeCapsule」）。新機能に導線を足す前に、既にある行動の痕跡で足りないかを先に問う。

## 0.5 ロードマップへの昇格基準

**[current_issues.md](current_issues.md) の優先度は「壊れている度合い」、[feature_ideas.md](feature_ideas.md) の🎯は「北極星への適合度」であって、どちらも「ユーザーがどれだけ気づき、困る／喜ぶか」を直接測っていない。** 台帳・資料からNow/Next/Laterへ拾うときだけ、両方のプールに共通の物差しを1本挟む。

### 判定軸: ユーザーインパクト（2軸のOR）

- **頻度** — 常用導線（Rediscover起動・ノートを開くたび、など）で踏むか、稀な操作（オプション画面の奥・特定の連続操作、など）でしか踏まないか
- **重さ** — 気づいたときが実害（データを失う・機能が使えない・誤解を与える）か、単なる違和感か

**どちらか一方が強ければ昇格候補。両方弱いものは台帳・資料に留め置く。**
**開発コスト（規模感）はこの判定に使わない** — 選ばれた後にNow/Next/Laterのどこへ置くかで別途効かせる。

### 優先度／🎯だけでは昇格しない

current_issuesの優先度・feature_ideasの🎯は「その台帳内での重み」であって、そのままroadmapへ乗せる理由にはならない。実例:

| 項目 | 出どころの評価 | ユーザーインパクト | 判定 |
|---|---|---|---|
| N-12（冊子モード） | 🎯・規模感中 | 常用導線 × 体験全体の摩擦軽減 → **高** | 昇格候補 |
| TRACE-4（返事の退避手段なし） | 優先度中 | 稀だが気づいたときの実害が最大級（自分の言葉が消える） → **高** | 昇格候補 |
| ANNOT-4（AI補記メモ削除の常設UI） | 優先度低 | オプション画面の奥。気づいても違和感程度 → **低** | 台帳に留め置く |
| MAINT-2（GradientHeaderの手動契約） | 優先度低・極小 | ユーザーには何も見えていない開発側の負債 → **低** | 台帳に留め置く |

**既存のLater項目（L-1・L-2・L-4・L-5）は本基準の導入前に乗っている。** 次回の見直し（§更新運用）で、この基準に当て直す。

### 運用

- 昇格判定は単発では行わず、§更新運用の「大きめのPRやマイルストーン到達時の見直し」と同じタイミングでまとめて行う。
- 昇格しても current_issues / feature_ideas 側の記述は消さない。**正本は元の台帳に残る**（roadmap冒頭の「基準」節と同じ非対称）。roadmap側は該当IDへリンクするだけにする。

## 🟡 Next — 次に取り組む（ループを豊かにし、土台を強くする）

**テーマ:「再会」を深く、機能追加に耐える土台へ。**
Nowを閉じた後、再会体験を濃くする拡張（X-2）と、蒸留の次の粒度（X-3）を検討する。
X-3は段階2の候補生成・非重複保存と主要な表示修正まで実機確認済みで、短文例外の表示修正を残す。

### X-2. 「意図して問いを残す」機能（旧 TimeCapsule の核）
- **なぜここ:** ReadingTrace は行動データなので「**何を考えていたか**」を回収できない。「前回は40%で止まった」は「前回は〇〇が引っかかった」ではない。思考の連続性は依然として未達。
- **なぜ今回見送ったか:** 「無意識に作られる」と「未来へ託す意図」は原理的に両立しない。代替としてセクションチャットの質問を使おうとしたが、**チャットに自由入力がなく**（`SectionChatSheet.kt` に `TextField` がない）AI候補のタップだけだったため、「自分の言葉の問い」にならなかった。→ [reflect_reading_trace](../dev/features/reflect_reading_trace.md) の「採らなかった案 — TimeCapsule」
- **取りうる道:** (a) セクションチャットに自由入力を足して「自分の言葉の問い」を痕跡に加える／(b) 作成は無意識のまま、再会カードに「これはまだ考えたい」を置いて**意図を再会側に宿す**／(c) 明示ボタンの機能として独立させる。**(b) が「意識させない」原則と両立する唯一の道**なので、まずここから検討する。

### X-3. 蒸留候補を語句単位へ細分化（段階2）
- **現在地:** 括弧内 `Term`、表層重複排除、最大2件、細かい範囲を残す非重複化を実装し、
  Pixel実機で候補集合、親の位置を借りる表示、語句種別、「箇所」単位、語句だけの保存まで確認した。
- **残り:** 短文例外・機能説明の「文」固定は修正済み（状態名からも単位を外し、走査検査を追加）。
  **実機の再確認だけが残っている** → [current_issues](current_issues.md) DISTILL-4。
- **規模感:** 小。文・句・語句の対象・対照を実機で再確認すれば閉じる。

> **X-3とは別に、蒸留v1の書き込み側が未検証のまま残っている**
> → [current_issues](current_issues.md) DISTILL-5（台帳で唯一の「高」）。
> **粒度の話とは別の穴**で、**このアプリで唯一ノート本文を書き換える経路の保証**にあたる。
> 段階3（太字範囲のユーザー調整 → [feature_ideas](feature_ideas.md) N-14）の着手条件はここが埋まること。
> 実機の依頼内容は作業ツリーの `review/pending_device_validation.md`（未追跡・使い捨て）が持つ。

## 🔵 Later — 将来の方向（北極星の解像度を上げる）

**テーマ:「読書相手」としての深みと、Vault規模への強さ。**
ループが確立した先の、体験の質とプロダクトの堅牢性を上げる投資。優先度は状況で見直す。

### L-1. フォーカスセクション文脈での関連ノート推薦
- **AI入力の抜粋化と予算調整は完了済み**（経緯は [change_history](../dev/change_history.md) と
  [ai_input_excerpt](../dev/system/ai_input_excerpt.md) が持つ）。**ここに残るのは1件だけ。**
- **残る1件:** 関連ノートは「ノートを開いた瞬間」に自動起動するのに対し、フォーカスはスクロールで動く。
  **どの時点のセクションで推薦するかを先に決める**必要がある。
  現在の全体抜粋を置き換えるか補助シグナルにするかも含め、別機能として扱う
  → [related_notes_ai](../dev/features/related_notes_ai.md)

### L-2. Reflect機能群の連携
- 蒸留（重要文の太字化）× ReadingTrace（読書痕跡）× セクションAIを横断させる。例：前回止まった箇所を蒸留の候補選定に効かせる、痕跡をセクションAIのコンテキストに含める。「読書相手」としての一貫した人格に近づける。→ [reflect_reading_trace](../dev/features/reflect_reading_trace.md)

### L-4. Vault規模・堅牢性への投資（必要になったら）
- YAML/Markdown対応拡充（画像・クリックリンク・複数行YAML）、キャッシュ戦略の見直し。ユーザー体験を壊す顕在化があった時に引き上げる。
  **Markdown対応拡充の課題は台帳から削除済み**（2026-08-02。困ってから新規IDで起票する方針）。
- **リストの入れ子・番号・タスク混在は 2026-08-02 に対応した**（→ [system/markdown_rendering.md](../dev/system/markdown_rendering.md)）。残るのはクリック可能リンク・画像・埋め込み・数式。
- **Markdown対応拡充を検討する際は、読書体験だけでなくAI品質側の効果も一緒に数える。** リストの件では、失われていたのが描画だけでなくAI入力の順序情報でもあったため、読書体験だけで測ると過小評価になっていた。**残っている項目にも同じ問いを当てる** — 画像は代替テキストが、リンクは遷移先のタイトルが、いずれもAI入力側で意味を持ち得る。

### L-5. 公開可能な成果物にする（→ current_issues REL-1）
- `applicationId` は `com.vigilith.ai` へ確定し release build type も入ったが、生成物は依然 `app-release-unsigned.apk` で `isMinifyEnabled = false`。**署名も R8 も未設定。** → [current_issues.md](current_issues.md) REL-1
- **設定を1行変える作業ではない。** ML Kit GenAI はリフレクションで解決される部分があり、縮小で消えると**release ビルドの実機でだけ全AI機能が落ちる**。JVMテストは縮小前のクラスを見るので検出できない。**keepルール＋AI 7経路の release 実機一巡がセット**になる。配布の意思が固まってから着手する。
- **効果とコスト:** 開発・リリース運用 7.5 → 8.5（**単一軸では最大の伸び**）。コストは大で、
  R8を有効にした瞬間にJVMテストの守備範囲外へ出る。

> **上の「効果」は品質再評価の軸別スコアから引いた見込みで、測定ではない**（→ [lessons.md](../dev/lessons.md) L12）。
> 総合の上がり幅だけを根拠に順序を決めない。現在の軸別評価は
> [レビュー一覧](../review/README.md) を正とする。

## 意図的にやらないこと（Non-Goals）

### ReadingTrace の move/rename 追従
**本文で「着手しない」と結論しているので Next には置かない。** 引き当てミスが**未読ノートで常時起きる**ため、
ミス時にフォルダ全走査をすると Rediscover が毎回重くなる。痕跡を失っても `.md` は無傷なので設計原則の範囲内
→ [reflect_reading_trace](../dev/features/reflect_reading_trace.md)（判断7: 可搬キー）。
**孤児掃除は手動削除まで実装済み**で、ここに残るのは追従だけ。


北極星に照らして、当面やらないと決めるもの。判断のブレを防ぐために明記する。

- **クラウドAIへの切り替え/併用** — オンデバイス完結がプライバシーの土台。Nanoの制約は受け入れるコストであって、逃げる先ではない。
- **汎用ノート編集機能** — 本アプリは「読む・再発見する・省察する」相手役。フルエディタ化はObsidian本体の領分。**ノート本文への書き込みは蒸留の太字化だけ**に限定し、それ以外（補記・読書痕跡）はサイドカーへ逃がす。
- **単独で便利なだけの機能** — Rediscover→Reflectループを濃くしないものは、どれだけ一般的でも優先しない。

## 更新運用

- 大きめのPRやマイルストーン到達時に、Now/Next/Laterの中身を1回見直す。
- **完了項目は取り消し線を残さず削除する。** 記録は [change_history.md](../dev/change_history.md) が持つ。
  取り消し線で残すと、完了分がNowの先頭に溜まって「次に何をやるか」が読み取れなくなる。
- 削除でNowが空いたらNextを繰り上げる。**番号は振り直さない**（設計書・`current_issues` が番号で参照するため）。
- 北極星（§0）は安易に変えない。変える時は「なぜ変えたか」をこのセクションに残す。
