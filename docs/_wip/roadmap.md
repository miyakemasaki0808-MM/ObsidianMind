## 0. 北極星 — このアプリは何であろうとしているか

> **Vigilith AI は「過去の自分の思考と再会し、もう一段深める、オンデバイスAIの読書相手」である。**

このアプリの心臓は **Rediscover（ランダムに過去ノートを引く）**。単なるVaultビューアではなく、「たまたま引いた過去のノート」を起点に、**AIが読書相手として思考を深める手伝いをする**ことに独自性がある。

### 3つのコア価値（ぶらさない軸）

1. **再発見（Rediscover）** — 偶然を"再会"へ変える。アプリの入口であり心臓。
2. **省察（Reflect）** — ノートの中身を育てる（蒸留）／前回の自分の読み方と再会する（ReadingTrace）。
3. **オンデバイス完結** — 全AIは端末内Gemini Nano。クラウド送信ゼロ＝プライバシーが差別化の土台。この制約は弱点ではなく設計哲学。

### 判断基準（機能を足すかどうかの物差し）

- **Rediscover→Reflectのループを濃くするか？** YESなら優先。単独で便利なだけの機能は後回し。
- **オンデバイスNanoの制約（出力256トークン・Mutex直列・60秒）の中で成立するか？**
- **機能ごとに堅牢性レベルを意図的に選べているか？**（蒸留＝重厚 / ReadingTrace＝ベストエフォート）
- **本質（ノートを読む）を妨げないか？** AIは主役ではなく相手役。
- **ユーザーに意識させる必要があるか？** ReadingTrace で分かったのは、**AIの役割を「創作」から「要約」に落とすと、ユーザーの操作を増やさずに価値を出せる**ことだった（→ [reflect_reading_trace](../design/reflect_reading_trace.md) §2）。新機能に導線を足す前に、既にある行動の痕跡で足りないかを先に問う。

### N-1. 読書痕跡の孤児削除（段階0〜4）

**着手対象は「孤児のみ削除」。** 検討途中で一度「全リセット」へ寄せたが、
**両者は代替物ではない**と整理して孤児削除へ戻した — 全リセットは逃げ道であって、
SYNC-1 の問題（ファイル数の単調増加）には答えない。

**§14 に書いた順序から2点ずらしている。理由もここに置く。**

1. **SYNC-2（X-4）は前提から外した。** 古くなるのは*セッション中のランタイム索引*で、
   掃除は `_ReadingTraces/` を**その場で新規列挙すれば足りる**。再会照合の話であって掃除とは独立。
2. **証拠索引は手動削除には要らない。自動化（段階5）に要る。** 手動削除の前に必要なのは
   **走査を正直にすること**で、候補を「完全に走査できた上で見つからなかったもの」に絞れれば、
   証拠の積み上げが埋めるのは残余リスクだけになる。**これで規模が中→小〜中に戻る。**

| ~~**1**~~ | **痕跡の列挙API** — ✅ 2026-08-01 完了。`listKeys`（キャッシュを経由しない新規列挙）と `loadByKey`（孤児はパスが分からないため必要）。`ReadingTraceKeyListing` で**列挙失敗と空集合を型で分けた** | `data` |
| ~~**2**~~ | **孤児判定の純関数** — ✅ 2026-08-01 完了。`assessReadingTraceOrphans`。遮断器5種を変異検証済み。**急増ガードを resolve の前に置いて安全ガードとコスト上限を兼ねさせた**（候補のパスはファイルを読まないと分からないため） | `domain` |

- **既存機能は壊さない** — Rediscover・さがす・関連ノートは不完全でも見つかった分で動き続ける
  （今より悪くならない）。完全性フラグを見るのは掃除だけ。

## 🟡 Next — 次に取り組む（ループを豊かにし、土台を強くする）

**テーマ:「再会」を深く、機能追加に耐える土台へ。**
Nowを閉じた後、再会体験を濃くする拡張（X-2）と、長期運用のための地ならし（X-3・X-4・X-6）を行う。
**新機能側の選択肢は X-2 ただ1つで、残りはすべて土台側である**点を意識して順序を決める。

### X-2. 「意図して問いを残す」機能（旧 TimeCapsule の核）
- **なぜここ:** ReadingTrace は行動データなので「**何を考えていたか**」を回収できない。「前回は40%で止まった」は「前回は〇〇が引っかかった」ではない。思考の連続性は依然として未達。
- **なぜ今回見送ったか:** 「無意識に作られる」と「未来へ託す意図」は原理的に両立しない。代替としてセクションチャットの質問を使おうとしたが、**チャットに自由入力がなく**（`SectionChatSheet.kt` に `TextField` がない）AI候補のタップだけだったため、「自分の言葉の問い」にならなかった。→ [reflect_reading_trace](../design/reflect_reading_trace.md) §2
- **取りうる道:** (a) セクションチャットに自由入力を足して「自分の言葉の問い」を痕跡に加える／(b) 作成は無意識のまま、再会カードに「これはまだ考えたい」を置いて**意図を再会側に宿す**／(c) 明示ボタンの機能として独立させる。**(b) が「意識させない」原則と両立する唯一の道**なので、まずここから検討する。

### X-3. ReadingTrace の move/rename 追従
- **孤児掃除は N-1 へ移した**（Now）。ここに残るのは move/rename 追従だけ。
- **v1でやらなかった理由:** 引き当てミスが**未読ノートで常時起きる**ため、ミス時にフォルダ全走査をすると
  Rediscover が毎回重くなる。痕跡を失っても `.md` は無傷なので設計原則の範囲内
  → [reflect_reading_trace](../design/reflect_reading_trace.md) §8・判断7。
- **N-1 が終わってから考える。** 孤児削除が入れば「改名で残った古い痕跡」は掃除される側に回るので、
  **追従しないことの実害が減る。** 先に N-1 の結果を見てから、追従がまだ要るかを判断する。

### X-4. ReadingTraceの同期索引を整える
- **同期索引:** `_ReadingTraces`のkey→Uri索引はプロセス中に再走査されず、別端末から同期された新規ファイルを認識しない。ミス時だけの再走査やTTLで、常時全走査を避けつつ最終的整合性を持たせる。→ [current_issues.md](current_issues.md) SYNC-2
- **累計回数は C案（2026-07-26）で解消済み。** `totalVisitCount` とサイドカー schema v2 で、直近30件の保持数と「これまで開いた回数」を分離した。**残っているのは同期索引だけ。**
- **N-1（孤児削除）の前提ではない。** 一度そう整理しかけたが、古くなるのは*セッション中のランタイム索引*で、
  掃除は新規列挙すれば足りる。**これは再会照合の課題**であって、順序の制約を持たない。

### X-6. AI状態UXの統一
- **なぜここ:** AI非対応・モデル未準備・一時エラーの見せ方が機能ごとにバラつく。蒸留の「インライン説明フォールバック」を良い先例として、要約・検索・クイズ・補記へ横展開。**ReadingTrace は例外として扱う**（意識させない機能なので、失敗は黙って劣化させるのが仕様）。→ [current_issues.md](current_issues.md) AI-2

## 🔵 Later — 将来の方向（北極星の解像度を上げる）

**テーマ:「読書相手」としての深みと、Vault規模への強さ。**
ループが確立した先の、体験の質とプロダクトの堅牢性を上げる投資。優先度は状況で見直す。

### L-1. AI入力抽出の残り（予算調整とフォーカスセクション文脈）
- **本体は 2026-07-28 に完了した。** 先頭固定長切り出しは、見出し骨格＋冒頭＋末尾を用途別予算へ配分する抜粋へ置き換わり、実機確認も済んでいる（[PR #43](https://github.com/miyakemasaki0808-MM/ObsidianMind/pull/43)・[ai_input_excerpt](../design/ai_input_excerpt.md)）。**ここに残るのは意図的に切り離した2件だけ。**
- **予算値の調整は 2026-08-01 に完了し、打ち止めにした**（→ [ai_input_excerpt](../design/ai_input_excerpt.md) §14）。関連ノートを 600 → 800 へ上げて実機確認まで実施したが、**体感は変わらなかった**。長く最優先としていた「注意書きが予算の38%」も**トークンでは1.7%**で、短縮注意書き案とともに撤回。**予算を減らしても増やしても品質が動かなかったことで、§9.1「効いたのは量ではなく配置」が両方向から追認された。** 関連ノートの品質に不満が出たら、**原因は予算ではなく候補の選び方・再ランク・指示文の側**を疑う。
- **フォーカスセクション文脈:** [related_notes_ai](../design/related_notes_ai.md) Phase 1 の未実装案。関連ノートは「ノートを開いた瞬間」に自動起動するのに対しフォーカスはスクロールで動くため、**どの時点のセクションで推薦するかを先に決める**必要がある。現在の全体抜粋を置き換えるか補助シグナルにするかも含め、別機能として扱う。

### L-2. Reflect機能群の連携
- 蒸留（重要文の太字化）× ReadingTrace（読書痕跡）× セクションAIを横断させる。例：前回止まった箇所を蒸留の候補選定に効かせる、痕跡をセクションAIのコンテキストに含める。「読書相手」としての一貫した人格に近づける。→ [reflect_reading_trace](../design/reflect_reading_trace.md)

### L-3. 統合テストの中身
- **土台の話はここには無い**（2026-08-01 に閉じた）。ここに残るのは中身 — SAF走査・補記保存/削除・端末AI・Compose Navigation・全画面遷移・画面回転/プロセス再生成・連続操作時の競合。いずれも実端末が要る。→ [current_issues.md](current_issues.md) TEST-2
- **着手条件は2つとも満たした。** ①instrumentation の土台が緑（2026-08-01・Android 16 で 2/2 成功）
  ②SAF境界が gateway の裏へ入った（2026-08-01・→ [saf_boundary_gateway](../design/saf_boundary_gateway.md)）。
- **JVMで書けるものは JVM へ寄せ切った。** さがす・補記の世代照合と走査キャッシュは
  2026-08-01 に21件のJVMテストで覆われた（5つのガードを削る変異で確認済み）。
  **ここへ残すのは実端末でしか確かめられないものだけ**にする — 逆に言えば、
  instrumentation に何かを書きたくなったら、まず「JVMで書けないか」を先に問う。

### L-4. Vault規模・堅牢性への投資（必要になったら）
- YAML/Markdown対応拡充（画像・クリックリンク・複数行YAML・ネストリスト）、キャッシュ戦略の見直し。ユーザー体験を壊す顕在化があった時に引き上げる。→ [current_issues.md](current_issues.md) FEAT-1
- **ordered list の番号は描画だけでなくAI入力でも失われる。** 抜粋も同じパーサを通すため、番号自体に意味があるノート（手順書など）では順序がモデルへ届かない。Markdown対応拡充を検討する際は、読書体験だけでなくAI品質側の効果も一緒に数える。

### L-5. 公開可能な成果物にする（→ current_issues REL-1）
- `applicationId` は `com.vigilith.ai` へ確定し release build type も入ったが、生成物は依然 `app-release-unsigned.apk` で `isMinifyEnabled = false`。**署名も R8 も未設定。** → [current_issues.md](current_issues.md) REL-1

- **効果とコスト:** 開発・リリース運用 7.5 → 8.5（**単一軸では最大の伸び**）。コストは大で、
  R8を有効にした瞬間にJVMテストの守備範囲外へ出る。

> **上の「効果」は品質再評価の軸別スコアから引いた見込みで、測定ではない**（→ [lessons.md](../lessons.md) L12）。

## 意図的にやらないこと（Non-Goals）

北極星に照らして、当面やらないと決めるもの。判断のブレを防ぐために明記する。

- **クラウドAIへの切り替え/併用** — オンデバイス完結がプライバシーの土台。Nanoの制約は受け入れるコストであって、逃げる先ではない。
- **汎用ノート編集機能** — 本アプリは「読む・再発見する・省察する」相手役。フルエディタ化はObsidian本体の領分。**ノート本文への書き込みは蒸留の太字化だけ**に限定し、それ以外（補記・読書痕跡）はサイドカーへ逃がす。
- **単独で便利なだけの機能** — Rediscover→Reflectループを濃くしないものは、どれだけ一般的でも優先しない。
