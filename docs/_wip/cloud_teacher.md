# クラウドAIの先生（A-13）の構想

**性質:** 使い捨ての検討資料。[feature_ideas](feature_ideas.md) の A-13 の詳細を、長さのためにここへ分けた。項目の要約と置き場は feature_ideas が持つ。

- **内容:** 端末の Nano を日々の読書の相手役に据えたまま、クラウドの Gemini API を**ユーザーが訪ねる先生**として足す。
  先生は Nano では扱えない量、つまり複数のノートや長文の全体を読み、ユーザーに向けて自分の言葉で説明する。
  設定で有効にしたときだけ使え、初期値はオフ。
- **出所:** 2026-11-25、オーナー起案。Gemini の Pro プラン（Google AI Pro）の特典で、Google Cloud のクレジットが毎月10ドル分使えると分かったことが契機。
- **設計思想は Local First, Cloud Optional.** オンデバイスが標準で、クラウドは補う側に回る。先生がいなくても全機能が今どおり動き、
  使うかどうかは利便性・プライバシー・費用を見てユーザーが決める。
- **狙い:** Nano の処理能力を補う。ノートを読むアプリから、知識の分析と学びの支えへ広げる。Google Cloud の開発経験を得る。クレジットを活かす。
- **先生の役（2026-11-25、オーナー判断）:**
  - **教わるのはユーザー。** Nano の出力を採点・添削する役は持たない。Nano の品質を測るなら [ai_quality_measurement](../dev/system/ai_quality_measurement.md) の側で扱う
  - **自分の言葉で説明してよい。** [feature_ideas](feature_ideas.md) の §0 の「選ぶAI」の例外
  - **生徒のこれまでを覚える。** ユーザーの質問と先生の答えを、可能な限り残す。
    ユーザーは覚えたものをアプリで一覧して、1件ずつでも全部でも消せる。置き場所は下の検討要素
  - **呼んだときだけ来る。** 有効にしただけでは送らない（下の非機能要件）ので、ノートを開くと自動で走る生成（要約・分野判定・結晶など）は Nano のまま残る
  - **送信中だけ姿を見せる。** 先生へ送ってから答えが届くまで先生のキャラクターを画面に出し、終われば消す。
    **「先生が見えている」と「先生とやり取りしている」を1対1にする。** ただし見えるのは先生への送信だけで、ML Kit の計測の送信（下）は表に出ない
  - **キャラクターは Vigilith と別に新しく作る。** Vigilith は端末内の相棒で、「生成せず、選び・指し・運ぶ」「アプリ内に常駐させない」と決めてある
    （→ [character_vigilith](../dev/features/character_vigilith.md)）。姿を分けると、端末の AI かクラウドの先生かが見た目で分かる
- **検討要素: 先生の記憶をどこに置くか。** どちらでもユーザーから見れば先生は覚えている。
  覚えたもののうち毎回どれを渡すかを選ぶ仕組みは、どちらにも要る。

  | | クラウド（Firestore） | 端末 |
  |---|---|---|
  | 残る場所 | Google Cloud | 端末だけ。質問のたびに、関係する過去のやり取りを選んで一緒に送る |
  | 消すとき | アプリから消せるが、アプリを消してもクラウドに残る | アプリから消せて、アプリを消せば消える |
  | 別の端末 | 引き継げる | 引き継げない |
  | feature_ideas の §0 | 「ステートレス維持」の例外になる | 「記憶は端末側が持ち、AI自身には持たせない」に収まる |
  | 費用 | Firestore の保存と読み書きがかかる | クラウドの保存はかからない |

  - **端末に置くなら、知識索引の DB には同居させない。** 索引は作り直せる写しで、正にしないと決めてあり、Vault を替えると消す
    （→ [knowledge_index](../dev/system/knowledge_index.md) 判断1・判断3）。先生の記憶は作り直せない正なので、別の置き場が要る。
    置き場は要約の控えや索引と同じく `noBackupFilesDir` にし、端末の自動バックアップにも載せない（→ 同 §9）
  - 端末に置くなら、Vault を替えたときに記憶を分けるか持ち越すかも決める
- **着手の前に、AIをオンデバイスに限った ADR を改める。この候補で一番重い前提である。**
  その ADR（[一覧](../dev/decisions/README.md)の0002番）は「任意でクラウド」も退けている。
  権限を1つ持てば「送っていない」を構造で保証できず、設定の状態に委ねた保証は保証ではない、という理由である。
  本案は **1つのAPKが INTERNET を持ち、設定のON/OFFで守る**形を採る（2026-11-25、オーナー判断）ので、これを置き換える新しい ADR が要る。
  - **オフにしても何も送らないことにはならない。** ML Kit の計測の送信経路が今止まっているのは権限を除いているからで
    （→ [dependency_policy](../dev/system/dependency_policy.md) 判断5）、INTERNET を戻すと先生の設定に関係なく動き出す。
    送るのは ML Kit 自身の計測で、ノート本文を送る経路ではないと見ている（中身は確かめていない）。新しい ADR はこれを帰結に書く
  - 権限の検査（`verify<Variant>ManifestPermissions` の `expected` と `ci.yml`）、dependency_policy 判断5、
    実機ケース [network_permission](../review/device_validation/network_permission.md) を同時に書き換える。
    **数える検査そのものは残す** — Firebase などの依存が INTERNET 以外の権限を持ち込んだときに気づくため
  - **ロードマップの北極星と Non-Goals も同時に改める。** 北極星の3つのコア価値の3本目「オンデバイス完結」（全AIは端末内の Nano、クラウド送信ゼロ）と、
    意図的にやらないことの「クラウドAIへの切り替え/併用」は、どちらも本案と正面から食い違う（→ [roadmap](roadmap.md) §0）。
    roadmap は北極星を変えるときに「なぜ変えたか」を更新運用の節へ残すと決めているので、新しい ADR と同じ日にそこへ書く。
    書き換えの向きは、この案の設計思想の Local First, Cloud Optional — 端末の Nano を標準にし、クラウドは呼んだときだけ補う側に置く
- **機能要件:**

  | 番号 | 項目 | 要件 |
  |---|---|---|
  | 1 | 有効化 | 設定でON/OFFを切り替えられる。初期値はOFF |
  | 2 | 接続 | 有効なときに Gemini API を使える |
  | 3 | 振り分け | 処理の内容で Nano と先生を使い分ける |
  | 4 | 回数の制限 | 日・月の単位で利用回数を制限できる |
  | 5 | 費用の制限 | 月の予算と、1回あたりのトークン数に上限を置ける |
  | 6 | 利用状況 | 回数・残り回数・消費トークン・推定料金を見られる |
  | 7 | 上限到達 | 上限に達したら送信を止める |
  | 8 | オフライン | 通信できなくても Nano の機能は今どおり動く |
  | 9 | 送信の確認 | 送る対象をユーザーが確かめて選べる |
  | 10 | 失敗 | 通信の失敗が既存機能とノートに影響しない |
  | 11 | 記憶 | 質問と先生の答えを覚え、ユーザーが一覧して消せる |
  | 12 | 送信中の表示 | 先生への送信中だけ先生のキャラクターを出す |

- **非機能要件:**
  - **独立性・保守性・拡張性:** 先生の有無が既存機能に効かない。Nano と先生の実装の責務を分け、モデルや提供元の差し替えに耐える
  - **鍵:** API キーをソースにも APK にも持たない。中継側の Secret Manager に置く
  - **プライバシー:** 有効にしただけではノートを送らない。送るのは先生を呼んだときだけ
  - **費用:** 中継側でも上限を強制し、意図しない従量課金を止める
  - **追跡:** 使ったモデル・日時・消費トークン・成否を記録する
- **先生に頼むことの候補:** 複数ノートの横断分析／ノート間の関連と食い違いの検出／知識の体系化／足りない知識と理解の穴の指摘／
  長文ノートの要約（Nano の出力上限と抜粋の制約を受けない）／複数ノートからの Q&A／学習計画／
  ノートから絵を描く（→ [feature_ideas](feature_ideas.md) の A-16）
- **構成:** 端末（Kotlin / Compose）→ 中継（Cloud Run）→ Gemini API。認証は Firebase Authentication、利用状況は Firestore、鍵は Secret Manager。先生の記憶の置き場所は上の検討要素。
  **中継を置く狙いはクラウド開発の学習**で、配布への備えではない（2026-11-25、オーナー判断）。使うのはオーナー1人なので、利用者の管理と料金の負担方式は決めなくてよい。
- **クレジット（2026-11-25 に公式の案内で確認）:**
  - Google AI Pro には毎月10ドル分の GenAI・Google Cloud 向けクレジットが付く。1回分は付与から12か月有効で、月をまたいで積み上がる（期限の早いものから使われる）
  - 受け取るには Google Developer Program のプロフィールを有効にし、AI Studio か特典のページで Cloud Billing のアカウントへ引き換える。使えるのはプランの契約者本人だけ
  - **Gemini API の支払いに使える。ただし Cloud Billing で Gemini API を使うには、5ドル以上の前払い残高が要る。** クレジットだけでは始められない
  - Cloud Run・Firebase にも使える。Firestore と Secret Manager は名指しされていないが、対象外の一覧に当たらなければ使える
  - 出典: [AI Studio でのクレジットの引き換え](https://blog.google/innovation-and-ai/technology/developers-tools/google-cloud-credits-gdp-ai-studio/)・[Google Developer Program の特典 FAQ](https://developers.google.com/profile/help/benefits)
- **段取り:**
  1. Gemini API への接続と、トークン消費・料金の検証。**アプリの外（Mac のスクリプト）で済み、APK も ADR も触らない**（→ feature_ideas の型2「測る道具はアプリの中に作らなくてよい」）
  2. Nano と先生の責務の分離と、有効化の設定。ここで ADR を改める
  3. 中継・認証・利用の制限
  4. 先生に頼む機能
  5. 品質とセキュリティの検証、費用の最適化
- **足場:**
  - [`AiClient`](../../app/src/main/java/com/example/newproject/ai/AICoreClient.kt) は `checkAvailability`・`generate`・`downloadModel` の3つで、**Nano の形をしている**（モデルのDLと、端末の可否の判定）。
    先生を2つ目の実装として差すと DL の口が空になり、通信の失敗・上限到達・費用という Nano に無い状態が増える。差すか別の口にするかが「責務の分離」の中身になる
  - 抜粋の予算（→ [ai_input_excerpt](../dev/system/ai_input_excerpt.md)）と出力の上限は Nano に合わせてある。先生は長文を丸ごと読めるので、予算を提供元ごとに持つ
  - 複数のノートを読むには本文の一括読み出しが要り、A-4 と同じく前例が無い。どのノートを渡すかは知識索引（→ [knowledge_index](../dev/system/knowledge_index.md)）から引ける
  - 通信の実装は `ai` に置ける（Android 依存可）。`controller` の Android 非依存は崩さない（→ [architecture](../dev/system/architecture.md) 判断5）
- **懸念:**
  - **「送るたびにユーザーが判断する」をそのまま背負う。** 元の ADR はこれを「再会の場所として成立しない」と書いていた。
    要件9の送信の確認を軽くしすぎると送信の判断が形だけになり、重くしすぎると先生を呼ばなくなる
  - **「可能な限り覚える」は、量が増えるほど毎回渡す量と費用を増やす。** 全部を渡せなくなったとき、覚えたもののどれを渡すかを決める
  - **学習計画は催促に化けやすい。** [feature_ideas](feature_ideas.md) の §0 が避けた「ポイント/ストリークのような催促」に寄らない形が要る
  - Gemini API の規約は無料枠と有料枠で入力の扱いを分けており、無料枠の入力は製品の改善に使われうる。
    クレジットの引き換えでは有料枠の API キーを付けると案内されているが、入力の扱いが有料枠と同じかは書かれていない。着手時に規約で確かめる
  - Firebase の SDK は依存を一度に増やす。機能単位で足し、実機確認を伴う（→ [dependency_policy](../dev/system/dependency_policy.md)）
- **未決:** 使う Gemini のモデル／Nano と先生の振り分けの基準（自動で走る生成は Nano、までは決まっている）／
  回数と月の予算の初期値（クレジットの月10ドルが目安）／先生の記憶の置き場所（クラウドか端末か）／覚えたもののうち毎回どれを渡すか／先生のキャラクターの造形
- **状態:** 技術検証前。
- **規模感:** 大。新しい ADR、権限と検査の書き換え、提供元の分離、設定と利用状況と記憶の画面、先生のキャラクター、中継（Cloud Run・Firebase・Firestore）がすべて新規。
