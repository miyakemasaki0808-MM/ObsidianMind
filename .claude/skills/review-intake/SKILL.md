# レビューの受付

**受け取った経路を問わず、対応に着手する前に受け付ける。** 本文を置かなければ受付簿の検査が起動せず、
行番号まで名指しされた指摘でも取りこぼしが落ちない。規則の正本は [docs/review/README.md](../../../docs/review/README.md)
と [findings.md](../../../docs/review/findings.md) の「書き方」で、ここは順序だけを持つ。

1. **前の本文が残っていれば、先に転記を済ませて消す。** 本文は最大1本
2. 本文を `docs/review/YYYY-MM-DD-<内容>.md` に置く。チャットで受けた指摘もそのまま写す。
   **置いた後は書き換えない。** 本文はコミットしない（`.gitignore`）
3. 指摘ごとに [findings.md](../../../docs/review/findings.md) の受付簿へ1行足す。
   ID は `<本文のファイル名から .md を除いたもの>/<P番号>`、処遇は `起票` か `統合` と課題ID
4. `起票` した指摘は [current_issues.md](../../../docs/_wip/current_issues.md) へ、問題と受理条件まで書く
5. **本文を置いたまま** `ReviewFindingsLedgerTest` を通す（`.claude/gate/gate.sh` でも走る）
6. 検証範囲・結果・未確認範囲を [README](../../../docs/review/README.md) のレビュー一覧へ転記する。
   一覧の行には本文のファイル名を併記する。別の作業のレビューの行は消す
7. 本文を削除し、もう一度検査を通す
8. 受付だけを1コミットにする。指摘の修正は別のコミット（修正1件＝1コミット）
